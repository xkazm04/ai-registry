# Prior art

One file per implementation of this problem that we have studied. Each records what it does, what
we take from it, what we deliberately do not, and where it is ahead of us.

These are working documents, not marketing. They exist so that a design decision made once does
not have to be argued from zero every time someone new asks "why don't we just do it the way
<OTHER PROJECT> does?"

## Rules

- Every claim about another system cites their source as `path:line`, against a pinned version.
- No code is copied in. A teardown records findings and decisions.
- Refusals are recorded with their reasons. That section is why this directory exists.
- Backlog items borrowed from prior art link back to the teardown they came from.
