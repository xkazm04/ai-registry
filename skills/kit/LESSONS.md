# Lessons - kit

Append-only reflection lane. One entry per run that taught something. Format:
`## <version used> - <YYYY-MM-DD> - <project>` followed by `- ` bullets.

## pre-0.1.0 - 2026-09-25 - personas (the forging campaign, run as a spark before this skill existed)
- Local module restyles lost three of four owner gates (two degradations, one "almost non-existent"); the first module composed from a contest-chosen kit passed first time. The setup track therefore puts the kit contest BEFORE any module work.
- The owner protected the theme's primary tint (Gate 0) and a primary-glow status rail (Gate 1). Removing brand tint as a "root-cause fix" reads as degradation; fix what the tint breaks instead.
- A token pass that cut divergence 90% was judged near-nothing; the approved change the same round was a shared table's height and cell layout. The owner grades what the surface visibly does.
- A module was rebuilt in full before anyone noticed its page was imported by nothing: the divergence ranking scored directories, never mount points. Reachability joined to the ranking fixed selection.
- Two close finalists were ported onto the same real page behind a dev switch; the owner chose the more visual one (drawn unit quantities) over the one that matched its source at 0 deviations. Choosing on the product beat choosing in the arena.
- Moving an unlayered token stylesheet into a cascade layer would have woken ~2,000 dead overrides at once; deleting them first, then moving the layer, gave pixel-identical pairs.
- A factory module's healthy and failing states pointed at CSS variables no theme defined and rendered invisible for months; only the BEFORE shots showed it.
- A contest seat stopped on a weekly usage limit mid-build; the rerun on reset delivered. Errored seats are reruns, completed seats are never redrawn.
- A worktree cleanup that followed a node_modules junction deleted the main checkout's .bin and packages mid-campaign; builders' gates failed for reasons outside the work. Check node_modules integrity when many gates fail at once.

## 0.1.0 - 2026-09-25 - personas (first run: /kit grow, then batch 1)
- Every script was a silent no-op with exit 0 when run through the linked skill directory (the registry's normal install): `isMain` compared resolved paths, and a link names the same file twice. Fixed with realpath on both sides plus a regression test that spawns a script through a junction. A "found nothing" run and a "ran nothing" run looked identical - the same failure the method warns about in gates, inside the method's own instruments.
- The ledger could only record a kit part against an existing batch, while the method's rule is "proposed parts not yet built trigger /kit grow". Added a proposed state (no --batch) with who asked and why; `status` prints each open gap as KIT-GAP.
- A kit batch builds parts, not modules, and the ledger refused a batch with no modules. Added `open-batch --kind kit`.
- The batch track needs a KIT SPECIMEN view (every part in its states, dark and light) that builders and the owner consult; the forging campaign never had one because the contest page served as the specimen. grow-1 builds it; the setup track's S6 should create it at promotion.
- The owner judged the first kit card at the scale of his real data, not the fixture's: "projects will have hundreds of contexts" - a flat card grid needs a parent layer that abstracts entities into groups first. The kit batch now builds a groups level with a synthetic 300-entity dataset in the specimen; the doctrine seed gained the rule "cards are for a level where the count is small".
- A kit batch is gated by the owner too: its first part (the card) came back with a layout defect and a scale requirement before any feature batch composed from it. Presenting a kit batch's visible parts before the next feature batch saved a rework cascade.
- Imported is not shipped: Home's Welcome tab (and the Releases page gated at module 1) are DEV-only (a devOnly sidebar flag plus a fallback to the production default tab), so the reachability walk called them live while production users never see them. Selection now traces the gate on the path too - dev-only flags, tier gating, feature flags - and asks the owner whether a dev-only surface is a target (he runs dev builds daily, users do not).
- The Director over-protected decoration: flagged the loss of illustrated nav tiles and per-tour icons on Home as a Gate-1-style degradation risk; the owner approved both. What he protected at every gate was theme tint and glow, not decoration in general. Doctrine rule 2 now says so.
