# A paused item never reaches an ad

An offering carries one flag that says whether it is for sale now. The owner sets it
to pause an item; an availability import sets it from what the feed reported. Every
surface that turns offerings into marketing - creative generation, the batch ad
export, each feed serializer, the pacing table, the brand context - sees only the
offerings whose flag is on, because the filter is applied once, at the seam where the
model is adapted for consumption, and not in each consumer.

The failure this prevents is ordinary and embarrassing: an owner pauses a product
because it is being recalled, discontinued, or repriced, and a week later finds an ad
for it, generated by a batch job whose author did not know the flag existed. The
owner's pause was an approval withdrawn; a surface that advertises anyway has
overridden a human decision by omission, which is the failure
[a gate before money and copy](../../../_laws.md#a-gate-before-money-and-copy) exists to
prevent.

## Procedure

1. **One flag, two writers.** The active flag is written by the owner's pause control
   and by an availability import that carries an explicit value. Nothing else writes
   it - not a pacing rule, not a stock count, not a generator.
2. **Filter at the adapter.** Wherever the offering model is converted into the shape
   consumers read - a plain product list, a feed row set, a brand summary - drop
   paused offerings there. Consumers receive a list that contains no paused item and
   have no flag to check.
3. **Keep the adapter's contract narrow.** If the consumer shape has no slot for a
   pause flag, do not add one; the absence of the slot is what makes forgetting
   impossible. A flag carried downstream is a flag someone will ignore.
4. **Distinguish "paused" from "feed said nothing".** An import whose availability
   field is absent has not reported the item live; it must preserve the existing flag.
   Only an explicit availability value overrides an owner's pause, and the owner's
   pause is the default when the two are in doubt.
5. **Ledger the flips.** Every change of the flag - who, when, from what to what -
   goes into the catalog event ledger, so a paused item's reappearance can be traced
   to the import that reported it available.

## Decision rules

- When a consumer needs to show paused items - the catalog manager itself - it reads
  the model, not the adapter, because the adapter's whole contract is that nothing
  paused passes through it.
- When an availability feed reports an item gone, set the flag off through the same
  path the owner uses, because two notions of "not for sale" (paused, and unavailable)
  produce items that are one but not the other and slip through whichever filter
  checks the wrong one.
- When a feed-imported product arrives with a stock of zero and availability "in
  stock", it is live: the zero is the feed's way of saying it does not carry a count,
  and reading it as sold out would pause a sellable item. See
  [not measured is not zero](../../../_laws.md#not-measured-is-not-zero).
- When the feed carries a real out-of-stock value, emit it there and omit the item
  from feeds that have no such value; never keep a paused item in a feed as "available
  with a long delay" to satisfy the schema.

## Verification

A test fixture with one live and one paused product, run through every consumer,
must produce output that mentions the paused product nowhere: no ad group, no feed
item, no label, no line in the brand context, no row in the pacing table. The test is
cheap and it is the only proof; a code review that checks "did they filter?" is the
manual version of the flag carried downstream.

## When NOT to use

Do not apply the filter to surfaces whose job is to manage the catalog or to explain
history: the catalog editor, the change ledger, the import preview diff. Those must
show paused items, because that is where the owner decides to unpause. And do not
model "temporarily out of stock but for sale" as paused - that is an availability
state told per feed, and conflating it with the owner's pause makes a restock silently
unpause an item the owner deliberately stopped.
