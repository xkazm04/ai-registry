# Codes on the wire, copy in the catalogs (React campaign tab)

The diagnostic crosses three layers with one rule, stated in the Python
module's docstring (`pipeline/jobfit/campaign.py:16-17`): *"Missing facts
surface as stable warning CODES (`no_salary`, `no_location`) the UI localizes —
codes on the wire, copy in the catalogs."*

## Producer: computed from the facts, not from the copy

`_fact_warnings` (`campaign.py:147-158`) takes the **fact dict**, never the
generated variants:

```python
def _fact_warnings(facts: dict[str, Any]) -> list[str]:
    """Stable codes for the concrete facts the pack had to do without —
    computed from the facts (not the output), so both paths report alike."""
```

That parenthesis is the technique's load-bearing detail. The pack has two
producers — the model path and the deterministic fallback — and a diagnostic
derived by inspecting output would disagree between them for the same
requisition. Derived from `_job_facts`, the codes are identical whichever path
ran, which is why `result["warnings"] = _fact_warnings(facts)` sits outside the
branch at `:291`, after both paths have converged.

The composite case is here too (`:153-155`): `WARN_NO_LOCATION` fires only when
**both** `location` and `workMode` are absent, because either fact alone
grounds the location beat. One omission, one code — not two.

Because the codes derive from the salary/location/skills slots of the fact set,
a defaulted value produces the warning rather than the copy: an anchored band
in `defaulted_fields` yields `no_salary`, which is the phantom-field rule and
the diagnostic being the same mechanism seen from two sides.

## Wire: a closed vocabulary, mapped explicitly

`app/features/library/jobs/jobsCampaignTabTypes.ts` holds the consumer side:

```ts
export const WARN_KEY = {
  no_salary: "warnNoSalary",
  no_location: "warnNoLocation",
  no_skills: "warnNoSkills",
} as const;
```

The comment above the neighbouring `HOOK_LABEL_KEY` explains the shape: *"Kept
as an explicit map (not string interpolation into `t()`) so next-intl's typed
keys stay checkable."* The practical effect is that adding a code on the Python
side without adding its catalog entry is a type error, not a raw token rendered
at a recruiter.

`jobsCampaignTabLogic.ts` filters unknown codes out rather than rendering them:

```ts
const warnings = (pack?.warnings ?? []).filter((w): w is keyof typeof WARN_KEY => w in WARN_KEY);
```

A pack generated by a newer pipeline than the loaded client degrades to showing
fewer warnings, never to showing `no_start_date` as literal text.

## Surface: the consequence is in the sentence

`JobsCampaignTab.tsx:94-105` renders the codes as an amber block under the
heading *"Missing facts limited this pack"*, and each catalog string names the
fact **and** what it cost (`messages/en.json:4031-4034`):

- `warnNoSalary` — *"No stated salary band, so pay hooks were skipped. A
  concrete number is the strongest-converting hook."*
- `warnNoLocation` — *"No stated location or work mode, so location hooks were
  skipped."*
- `warnNoSkills` — *"No extracted skills, so stack hooks were skipped."*

Each is a claim about the record plus the angle it would have bought, which is
the technique's whole ask: the recruiter reads a trade, not a complaint about
quality. The salary string additionally ranks itself — naming the pay hook as
the strongest-converting one is how a recruiter facing three warnings knows
which to chase.

Alongside it (`:88-91`) the tab renders `record.source`, green for the model
path and amber for the deterministic one, so a thin pack is legible as
*degraded generation* or *thin record* rather than being ambiguous between
them. Nothing blocks: the pack renders with its warnings above it.

## Deviations from the standard

- **No routing to an owner.** Every code lands on whoever opens the tab. The
  standard asks that a salary absence route to whoever can decide the band and
  a skills absence to whoever wrote the requisition; here it is one panel and
  one audience.
- **No confirm-the-default path.** A defaulted salary band produces
  `no_salary` and no affordance to turn the phantom into an asserted fact. The
  recruiter must go and edit the requisition, which is the friction that makes
  a phantom get re-stamped rather than resolved.
- **No cross-role frequency view.** Codes are per pack and never aggregated, so
  the highest-value output of the technique — which fact this organization
  systematically fails to capture at intake — is not available anywhere.
- **No withholding state.** A deliberately confidential band warns forever,
  which over time trains the recruiter to skip the amber block.
