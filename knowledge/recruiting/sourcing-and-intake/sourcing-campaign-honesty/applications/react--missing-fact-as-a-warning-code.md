# Codes on the wire, copy in the catalogs (React campaign tab, since withdrawn)

**The recruiter-facing half of this page no longer exists in the tree.** kp deleted
the posting modal's Campaign tab on 2026-09-16 (`7198f0c31`: `JobsCampaignTab.tsx`,
its variant card, `jobsCampaignTabLogic.ts`, `jobsCampaignTabTypes.ts` and
`jobsCampaignPackKey.ts`), and `docs/features/jobs/README.md` says so: "Bringing a
pack back to a screen is a new surface, not a revert." The producer, the API and
the pack store remain. The React sections below are therefore the **last state of
a withdrawn surface**, re-read at `402b1f4b8`, the final commit that had it; the
producer sections are re-read at kp `092f2e1e3` (local, unpushed when written).

The diagnostic crosses three layers with one rule, stated in the Python
module's docstring (`pipeline/jobfit/campaign.py:16-17`): *"Missing facts
surface as stable warning CODES (`no_salary`, `no_location`) the UI localizes —
codes on the wire, copy in the catalogs."*

## Producer: computed from the facts, not from the copy (still live)

`_fact_warnings` (`campaign.py:195-205`) takes the **fact dict**, never the
generated variants:

```python
def _fact_warnings(facts: dict[str, Any]) -> list[str]:
    """Stable codes for the concrete facts the pack had to do without —
    computed from the facts (not the output), so both paths report alike."""
```

That parenthesis is the technique's load-bearing detail. The pack has two
producers — the model path and the deterministic fallback — and a diagnostic
derived by inspecting output would disagree between them for the same
requisition. Derived from `_job_facts`, the codes are identical whichever path
ran, which is why `result["warnings"] = _fact_warnings(facts)` sits outside the
branch at `:410`, after both paths have converged. That stayed true when this
pass began dropping model-written variants at the boundary: dropping a variant
changes the copy, not the codes.

The composite case is here too (`:201-202`): `WARN_NO_LOCATION` fires only when
**both** `location` and `workMode` are absent, because either fact alone
grounds the location beat. One omission, one code — not two.

Because the codes derive from the salary/location/skills slots of the fact set,
a defaulted value produces the warning rather than the copy: an anchored band
in `defaulted_fields` yields `no_salary`, which is the phantom-field rule and
the diagnostic being the same mechanism seen from two sides. Since 2026-09-17
(`70342c7be`) the pack also ships `defaultedFields` (`:417`), so "assumed" and
"missing" are two lists on the same payload.

## Wire and surface: what the tab did, at its last commit

`app/features/library/jobs/jobsCampaignTabTypes.ts` held the consumer side, at
`402b1f4b8`:

```ts
export const WARN_KEY = {
  no_salary: "warnNoSalary",
  ...
} as const;
```

(`:27`), beside an explicit `HOOK_LABEL_KEY` map (`:21`) and an `isHookType`
guard (`:40`), for the reason its comment gives: an explicit map rather than
string interpolation into `t()`, so the typed catalog keys stay checkable. Adding
a code on the Python side without its catalog entry was a type error, not a raw
token rendered at a recruiter.

### A correction to this page's own 2026-08-20 account

This page said the surface *"filters unknown codes out rather than rendering
them: a pack generated by a newer pipeline than the loaded client degrades to
showing fewer warnings."* It presented that as the design. kp's tab had already
reversed it by 2026-09-02 (`c585d5dba`), and left its reason in a comment
(`jobsCampaignTabLogic.ts:138-141` at `402b1f4b8`):

> A warning code this build has no sentence for used to be filtered out in
> silence: the pipeline could add a fact the pack had to do without and the
> recruiter would never learn of it. Unknown codes now render as a generic
> warning naming the code — visible, and traceable back to the generator.

`JobsCampaignTab.tsx:111` rendered them through `t("warnUnknown", { code: w })`
inside the same amber block (`:101-115`). The technique now says a code the
surface does not recognise is shown, not dropped; this tree is where the rule was
learned.

### The consequence in the sentence

The tab rendered the codes as an amber block under a `warnTitle` heading, and each
catalog string named the fact **and** what it cost, which is the technique's
whole ask: the recruiter reads a trade, not a complaint about quality. The
sentences quoted on 2026-08-20 (`messages/en.json:4031-4034`) are **not re-quoted
here**: at `402b1f4b8` the catalogs were mid-way through a namespace move and the
keys do not resolve under the same names, so the wording is not something this
pass read.

Alongside it (`JobsCampaignTab.tsx:96-97`) the tab rendered `record.source`,
green for the model path and amber for the deterministic one, so a thin pack was
legible as *degraded generation* or *thin record*. Nothing blocked: the pack
rendered with its warnings above it.

## What is left

The codes still ride every pack payload, through `GET /api/jobs/[id]/campaign` and
the tasks dock, and nothing in `app/` renders them. `jobsCampaignDefaulted.ts`
(the assumed-fact chips) and its `jobs.campaign.defaulted` catalog strings are
orphaned by the same deletion: only their own test imports them. The technique's
claim that thin output becomes tolerable because it is legible has **no live
instance in this tree**; it has a producer and a payload.

## Deviations from the standard

- **The recruiter surface is gone.** Every deviation below was true of a tab that
  no longer exists, and is recorded as the shape a return would have to fix.
- **No routing to an owner.** Every code landed on whoever opened the tab. The
  standard asks that a salary absence route to whoever can decide the band and
  a skills absence to whoever wrote the requisition; there was one panel and
  one audience.
- **No confirm-the-default path.** A defaulted salary band produced
  `no_salary` and no affordance to turn the phantom into an asserted fact. The
  recruiter had to go and edit the requisition, which is the friction that makes
  a phantom get re-stamped rather than resolved.
- **No cross-role frequency view.** Codes were per pack and never aggregated, so
  the highest-value output of the technique — which fact this organization
  systematically fails to capture at intake — was never available anywhere.
- **No withholding state.** A deliberately confidential band warned forever,
  which over time trains the recruiter to skip the amber block.
- **No severity by market.** Every code was advisory in every market. The
  technique now keys a pay code's severity to the regime (a block where the asset
  is itself the advertisement and the law requires the range there); no such
  distinction exists in `_fact_warnings`, which takes no market.
