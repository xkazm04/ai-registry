# Process: gating agent runs against three repositories that were not green

Measured 2026-09-15/16 across a Next.js product, a Rust workspace and a Python agent
platform.

## Why absolute gates were impossible

The Next.js product's unit suite was already red at the benchmark's pinned revision: a
"recipe literals ratchet" test fails there by design. An absolute green requirement would
have failed every run on that repository and made the gate useless as a discriminator. The
harness therefore captured a baseline per repository and revision, once, and stored it —
`{typecheck: 0, lint: 0, unit: 1}` for that product — then required each run's failures to
be a **subset** of the baseline's failing test identities.

The set comparison, not a count, is what makes this safe: a run that had repaired the
ratchet test while breaking another would have kept the count at one and would have been
caught by identity comparison.

## Three red gates that were not the model's fault

- **Stale binaries from a shared build directory.** Rust test gates went red intermittently.
  The first hypothesis was CPU contention; it was wrong. The cause was that gate builds for
  different clones shared one output directory, so a test binary could be replaced between
  build and execution by a sibling run — including by probe clones that had since been
  deleted. Fix: each clone's gates build into their own output directory, removed after use.
- **A type-check reading another clone's build output.** The product's clones linked the
  real repository's build directory to save disk, and its type-check configuration includes
  the generated route types in that directory. When runs at the top tier began building the
  app, those builds wrote through the link, and two later runs type-checked against route
  types generated by a sibling. Their red gates were void; the link was removed from all 75
  clones and from the configuration.
- **A flaky suite.** One soak test failed once and passed on retry. The harness retries a
  failing test gate exactly once, records that a retry was used, and never retries the
  set-comparison gate whose baseline was captured without retries.

## What the shared-state finding exposed about the repository

The link removal also surfaced a genuine defect in the product: its route file exports two
constants beside its handler, which the framework's generated route types forbid. The
type-check gate is green only while no build has generated those types — so the first build
in any fresh checkout turns it red for everyone. That is now a fix request against the
repository, found because the harness stopped sharing build state and started asking why a
gate was red.
