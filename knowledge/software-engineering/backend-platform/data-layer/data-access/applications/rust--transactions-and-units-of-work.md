# The same read-modify-write, guarded once and generated unguarded (personas)

Citations are against `personas` at `58cf9557f` (2026-08-29),
`src-tauri/db` (`personas-db`, `rusqlite@0.38`, SQLite). One tree, one
invariant — a status machine whose transitions are validated before the
write — implemented twice: once by hand with the technique's conditional
write, once by a macro that expands into every lab module without it.

## The hand-written one: compare-and-set, with the verdict read

`update_status` (`db/src/repos/communication/events.rs:339-394`) is the
technique's "single conditional write beats the transaction it replaces"
in full. It reads the current status (`:349-354`), validates the transition
in code (`:356-361`), and then writes with the precondition in the
predicate — `WHERE id = ?4 AND status = ?5`, binding the status it read
(`:373-384`). The comment says why: "to close the TOCTOU gap: if another
thread changed the status between our SELECT and this UPDATE,
rows_affected will be 0 and we reject the stale transition" (`:370-372`).
And the iron obligation is met — the verdict is read and acted on: `if
rows == 0` returns a validation error naming the expected status
(`:386-390`). No explicit transaction, none needed; the race loses loudly.

## The generated one: the same three steps, minus the predicate

> **Resolved 2026-08-29 (personas commits `12668c625` + `be121cf18`).**
> `lab_crud!` now emits the CAS predicate (`AND status = ?7` bound to the
> read status) and reports the changed-concurrently verdict, and the two
> hand-written twins of the same read-then-write (`test_runs.rs`,
> `genome.rs`) received the same predicate. The text below is kept as the
> dated specimen.

`lab_crud!` (`db/src/macros.rs`) generates `update_run_status`
(`:429-482`) for five lab modes — `arena`, `ab`, `eval`, `matrix`,
`consensus` (`db/src/repos/lab/{arena,ab,eval,matrix,consensus}.rs`, each
invoking the macro at `:42-46`). The steps are the same: read the current
status (`:440-454`), validate the transition (`:455-458`), update. The
update is `WHERE id = ?6` (`:469`) — no status in the predicate, no
transaction around the pair, and `Ok(rows > 0)` (`:480`) answers only
"did the row exist". Two concurrent transitions on one run both read the
same starting state, both pass validation, and the second write silently
overwrites the first; the caller of the loser is told `true`. This is the
technique's "read-modify-write is a transaction, not a habit" defect in
its most expensive costume — generated, so it is instantiated five times
and reviewed zero times, in the same crate as the correct spelling.

The repair is the one thirty lines of the sibling file already shows: add
`AND status = ?7` bound to `current`, and turn `rows == 0` into the
"changed concurrently" verdict rather than folding it into not-found.

## The rest of the boundary discipline, for contrast

Where the tree does open boundaries, it opens them for the reason the
technique gives — a read whose result feeds a write — and says so.
`research_lab.rs:159` and `:646` use an immediate-mode begin so "the dedup
SELECT and the INSERT are one serialized unit" and "the `MAX(run_number)+1`
read and the INSERT are one", the lock-first form that makes the
read-then-insert race impossible on a single-writer engine. Repository
functions own their boundaries and never take a scope parameter; the
composability question the technique raises is therefore answered by the
engine's refusal to nest, and the tree carries eighteen sites of the
unchecked-nesting variant of begin (listed by the survey across
`memories.rs`, `personas.rs`, `tools.rs` and the migration helpers) whose
safety depends on no caller already holding a transaction on the same
connection — an audit the technique's "operations must not care" rule says
should not need to exist.

Side effects wait for commit, and the design is explicit: the engine's
change hook fires inside the writing transaction and does nothing but push
onto a channel; the emit and the wake-ups happen from a drain task after
the write has landed (`db/src/cdc.rs:3-7`, `:397-401`).

## Reconciliation summary

Confirmed: the compare-and-set update with its verdict read and acted on;
immediate-mode boundaries opened exactly where a read feeds a write, with
the reason written down; side effects deferred past commit by construction.
Deviation: the identical invariant generated by macro into five modules
without the predicate and without a boundary, returning success to the
loser of the race — the defect the tree fixed by hand elsewhere, reproduced
by generation. Upward lesson: a generated operation inherits the review of
its template and nothing else; a macro that emits a read-then-write is a
macro that must emit the predicate.
