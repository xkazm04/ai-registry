# A readiness passport that records the pointer and cannot record the reason (Node, JSON manifest)

A desktop application in this fleet publishes a machine-readable **readiness
passport**: fifteen dimensions — context coverage, agent instructions,
documentation, tests, evals, observability, security, hosting, database,
auth, CI, cost and so on — each carrying a `level` naming the rung it has
reached on that dimension's ladder, a `tool` naming what discharges it, a
`skippedByChoice` flag, and an optional free-prose `note`. It is exactly
the shape this technique is about: a long-lived item advancing through
stages, whose per-obligation evidence must stay readable long after the
assessment that produced it.

## The A/B

The measurable is **how many dimensions' evidence state is determinable
from structured fields alone**, without a human reading prose. Both arms
were run as read-only predicates over the same live passport; no product
code was changed.

- **Arm A — the schema as shipped.** `tool` is a string or null,
  `skippedByChoice` is a boolean, and everything else lives in `note`.
  **11 of 15** dimensions resolve: they carry a `tool` pointer, so the
  obligation is discharged and the artifact is named. The remaining four do
  not. Three (`agent_instructions`, `reusable_skills`, `app_cost`) hold
  `tool: null`, which merges three different claims — *no tool is needed
  here*, *a tool exists and nobody recorded it*, and *nobody has looked* —
  into one value. One (`llm_tracking`) is flagged skipped, which says a
  decision happened but not what it was.
- **Arm B — the four-state field.** Satisfied-with-pointer,
  in-progress-with-pointer, absent-with-pointer-to-why, explicit unknown.
  **15 of 15** resolve, by construction.

A second measurable, run the same way: **dimensions whose evidence age is
individually knowable.** Arm A returns **0 of 15** — the passport carries
one collection-level `generatedAt`, five weeks old at the time of reading,
so a dimension re-verified last week and one last checked before that date
are indistinguishable. Arm B returns 15 of 15. This is the cheaper of the
two changes and the one with the larger effect, because a passport ages as
a unit today and therefore ages entirely or not at all.

## The prediction that did not come true, and why it still matters

The technique predicts an unreadable-blank population: cells with neither a
pointer nor an explanation. **This tree has none** — 0 of 15 dimensions
carry a null `tool` *and* no `note`. Every non-satisfied dimension has a
prose sentence saying why, several of them good ones ("local single-user
app; auth = key management"; "schema_version ledger deliberately
deferred").

That is a real negative and it is reported as one: on this tree, today, the
failure mode the technique is most worried about is absent. But it is
absent for the reason the technique names as the hazard rather than the
fix — **the discipline is the author's, not the schema's.** Nothing
requires the note, nothing validates it, and nothing distinguishes a note
that explains an absence from a note that decorates a success. The passport
is regenerated by a maintenance command; the first regeneration that fills
`level` and `tool` without prose loses the explanation with no error
anywhere. What the technique buys here is not a repair of current state, it
is making the current state survive its next author.

## The structural fact: the most valuable state is inexpressible

The finding worth more than either arm came from asking what the schema
*cannot* say. Across all fifteen dimensions there is **no `reason` field,
and no field of any name that pairs an absence with a pointer** — verified
by enumerating the union of keys actually present, which is exactly
`level`, `tool`, `skippedByChoice`, `note`.

So the state this technique calls the most valuable of the four — *absent,
with a pointer to why* — has no home in the model. `skippedByChoice` is a
boolean: it records **that** a skip happened and structurally cannot record
what it was for. The one dimension using it is an external-tracing
capability whose skip is a genuine architectural decision, precisely the
case where the reason is the whole content of the record, and the schema
routes that content into free prose or drops it.

Nobody designed this. It fell out of modelling a skip as a flag, which is
the natural thing to do when the field is added — and it is better evidence
for the technique than the counts above, because the passport's author was
clearly *trying* to record reasons and the schema gave them nowhere
structured to put one. A boolean is what an absence state degenerates to
when it is added as an afterthought rather than designed as a vocabulary.

## The same error again, one layer down, in a type system

The passport above is a hand-maintained document with no type behind it —
the skip flag appears in no source file, so nothing generates or validates
it. The same project also carries a **typed** passport model, used to render
many projects side by side, and reading it found the identical failure in a
form that no author discipline can paper over.

Every one of its eleven per-dimension level unions begins with the member
`none`. None of them has a member for *not assessed*, and the level field is
non-optional — so a dimension nobody has evaluated must still be given a
value, and the only value available means "this project genuinely has none
of this." The conflation is not an oversight: the deriving module documents
it as the intent, stating that where there is no signal the passport shows
an explicit gap.

What makes it worth recording is that the mistaken value does not sit
quietly. It propagates all the way to a claim:

- one dimension's level is derived as a **binary** over a five-member union,
  leaving three levels unreachable — the record can express states the
  producer can never emit;
- the `none` value scores zero of that dimension's eighteen points, so an
  unassessed project ranks as a failing one;
- and it is rendered to the reader as a **sentence asserting the absence** —
  a blocker line telling the user this project has no monitoring bound.

An absent measurement is thereby published as a definite negative claim
about a real project, which is
[unknown-is-not-a-value](../../../../_laws.md#unknown-is-not-a-value) at the
type level in eleven places at once.

Two further asymmetries fall out of the same read. The evidence fields per
dimension are uneven — one dimension carries three, another two, another
one, and one carries **none at all** — and the dimension with no evidence
field is precisely the one whose level cannot be corroborated from the
record. And the skip flag that the hand-maintained document does carry has
no counterpart in the typed model, so a deliberate, reasoned skip is not
merely unstructured there: it is **discarded at the boundary**.

The pair is the argument for the technique in miniature. One project
produced two independent shapes of the same error — an absence state
degenerating to a boolean in the document, and to a definite value in the
types — and neither was designed. Both are what happens when the
non-satisfied side of an evidence field is added as an afterthought instead
of enumerated as a vocabulary. The instrument that makes it visible is
cheap and precedes any change to scoring or gating: add the not-assessed
member, then count the dimensions holding it. That count immediately
separates the absence claims that are findings from the ones that are
guesses.

## What this application cannot claim

Both arms measure **readability of the record**, not compliance: no
dimension's actual readiness changed, and arm B does not make a single
obligation more likely to be met. The technique's own limit applies in
full — this reports, it does not refuse. The passport blocks nothing today
and would block nothing after the change.

The one number that would test the stronger claim — that a countable
backlog attracts work an uncountable one does not — needs two passport
generations under the new schema to compare, and this tree has one. That is
the return condition.
