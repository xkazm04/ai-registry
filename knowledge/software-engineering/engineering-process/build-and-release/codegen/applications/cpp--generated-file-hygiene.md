# Two generators, one that formats its output and one whose twin is hand-written

Read against Chatterino 2.5.5 (`CMakeLists.txt:71`, Qt 6 required per
`CMakeLists.txt:30,100`) at commit `fda51f0d3a4a5cd15f099b951b796e299d566e9e`.
Two generators write tracked files in this tree: a libclang-driven script
that derives JSON deserializers from annotated C++ structs for the push-event
payload library (`lib/twitch-eventsub-ws/ast/generate.py`), and a
doc-comment scraper that derives editor type definitions for the plugin API
from the C++ header that exposes it (`scripts/make_luals_meta.py`).

## A correction to the design read first

The design read describes the payload generator as writing into
"marker-delimited regions of hand-written files". That is the retired
scheme. At this commit `generate.py` writes two whole files per annotated
header: the declarations to a sibling `.inc` that the header `#include`s
inside its own namespace (`ast/generate.py:72`,
`include/twitch-eventsub-ws/payloads/channel-update-v1.hpp:40`), and the
implementation to `src/generated/payloads/<name>.cpp` (`generate.py:73-74`).
The marker-region scheme survives only in documentation:
`lib/twitch-eventsub-ws/src/payloads/README.md:33-34,50-51` still shows
`// DESERIALIZATION DEFINITION START/END` blocks and `:60` still names a
`generate-and-replace-dir.py` that no longer exists in `ast/`. That README
sits beside two hand-written sources in a directory the generator no longer
targets (`src/payloads/channel-ban-v1.cpp`, `channel-moderate-v2.cpp`) -
the technique's "retired root abandoned in place, still carrying
instructions" state, with the instructions pointing at the old mechanism.

## Where the tree confirms the technique

**The generator absorbs the formatter.** Both generated outputs are run
through the project's formatter before being written (`ast/lib/generate.py:52-57`
via `format_code`), and the pre-flight check refuses to run at all if the
formatter is missing (`ast/check-clang.py:25-29`). The formatting gate
covers `lib/twitch-eventsub-ws/include` and `src`
(`.github/workflows/check-formatting.yml:33`) with no carve-out, and there
is no oscillation because the generator's output is already formatted output
- the one-writer rule kept by folding the second writer into the first, the
same branch the corpus's Rust application took.

**Timestamps stay out of the artifact.** The generator's `--timestamp`
writes the build clock to a side file in the build directory
(`generate.py:58,89-92`; `cmake/GenerateJson.cmake:176-179,186`) used as a
dependency stamp, never into the generated source. The outputs are a pure
function of the header and the templates.

**The drift gate forces the generator.** The build regenerates only when a
working toolchain is detected and otherwise compiles the committed outputs
silently (`GenerateJson.cmake:146-161`); the pipeline sets
`FORCE_JSON_GENERATION=On`, which turns "toolchain missing" into a fatal
configure error (`GenerateJson.cmake:151`), builds, then diffs
`include` and `src` against the checkout (`.github/workflows/eventsub-test.yml:53-59`).
The generator's own unit tests run first in the same job (`:46-49`).

**The plugin typings' header does most of the technique's job.** The
generated `docs/lua-meta/globals.lua` opens with "This file is automatically
generated from src/controllers/plugins/LuaAPI.hpp by the
scripts/make_luals_meta.py script" (`make_luals_meta.py:51-59`): generated,
derived-from, and generated-by, in one line emitted by the generator. The
lint job regenerates it and fails on any diff (`.github/workflows/lint.yml:28-31`).

## Where it falls short

**The declaration files carry no header at all.** A generated `.inc` begins
directly with a function declaration
(`include/twitch-eventsub-ws/payloads/channel-update-v1.inc:1-5`); nothing
in it says it is generated, by what, from what, or how to rebuild it. It is a
generated file impersonating an authored one, sitting in the same directory
as the authored headers it is included from, and its only protection is the
drift gate catching the edit after the fact. The implementation files do
better but not fully: `// WARNING: This file is automatically generated. Any
changes will be lost.` (`ast/lib/generate.py:17`; e.g.
`src/generated/payloads/automod-message-hold-v2.cpp:1`) states the
consequence and includes the source header on the next line, but names
neither the generator nor the rebuild command - two of the technique's four
lines, and the reader who wants to change something is left to find
`ast/README.md` on their own.

**The plugin API has a second, hand-maintained typing.** `docs/chatterino.d.ts`
describes the same API for a second language's users
(`docs/wip-plugins.md:108-110`), carries no generation header, is referenced
by no script, and is gated by nothing. It is the hand copy of a vocabulary
whose authority is the C++ header, and it drifts exactly when someone adds
an exposed function and regenerates the one that has a generator.

**Two mechanisms for one class.** The payload generator is invoked by the
build system and stamped per header; the typings generator is a script run
by hand and by the lint job. Neither is registered anywhere a reader could
enumerate "what in this tree is generated" - the inventory is two READMEs
and a workflow file.

**No determinism test.** Nothing runs the generator twice and compares; the
drift gate compares one run against the checkout, which catches
nondeterminism only when it happens to differ from what was last committed.
