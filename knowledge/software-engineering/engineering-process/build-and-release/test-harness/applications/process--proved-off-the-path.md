# Process: looking for a twin in a skills lane

The miner proposed this registry's own `skills/leonardo` as a small instance: tests beside a tool no
method file names. That seam was chosen because it could falsify the claim that the shape exists here.

## The run

A throwaway census over `skills/`, using stems as the join: an instrument under `scripts/` or
`tools/` counts as reached if `SKILL.md` or a file in `references/` names it, or if a sibling
instrument imports it.

| Count | Result |
| --- | --- |
| Skills with instruments | 17 |
| Instruments | 134 |
| Named by no method file, imported by no sibling | 5 |
| Of those, with a test | 1 |

The miner counted 117 and 4 with a different walker, and the difference was not reconciled.

**It refuted the miner's reading.** The one tested tool is `tools/qwen-image.mjs`, and
`tests/test_api-tools.mjs` spawns its real command line against a server that never answers. That
test is on the path an operator runs. What is missing is a line in the method, so the technique gained
that exclusion. Of the rest, `tight-crop` is named by a sibling skill's method, which a walk of one
skill cannot see.

## The verdict

Target: twins or hand-composed guards in the lane. Floor: no tool wrongly reported as off the path,
which the miner's reading of this seam failed. Nothing moved because the lane holds no instance, so
the verdict is `unmeasurable`. Return when a project keeps a program beside a model-run procedure;
the instrument is then the procedure edit in the technique's second test, run against that suite.

## What this cannot do

Stems are a coarse join: a word in prose counts as naming a tool, so the count of 5 is a floor for
what no method names. It says nothing about a guard's callers inside a tool. No suite was run and no
file changed.
