# Suite partitioning — five configs, one of which quietly owns another's files

*Verified against the project tree at `bf2a1e249`.*

An A/B against a desktop app's vitest portfolio, testing the technique's
[implicit-default-suite](../techniques/suite-partitioning.md) rule: *make the
default suite's discovery boundary as explicit as every other suite's, and
verify the partition is exhaustive and disjoint.*

## The seam

The portfolio is real and legible — five vitest configuration files plus a
Playwright config, membership by location, each lane with its own environment
and budget. The default lane declares itself at `vitest.config.ts:17`:

```ts
include: ["src/**/*.test.{ts,tsx}", "tests/playwright/**/*.test.ts"],
```

and the CLI end-to-end lane declares itself at `vitest.e2e.config.ts:15`:

```ts
include: ['src/test/e2e/cli-*.e2e.test.{ts,tsx}'],
reporters: ['default', new CliE2eReporter()],
```

Those files are named `cli-<thing>.e2e.test.ts`. They end in `.test.ts`, they
live under `src/`, and the default lane therefore matched all five of them
too. Two configurations claimed one set of files — with different reporters
and different intended budgets — and nothing said so.

## A and B

**A** is the tree as it stands. **B** adds one explicit boundary to the
default lane and one invocation to CI:

```ts
exclude: [...configDefaults.exclude, "src/test/e2e/**"],
```

plus a `Run CLI e2e lane` step (`npm run test:e2e:cli`) beside the existing
`Run frontend tests` step in the workflow. The second half is not decoration:
the workflow runs `npm run test -- --run` and nothing else, so removing the
e2e files from the default lane without adding their own lane to CI would have
dropped 179 tests out of the only gate that runs.

## What was read

The runner's own discovery, per configuration, before and after:

| | default lane | e2e lane | overlap |
| --- | --- | --- | --- |
| A | 521 files | 5 files | 5 |
| B | 516 files | 5 files | 0 |

The diff of the two file listings contains exactly the five e2e files and
nothing else. Under B, `vitest run src/test/e2e --config vitest.config.ts`
answers `No test files found` and prints the boundary it applied; the e2e lane
run reports `5 passed (5) / 179 passed (179)`. Partition exhaustive
(516 + 5 = 521), disjoint, and the same tests still gated. Verdict: **better**.

## The fact the tree gave up that nobody designed

The double claim was not the interesting part; the reporter was. The e2e lane
exists *because* it carries `CliE2eReporter` — a lane-specific report is the
whole reason it is a separate configuration. But CI never invoked that
configuration. So the 179 tests did run on every push, under the default
lane's environment, and produced no e2e report at all: a lane whose output
artifact had never once been generated by CI, while its tests were green the
whole time. This is the technique's *counts travel with their suite* claim in
its sharpest form — "all tests pass" was true and "the e2e lane passed" was
never a statement anyone had made.

The second lane is worse and needed no A/B: `vitest.integration.config.ts:3`
imports `./src/test/integration/integration-reporter`, and `src/test/` contains
no `integration/` directory. Invoking that lane fails at config load with
`Module not found`. It appears in the portfolio, it has an npm script, it is
referenced nowhere in CI, and it certifies nothing. The technique's
observation that an unavailable answer gets replaced by folklore is visible
here as a lane that exists only as a filename.

Also worth recording against the technique's cost-tier argument: the five e2e
files spend `environment 8.10s` and `transform 4.34s` against `tests 1.51s`.
The per-file environment tax dominates by roughly five to one, which is the
technique's "the fix is partitioning, not a longer timeout" point measured in
a tree that had already partitioned — and then let the boundary leak.

## What this realization cannot do or prove

- It proves the *partition* is now disjoint. It does not prove the e2e lane's
  budget or environment is right for its tests; nothing here measured whether
  those five files belong in the e2e lane rather than the default one. The A/B
  moved a boundary to match the declaration, and took the declaration's word.
- It cannot show what B does to CI. The workflow change was never executed —
  no run of the pipeline exists on the branch — so "the same 179 tests keep a
  gate" is read from the two local lane runs plus the workflow's text, not
  from a green pipeline.
- It says nothing about the report-reconciles-its-own-denominator rule. This
  tree's runner reports discovered-versus-reported counts on its own; no test
  was starved in these runs, so that half of the technique was not exercised
  and remains unverified here.
- The dead integration lane was diagnosed, not repaired. Deleting a config
  that a person may be mid-way through building is a product decision, and
  an A/B that removes a lane cannot distinguish "abandoned" from "unfinished".
