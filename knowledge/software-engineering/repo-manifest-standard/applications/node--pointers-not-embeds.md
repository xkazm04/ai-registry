# Only pointing at what the generator actually ships

The `paths` block of the manifest generated by
`src/lib/standard/manifest.ts` in the Ascent repo
(`C:\Users\kazda\kiro\ascent`) is a compact case study in the rule that costs the
most to learn: never point at what you do not ship.

## The dangling pointer, and the two ways it was repaired

`manifest.ts:54-60` carries the incident in the code comment:

> ONLY pointers the foundation ships. The doctor validates every path declared
> here, so a pointer to something we never generate (the old `evals: "evals/"`)
> was a guaranteed warn on every fresh install for a subsystem a scan cannot
> synthesize. Declare `evals` when you have one.

The shipped `paths` map is therefore exactly three entries — `contextIndex`,
`memory`, `guardrails` — each of which the generator actually writes. The
resolution contract is stated in the emitted file itself (`manifest.ts:122-125`):
"Every path DECLARED here must exist (the doctor checks it); a pointer you don't
declare is not a finding," with a commented example of how to add an optional one.

That is one of the two repairs. The other, for `paths.guardrails`, went the
opposite direction — `src/lib/standard/guardrails.ts:1-7` explains that the
pointer "used to point at a file the foundation never generated: a dangling
pointer in the very contract that sells 'pointers, not embeds'. Rather than drop
the pointer we made it real." Both repairs satisfy the same invariant. What is
forbidden is the third state: a declared pointer with nothing behind it.

## The invariants file is real *and* partly enforced

Making the pointer real was not sufficient on its own. The same comment continues:
"and — critically — made part of it MACHINE-CHECKED: the doctor fails when git
tracks a file matching `secrets.neverCommit`. An invariants file nothing enforces
is just prose."

The generated `guardrails.yaml` (`guardrails.ts:25-50`) is the manifest's other
half: `neverTouch` globs, `secrets.neverCommit`, `secrets.from` (a vault *name*,
never a secret), and a `review` block (`humanApproval: required`,
`verifyBeforePropose`, `attributeAiWork`). It is a separate file behind a pointer
precisely so it "can grow without touching the spine," and it is written in the
same regex-friendly subset so the zero-dependency runner reads it with the same
helpers it uses on the manifest.

## Precision as a design constraint on the enforced subset

`guardrails.ts:15-20` fixes the never-commit list at `.env`, `.env.local`,
`*.pem`, `*.p12`, `*.pfx`, `id_rsa`, `id_dsa` and documents the exclusions as
deliberate: it

> Deliberately EXCLUDES near-miss globs that match legitimate committed files
> (`.env.example`, `*.key` used for non-secret key material) — a guardrail that
> cries wolf on a fresh install is the failure mode this whole direction exists
> to remove.

`standard.test.ts:340-347` pins the exclusions as assertions — `NEVER_COMMIT`
must *not* contain `.env.*` or `*.key`, and must contain `.env` and `*.pem` —
with the reasoning restated in the test: "A guardrail that fires on `.env.example`
or a committed public key is worse than none: the gate becomes noise and gets
disabled."

Pinning an *absence* is the unusual and correct move here. Nothing about normal
review pressure protects a conservative pattern list; the natural drift is toward
broader globs, one well-meaning addition at a time.

## Existence is not resolution

The shipped spec's pointer check (`spec.ts`, conformance item 2 inside `SPEC_MD`)
adds the second half of resolution: a co-located context document that is "still
the shipped template (its `<placeholder>` markers intact) is reported as
unfilled: existence alone is not context." The scaffolded templates carry a
machine-detectable marker for exactly this reason — without it, a repository full
of untouched templates would score as fully documented.

Correspondingly `standard.test.ts:312` asserts that the manifest's own `spec`
pointer is a member of the generated file set, so the rule "declare only what you
ship" is enforced against the contract's most important pointer too, not merely
documented.
