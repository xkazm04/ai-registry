# Declared mapping is terminal

## The concern

A compliance check cannot compare a design item to an implementation until something says
*which* implementation. That relation is a quantity like any other, and it needs exactly one
authority. When it is inferred at scoring time by string similarity, the inference is
recomputed on every run, changes when either name is edited, and is reported with the same
confidence as a relation somebody actually established.

## Three resolution states, and only three

Every design item resolves to exactly one of these, and each is a different fact:

1. **Mapped** — a declared entry names the implementation artifacts that evidence this item.
   The declaration is terminal: no heuristic may override it, supplement it, or "improve" a
   declared relation it thinks is incomplete. If the declaration is wrong, the fix is to
   change the declaration.
2. **Heuristic** — no declaration exists; a fallback guessed a relation. The guess may be
   used, but it is labelled as a guess on the finding itself, and the item is simultaneously
   listed as unmapped. It is second-class in output, not merely in the author's intent.
3. **Unmapped** — no declaration and no fallback hit. The item is invisible to every
   cross-check that depends on the relation. This is a finding, not a pass.

Do not add a fourth state for "probably mapped" and do not let confidence scores blur the
first two. The value of the split is that a reader can filter to declared relations and get
a report with no guesswork in it at all.

## A declared empty mapping is a real answer

The state most implementations lack: an item declared to map to **nothing** — because
nothing in the implementation surface can evidence it. Verification items ("test the full
save and load cycle"), tuning items, and process items are like this. Mapping them to a
plausible-looking artifact is precisely the false positive the declaration exists to
eliminate, so they are declared empty on purpose.

An empty declaration must render as *no artifact can evidence this item*, never as a clean
pass and never as "unmapped". It produces no conformance finding by construction, and it
tells the reader why. The three-way distinction — mapped to things, mapped to nothing,
not mapped yet — is what keeps a well-covered document from looking identical to an
unexamined one.

## Arity: a mapping resolves to every named artifact

The common bug is taking the first hit. One design item routinely covers several
implementation artifacts — a "foundation package" item may name six classes — and grading it
against whichever one matched first means five of the six were never checked, silently.

Rules:
- A declared mapping resolves to **all** named artifacts; the item is graded against every one.
- A design-ahead finding fires if **any** named artifact is missing, and states how many of
  how many.
- A code-ahead finding fires only if **every** named artifact is done. One artifact complete
  out of six is not a box somebody forgot to tick; it is an item still in progress, and
  reporting it as bookkeeping is how a partially-built item gets closed.

## Dangling names, and when not to report them

A declared name that matches no artifact in the scan is a **dangling mapping** — either the
artifact was renamed or the declaration was written against something that never existed.
Count it and report it; it is a defect in the mapping table itself.

But suppress it when the area has no scan at all. A never-scanned area reports every declared
name as dangling, which says nothing beyond "nobody scanned it" — a fact already reported as
an evidence gap. Emitting hundreds of dangling names for one missing scan buries the finding
that matters under noise generated by its own absence.

## Key the declaration by scope, not by item id

Design item identifiers are rarely globally unique; the same short id often exists in several
areas of a document. A flat identifier-to-artifact table silently cross-wires them, producing
findings about one area from another area's evidence. Key the declaration **area → item →
artifacts**, and refuse cross-area references outright: a cross-check compares one area's
design against that area's own evidence, and an item that genuinely depends on another area's
work is a dependency edge, not a mapping.

Pin the declared names against the artifact registry with a test. A mapping table whose names
have drifted out of the registry fails loudly rather than degrading into dangling entries.

## Publish the mapping's own coverage

The relation table has a coverage figure of its own, and it bounds every cross-check built on
it. If only 88 of 216 items are related to anything, the cross-check categories are dark over
59% of the document, and a report showing few findings is showing few findings *about the
41% it can see*. State mapped, empty-by-declaration, multi-artifact, heuristic, unmapped and
dangling counts in the report header. Without them, an absence of findings reads as health.

## Treat the heuristic as a shrinking budget

A fallback keeps the check useful during migration. It should not be permanent furniture. The
heuristic count is a debt figure: it starts at whatever the guess covers and is driven toward
zero by writing declarations, with the report making the remaining debt visible each run. A
fallback whose count never falls has become the authority by default, which is the failure
this technique exists to prevent.

## When not to use this

- **Surfaces with a genuine identity join.** If the design item and the artifact already
  share a stable identifier, use it; a declaration layer adds a second authority for a
  relation that already has one.
- **Exploratory one-off analysis.** A throwaway pass over an undocumented surface is allowed
  to be entirely heuristic — as long as its output is labelled as an estimate and never
  becomes an input to a gate.
- **Where the relation is many-to-many and volatile.** If items and artifacts are re-cut
  weekly, a hand-maintained table will be stale more often than right; invest instead in
  making the artifact registry the place items are declared.
