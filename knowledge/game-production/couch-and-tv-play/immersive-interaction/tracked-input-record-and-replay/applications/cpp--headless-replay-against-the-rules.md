# Replaying synthetic hands against the shipped detectors, before any device recording

Source tree: `mage-arena-vr` on `master` at `27e1633` (the root of every path below),
read in a detached checkout. The stack is C++ in an Unreal Engine 5.8 project, witnessed by
`"EngineAssociation": "5.8"` in `apps/vr/Game/MageArenaVR.uproject`. The project declares no
`CppStandard` override, so the language level is the engine default, C++20. Node scripts
generate the clips.

**No tracked hand made any clip counted here.** All 111 clips under `apps/vr/Game/Clips` carry
`"source":"synthetic"` in their header. The corpus, impostor, noise and mouse sets live in
`apps/vr/Game/TestClips/`, which is gitignored (`.gitignore:31`) and regenerated by
`apps/vr/tools/clipgen/`. The plan records real hands for its V2 window, 5 to 8 November 2026.
Until then every figure below is a proxy figure about the rules, and none of it is device
evidence.

## The seam, chosen to falsify

The technique has three parts: run the shipped rule, treat a replay divergence as a finding,
and bind the verdict to the clips and the rules revision. Its decision rules add one more
claim: an expectation produced by running the rule is circular and is a snapshot. This tree
has many expectations produced by running the rule, so it can falsify that claim. If they
turned out to be real checks, the rule would be wrong as written.

The audit read all 33 automation tests in the five gesture suites, `BlinkTests.cpp`, `SigilTests.cpp`,
`WardTests.cpp`, `SystemGestureTests.cpp` and `HeldSampleTests.cpp` under
`apps/vr/Game/Source/MageArenaVR/Tests/`. Each test was classified by where its expected
value comes from. Other suites, such as the defence and settings tests, also call the
detectors. They were read only to check a claim, and they are not in the counts.

| Oracle class | Tests | Example anchor |
| --- | --- | --- |
| authored: clip intent or a plan number | 18 | `apps/vr/Game/Source/MageArenaVR/Tests/SystemGestureTests.cpp:218` "none fires with the bit forced on every frame." |
| pinned from an earlier run | 2 | `apps/vr/Game/Source/MageArenaVR/Tests/HeldSampleTests.cpp:1092` "Floors set to what the first run measured (phase 0)." |
| two-sided ratchet | 1 | `apps/vr/Game/Source/MageArenaVR/Tests/HeldSampleTests.cpp:1374` "so a loss fails and a gain fails until this table is updated." |
| differential: same rule, 72 Hz vs modelled 30/25 Hz stream | 6 | `apps/vr/Game/Source/MageArenaVR/Tests/HeldSampleTests.cpp:566` "const bool bMatch = HeldResult == Reference;" |
| structural: loading, plumbing, no rule verdict | 6 | |

Every rule verdict comes from a shipped class: the blink, ward and staff detectors, the
sigil stroke builder and recognizer, and the system-gesture gate inside each subsystem. **No
test replaces a detector with a double.** That is the technique's first rule, and the tree
already meets it.

## Arm A and arm B

- **Arm A (the gate as it reports today):** a green `Automation RunTests MageArena` counts
  all 27 rule-verdict tests as checks on the rules.
- **Arm B (the technique's decision rules applied as written):** every expectation produced
  by running the rule is relabelled a snapshot. That covers 9 tests: the 2 pinned, the
  ratchet and the 6 differentials.

**Target:** the rule-verdict tests that the technique says must not count as a rule check.
**Floor:** no real check is demoted. Arm B breaks the floor. The six differentials are not
circular: a wrong rule does not make "the input path leaves the verdict unchanged" pass.
They are the technique's own divergence section, built before any device exists. So the
verdict on the technique **as written is `not-better`**, and it gained a boundary section.
With the boundary applied there are 3 snapshots and 6 differentials kept as input-path
checks, with two conditions on the differentials.

## What the decision rules did find

The parts of the technique that held found three real gaps. They are filed as the project's
next changes and not built, because this pass ran no headless engine build.

1. **Differentials with no anchor on the reference.** The ward differential fails when the
   reference is empty, with `apps/vr/Game/Source/MageArenaVR/Tests/HeldSampleTests.cpp:585` "raised no ward at 72 Hz: the reference is broken".
   The blink, sigil-line and staff differentials do not. A detector that fires
   nothing at 72 Hz and nothing on the stream matches itself and passes. Blink, sigil and staff clips are asserted to fire with
   authored counts in other tests, so today this is a latent gap, not a live false green.
2. **No binding.** No test output names the clip set it read or a rules revision. The
   regenerated corpus means a green run is tied to whatever the generator produced on that
   machine.
3. **An authored oracle that is a copy of the rule.** Four ward tests compute the expected
   onset with the rule's own constant, `apps/vr/Game/Source/MageArenaVR/Tests/WardTests.cpp:380` "if (Speed >= FWardThresholds::OnsetSpeedMps)".
   A wrong threshold moves the test and the
   rule together. This is the second half of the new boundary section.

A fourth candidate was refuted on review: that the staff detector has no reject clip. A
reader limited to the five suites reported none. The defence suite feeds the staff detector
a mudra clip and asserts it, `apps/vr/Game/Source/MageArenaVR/Tests/DefenceTests.cpp:1324` "mudra does not plant".
A rule's coverage is the union over every suite that drives it, not the suite named after it.

The sigil acceptance gap is already recorded in the drawn-gesture recognition subject's
held-out acceptance application, so it is not repeated here. The plan asks for 95% on the
owner's held-out draws, and the test asserts 90% on generated mouse clips.

## What this realization cannot do

It cannot say anything about real hands. The divergence half of the technique, a replay
that disagrees with the live session it recorded, has no live session to compare against
yet. The held and extrapolated streams are the project's own models of a runtime, and its
comments say so. The project row for this application is in `mage-arena-vr`'s
`.ai/applied.jsonl` at `d25ecc7`. Return condition: re-run the divergence half once V2
records real hands, and add the reference guard as a paired code A/B
once a pass includes a headless engine build. The A/B uses a mutation: a detector that never
fires should be red under arm B and green under arm A.
