# The `publications/` lane

Approved technical posts, written for readers outside this registry. One directory per
post: the structured record in `publication.json`, the post in two renderings
(`post.html`, a self-contained page; `post.md`, the Medium-ready text), the research log
in `SOURCES.md`, the figures as portable SVG, and a paste-ready Medium package. The lane
is text-only: the SVGs are canonical, and the PNG renders Medium needs are derived, not
stored here.

Every other lane holds material that agents and projects consume. This one holds what
the registry *says in public*: once a post is pasted into Medium it cannot be recalled.
That is why the lane has two rules no other lane has. **Only approved posts land**, and
**the gate checks mechanics, never quality**. Whether a post is good is decided by the
human at the approval gate; whether it has a dangling citation, an undated source, a
"we" the standard forbids or a page that fetches a font from a CDN is decided here,
mechanically, so that an approval is never spent on a defect a machine could find.

The standard a post is held to is registry content: the `technical-blog-post-authoring`
recipe in `recipes/` and the `technical-writing` bundle in `knowledge/`. A publication
references that standard **by address** (`standard: {recipe, version, bundle}`) and
never copies it.

## The shape

```
publications/<slug>/publication.json     # required - the publication/1 record
publications/<slug>/post.html            # required - self-contained page, fetches nothing
publications/<slug>/post.md              # required - the Medium-ready text, [n] citations
publications/<slug>/SOURCES.md           # required - sources, claims map, experiments log
publications/<slug>/figures/NN-<name>.svg   # one per listed figure
publications/<slug>/medium/story.html    # required - clean, script-free paste source
publications/<slug>/medium/tags.txt      # required - 1 to 5 Medium tags, one per line
publications/<slug>/medium/README.md     # required - the paste steps for a human
publications/<slug>/medium/figures/NN-<name>.png   # optional, never required - derived PNG renders (not committed)
publications/<slug>/critique/reviews.json       # optional, with dispositions.json - the critique detail
publications/<slug>/critique/dispositions.json  # (both or neither; only with a `critique` block)
publications/index.json                  # GENERATED by scripts/build-publications-index.mjs
```

`depth: fixed` (registry.yaml): exactly one directory level. The article pipeline's
write-back is deterministic code that writes `publications/<slug>/`; a category folder
inserted here would be a broken write-back, not a reorganization. Consumers select
posts through the generated index.

The set is **closed**. A file outside it fails the gate - a stray draft, a screenshot,
a notes file, a raw reviewer transcript dropped into `critique/` - because everything in
this directory is publishable by construction. Working material stays in the pipeline's
run directory.

`<slug>` is kebab-case and is the publication's identity: the directory name and the
`slug` field must agree.

### Figures

`figures/NN-<name>.svg` is the portable source of each figure: `NN` is its reading
order, `<name>` a kebab-case handle. Every SVG must be listed in `publication.json`
`figures` with a caption and a source list - an unlisted SVG is a figure without a
caption, which is what the rule forbids. SVGs fetch nothing (no external `href`, no
script). Tables that Medium cannot render are figures too.

`post.html` may render a figure natively (HTML, inline SVG, an interactive viewer)
instead of embedding the SVG; the SVG is what `post.md` and the Medium package use.

**The lane is text-only, like the rest of the registry** (`.gitattributes`: there is not
one binary asset). The SVG under `figures/` is the canonical figure. Medium does not
take SVG, so pasting needs a PNG of each - and that PNG is a **derived artifact**: a 2x
render of the SVG that lives in the article pipeline's run directory and is regenerated
from the SVG whenever it is needed (`medium/README.md` gives the steps). The registry
does not store it and the gate never requires it.

`medium/story.html` refers to the renders **by name**: an image is
`<img src="figures/NN-<name>.png">`, relative, for a listed `figures/NN-<name>.svg`
with the same `NN-<name>` stem, and is valid whether or not the PNG exists. Any other
image source fails: another relative path, an absolute path, a `data:` URI, a network
URL, or a PNG name whose SVG is not listed. `medium/figures/` is optional; when it is
present (a render made beside `story.html` for a paste), it may hold only
`NN-<name>.png` files whose SVG is listed. Renders are not committed.

## `publication.json` - schema `publication/1`

```json
{
  "schema": "publication/1",
  "slug": "the-token-tax",
  "title": "The Token Tax",
  "subtitle": "One sentence on what the post shows.",
  "topic": { "kind": "subject", "bundle": "localization", "subject": "some-subject",
             "text": "The topic as a sentence.", "angle": "optional framing" },
  "date": "2026-10-05",
  "readMinutes": 14,
  "status": "approved",
  "standard": { "recipe": "technical-blog-post-authoring", "version": "0.1.0", "bundle": "technical-writing" },
  "sources": [
    { "n": 1, "url": "https://...", "title": "...", "publisher": "...", "date": "2026-10-05",
      "primary": true, "counter": false, "took": "What the post took from it." }
  ],
  "claims": [ { "text": "A claim the post makes.", "source": 1 } ],
  "figures": [ { "file": "figures/01-name.svg", "caption": "Figure 1. ...", "sources": [1] } ],
  "check": { "citations": "pass", "first-person": "pass" },
  "run": { "id": "<run id>", "model": "<model id>", "effort": "medium", "costUsd": 1.23 },
  "critique": {
    "rounds": 1,
    "reviewers": [
      { "id": "reviewer-claude", "engine": "claude", "model": "<model id>", "effort": "high",
        "outcome": "completed", "costUsd": 0.42 },
      { "id": "reviewer-grok", "engine": "grok", "model": "<model id>", "effort": "high",
        "outcome": "unavailable" }
    ],
    "findings": { "total": 3, "accepted": 1, "rejected": 1, "deferred": 1 },
    "decision": "keep"
  }
}
```

| Field | Meaning |
| --- | --- |
| `topic.kind` | `subject` (the post writes up a registry subject: `bundle` and `subject` are required slugs) or `free` (free text: `bundle` and `subject` are omitted). `text` is always required; `angle` is optional. |
| `date` | Publication date, `YYYY-MM-DD`. |
| `readMinutes` | Integer read time, computed (words over reading speed plus figure time), not guessed. |
| `status` | Always `approved`. A post is written here only after the human gate. |
| `standard` | The recipe slug, its version, and the bundle slug the post was held to - an address, resolvable in `recipes/index.json` and `knowledge/<bundle>/index.json`. |
| `sources[].n` | `1..N` in order; the number every `[n]` citation uses. |
| `sources[].date` | The page date when the page states one (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`, as precise as the page is), otherwise the date it was read or downloaded. `SOURCES.md` says which. |
| `sources[].primary` | The source is the origin of what the post takes from it (a paper, a standard, vendor documentation, a dataset, the post's own measurement). |
| `sources[].counter` | The source cuts against the post's thesis or limits it. |
| `sources[].took` | What the post took from this source, in one or two sentences. |
| `claims` | The load-bearing claims, each anchored to one source number. |
| `figures` | Every figure file, its caption, and the source numbers behind it. |
| `check` | The deterministic quality check the pipeline ran: dimension -> `pass` or `fail`. A `fail` does not block the lane - the human approved over it - but it stays on the record. |
| `run` | The run that produced the post: `id`, `model`, `effort`, and `costUsd` when the CLI reported one. |
| `critique` | Optional. Who reviewed the first draft and what the writer decided - see [The critique record](#the-critique-record). |

**Absent-value convention: omit the key, never `null`.** `costUsd` is omitted when the
CLI reports no cost; `topic.bundle`/`topic.subject` are omitted for a free topic;
`critique` is omitted for a post that never went through the critique step. The gate
rejects any `null` anywhere in the record. Unknown keys are rejected too: within
`publication/1` the key set is closed, and a new field is a schema bump. `critique` is
the one optional top-level key the schema names, declared with the critique step on
2026-10-05; a record without it is the same schema, not an older one.

A source's own measurement is a source like any other. It is cited as `[n]`, it is
`primary`, and its `url` points at the experiments section of the publication's own
`SOURCES.md` on the registry's public remote, where the commands are logged.

## The critique record

The article pipeline runs a multi-model critique between the first draft and the
deterministic check. Up to four reviewer models, from different providers and at high
thinking effort, each read the draft blind to the others and return findings. The writer
records a disposition for every finding - accepted, rejected or deferred, each with a
reason - and decides whether the draft is kept, rewritten or sent back to research, for
at most two review rounds. A reviewer can be unavailable (a provider out of balance, a
seat limit, a timeout); the pipeline continues when at least two reviewers completed.

That history is published with the post because the field should be able to learn from
it: which reviewers found what, which findings a writer took and which it argued down.
Reviewer ids and model strings are public identifiers, not private evidence.

**The pipeline always writes the `critique` block.** The imported contest winner,
`the-token-tax`, predates the critique step and carries none; it stays valid as it is.

```json
"critique": {
  "rounds": 1,
  "reviewers": [ { "id": "<slug>", "engine": "claude", "model": "<model id>",
                   "effort": "high", "outcome": "completed", "costUsd": 0.42 } ],
  "findings": { "total": 3, "accepted": 1, "rejected": 1, "deferred": 1 },
  "decision": "keep"
}
```

| Field | Meaning |
| --- | --- |
| `rounds` | Review rounds that ran: `1` or `2`. |
| `reviewers[]` | 1 to 8 entries with unique `id` slugs. `engine` is `claude`, `codex`, `grok` or `agy`; `model` is the model id the engine ran; `effort` is `low`, `medium`, `high`, `xhigh` or `max`; `outcome` is `completed`, `unavailable`, `timed-out`, `errored` or `seat-limit`; `costUsd` only when the CLI reported one. |
| `findings` | Counts over every round: `total`, `accepted`, `rejected`, `deferred`. `total` equals the other three summed. |
| `decision` | What the writer decided after the last round: `keep`, `rewrite` or `research`. |

A publication with a `critique` block **may** also carry `critique/`, holding exactly
two files. The directory never stands alone: without the block it is review evidence for
a decision nobody recorded, and the gate fails it.

`critique/reviews.json` - one object per reviewer per round:

```json
[ { "reviewer": "<reviewer id>", "round": 1, "model": "<model id>", "effort": "high",
    "verdict": "revise", "summary": "One paragraph.",
    "findings": [ { "id": "f1", "kind": "factual", "severity": "major",
                    "location": "Section 2, second paragraph", "claim": "What is wrong.",
                    "evidence": ["https://..."], "suggestion": "What to do instead." } ] } ]
```

`verdict` is `publish`, `revise` or `rework`; `kind` is `factual`, `format`,
`engagement`, `insight` or `voice`; `severity` is `blocker`, `major` or `minor`. A
finding `id` is unique within its review; a finding is identified by reviewer, round
and id together. `findings` and `evidence` may be empty arrays.

`critique/dispositions.json` - one object per finding:

```json
[ { "reviewer": "<reviewer id>", "round": 1, "findingId": "f1",
    "disposition": "accepted", "reason": "Why.", "action": "What changed." } ]
```

`disposition` is `accepted`, `rejected` or `deferred`; `reason` is required and
non-empty; `action` is optional and omitted when nothing was done.

**The gate checks the mechanics only.** It can tell that every finding has exactly one
disposition and that every disposition has a reason; it cannot tell whether the reason
is a good one, whether a rejected finding was right, or whether the decision follows
from the findings. That judgement belongs to the human at the approval gate, who sees
the same files.

## Citations

One `[n]` per source, in running text and captions alike: `[3]`, or `[9] [10]` for two.
A grouped form (`[9, 10]`, `[17-21]`) fails the gate, because a reader and a checker
both need to resolve each reference on its own. `post.html` may wrap the citation in a
link to its list entry (`<sup><a href="#r3">[3]</a></sup>`); the visible text is still
`[3]`. A `[n]` inside code is not a citation.

## The gate

`node scripts/check-publications.mjs` (lane row: `node scripts/gate.mjs --lane
publications`). Every rule is mechanical; quality judgement is not gated.

| Rule | Fails when |
| --- | --- |
| `shape` | a required file is missing; a file sits outside the fixed shape; a figure file is misnamed or missing; `medium/tags.txt` holds 0 or more than 5 tags or repeats one; a `medium/story.html` image is not `figures/NN-<name>.png` for a listed `figures/NN-<name>.svg` (the PNG itself is never required); `medium/figures/` holds anything but `NN-<name>.png` renders of listed figures; `critique/` holds anything but `reviews.json` and `dispositions.json`, or lacks either |
| `schema` | `publication.json` does not parse, is not `publication/1`, has an unknown or missing key, carries a `null`, has `status` other than `approved`, or a field has the wrong type or form |
| `slug` | `slug` differs from the directory name, or either is not kebab-case |
| `citations` | a `[n]` in `post.md`, `post.html` or `medium/story.html` does not resolve to a source; a claim cites a missing source; a citation groups sources; `post.md` cites nothing |
| `sources` | a source has no date or a malformed one, or no URL or a malformed one (an `http(s)` URL with a real host) |
| `source-mix` | fewer than 8 sources, 3 primary, or 1 counter |
| `figures` | a figure has no caption or no source list, cites a missing source, or an SVG under `figures/` is not listed |
| `first-person` | `I`, `my`, `me`, `we` or `our` appears in the prose of `post.md`, `post.html` or `medium/story.html`. Exempt: code, blockquotes, `<q>`, and text inside double quotation marks |
| `self-contained` | `post.html` has an `http(s)` (or protocol-relative) `src`/`srcset`, an external stylesheet or resource `<link>`, an external script, or a CSS `@import`/`url()` to the network; an SVG figure references the network or carries a script; `medium/story.html` carries a script or a network source |
| `placeholders` | lorem ipsum, a bracket placeholder (`[TODO]`, `[TBD]`, `[citation needed]`, `[insert ...]`, `[n]`...) or a `{{template hole}}` survives in a post rendering, `SOURCES.md`, the Medium files or any string of `publication.json` |
| `privacy` | a machine home path (`C:\Users\<name>\...`, `/home/<name>/...`) appears in any file of the publication, `critique/` included - the same rule as `check-public-paths.mjs` for the other lanes |
| `critique` | the `critique` block has an unknown or missing key, a value outside its vocabulary, `rounds` outside 1-2, 0 or more than 8 reviewers or a repeated reviewer id, or a `findings.total` that is not accepted + rejected + deferred; `critique/` exists without the block; a critique file does not parse, has the wrong shape or carries a `null`; a review names an undeclared reviewer or a round past `rounds`; a `completed` reviewer has no review; an evidence URL is malformed; a disposition names a finding that does not exist, a finding has no disposition or more than one, a `reason` is empty; the block's counts differ from the dispositions |

A source listed but never cited is a **warning**, not a failure: an uncited source is
untidy, not wrong.

The gate asserts its own detectors on planted cases before it reads the lane, and exits
`2` (FATAL) when the lane is missing or empty: reporting nothing is not finding nothing.
`--root <dir>` points it at another lane root (tests and fixtures); positional
arguments check individual publication directories.

**Fix the publication, never the rule.** A rule that a real post cannot honestly pass
is a finding about the rule, raised as a change to this document and the script
together, with the post that exposed it.

## The index

`node scripts/build-publications-index.mjs` writes `publications/index.json`: slug ->
path, title, subtitle, date, read minutes, status, the topic's address (never its
text), the standard, and source, primary, counter and figure counts. A publication with
a critique also gets `critique: {reviewers, rounds, decision}`, where `reviewers` counts
the reviewers whose outcome was `completed`; the key is omitted when the post has no
critique. It excludes the topic text, sources, claims, figures, check, run, the
critique's reviewers and findings, and `critique/` - open the publication. `--check`
verifies freshness without writing, newline-insensitively, and the gate row runs it
after the content gate so an index is never built over a lane that failed its shape.

`publications/` is not one of `build-catalog.mjs`'s hashed lanes; its index is its
selector, and a publications-only change cannot make `catalog.json` stale.

## How a post gets here

1. The article pipeline (gravitone `/articles`, or its CLI) researches, outlines,
   drafts, critiques and checks a post against the standard it resolves by address,
   and stops at the human gate with the post, its sources, the critique record, the
   check report and any proposed registry patches.
2. On approval, deterministic code - never the agent - writes `publications/<slug>/`
   on a new branch of this registry, applies the approved patches, runs
   `node scripts/gate.mjs --lane publications` plus the lanes the patches touch, and
   opens a pull request. A red gate leaves the branch local and opens nothing.
3. A CODEOWNERS owner merges. Merging is adopting, here as everywhere.

A post may also be imported by hand, as the first one was: `the-token-tax` is the
winning entry of the technical-writing contest run on 2026-10-05, imported after the
owner declared it the winner. Its `run` block records the contest run that wrote it, and
its `check` block records the mechanical checks this lane's gate and an inspection of
the page established at import (content preview present, code highlighted) - not a
pipeline run. It has no `critique` block: the contest that produced it predates the
critique step.

## What this lane does not do

- It does not judge quality. The recipe's dimensions (structure, storytelling, depth,
  figures, voice, medium fidelity, truth) are the human's checklist, not this gate's.
  Nor does it judge the critique: a disposition's reason is checked for presence, never
  for merit.
- It does not talk to Medium. The Medium package is files a human pastes.
- It does not resolve URLs. A well-formed URL may still be dead; liveness is a report,
  not a gate, for the same reason `check-citations.mjs` reports and never fails.
- It does not check that `standard` resolves. The recipe and bundle can move under a
  published post; the address records what the post was held to at the time.
