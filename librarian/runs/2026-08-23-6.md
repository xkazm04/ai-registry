# Run 2026-08-23-6 - twelve pairs, five repos, and one pattern under eight of them

The second `/conform` wave, following the five-pair first run. Twelve pairs across
five projects and four bundles, chosen to reach the three bundles that had never been
evaluated against a consumer at all: `recruiting`, `game-production`, `media-generation`.

Verdicts: **11 deviations, 1 not-applicable.** Every deviation carries a
`file:line` anchor and a consequence. Written back to five maps; consults logged locally.

## The finding this run exists for

Eleven deviations, and **eight of them are at a boundary the technique never mentions.**

Not one of these repos lacks the machinery a technique asks for. In almost every case the
mechanism exists, is well built, is commented with the incident that produced it - and then
stops at the edge of the module that owns it:

| Repo | The mechanism, built correctly | Where it stops |
| --- | --- | --- |
| pof | `scoreMesh` enforces coded findings, `measured` flags, three-valued readiness at the type level | the asset-forge wire type keeps the prose `reasons` and drops the codes; the badge prints the conflated count under the label the split replaced |
| systedo-case | `truncated`, one freshness rule, `tileSnapshotValue` refusing a confident `0` | all three are wired to the interactive report and dropped at both export seams - the caveats live where a reader could check and vanish where they cannot |
| ascent | the gate endpoint fails **closed** on an unreadable org policy, with a comment naming it as the one path that used to fail open | the badge route - same helpers, 100x the readership - still carries the `.catch(() => null)` that was removed there |
| kp | six named sample floors, each justified at the arithmetic, each unit-tested | every one lives in an extracted `app/_lib` module; the claims with no floor are the ones computed inline in the query layer |
| kp | `metric-pack.ts` holds the richest three-state contract in the codebase | it reaches the reader only as a file download - the tab exports more honesty than it displays |
| personas-web | a genuinely good bulk path: revert-on-failure, undo window, bounded concurrency, cross-tab lock | the triage surface lives in a different process from the state machine, so Retry can only *create* - each click duplicates and the lane never drains |
| ascent | `governance.ts` refuses to derive `protected:false` from a failed read - "protection UNKNOWN → null, never a confident false negative" |  the PR sensor in the same pipeline swallows a thrown fetch to `null` and warns only when the token is absent, so a failed sensor is indistinguishable from "no PRs" - and is cached and written to the shared corpus as the repo's standing |
| pof | one exclusion set, one scheme constant, a documented v1 to v2 history | the digest's projection and the judged payload's projection are two sets, because unifying them costs a corpus-wide `unknown` |

The corpus writes its techniques as properties of a mechanism. These repos show them
behaving as properties of a *path*: re-applied at the module that owns them and silently not
re-applied at every projection, export seam, error branch, and process split that carries the
value onward. kp states the corollary most cleanly - **the extraction boundary, not the
claim's importance, predicts which numbers are honest.**

The ascent row is the sharpest form of it: **the same repo, the same pipeline, one sensor doing
it right and its neighbour not.** The rule was known, written down, and applied once.

This is not a gap in any one subject. It recurred in four bundles under eight different
techniques, which is what a cross-cutting rule looks like before anyone writes it down.

**Owed:** decide whether this is a technique inside an existing subject or a subject of its
own. The candidate rule, in the repos' own words: *a guarantee holds at the boundary it is
carried across, or it does not hold; name, for each guarantee, the artifact that carries it
past the module that computes it.* Three techniques independently proposed a local version of
it this run (`structural-scorecard`, `provenance-caveats`, `customization-scope-guard`).

## The doubtful flags: both falsified, and that is the result

Per the method rule from run 1 ("a reader told only to find deviations will find them"), two
of twelve pairs were briefed as *probably not applicable* and told that refusing was a
first-class answer. Both premises were wrong, and in both cases testing the premise was the
finding:

- **personas-web x `hitl-approval`** - briefed as probably a demo surface. The reader traced
  the dispatch: `mockApi` is reachable only behind an explicit `isDemo` click, the
  orchestrator proxy route exists in the repo, and the resolve path PATCHes real approval
  state. A `not-applicable` would have been the wrong refusal, and would have silently
  retired a surface with an unattended auto-approver on it.
- **systedo-case x `executive-reporting`** - briefed as an engineering-assessment subject
  facing an ad report. The reader checked the golden path's own object definition and the
  bundle index's transplant-clean clause before the code: the subject defines a
  stakeholder-facing document generically, and taxonomy location is not a boundary.

So the rule earns a second half. **Brief the doubt, but require the premise to be tested
rather than honored.** A flag is a hypothesis handed to the reader, not a verdict handed down;
both readers reported the test itself, which is why both refusals were caught as wrong.

The single genuine `not-applicable` this run was argued the same way and from the same
direction - `generative-provider-routing` scopes itself to image and video vendors in its
opening line, and `llm-core-providers` routes structured text calls. `model-routing` was
written back as the corrected pairing, so the next run judges the right standard.

## Verification, and one claim narrowed

Every load-bearing claim was re-checked against the tree before recording; the Director reads
diffs, not reports. The checks confirmed the sharp ones exactly - `isStanding` does admit
`unknown` and the UI copy says "and counted" out loud; kp's bulk *accept* does fire
unconfirmed where bulk *reject* is gated; systedo's `validateRecap` does check field presence
only while the UI promises in two languages that the model may not invent numbers.

One claim was **overstated and narrowed before it entered the map.** The mesh reader reported
that defect codes "reach no route or component". They reach two: the mesh-finish remediate and
status routes both project `failCodes` from `findings`. The drop is real but lane-specific, and
the recorded evidence says so. A conformance finding that overstates its reach is the same
defect class as the instrument bugs this registry keeps catching - it would have been re-found
forever as a contradiction.

## Coverage questions raised (not yet dispositioned)

- **A subject for the mirror surface** (personas-web, twice): every technique in
  `delivery-guarantees` and `hitl-approval` assumes one codebase owns the queue, the record
  and the console. Which repo is judged when they are three?
- **A subject for demo honesty**: a surface whose data plane can be swapped for fixtures owes
  a persistent, non-dismissible label naming which plane is live. Named rather than folded
  into `hitl-approval`. Forge lead.
- **Two medium-agnostic rules stranded in the visual lane**: asymmetric steering (*prefer* is
  advisory, *avoid* is binding) and credential elimination that must be recorded rather than
  filtered. `model-routing` has neither.
- **A transitional two-projection state** (pof): the standard's own decision rule makes the
  correct fix maximally expensive, which is precisely why a well-run repo ends up with two
  exclusion sets and a comment explaining why. The missing half is "how to converge".
- **Measured-but-not-routed** (pof): how does a reviewer grade an axis that is implemented,
  tested, exported, and unreachable from any production path?
- **Which score is the score of record** (kp): no technique says which score a bulk boundary
  reads when a system holds several, or that the deciding score must be the one shown on the
  surface that reviews the decision.
- **conform vs applications overlap** (personas-web): one pair re-derived findings an
  application file recorded the day before. Should conform read `applications/` first and
  report only the delta?

## Upward lessons offered by the repos

- **kp** improves `terminal-decisions-stay-with-a-person` twice: the guard against a re-run
  overtaking a human is *event-keyed* rather than time-keyed (a window expires; a reinstated
  marker does not), and the signed approval is invalidated by **rule** drift as well as cohort
  drift - a policy change that leaves the reject set byte-identical still forces a fresh
  review. Also seal-first ordering: a candidate whose record cannot be written is *kept* and
  counted, so the wave under-rejects loudly rather than emailing unrecorded rejections.
- **systedo-case** on why a written rule is not a gate: the team wrote the no-invented-numbers
  rule three times - prompt fragment, schema description, and user-facing UI copy promising the
  guarantee to the operator - and enforced it zero times. Worth naming in the smell list: *a UI
  string asserting a guarantee is the strongest single tell that no gate exists.*
- **ascent** on `customization-scope-guard`: a tighten-only merge is vacuous when the baseline
  it tightens can silently evaporate. *An unreadable authority is not an absent authority.*
- **personas-web** on `severity-sla-ladder`: name the durable artifact each rung's terminal
  action produces. A rung that leaves nothing behind an API boundary is a hold rung and must be
  declared as one.
- **ascent** on `llm-assisted-scanning`, and this one is the best single offer of the run.
  The technique says a model finding is a candidate verified against the target; it has no rule
  for when verification is *structurally unavailable*. ascent has one, stated as a design law:
  at most two dimensions may be widened by the model's own discrepancy report, **and if more
  than two are flagged, none are** - because "a scan whose audit claims most detectors are
  broken is not a scan where the model has earned more trust". All-or-nothing on purpose:
  any keep-the-first-N rule needs a tie-break the model controls (ordering). Proposed rule:
  *when a model's self-report can move a number and corroboration is unavailable, bound the
  payoff rather than the claim - cap how many claims may pay out, void the channel above the
  cap, and never keep a prefix.*
- **ascent** on `ingestion-budget`: the coverage figure does not only gate caching and print a
  caveat, it proportionally reduces the model's authority over the score (`effectiveBlend =
  SCORE_BLEND x coverage`), and the realized blend weight is persisted on the report. Stronger
  and checkable: *confidence weights the inference's pull, and the realized weight is recorded.*

## Method notes

- Twelve concurrent readers held quality with no Director reverts, on the same scope rule as
  the deepen batches: read-only, standard before code, `unknown` when uncertain.
- Briefing the two bundles forged *from* the repo they were judging ("judge the code as it is
  now; a technique describing what this repo used to do is not automatic conformance") was
  necessary - both returned deviations against their own origin repo.
- `.ai/consults.jsonl` is gitignored in all five consumers by design, so the consult ledger
  stays local while the verdicts travel in the map. Confirmed, not assumed.
