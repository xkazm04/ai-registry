# Run 2026-08-23-4 - the usability reflection: is anyone better off?

The operator asked two questions the sweeps had never asked, because every sweep
grades supply. Will an AI developer benefit from this structure and its information
going forward? Will a product benefit from this being documented, against a
library-less world? Both were answered by measuring, and the honest answer to both is
"yes, with one condition that is not yet met".

## Question 1 - will an AI developer benefit from the structure?

**What a consult costs.** The consult skill's own default path was measured, not read:
a subject consult is the golden path plus the techniques that apply, about 12K tokens
for a six-technique subject (webhook-ingestion: 49KB). That is the right price. But the
skill's default routing step said "score every technique's `use_when` by hand" over
`index.json`, and the software-engineering index is ~142K tokens (569KB; recruiting
80K, the five small bundles 14-47K each). A routing-only projection is still 31% of
that. So the index is an address book for a script and was being offered to an agent
as a document. The router (`research-map.mjs`) costs zero context tokens - and its
default path scored slugs only, with `use_when` behind an opt-in flag that re-opened
every file, under a comment saying the index did not carry the field. The index had
carried it since the use_when backfill: 1,900/1,900 entries.

Measured consequence: a query phrased exactly as a technique's routing trigger ("one
delivery minted two internal events") ranked its subject THIRD on the default path,
behind two slug-word coincidences. The 1,900 phrases written to be matched on were
unreachable on the path every consult takes.

**Fixed in-session.** The router now scores technique `use_when` from the index by
default, with the file-read fallback reserved for `--deep` (which adds the golden
path's own `use_when`, the one thing the index does not carry). The same query now
ranks its subject first (27 points, `use_when shares ...` in the reason). The consult
skill (1.1.0) routes by script whenever a checkout exists, and tells remote-only
consumers to fetch ONE bundle, named by the manifest. The standard carries a
reachability clause with the test spelled out.

**Whether anyone consults at all.** Six connected projects adopted the consult skill.
Three consults have been logged in total, all on 2026-08-23, all in one project,
none had reached `signals/` (the collector last ran the day before; folded now: three
bundles witnessed, four deviations). Every one of the six projects declares its bundles
in a manifest; none of their agent guides says "consult". The knowledge is reachable
and not recalled - the weakness the README names for a consult-only design, now with
a number on it.

A sibling session committed the fix for this while the reflection was measuring it:
a rules file for consumers' standing context that says when to open a subject and
that the standard does not bend to the code; a generated `registry-map.json` per
project joining its contexts to the subjects that govern them; a `conform` skill that
writes `conformant` / `deviation` / `not-applicable` back per pair. This reflection
does not re-propose the mechanism. It records the baseline it will be judged against:
**3 consults, 4 deviations, 3 bundles in thirty days.** The next sweep reads
`signals/` and says whether those numbers moved.

So: the structure serves an AI developer when the path is a script and a subject - and
as of today it is. Going forward the index keeps growing with every application; the
router absorbs that, a remote consumer does not. A routing-only projection
(`routes.json`, ~31% of the index) is the obvious artifact for remote consults, banked
below rather than built beside a sibling mid-flight in the build scripts.

## Question 2 - does the information beat a library-less world?

Three lines of evidence, in increasing strength.

**The deviations.** Four deviations from three consults - every consult found the
consuming repo short of the standard somewhere. Small n, but the sign is the point: a
library whose every reading surfaces a gap is doing the job a review does, cheaper.

**The campaign's findings.** Holding famous code to a written standard found two
upstream-reportable bugs in three days: a restore path that verifies before the
rename and a form library's in-flight guard nested under a retry hatch so two submits
10ms apart both fire (measured). Neither was found by reading for bugs. Both were
found because a technique said what correct looks like, and the code did not match.
A library-less reviewer has "does this look right"; this one has "does this do what
the standard says, and if not, is it the code or the standard". Twelve laws now exist
that no single repository could have produced, because each is a convergence across
four or more trees.

**The experiment.** `scripts/experiments/library-vs-cold.mjs`, run today on the free
fleet: three design tasks (webhook dedup, retry storm control, migration boot
failure), each answered COLD and WITH one technique document in context, by the same
model, graded blind by the same model against the technique's seven rules with quoted
evidence, the raw answers kept so the grader can be overruled.

| task | cold | with library | words cold / lib |
| --- | --- | --- | --- |
| webhook-dedup | 5/7 | 7/7 | 1303 / 992 |
| retry-storm | 5/7 | 7/7 | 1321 / 1302 |
| migration-boot | 4/7 | 7/7 | 1256 / 956 |
| **total** | **14/21** | **21/21** | shorter in all three |

The seven absent verdicts were re-read by hand: six hold, one is a half (the cold
migration design refuses "skip the failed step" but not "log it and mark it done").
What a capable model did not produce unprompted is exactly the incident-earned
material: a digest fallback when a sender mints no id; retry vs replay with a signed
timestamp window; a fleet-wide retry budget as a fraction of volume; warn-once logging
with a suppressed count; the failed verdict persisted in the ledger; the error's
required fields; the named refusals. And the library answers were shorter - the
document replaced exploration, not added to it.

Caveats stated plainly: the rubric IS the technique's rules, so this measures transfer
and unprompted-knowledge gap, not whether the cold answers held merit the rubric does
not reward (the cold migration design was good - five outcomes, a refusals table);
n=3 tasks; one model family; the grader is a free model. The instrument is in the repo
to be re-run with a stronger grader and more tasks.

## The rung nobody could claim

The standard's first known gap - "the maturity ladder is unused" - turned out to be a
definition gap. `reconciled` and `transplant-tested` were names without criteria, so
the external-reconcile lane produced the substance of `reconciled` twenty-nine times
and every one of those subjects still says `forged`. The standard now defines both
rungs. The 29 are candidates; flipping the field is a reviewer's act, proposed here,
not done.
