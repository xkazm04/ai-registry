## Accepted (2)

### 1. `excess-indicts-the-instrument` → quality-gates *(new technique, corrects two claims)*

`gate-liveness` enumerates every instrument-failure signal and **all of them are
deficiency signals** — zero files walked, rules failed to load, tool absent,
trigger never fired, green for a year. There is no excess signal anywhere in the
subject. Meanwhile `blocking-by-input-determinism` asserts that a thousand
pre-existing findings is *"a statement about the backlog, not about the check"*,
and `ratchet-design` then freezes that number as a baseline while guarding only
the **drop** below it. The three compose into a trap: baseline a population
produced by a wrong root set and the ratchet defends the misconfiguration
forever, because the count only ever goes down.

The source takes the opposite position in code: `counters.files > 20` → bucket by
workspace, rank by contribution, emit *"you are probably unconfigured (N unused
files)"* as `hintTypesOrder[0]`, above every individual finding.

**The A/B refuted my own first draft** — see the applied section. The technique
shipped with the correction already folded in.

### 2. `precision-trades-have-a-direction` → codebase-scanning *(new technique, corrected premise)*

**"false negative" appears 6 times in the entire 155-subject bundle and zero
times in `false-positive-economics`, `checker-false-positive-discipline` or
`dead-code-detection`.** The corpus's checker material is one-directional.

Wall 2 of `codebase-scanning` states the asymmetry — *"recall failures are
invisible and forgiven"* — and uses it to justify deprioritising recall. The
correction: invisible-and-forgiven is a description of a defect class nothing
will ever surface on its own, which is the reason recall needs a deliberate
instrument, not the reason to forgive it. Two dated first-party instances from
one tool: v3→v4 discarded a reference tracer and **announced a false-positive
risk to users**; v5→v6 discarded the type layer for name-based matching and
introduced **false negatives on shadowed bindings, recorded only in
`.agents/EXPORTS.md`**. The direction users can act on got the loud channel; the
direction they cannot got the quiet one.

**Terminology hazard recorded:** the corpus already uses "shadow-declaration
defeat" for something else entirely — dead code referencing dead code. The new
technique avoids the word.

## Applied (2 rows, both experiment mode)

| technique | verdict | what it cost |
| --- | --- | --- |
| `excess-indicts-the-instrument` | **not-better** | the discriminator has a confound |
| `precision-trades-have-a-direction` | **better** | measured a zero where no number existed |

Row 1 is the valuable one. A managed project carries a committed ratchet baseline
with **230 unreachable files out of 982 walked (23.4%)**, frozen 2026-08-24 —
eleven and a half times the source tool's own self-suspicion threshold, and
nothing asked. Bucketing reproduced the baseline exactly and fired on 7 clusters
at 2.4x–4.3x lift, several at 100% directory saturation. **All seven were genuine
dead code. Zero were root errors.** The confound: *dead code arrives in whole
features*, so "no root declares this" and "this island is dead" predict the same
distribution. Clustering is a **sampler**, not a discriminator; the second stage
(a referrer check per cluster) is what decided all seven. The technique gained
that section before it was committed.

Incidental structural fact from the same run: one fully-unreachable eight-file
component's only reference from live code is **a doc comment in a live component
recommending it**. Nobody designed that; it fell out of code being deleted around
prose that stayed.

Row 2: the project adopted the scanner at v6, so the pre-swap arm never existed
and its 1329-export baseline carries an unrecoverable unknown. Built the seeded
construct corpus the technique prescribes — 11 dead exports, one per shadowing
construct on the maintainer doc's own enumeration — and ran it against the exact
binary the project consumes. **11 of 11 detected, zero false negatives:** the
documented recall class is real as history and closed in 6.32.2. `better` because
the instrument converted an unmeasurable property into a measured negative in ten
minutes.

## Lead (1)

- **Serializability is the architectural gate, and one feature can hold it
  hostage.** One analysis capability (class members) required a resident
  typechecker; dropping it made every intermediate state serializable, which
  unlocked per-unit disposal, resume-from-last-completed, disk caching, remote
  caching and parallelism *at once*. The v4 post promised to restore the feature
  behind a flag; v6 made the removal permanent because the upstream API is being
  rewritten in another language. **Return condition:** a second independent source
  describing a pipeline whose decoupling was blocked by exactly one feature — at
  which point this is a doctrine about pricing an architecture against its least
  serializable capability, and probably belongs near `module-design`.
