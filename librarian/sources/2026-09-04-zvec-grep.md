## The design record (Phase 2d)

Seven entries across four systems, abbreviated here to decision / forces / corpus.

**System A - the agent-facing search surface**

- **A1. One tool of six on the default agent toolset; index create, rebuild and
  drop live on the human CLI only.** Forces: an agent's tool budget, and index
  mutation being destructive, persistent and unreviewable - the docs say "an
  agent must never silently create, rebuild, or delete a persistent index."
  corpus: `mcp-tools/catalog-projection-modes` plus
  `operator-surfaces-for-llm-spend/read-tools-default-writes-gated`. **COVERED.**
- **A2. The agent's option set is a strict subset of the human's, and the
  subtraction is exactly the options that break root containment** - symlink
  following, the output-format flags, shell operators. Forces: one engine, two
  callers, one of them at the trust boundary rather than inside it.
  corpus: **NONE.** Nearest is `catalog-projection-modes`, which is about
  catalog *size* and insists nothing downstream differs. HOME IF NEW: `mcp-tools`.
- **A3. The agent passes a shell command line that is never given to a shell**:
  parsed to argv, operators refused by name, `$(` and `${` refused as expansion,
  exactly one operator admitted (a trailing `head` bound) because the tool's
  contract is exhaustive-by-default and the model needs a bounding idiom it
  already writes. Forces: model fluency in the notation against arbitrary code
  execution at the daemon.
  corpus: **NONE** - zero corpus-wide hits for the concept. HOME IF NEW: `mcp-tools`.

**System B - the index and its freshness contract**

- **B1. Freshness is a value returned with the results, and the stale state is
  asserted only on evidence of drift**; watchers are a lossy fast path backed by
  an hourly full reconciliation probe; the refresh default varies by execution
  mode. Forces: watchers silently miss events, and an agent forced to preflight
  status pays a round trip per search.
  corpus: `retrieval/chunking-and-indexing`, **PARTIAL** - see the promoting
  question below.
- **B2. The embedding endpoint is part of the stored index schema**; changing it
  forces a rebuild at the same model and the same dimensions.
  corpus: `retrieval/embedding-lifecycle`, which enumerates four inputs -
  content, model, version, preprocessing. The endpoint is a fifth.
  **BOUNDARY CASE.**

**System C - the paired agent benchmark**

- **C1. The treatment arm's election rate is a reported quantity** - 300 of 300
  trials, 989 calls, 3.3 per trial, with the reason stated in the source's own
  prose: agents decide when and how to use it. Forces: the candidate, not the
  harness, decides whether the treatment is applied, so a null is ambiguous
  between no effect and no use.
  corpus: **NONE.** HOME IF NEW: `eval-harness`.
- **C2. Efficiency deltas are computed on the both-succeeded subset (294 of
  300), published as secondary with the primary retained over all completed
  trials**, and the reason is in the document: a failed trajectory's cost is
  premature stopping or unfocused searching, not efficiency. Forces:
  conditioning fixes the denominator but selects on a post-treatment variable.
  corpus: **NONE.** HOME IF NEW: `eval-harness`.

**System D - extraction and scanning admission.** Type-aware default size
limits, silent skips excluded from the scanned count and not counted as
failures, structure-aware extraction with a per-file plain-text fallback so
every admitted file participates. corpus: `chunking-and-indexing` covers the
shape. **COVERED**, no NONE.

## Leads

- **A second independent paired agent-tool benchmark that publishes an election
  rate.** `treatment-election-rate` currently rests on one report's practice
  plus a corpus-internal argument. A second source reaching the same rule makes
  it a convergence, which is what this corpus asks for before a rule rises
  further. Return condition: when a second first-party agent-tool evaluation
  reports treatment-arm uptake beside its deltas.

- **Three fleet projects spawn the same coding CLI; personas is the outlier
  two-to-one, and both of the others wrote down why.**
  `xprice/grant-writing-nonprofits/src/lib/llm/claudeCli.ts` is the clearest:
  static argv (`["-p", "--output-format", "json"]` plus flags), the prompt on
  stdin, and `shell: true` used *only* so Windows can resolve the `claude.cmd`
  shim - with the reasoning stated, "this is safe because the command line is
  static flags only - the prompt is written to stdin, never the argv/shell". It
  also spawns from a neutral cwd so the call does not ingest the project's own
  agent config into every prompt. `gravitone-gcloud/lib/claudeCli.ts` reaches the
  same shape independently and carries a long comment on the hazard it is
  avoiding: `spawn(..., { shell: true })` concatenates argv into one
  command line, so an intentional empty-string argument vanishes *and takes the
  following flag with it* - the comment shows the exact before/after argv.
  `personas/src/lib/harness/executor.ts:146,167-169` puts the prompt in argv and
  passes `shell: true`. Same operation, three implementations, two of them
  agreeing on the safe shape with independent written rationales - which makes
  personas a deviation from a fleet norm rather than one half of a coin-flip. This is not `fluent-syntax-bounded-grammar`'s seam - it is the
  inverse direction - and it was found only because that technique's absence
  search had to be redone properly. It is filed here rather than acted on
  because it is outside what this run was asked to do and it touches a tree on
  a security-shaped question that deserves its own look. Return condition: when
  a run is authorized to look at agent-process spawn discipline across the
  fleet, start from these two files and decide which one is the standard.
