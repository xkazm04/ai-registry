# RevoGrid: scroll-space compression, a second write door, a lossy clipboard pair and a CSV exporter without a formula layer

**Class:** vendor-adjacent library repository, first-party, mined from a clone at
`8b606d6d15e24841aa6cd343cf4aa0e4b0739957` (package 4.28.4). Operator focus: raise the
quality of the `table` subject. Expected yield said before the table: the subject already
has seven techniques on paging, sorting, filtering, performance, states and keyboard, so
the yield would sit in the half a grid has and a list-style table does not: editing,
clipboard, range selection, export, pinning and the scroll mechanics. It did.

**Sweep order.** Operating documents (`AGENTS.md`, the e2e suite titles as a failure
taxonomy), then the instruments (scroll helpers, column service, data provider,
export plugin, clipboard component), then the README last. The e2e titles were the
densest map: each names a defect somebody paid for.

**Siblings at claim:** 2 live (a framefields intake, a harvest on `grid-keyboard-model`);
4 by the time of the regeneration. None held the `table` subject.

## Design record (v2 Phase 2d)

All four entries are `corpus: NONE` with the same home, the existing `table` subject, so
the routing is "technique quad inside an existing subject", not a forge handoff.

| decision | forces | buys | rejects | corpus |
| --- | --- | --- | --- | --- |
| Map logical scroll to a capped physical extent | The grid holds the whole dataset and sorts it locally; the spacer outgrows the browser's ceiling | every row addressable, correct hit-testing | paging | NONE; `performance` rung 4 never mentions the ceiling |
| Block writes use a different event from cell edits | Paste and fill carry many cells; one event per cell would be a storm | batching | one door | NONE |
| Copy and paste are separate functions on bare tab and newline | Simplicity; spreadsheet interop for the common case | small code | quoting | NONE |
| The exporter is a pure formatter behind a before-event | Hosts differ in data | host control | built-in policy | NONE for the formula layer; `filtering` already owns row selection |

## What landed

- Four techniques in `table`, listed in its golden path.
- Five applications: four source-tree (`node`), one fleet (`next`) with `applied: code`,
  `ab_verdict: better`, `proof: ab-paired`.
- The export technique carries a measured boundary the public specimens did not: a
  number-only guard altered 25 of 800 formatted phones (3.1%), a number-plus-phone-shape
  guard altered none and still neutralised six of six hostile cells.

## Apply (Phase 7.5)

- `export-escapes-for-its-consumer`: code, a private fleet example host app; the seam was
  chosen to falsify (the obvious port of the public specimen lost on the host's data).
  Local commit, not pushed.
- `compressed-scroll-space`: unapplied. The only windowed table in the fleet (personas,
  44 px rows) reaches the ceiling at roughly 340,000 rows; its data is arena results in the
  hundreds. Return: when a surface holds more than about 300,000 rows.
- `one-door-for-range-writes`, `clipboard-range-round-trip`: unapplied. No fleet project has
  an editable grid with block paste. Return: when one grows it.

## Directions not proposed

Phase 7.6: none proposed. The fleet has no grid-class peer; the one windowed table
