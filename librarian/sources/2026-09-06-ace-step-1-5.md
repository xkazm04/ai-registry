## Design record

### System A — the capacity and admission plane

**A1. Read remaining capacity as platform-free plus the process's own allocator
reserve, clamped by the allocator's budget.**
- *forces*: after models load, the driver reports zero free while the process's
  caching allocator holds gigabytes reserved-but-unused. An admission check
  believing the platform refuses work that fits, permanently — the allocator has
  no reason to release.
- *buys*: a denominator that is the capacity available *to this process*.
- *rejects*: the platform's free-memory figure as the budget — what the code did
  before the regression.
- *where*: `acestep/gpu_config.py:1188-1244`;
  `acestep/gpu_config_effective_free_vram_test.py:90-95` records the primary
  regression in its own docstring.
- *stage*: budget derivation, at the admission door.
- *falsifier*: an admission granted on the corrected figure that then failed to
  allocate. **Answers** — the clamp by allocator budget exists because the naive
  add-back over-reported, and both the under-count and over-count cases have
  tests.
- *corpus*: **NONE**. Nearest `admission-queue/resource-denominated-bounds`,
  which governs the per-item *charge* and derives the ceiling, and never asks
  whether the remaining figure is read correctly. HOME IF NEW:
  `software-engineering/backend-platform/work-execution/admission-queue`.

**A2. One central tier table, because the rows must sum into one shared pool.**
- *forces*: four models compete for one allocation; the per-tier decision is
  joint — duration, batch, offload, quantization and backend are chosen together
  because relaxing one pays for another.
- *where*: `acestep/gpu_config.py:305+` (`GPU_TIER_CONFIGS`), budget tables at
  `:141-181`, and `VRAM_AUTO_OFFLOAD_THRESHOLD_GB = 20.0` whose comment states
  the coupling outright.
- *falsifier*: it would be wrong if component costs were independent, making the
  central table pure coordination cost. **Answers** — the tree states the
  coupling in the threshold's own comment.
- *corpus*: `adaptive-fidelity-tiers/per-tier-budget-tables` states the
  **opposite** rule and argues it well. A boundary case, not a gap → row 3.

**A3. Override the capacity probe to reach untestable rungs; make the sweep a
mode.**
- *forces*: seven-plus rungs, no contributor owns seven accelerators, and the
  low rungs carry the offload and fallback paths.
- *where*: `acestep/gpu_config.py:23-25` (per-family overrides);
  `profile_inference.py:11,717,730` (`--mode tier-test`, labelled "THE KEY
  FEATURE", rungs 4/6/8/12/16/24/48).
- *falsifier*: divergence between a capped number and real exhaustion. **Partly
  answers** — the tree records that its measuring machine has an attention
  kernel the low rungs lack and compensates in the *table*, but shows no case
  where the sweep passed and hardware failed.
- *corpus*: **NONE**. `adaptive-fidelity-tiers/measured-not-declared-capability`
  rejects declared capability wholesale and has no lane for injecting a false
  declaration deliberately as an instrument. HOME IF NEW:
  `software-engineering/engineering-process/build-and-release/test-harness`.

**A4. The capacity table is checked-in constants with a named calibration
instrument.**
- *where*: `acestep/gpu_config.py:141-143` ("should be calibrated using
  scripts/profile_vram.py"), `scripts/profile_vram.py:1-19`.
- *falsifier*: a table drifted from reality. **DOES NOT ANSWER** — "should be
  calibrated" is unenforced, no gate runs it, and the constants carry no
  calibration date and no measured-on hardware. Per the round-26 rule this is a
  **lead**, whatever its forces say → row 9.

**A5. A regressed tier is split, not retuned.** `gpu_config.py:305-308` records
tier6 → tier6a/tier6b "to fix the 16GB regression". Supporting evidence for A2
rather than its own entry.

**A6. A capacity class boundary carries a tolerance because the reported number
is not the nominal one.** `gpu_config.py:28-31` — nominal 16GB reports 15.7-15.9
after driver reservation, so the boundary is `16.0 − 0.5`. Real, thin, and the
tree states no bound on what the tolerance misclassifies → untriaged, row 10.

### System B — constrained generation

### Row 3 — the row this run believed and did not land

Required by the round-26 closing check ("did the run decline to land something it
believed in, and did it say which rule made it decline?"). **Yes, and the rule is
the rewrite penalty.**

`per-tier-budget-tables` rejects a central table and argues it properly: what a
tier costs is a fact about the effect; a central registry rots because its
author does not own it; adding an effect means a merge conflict for a mapping
with one consumer. Every reason holds **while the costs are independent**. When
the budget is one shared pool the rows must sum into — four models in one
allocation — the central table is not a coordination cost, it is the only form
that can express the constraint, and the tree states the coupling in a threshold
comment.

That inverts a stated rule (GAIN 2), but the amendment makes the technique's flat
"it fails" false as a universal, which is a scope rewrite (RISK 0+2). G−R = 0,
below the +2 threshold, so it is banked with its anchors rather than landed.

Recorded because the *consistency* is the interesting part: row 1 was scored an
append on the same test, since the golden path's sentence stays literally true and
merely becomes incomplete. Incompleteness is not falsity; wrong scope is. Applying
one test both ways in one run is the only reason the two rows scored differently,
and if a later run judges that distinction too fine, this is the pair to read.

## Leads

- **A capacity table whose calibration is a comment.** `gpu_config.py:141-143`
  names `scripts/profile_vram.py` as the instrument that should calibrate the
  empirical constants. The script exists and measures real footprints. Nothing
  runs it, nothing compares its output to the constants, and the table records
  neither a calibration date nor the hardware it was measured on — while a
  sibling comment concedes the measuring machine has an attention kernel the low
  rungs lack. The shape is a checked-in derived number with a named derivation

  capacity/cost table whose calibration script is unenforced), or when a fleet
  project grows a checked-in measured table — then it is a technique in
  `standards-and-gates`, not a lead.
