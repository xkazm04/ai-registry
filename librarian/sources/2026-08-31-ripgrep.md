# ripgrep

a decade of operating documents. The class is reliable for what they built and
measured (n=1) and corroborates corpus-internally, so the fetch budget was not
expected to bind and did not — **0 of 3 fetches spent**. Expected yield stated

## Accepted

### 1. The tree is not the population — `se/codebase-scanning`, new technique

The subject models the *sensor* denominator with four measures — which sensor,
why, what coverage is missing, and a headline reading "N findings from M of K
sensors" — and gives the *file population* denominator one sentence, inside a
section scoped to foreign trees nobody can afford to read fully. So a sweep can
report twelve of twelve sensors and zero findings over a tree whose traversal
removed a third of the files, and every clause is true.

The source is the strongest available evidence: its second chapter is what it
*doesn't* search — three ignore-file layers in strict precedence each rooted at
its own directory, plus hidden files, a content heuristic and a link policy,
all on by default — and it ships an escalating repeatable control whose stated
purpose is diagnosing exactly this ("useful when you're using it and you aren't
sure whether its filtering is hiding results from you"). Also taken: the rule
that an explicitly named path overrides every automatic filter, and the
observation that a content classifier's verdict can depend on whether the file
was memory-mapped — an internal strategy choice the operator never made.

**Boundary drawn against a close neighbour.** `docs-sync`'s
`checked-vs-skipped-denominators` covers *units the report set out to
evaluate*, three states, checked/failed/skipped. Its model cannot see this
failure: the removed files land in none of the three states, because nothing
skipped them — nothing enumerated them. They were gone before the denominator
existed. That boundary is stated in the new technique's second paragraph.

### 2. The one channel where authorship of the text is the point — `se/machine-paced-delivery/stake-before-merit`, amendment

**A contradiction, which is the best case.** The technique closes its central
argument with "the distinction is authorship of the accountability, **not**
authorship of the text." The source's `AI_POLICY.md` draws exactly that denied
distinction and draws it by channel: machine-authored code is welcome,
machine-authored replies to maintainers "may be hidden without notice", and
"do not copy responses from the AI when replying to questions from
maintainers."

The technique is right that stake is *asked for* at admission — and it is only
*tested* in the review round trip it separately names as the expensive half.
The reviewer's question there is a probe of comprehension, not a request for
text, and a generated answer has the probe's exact surface with none of its
content. The asymmetry is structural: the diff has instruments that do not care
who wrote it (tests, checks, a reviewer reading code); the conversation has
only the reviewer's attention, which is the scarce server the whole technique
exists to protect. So machine-authored discourse is the one contribution class
that consumes the protected resource while adding nothing to it.

Three details from the source made the amendment operable rather than merely
correct: name the channel and not the tool; permit disclosed quotation but
require the human's own commentary with it; and carve out translation by asking
for the contributor's own language plus a translation, so the rule does not
become a language test. The enumeration-hunt framing applies — the technique
denied a symmetry, and it denied too much.

## Applied

Both landings carry a row in `librarian/applied.md`.

**`the-tree-is-not-the-population` → `personas`, mode `experiment`, verdict
`better`.** Seam: a dependency-free content-security-policy gate that walks the
frontend tree, keeps files by a two-extension allowlist, and closes with a line
naming findings and no population. Arm A reproduced the gate's traversal
verbatim; arm B enumerated first and classified each removal. **5,033 examined
of 5,955 enumerated — 922 excluded (15.5%) by one undisclosed filter.**

The falsifier — do any excluded files carry something the gate existed to
judge — returned **184 raw and 0 after hand-classification**: 183 are data
files whose translated strings legitimately contain URLs, one is a design
document, and no code-bearing file is excluded. The scorecard's standing lesson
held again: an instrument's first number is not its measurement, and reporting
184 would have been wrong in the direction that flattered the finding. The gate
is sound — but sound because every executable file under that root currently
happens to carry one of two extensions, which is an invariant the project
satisfies and does not state.

**`stake-before-merit` → `personas`, mode `simulation`, verdict `better`.** No
experiment is reachable: the technique's subject is what an outside contributor
does in a review conversation, and this public repository has had no outside
contributors — all 8,294 commits and all 17 pull requests are the owner's own.
Three real cases from the tree decided it. The strongest: the contribution
guide already requires a contributor to write translator context in the commit
message because the catalog format carries no comments, enforces the
*translation* half with two pre-commit hooks, and cannot enforce the *context*
half at all — because its value is entirely in whether a person who understood
the string wrote it. **The project independently invented the amendment's rule
for one field, could not generalize it, and left it unargued.** The same rule
is also the carve-out under maximum pressure: the guide mandates translations
into thirteen locales that an individual contributor realistically produces
with a machine, so an unqualified restriction on generated text would forbid
what the guide requires.

Proof status `structural-only`, stated as a limit rather than softened: nothing
here measures behaviour. Return condition — the first outside pull request.

my candidate homes were contended at triage — `optional-dependency-degradation`
and `quality-gates` by `intake-semantica-0831`, `test-harness` by
`intake-pgrust-0831` — which is why rows 4, 7 and 9 route to the untriaged

`machine-paced-delivery` and was editing its golden path and
`human-gate-capacity.md` while this run amended `stake-before-merit.md`:
contended subject, disjoint files, no lock needed and none taken.

**The index and catalog were regenerated and deliberately left uncommitted.**
The regeneration referenced four sibling techniques absent from `HEAD`
(`verification-scope`, `refusal-is-not-failure`, `vacuous-by-evaluation`,
`destination-guard-integrity`), so committing the artifact would have baked
their in-flight work into a hash under this run's name. A stale index in a
shared checkout is self-correcting; that is not.

**The gate went red inside the `index` lock on a file this run does not own**
— `security/supply-chain/techniques/verification-scope.md` exists without its
golden path declaring it, which is `intake-semantica-0831`'s half-written
subject. The lock was released before investigating, per the method, and the
breakage is named here rather than fixed.
