## Design record (abridged — full entries in the forge spec)

1. **Conjunction-activated fragments.** A fragment naming several handles
   participates iff every handle is in the active set. *Forces:* the
   integration surface is combinatorial — **540 cross-integration fragments
   against 157 base service fragments, 3.4x** — and an integration between two
   services belongs to neither one's own file. *Rejects:* a central manifest.
   *corpus:* NONE; nearest `import-normalization/overlay-merge-absence-semantics`,
   which owns what an overlay's silence about a key means once merging, not
   whether it merges at all.
2. **Specificity-ordered layering.** Merge order derived from the identifier's
   dot-segment count, ascending then lexical. *Forces:* filesystem enumeration
   order is unstable across platforms and the merge is order-dependent, so an
   undefined order is a per-machine heisenbug — the source says so in a comment
   at the sort. *corpus:* NONE, and it **inverts**
   `settings/cross-source-precedence-chain`, which requires the order be
   "declared, named, and singular". At 697 fragments that list is
   unmaintainable; a total ordering function replaces it.
3. **Intent and environment in one namespace.** The active set holds operator
   requests and probed host capabilities as one token space, so one conjunction
   rule serves both — with a special case the source had to add: a wildcard
   must not select capability tokens. *corpus:* NONE; nearest
   `sidecar-provisioning/capability-detection` detects but does not compose.
4. **Inline-predicate specification.** Every claim in the spec sheet carries
   its own shell verification command; there is no separate checker to drift
   into a transcriber. *corpus:* the rung ladder in
   `conformance-checking/declared-then-proven` assumes two artifacts and does
   not model the collapsed form. → **landed as a technique.**
5. **Registry-enumerated fixture pairing.** Every lint rule must ship a
   pass/fail fixture pair under a directory named for its id, and a self-test
   iterates the rules document asserting both directions. *corpus:*
   `fixture-repo-testing` pairs at repository granularity and names the
   per-rule fixture only as a fallback clause. → **landed as a technique.**
6. **Ragged test matrix.** Heavy suites pinned to a subset of distro rows;
   unplanned cells render `-`, not pass. *corpus:* covered —
   `test-harness/suite-partitioning` already carries "a green badge hides tiers
   that never ran", "counts travel with their suite" and "the report reconciles
   its own denominator". **Catch.**
7. **Config mediated through one CLI surface**, `.env` never hand-edited,
   profile→env propagation explicit rather than automatic. *corpus:* covered by
   `settings` plus `packaging/variant-config-parity`. **Catch.**
8. **Conversation as a scored tree.** The proxy's universal message
   representation is a tree carrying `visits`/`value`. **Lead** — see below.
9. **Plugin discovery by attribute presence.** A module registers iff it
   exposes an id constant, so a malformed or zero-byte module is silently
   skipped; the hole is covered by a lint rule rather than a runtime error.
   Folded into decision 5's technique as its motivating failure.
10. **Resolved-artifact escape hatch.** Final resolution is delegated to the
    engine's own resolver and emitted standalone. **Lead** — see below.

## Landed

**`conformance-checking/inline-predicate-rung-inference`** (technique) —
a spec format where each claim carries its own predicate collapses the
declaration/checker split and removes the transcriber failure, but moves the
rung choice to the claim's author with no field to record it in. Measured
against the source: **593 claims, 543 (91.6%) carry a command; by invoked
binary, 62.8% are text matches, 16.0% parse-and-assert, 20.8% execution.**
57.5% of the whole specification is proven by the presence of a string in a
file, and all of it renders as one `ok`. The coverage number and the proof
number are five times apart at the execution rung.

**`conformance-checking/rule-registry-enumerated-fixtures`** (technique) —
pair fixtures per rule and enumerate the pairing from the rule registry, so an
unfixtured rule fails discovery rather than review. Boundary, present in the
source and predicted by the technique: the enumeration covers only the
declarative registry, and a rule implemented in code in another pass is
covered by a hand-maintained map — the hole the enumeration was built to
close, reopened one entry at a time.

**Applications** (source-tree, both against the clone at the pinned commit):
`bash--inline-predicate-rung-inference` (`experiment`, `better`, `ab-paired`)
and `deno--rule-registry-enumerated-fixtures` (`simulation`, `unmeasurable`,
`structural-only`, with the instrument that would make it measurable named).

**Forge dispatch:** `librarian/handoffs/2026-09-06-conditional-service-composition.md`,

## Leads

- **A shared representation carrying single-consumer fields.** The proxy builds
  every request into a tree node type carrying `visits` and `value`; exactly
  one module of 28 reads them, and the declarative workflow registry ships
  empty. The general question — what it costs when a universal representation
  carries fields one consumer needs — is real, but one instance where the
  machinery is near-unused is thin evidence. *Return when* a second source
  shows a shared representation whose optional fields have measurable cost, or
  when a fleet project grows the same shape.
- **Resolution as a secret-materialization event.** The escape-hatch export
  delegates to the engine's own resolver and emits a standalone artifact that
  inlines every environment value, credentials included; the tool warns twice
  in prose. Flattening a layered config for portability is exactly what
  destroys the layering that kept secrets out of the flat file. *Return when* a
  security-bundle subject on config egress is being worked, or a second source
  shows the same flatten-then-share hazard.

## Notes on method

- The `--json` ingest was the trigger, not the extraction; everything above
  came from the clone.
- Two self-catches on instruments this run built, both in the direction that
  flattered the finding, both recorded in the technique and the application:
  a rung classifier matching binary names anywhere in the string (execution
  share 40% vs the corrected 20.8%), and a paired A/B whose two arms were never
  written to disk so both "ran" against a missing file and one appeared to
  pass. A third self-catch was a read of a missing fixture directory as a
  retired rule; the rule was live under a different pass's naming convention.
- The gate was red on entry to Phase 7 for two files owned by live siblings
  (`measurement-honesty` and `diff-comparison` applications, `verified_against`
  format). Reported, not fixed, no lock held.
- **This run swept a sibling into its own commit, and the sweep is recorded rather
  than rewritten.** `321c96b8` names `SCORECARD.md` and `LESSONS.md` in its pathspec
  for this run's own row and lesson, and both files also carried the `openclaude`
  run's uncommitted round-29 block, which went in under this commit's message. No
  content was lost and none was overwritten; the cost is attribution. History was
  **not** rewritten to correct it — with four live siblings, a rewrite of a shared
  branch is a worse failure than a misattributed block, and the method says so. The
  general lesson: a pathspec protects you from staging files you did not touch, and
  not at all from a shared append-only file a sibling appended to between your
  append and your commit. The only real defence is to commit the shared ledger
  inside the same lock hold as the append.
