# Fluxer — a polyglot real-time chat platform, read as a system

**Class: first-party practitioner codebase in repository form, read as a system.**
The landing page is 24 lines of README and three badges; the tree is 1.35M lines
across 14,093 files. Markdown is ~21k words total — the *inverse* of a
documentation-heavy repository, and the ratio (about 1 word of prose per 64
lines of code) is itself the routing signal: this source's knowledge is design,
not prose, and a claim-hunting pass would have returned badges.

Expected yield for the class, said before the triage table: high on design
decisions, near-zero on quotable claims. That held.

## What was swept

Cloned at `baa18aed`, swept in the Phase 2b order by five parallel design
readers plus the director. Six systems:

- **Real-time gateway** — Erlang/OTP, cluster membership, session handoff,
  presence, dispatch relay, calls.
- **API** — TypeScript/Hono, ~275k lines, over a Cassandra-or-Postgres seam.
- **Client** — TypeScript/React, ~685k lines, plus a Rust/WASM core.
- **Toolchain and governance** — ~28k lines of Rust tooling, an LLM
  localization pipeline, and an RFC-2119 AI-contribution policy.
- **Edge/media plane and desktop** — Rust proxies, an Electron shell.
- **Shared service framework** — the router/shard runtime, read by the director.

Two of the director's briefs to the readers were **refuted by the readers**, and
both refutations were better than the questions: the CI workflows are not
generated from Rust (the YAML is deliberately dumb glue invoking one typed
binary, so there is no generator and therefore no drift surface to check), and
the localization pipeline's `tokens.rs` is placeholder protection rather than
cost accounting — there is no spend cap or usage accounting anywhere in a
production LLM pipeline running 33 locales.

## Prior-art mapping: the two queries disagreed, and the disagreement was the signal

Run per the round-9 focus. For the AI-contribution policy, the concern-phrased
query ("ai generated contribution policy", "authorship provenance disclosure")
routed to provenance and disclosure homes; the forces-phrased query ("reviewer
capacity is the scarce resource") routed to `machine-paced-delivery`. The
disagreement is the finding: the policy is not a provenance regime but a

the method warns is more dangerous than a total empty.

## Landed (rows 1–4, operator-picked)

All four in `backend-platform/work-execution/admission-queue`.

**1. `zero-depth-admission` (technique).** The subject surfaces two assumptions
before it begins — the step trigger, and the definite article in "the queue" —
and never surfaces the third: whether there is a line at all. Stage zero was
missing from a subject thorough from stage two onward, which is the shape the
method predicts.

**2. Amendment to `admission-vocabulary`.** The technique states that "every
request that reaches the gate receives exactly one of three verdicts" and warns
against collapsing two. A deliberately zero-depth gate emits two arms and is
not collapsing anything — `queued` is unreachable by construction, not erased in
transit. The amendment states the discriminator and, more usefully, where such
designs *do* fail: dropping `queued` is free, dropping the refusal's *reason* is
the original outage by another road.

**3. `remediation-derived-bounds` (technique).** A bound whose breach triggers a
destructive remediation elsewhere must be derived from that remediation's
threshold, not configured beside it. Instantiates `limits-are-derived` at the
seam that law names but does not identify: of all the numbers a bound could be
derived from, the one that destroys the component is where inversion is
unrecoverable.

**4. `refusal-without-release` (technique).** When the reason for refusing is a
property of the server, every caller is refused in the same instant, and a
refusal that *releases* the caller is a synchronizing event. The classification
into terminal-close versus transient-hold, the bounded hold, and the
control-plane push that makes recovery track the fix rather than a polling
interval.

## Leads (with return conditions)

**L1 — A verified production/development divergence in the source.**
`fluxer_gateway/config/vm.args.src` (the release, per `rebar.config:42`) is
line-for-line identical to `vm.args.template` (development) except that it
parameterises scheduler counts *and* omits
`-kernel prevent_overlapping_partitions false`. OTP 28 — the version the tree's
CI installs — defaults that to `true`, which resolves overlapping partitions by
killing nodes. The cluster design assumes the opposite: coordination-free
ownership recomputed from DNS-discovered membership with a 60 s reconcile as the
correctness backstop. The environment that is tested tolerates partitions; the
environment that ships resolves them by node suicide, and the intended
difference camouflages the unintended one.
*Sharpest part:* the same repository holds the cure in another language and
never applied it here — `PostgresKvRustParity.test.ts` reads two implementation
files as *text* and asserts their shared literals precisely to stop this class
of drift. **Return:** when a second source shows a forked-config parity
assertion in the wild, this becomes a technique amending
`chokepoint-tag-registry` for the case where both copies are authoritative and
must legitimately differ, so equality cannot be asserted and the *delta* must be.

**L2 — "Test where you own the semantics, not where the traffic is."**
~5,261 lines across eleven test files defend the hand-written Postgres KV query
engine; zero defend the Cassandra driver path, which carries the production
traffic. Nobody designed that distribution; it falls out of which side the team
owns the semantics of. **Return:** when a second tree shows the same inversion,
or when a fleet project's test distribution can be measured against ownership.

## Parallel-run notes

Claimed with 0 live siblings; by Phase 4 two were live (`jetkvm`, `everywhere`),
both `/intake` over repositories on `main`. `jetkvm` held `release-pipeline`,
`test-harness` and `signed-artifacts` — three of this run's candidate homes for
rows that were not picked, so no collision materialised. `admission-queue` was
held by this run alone from Phase 3.

**One parallel-safety observation worth carrying into the method.** This run
executed in a worktree while both siblings worked in the shared checkout on
`main`. The regeneration hazard the method warns about — an index built over a
sibling's uncommitted subject, then committed under this run's name — is
*structurally impossible* from a worktree, because the build reads only this
working tree. `git status --porcelain knowledge/` returned exactly one file this
run did not author, and it was the generated index itself. The worktree is not
merely a branch-isolation device; it removes the shared-artifact contamination
class entirely, and the method's parallel section does not say so.
