## Phase 2d - the design record

Grouped by system, because a repository holds several and the routing count
is per system.

### System A - the turn runtime (event-sourced agent loop)

**A1. The durable log may not claim liveness.**
- forces: a process can crash at any point, which makes any persisted "this
  is running" claim unfalsifiable after the fact.
- buys: recovery needs no repair pass, and no consumer can read a stale
  running flag; the rule extends to *derived* state - the reduced turn state
  has no status field at all, and consumers derive from suspension, terminal,
  and outstanding records.
- rejects: a status column, and a reducer-derived status.
- where: `turn-runtime-design.md` sections 4.2 and 14.3
- stage: the reducer's output shape
- corpus: **NONE**. Nearest is `fleet-orchestration/durable-fleet-state`,
  which is the *opposite* stance - it mirrors a state machine including
  running states and reconciles at startup. A genuine boundary, not a
  duplicate.

**A2. Durable barriers precede side effects.**
- forces: ambiguous interruption between intent and effect.
- where: section 4.4
- corpus: **CATCH** - `_laws.md#record-precedes-effect` states it, including
  the load-bearing second half (when the record cannot land, the effect does
  not happen).

**A3. Reduce before persist, as a validation gate.**
- forces: a persisted illegal event makes every future read of the file fail
  *and*, through context references, blocks the whole session chain behind
  it. The blast radius is what makes in-memory rejection worth the cost.
- buys: an illegal append rejects for its caller only and never becomes
  durable.
- where: section 4.5
- stage: between reduce and persist, per batch
- corpus: **NONE**. `one-validation-door` is adjacent (a single door) but
  says nothing about validating *before* durability in an append-only log.

**A4. Context by reference, not by inlining.**
- forces: tens of KB per turn if inlined; compaction needs a way to bound
  resolution depth.
- buys: compaction becomes a zero-schema-change operation - an inline
  context restarts the chain.
- where: section 6.6
- corpus: **NONE** as a mechanism; `prompt-assembly` owns composition, not
  reference chains.

**A5. Provider continuation metadata is sealed to the endpoint that minted it.**
- forces: a provider rejects a replayed encrypted payload outright after a
  mid-session model switch.
- where: section 6.6
- corpus: **partial** -> landed as a technique (row 3).

**A6. Transmit-time elision as a resolver decorator.**
- forces: prefix caches need byte-stability; historic tool results and
  captured frames dominate the window.
- where: section 6.6, plus the context policy config
- corpus: **partial** -> landed as a technique (row 5).

**A7. Steering is additive injection at a model-call boundary.**
- forces: elision would blank the just-read batch; stripping would void a
  cancelled turn's signatures; supersede is destructive to suspended turns.
- where: section 8.6, and `session-design.md` 12.4 with the rejected
  alternative written out
- corpus: **partial** - `chat-transcript/composer-turn-queue` models the UI
  half only -> landed as a technique (row 4).

**System A count: 4 entries with no home.** Clears three.

### System B - the session layer

**B1. Write order: create the turn file, then reference it, then advance.**
The reverse is a dangling reference and therefore corruption; an orphan turn
file is benign because turns are only ever found by reference.
(`session-design.md` section 7.) corpus: adjacent to
`data-access/sequence-token-write-ordering`; **partial**, untriaged.

**B2. The pending queue is ephemeral, superseding a committed durable design.**
One durability point; a durable queue would promote at startup and begin
model calls nobody asked for; the accepted cost - a remote sender's queued
message is lost silently on a crash - is recorded beside the decision.
(Section 12.1.) corpus: **NONE**, untriaged.

**System B count: 1.**

### System C - the multi-writer collaborative asset plane

Nine entries, eight with no home. Abbreviated, because the operator declined
the handoff and these are recorded for the next pass rather than landed:

- **C1** Change-sets are full content against a declared base; the org runs
  the merge; three outcomes, all HTTP 200 (`applied` / `merged` / `conflict`).
- **C2** One core, three doors - the HTTP, WebSocket and agent faces are thin
  projections of one service; the first-party agent "gets no privileged path,
  enforced by there being no other door."
- **C3** Golden fixtures as the dispute-settling instrument: "add a fixture
  with every merge-behavior dispute, and the dispute stays settled."
- **C4** Contract self-enforcement - the server validates its own responses
  against the shared schemas before sending, so "drift fails in the stub, not
  in a client."
- **C5** The path is the product's identity; storage keys on an internal
  per-asset id, so move/delete/restore are attributed property updates and
  **only content edits bump versions**.
- **C6** Ephemeral relay frames are content-blind by design; durable board
  state travels the existing propose path, so a dropped frame costs
  smoothness, not data.
- **C7** A clean merge landing identical content **still writes a
  change-set** - attribution over dedup. -> landed as an amendment (row 6).
- **C8** The liveness beacon: prolonged frame-silence is the client's only
  evidence of a half-open socket, so periodic frames are the server's
  obligation.
- **C9** Auth stated as tiered MUST/SHOULD requirements rather than schemas;
  the org is only ever a resource server.

**System C count: 8 with no home.** Clears three decisively.

## The routing decision

Both clauses of the Phase 2d count fire. Per system: A at 4 and C at 8,
either of which alone is a forge job. Across systems: A5, A6 and A7 share
`HOME IF NEW: software-engineering/llm-agent/prompt-and-context`, which is
three sharing one home.

**The count was met and the handoff was declined by the operator**
(`--no-handoff`, "land 3-7"). Recorded here so the next pass over this
repository does not re-derive the record: System C in particular is a
subject-shaped hole - no subject in the corpus models a plane where agents
and humans are co-equal writers against one document store.

### The catch

A2 (durable barriers) is `record-precedes-effect`, already a law, stated
better than the source states it.

### The correction that ran backwards

Row 7 was picked because a connected tree looked like it had the defect the
technique names - a boot sweep writing `failed` plus a prose marker, with a
string-matching classifier downstream in *two* languages. That reading was
wrong: the tree had already replaced it with a three-class boot
classification, and the string arms are backward compatibility for 74 of
2,188 historical rows. The tree then refuted the technique on a case the
technique did not cover - **a run that kills the process on every resume
always looks fresh, so honest closure plus re-admission is a boot loop** -
and four mechanisms were read out of it into the technique: classify rather
than declare, reuse the existing liveness threshold, count involuntary
interruption on its own key, and clear the mark on completion rather than on
the attempt. Verdict `not-better`, and it is the most valuable row this run
produced.

## Leads

1. **A law candidate: a write's record is about the decision, not about the
   bytes.** Two independently designed systems refuse to let "the value did
   not change" mean "nothing happened" - one for serialization correctness,
   one for attribution. Recorded in the row 6 amendment, not minted.
   *Return condition:* a third independent sighting in another run.
2. **System C is a subject-shaped hole** (see the design record).
   *Return condition:* when a second source shows a multi-writer document
   plane with agents as first-class writers, or when the operator lifts
   `--no-handoff` on this repository.
3. **Span-count capping as the second granularity of elision.** The applied
   change proved elision bounds payload-per-item and cannot bound an
   unbounded item count. *Return condition:* when the connected tree caps
   spans, tighten the pinned residual and re-measure.

  ("steering a running agent turn" -> `chat-transcript`), but that hit was the
