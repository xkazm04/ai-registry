## Design record

Grouped by the system each decision belongs to, with the `corpus:` line that
decides routing.

**System A — the async execution core** (`src/base/`)

- **A1** *Callbacks must be called; unwanted calls must be cancelled; both
  obligations are unconditional and neither party inspects the other's
  liveness.* forces: in an async system the classic bug is a callback into a
  freed recipient, and the classic fix — the caller checking whether the
  recipient still lives — is a race. buys: deliverability is decided by the
  queue at dial time, so neither side needs a model of the other. rejects:
  caller-side liveness checks. where: `src/base/AsyncCalls.dox:60` "Unwanted calls must be canceled: If Recipient may not be able to".
  stage: call scheduling. **corpus: `llm-agent/orchestration/durable-agent-operations`**
  — `two-cancellations-and-a-synchronous-door` models the caller/operation
  split and the admission door; it does not state the two-sided unconditional
  obligation. PARTIAL.
- **A2** *Late cancellation — after the call was already dialed — is a no-op and
  explicitly not a bug.* buys: a total cancel API; no caller checks whether it
  is too late. where: `src/base/AsyncCalls.dox:95` "Late cancellation is a no-op. It is not a bug to cancel". **corpus: same
  subject** — "a repeated request against an already cancelled operation is not
  an error" is the same rule one step away. CATCH.
- **A3** *`swanSong()` is a cleanup path that must tolerate any state* — "the
  entry may be gone, the Abort may have been called, the fd may have been
  closed" (`src/base/AsyncJobs.dox:81` "The entry may be gone, the Abort may have been called, the")
  — and unlike a destructor it may throw. **corpus: NONE identified;
  not chased.** UNTRIAGED.
- **A4** *`doneAll()` computes the termination condition directly; "return
  isDone" is called out as wrong (`src/base/AsyncJobs.dox:109` "you are doing it wrong. Compute the condition directly rather than").* forces: a maintained flag drifts from the
  condition it stands for. **corpus: `_laws.md#derivation-names-recomputation`**
  states the principle. CATCH.

**System B — the policy engine** (`src/acl/`)

- **B1** *A policy answer is four-valued and stays four-valued to the call site;
  the type exposes one named accessor per fold direction, ranks them in prose,
  and offers no boolean.* forces: the same answer type is consumed by
  authority-bearing directives and by directives that merely select between two
  authorized behaviours, and their safe directions differ. buys: `!allowed()`
  and `denied()` cannot be mistaken for one test. rejects: a kernel-side fold; a
  bool conversion. where: `src/acl/Acl.h:78-91` "If in doubt, use this popular method.",
  `src/acl/Acl.h:96` "aclMatchCode code = ACCESS_DUNNO;",
  `src/acl/Acl.h:102` "bool implicit = false;".
  stage: verdict consumption. **corpus: NONE.** Verified against
  `failure-direction` (prescribes the direction, assumes a two-valued kernel),
  `read-write-predicate-symmetry` (owns the producer side: do not fold before
  the check), `truncated-verdict-space` (deletes the positive branch),
  `route-vocabulary-narrower-than-verdict-vocabulary` (narrows what is
  executable), `policy-verdict-in-the-status-space` (carries a verdict across a
  transport), plus a `--prose` map and a corpus-wide grep for the negation
  asymmetry. **LANDED.**
- **B2** *Two empty inputs, opposite defaults, four lines apart* — no rules at
  all resolves uncertain; an empty condition list resolves allowed. And the
  implicit fallback is "the negation of the keyword of the last seen rule",
  i.e. derived from the policy's own last line rather than a constant. where:
  `src/acl/Checklist.h:50` "Its result is the negation of the keyword of the last seen rule.",
  `src/acl/Checklist.h:60` "If there are no rules to check at all, the result becomes ACCESS_DUNNO.",
  `src/acl/Checklist.h:83` "If there are no ACLs to check at all, the result becomes ACCESS_ALLOWED.". **corpus: folded into B1** as the
  technique's "two empties are two facts" section rather than landed
  separately — it is the same mechanism (the API refuses to have one default).

**System C — the operator-facing diagnostic surface**

- **C1** *A log message carries a stable numeric ID keyed to its semantics, not
  its text or its source location; a substantial semantic change mints a new ID;
  retired IDs are never reused.* forces: operators suppress and rate-limit
  messages by ID in config that outlives the binary, and a suppression rule is a
  negative rule — silent transfer means an important message stops being logged.
  where: `src/cf.data.pre:5767-5772` "Message ID corresponds to the message semantics rather than message",
  `doc/debug-messages.dox` (the register,
  with IDs 44, 45, 47-55 and 61 visibly absent). **corpus: PARTIAL** —
  `must-ignore-unknown`'s decision rule already says "when a field's meaning
  must change, do not reuse its name", `_laws.md#identity-survives-reuse` owns
  the positive half, and `step-identity-stability` owns it for pipeline units.
  The delta is the published tombstone register and the suppression framing.
  UNTRIAGED with anchors.

**System D — the helper/extension boundary**

- **D1** *The extension namespace is claimed by SHAPE, not by enumeration: a
  trailing underscore marks "mine", and everything unmarked is reserved to the
  host including names the host does not use yet.* forces: a list-based
  reservation cannot protect names the host has not invented, so every host
  addition silently captures an extension's key; a shape-based one can be
  validated in one comparison against the last byte. buys: the host may add keys
  forever without collision, and warns with the repair named
  (`rename it to add a trailing underscore: key_`) while staying silent on
  compliant keys. rejects: an owner-name prefix (needs a registry; unverifiable
  host-side), and silent must-ignore. accepts a cost openly: no inter-extension
  collision protection — repetitions of custom keys are supported on purpose.
  where: `src/helper/Reply.cc:193-206` "if (*key.rbegin() == '_')". **corpus: PARTIAL, home contested** —
  `must-ignore-unknown`'s decision rule states the owner-prefix variant and
  `unenforced-collision-is-a-documented-capability` part 4 recommends the
  *opposite* assignment ("publish under a distinct prefix of your own"). The
  concept spans `repo-manifest-standard` (a committed file) and
  `extension-trust-boundary` (an in-process host), and the source is neither —
  it is a subprocess protocol. RISK +1 for the contested home took it below
  threshold. UNTRIAGED with anchors.

**System E — the test and build harness**

- **E1** *A stub aborts loudly when called and names the library it stands for*
  (`FATAL: foo/libexample.la required for use of <func>`), rather than returning
  a plausible default — the stub satisfies the linker, and reaching it at runtime
  means the test's dependency graph is wrong. A second form, `STUB_NOP`, prints
  SKIP and continues, reserved for registration-pattern APIs where the result
  genuinely cannot affect the test; the two-way split is made once at the stub
  definition. where: `src/tests/STUB.h:31-46` "stub_fatal(STUB_API". **corpus: PARTIAL** —
  `vacuous-by-evaluation` owns "a check that cannot fail" by a different
  mechanism (the evaluator supplies the condition). UNTRIAGED with anchors.
- **E2** *A build-layer matrix compiles combinations of configure flags*
  (`layer-00-default`, `01-minimal`, `02-maximus`, `04-noauth-everything`).
  **corpus: `build-economics`, `machine-paced-delivery`.** CATCH.

**System F — the HTTP message plane**

- **F1** *Strictness is a tristate `on|warn|off` where `warn` accepts and logs,
  and accepted non-compliance is normalized to canonical form on forward.*
  where: `src/cf.data.pre:7240-7257` "of non-compliant HTTP messages where it is unambiguous". **corpus: `failure-direction`** — its
  "Graduated enforcement is a migration state, not a destination" section owns
  the warn mode, including the rule that degradation must not be more permissive
  inside it. CATCH. (The normalize-on-forward half is a lead, below.)

## Applied and shipped

**Seam chosen to falsify, and it refuted the stronger reading first.** The hunt
found an entitlement gate computing permission by negation over a four-valued
charge type — exactly the `!allowed()` shape — and it is **correct there**,
because the enum is closed and its three non-denied members are homogeneous. A
negation fold over a closed, homogeneous enum is safe; the technique's rule is
about what happens when the enum grows. Recorded as a refutation, not hidden.

The defect was one function on, in the lane-aware generalization written
explicitly to settle the shape before anything depends on it: both empties of
its allowance map answered the same value, in a line whose own comment names
them as two different facts, and the test above it asserted the distinction in
a comment and then asserted the value that erases it. Paired: the predicate
fails on the old code (`expected 'unlimited' not to be 'unlimited'`, 54/55) and
passes on the new (55/55). Floor declared and held — no billing path changes,
the scan lane byte-identical under its standing table-wide equality test, full
suite 12,597 passed / 2 skipped / 0 failed, `tsc --noEmit` clean after the
return type widened. Shipped `21b2bebe`, not pushed.

The `verified_against` line was corrected by the tree itself during the gate:
the draft said Next 15 from memory, the lockfile witnesses 16.

## Leads

- **Normalize-on-forward as a parser-differential defence.** Accepting
  unambiguous non-compliance and re-emitting canonical form means a downstream
  parser never sees the ambiguous bytes, which closes the disagreement that
  request smuggling lives in. The tree states the normalization
  (`src/cf.data.pre:7246-7250` "of non-compliant HTTP messages where it is unambiguous")
  and never states that consequence, so this is
  reconstruction, not the source's claim. *Return condition:* when a second
  independent source ties message normalization to parser-differential defence,
  or a fleet project gains a proxying hop.
- **The register with holes.** `doc/debug-messages.dox` is a published ID
  register whose gaps are load-bearing (retired IDs), and the gist — the message
  with its variables elided — is a second artifact worth a look as an error
  taxonomy shape. *Return condition:* when a fleet project gains an
  operator-suppressible diagnostic surface, which none has today.
- **Two reserved-key lists that have drifted.**
  `src/helper/Reply.cc:179-181` "TODO: Merge with Notes::ReservedKeys()."
  records that the runtime list and `Notes::ReservedKeys()` disagree —
  one holds a name the sources do not recognize, and is missing four they do.
  A live instance of two authorities over one vocabulary. *Return condition:*
  if row 2's home is settled and the technique lands, this is its negative
  application.
