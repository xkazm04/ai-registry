## Row 1 — the unit belongs to the branch that has a value

The `fix(bench)` commit is a reversal in the brief's sense: production found a
formatting decision wrong. The old row formatter appended the unit as a literal
**outside** the padded slot:

```rust
"  {:>3}  {:>6.1}   {:>5}ms  {:>5.0}ms  {:>5}"
```

`ttft_ms` is optional and its absent case was handled correctly, inside the
mapping, producing `"n/a"`. Then the column's unit was glued to it: **`n/ams`**.

Nothing rounded wrong and no false quantity was claimed, which is why this is not
the failure the subject usually guards. It is a vocabulary failure — the token
meaning *no measurement* became column-specific, so a reader scanning for absence
has to know each column's unit to recognise the placeholder.

**The home was decided by an enumeration the golden path declares.**
`status-vocabulary` states that the hard cases are *"handled inside the authority
so no call site can get them wrong"* — and here the unknown case **was** handled
inside the authority and rendered wrong anyway, because the concatenation happened
after the authority returned. That is the boundary: handling the case inside the
branch is necessary and not sufficient, since anything concatenated to the
authority's output re-opens every case it just closed. The technique's existing
*"the unit is part of the value"* section argues the same rule from **locale**
(symbol position, spacing, compact magnitude); this run reaches it from **column
alignment and the absent branch**, independently, which is the row's `+1`.

Landed as a section in `number-formatting`, plus the enforcement note the defect
requires: assert the present and absent renders **in the same test**, because each
branch is correct alone and the defect lives only in what they share. The source's
own new test does exactly that, and its fixture values (`222_367.0` ms, `1.3`
tok/s) are a real slow run rather than round numbers — the tell that this was
found in use.

Source-tree application: `rust--number-formatting.md` (`rust@1.85`, witness
`AGENTS.md:16` plus `edition 2024` at `Cargo.toml:5`).

## Row 2 — the count was wrong, and the gap between the numbers was the finding

`rust--named-members-over-a-uniform-collection.md` was titled *"A trait that is
implemented eight times and dispatched through zero times"*. It is implemented
**seven** times.

Established from two independent angles at **both** commits: `impl ModelProvider
for` returns 7 (single-line and multiline), and `pub struct …Provider` returns the
same 7 names. `providers.rs` is byte-identical across the delta, so the count was
wrong when written rather than overtaken by the tree. The load-bearing half —
*dispatched through zero times* — is true, verified uncapped: `dyn ModelProvider`
returns nothing across 55,756 lines.

The error was a conflation the tree invites, and reconstructing it produced the
better fact. The aggregate has **eight** members and the interface has **seven**
implementations, because the eighth probe is:

```rust
let lmstudio_disk = s.spawn(providers::scan_lmstudio_models_dir);
```

A free function. Not a runtime, no `is_available`, no `start_pull`, and no
sensible implementation of either. It is a second *view* of a runtime already in
the aggregate under its own name — **and it is the same member that carries both
asymmetries the application already documented**, the equality-vs-substring match
rule and the `unwrap_or_default` failure policy.

So the member most responsible for the technique's argument is the one member a
`Vec<Box<dyn ModelProvider>>` could not have held at all. Not *would have erased
its distinctions*: **could not have contained it**, because membership in a
collection of an interface is decided by the type. That is a third cost the
technique did not carry, and it is the one that leaves no trace — a collection
does not enumerate what it excluded, so the design question *"should this source
contribute?"* gets silently answered by *"can it implement the trait?"*. The two
moves available are to drop the source, or to force a stub whose unreachable
methods are the fake decisions
`shape-with-a-not-applicable-member` describes.

Landed as a technique section (*"The collection also decides membership, and that
decision is silent"*), with the corrected count and the new section in the
application, and the subject note corrected. The technique itself never carried
the wrong number.

## Apply — the seam was chosen to falsify, and it partly did

**tracklight**, `crates/render/src/traces.rs`. Chosen because the ledger records
this tree as already careful about absence, so a clean result would have been a
real refutation. Before committing to it, the pre-check: a caught outcome would
have taught that disciplined absence handling gets this right for free, which
would make the amendment's *necessary-but-not-sufficient* framing too strong.

**It caught, and then it did not.** Three of the four unit-bearing optional renders
in the crate are correct **by construction** — `.map(|m| format!("{m}ms"))
.unwrap_or_else(|| "—".into())` at `benchmarks.rs:78`, `collective.rs:293`,
`compare.rs:249` — because `Option::map` structurally puts the unit inside the
`Some` branch. `schedules.rs::every` is textbook: every unit inside its own match
arm, bare sentinel for zero. So the *concatenate-after-the-branch* mechanism is a
**format-string** failure, not a universal one, and the amendment was written to
say so.

What survived is the second mechanism, and it is the one the idiom does not
protect against: with `map` you write the `None` branch **by hand**, and the
temptation is to decorate it to match the column.

```rust
let lat = opt_u(node, "latency_ms")
    .or_else(|| opt_u(ev, "latency_ms"))
    .map(|m| format!("+{m}ms"))
    .unwrap_or_else(|| "+—".into());   // ← the ornament, copied onto the sentinel
```

Two lines above it in the same function, the absent `cost` renders as bare `—`.
Arm A printed both on one row:

```
- ✅ `anthropic/m1` · @0ms +— · 0/0 tok · —
```

- **Mode** `code`, **measurable** distinct absent-value tokens on one span row.
- **A** = 2 (`+—` and `—`). **B** = 1 (`—`). **Verdict `better`, proof `ab-paired`.**
- The new test fails on arm A with the output above and passes on arm B; the

  one pre-existing unrelated failure (`guidance_guard`: projection
