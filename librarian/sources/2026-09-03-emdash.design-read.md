## The finding that decided System B

`agent-runtime-assembly/techniques/operator-tier-code-loading` states its tiers as a
two-row table whose second row is absolute — *service-writable configuration, written
by any authenticated administrator through the service's own interface, may name code:
**never***. Its own justification names the precondition: *"There is no protocol
boundary here and no process boundary; the isolation story the tool protocol offers
across a wire is unavailable in the host's own address space."*

This source is the case where that precondition fails. An administrator installs
third-party code from a UI in one click, on purpose, and the four things that make it
survivable — a real isolation primitive with the host's resource ceilings, one manifest
that is both the consent artifact and the runtime's enforcement input, consent at
install, and a separate gate on privilege *increase* at update — are a mechanism set
large enough to be a subject. An enumeration with a hole, found by walking the
technique's own table.

## Design record

### System A — content core, schema, localization, edge performance

**A1 · Operator-defined content types materialize as real typed tables.**
Definitions are rows in two system tables; each type gets its own table with real typed
columns. Forces: a non-developer must change the model at runtime, which rules out
schema-in-code; and the read path is a distributed edge store where every round trip is
the cost model, which rules out entity-attribute-value and a single JSON blob. The
rejection is explicit in the tree — real columns buy indexes, foreign keys, an
inspectable schema and no per-field parsing. The deepening the sweep added: the
rejection is **per field type**, not flat. Scalar-shaped fields get columns and are the
queryable set; rich text, multi-select and nested repeaters get a JSON column and are
explicitly not queryable, and index creation on a user field is opt-in per field.
`contributing/architecture.mdx:37-105,116-128` [V]; `schema/types.ts:52-62,71-93` [V].
`corpus: NONE` → landed as a technique in `data-access`.

**A2 · Migrations are statically registered, immutable, and their currency check is a row count.**
Three platform constraints stack: no filesystem in the deployment target so the bundler
must see the graph statically; the query builder's own introspection-based currency
check costs ~116 queries per cold start against ~57 tables, replaced by one `COUNT(*)`;
and the migration lock is a no-op on this engine, so two isolates race and the loser's
uniqueness violation is classified as benign rather than as a failure.
`runner.ts:6-153,257-283,414-490` [V]. `corpus: PARTIAL` — `migrations` owns
immutability and `idempotent-steps` owns replay.

**A3 · Content localization is row-per-locale with a shared group identifier.**
Each translation is its own row with its own id, slug, status and revision history;
slug uniqueness is scoped to (slug, locale). Adding a language is then zero DDL — the
requirement that kills column-per-locale — and a single-locale list touches one table
with no join, which kills the sidecar table. The load-bearing part is the question it
forces on every later feature, which the tree states as a rule: *per-locale (display
fields) or per-translation-group (anything identifying "the same thing" across
languages)?* Two confirmations that it is real: a categorization assignment stores the
*group* id, so one assignment spans every language; and fallback is asymmetric by
design — single-entry lookups fall back, lists never do, because a list fallback makes
one entry appear twice. `019_i18n.ts:7-28,135-160` [V]; `internationalization.mdx:60-76,103-109,147-150` [V].
`corpus: NONE` — `client-architecture/i18n` covers UI catalogs and says so in its
opening. Landed as a technique in `data-access`.

**A4 · The logged-out hot path is measured per route and per phase, in counts *and* query text.**
A fixture site is built and served through the **production** adapter entry — never the
dev server — and each route is measured cold and warm on two targets. The text snapshot
exists because a count alone cannot see a change that swaps one query for another or
alters a query's text at constant total. **Correction to the premise this run started
with**: "the hot path only ratchets down" is a *policy, not a mechanism*. CI does not
fail on an increase; it regenerates with `--update` and commits the new snapshot back
to the change under review. The force is stated — an outside contributor cannot
regenerate the platform-specific snapshot locally, so failing on drift would make every
performance-affecting change unmergeable by an outsider.
`query-counts.mjs:1-57,98-125,387-427` [V]; `query-counts.yml:31-59` [V]; `AGENTS.md:207,240` [V].
`corpus: HOME EXISTS` → amendment to `ratchet-design`, whose text says "Never auto-update".

**A5 · Isolate-lifetime caches store the resolved value behind a reclaimable claim, never a shared promise.**
From an observed failure, recorded in the source: a request cancelled mid-await never
runs its continuation, so a shared promise settles neither way and every later awaiter
hangs until the isolate is evicted — seen as 100-second timeouts at near-zero CPU. A
`catch`/`finally` cleanup cannot help, because neither handler fires. One cancelled
request poisons the isolate for its lifetime. The reclaim deadline sits strictly above
the owner's timeout, because a deadline below it supersedes a slow-but-live owner and
steady traffic turns that into a self-sustaining stampede. An independent instance of
the same hazard sits in the database dialect, where the driver declares support for
concurrent connections purely to stop a connection mutex from deadlocking the isolate —
and the *session-backed* dialect deliberately keeps the mutex, because a bookmark
protocol needs serialized calls. `single-flight-cache.ts:1-31,56-81` [V]; `d1-dialect.ts:34-64` [V].
`corpus: HOME EXISTS` → technique in `concurrency-guards`; `single-flight-primitives`
describes exactly the vulnerable construction as "the classic single-flight".

**A6 · Secrets read the runtime environment only, never the build-time constant.**
The build tool statically replaces the build-time expression, so reading a secret from
it bakes the build machine's environment into the bundle *and* shadows the runtime
value set on the platform. The same file deliberately keeps the build-time constant for
public config and for gating development-only endpoints, where being unspoofable at
runtime is the point. Site-scoped secrets are generated on first use and persisted;
only the encryption key is operator-mandatory, and it is never stored in the database so
a leaked backup does not carry it. `secrets.ts:1-28,516-538` [V]; `AGENTS.md:376-379` [V].
`corpus: PARTIAL` — `supply-chain`, `build-economics`.

**A7 · Consistency tier is chosen by requester identity, and the response cache is taught about the routing artifact.**
Anonymous requests read the nearest replica; authenticated ones carry a bookmark that
guarantees read-your-writes; writes always start at the primary. The second half is the
design: the bookmark is delivered as a cookie, and a response carrying a cookie is by
default uncacheable — so enabling replica reads would have silently disabled the edge
cache for every anonymous page. The cache provider strips *that* cookie and refuses to
cache a response carrying any other. Two individually correct mechanisms, jointly
destructive until one is taught about the other. `database.mdx:95-129` [V]; `cache/runtime.ts:44-60,153-190` [V].
`corpus: PARTIAL` — `read-serving-replicas` (forged 2026-09-02) is close.

**A8 · One store, two connection policies, routed by request class, with a post-write suppression window.**
A second connection configuration over the same database with query caching on, used
only for anonymous public reads; every other request uses the uncached one, because the
admin writes a row and immediately reads it back. Then the second-order hazard: a
post-publish rebuild reading through the cached connection would reseed the edge and
object caches from stale rows, converting bounded staleness into persisted staleness —
hence a window after any publish during which even anonymous reads are forced onto the
uncached path. `database.mdx:343,362-378,404-419` [V]. `corpus: PARTIAL`.

### System B — plugin platform (handed to a scoped forge)

**B1 · Two formats, split by where the code runs.** Sandboxed (one-click install, runs
in a runner-provided isolate) versus native (package install plus a redeploy, runs
in-process). What forces the high-trust tier is the set of things that genuinely cannot
cross an isolate boundary: build-time-resolved admin components, host-rendered
templates for the public site, and raw injection into visitor pages. The doctrine is
that the low-privilege tier is also the *lower-ceremony* one, and the high-trust format
is refused on the one-click channel outright. `choosing-a-format.mdx:10,16-58` [V]. `NONE`

**B2 · The format changes isolation, never the API.** Same hooks, same context, same
capability vocabulary in both tiers, so tier migration is a config move rather than a
rewrite and a host with no runner degrades by skipping the sandboxed set.
`choosing-a-format.mdx:60-74` [V]; `context.ts:1095,1114-1174` [V]. `PARTIAL`

**B3 · Capabilities are one static declaration enforced at three places by three different mechanisms** — shape-based in-process (the property is simply absent), check-based in the isolate (the property exists and the broker throws), and registration-based (a hook whose required capability is undeclared never attaches). One string set, three consumers: consent artifact, build-time validation target, runtime input. `capabilities.mdx:8,30-44,82-98` [V]; `hooks.ts:268-317` [V]. `PARTIAL`

**B4 · The structured privilege declaration is authoritative; the flat strings are re-derived from it.** Category → operation → open constraint object, canonicalized (sorted, deduped, implication-closed) so it can be diffed, hashed and signed. Escalation polarity is per change kind and **not uniform**: removing a category or operation narrows, removing a *constraint* widens. Absent and empty differ, and the most restrictive spelling must not grant the most. `declared-access.ts:34-56,233-249,300-383` [V]; `index.ts:163-192,274-277` [V]. `NONE`

**B5 · The isolation primitive is an injected dependency; the enforcement surface is not.** Two runners ship, and the tree publishes the asymmetry: one enforces CPU, memory and subrequests because the platform provides them, the other enforces wall time only. `plugin-sandbox.mdx:8-19,109-130` [V]; `sandbox/types.ts:19-28,96-120` [V]. `NONE`

**B6 · The admin extension surface is a server-driven block protocol: no extension JavaScript reaches the browser.** Sandboxed extensions describe pages and forms as JSON returned from a route; interactions round-trip. Shipping extension code into the admin bundle would put untrusted code inside the origin holding the operator's session. `block-kit.mdx:8-25` [V]; `react-admin.mdx:8-27` [V]. `PARTIAL` — `schema-driven-ui` owns the pattern; the *force* here is a trust boundary rather than flexibility.

**B7 · Extensions get persistence without DDL.** One shared table namespaced by extension id; collections and indexes declared in the manifest and created by the host; queries on undeclared fields refused so the performant set is exactly the declared index set, enforced rather than documented. Replaces the prefix-a-table-name convention whose costs are extension-authored migrations, an injection surface, and orphaned tables at uninstall. `storage.mdx:8-14,171-173,292-320` [V]. `NONE`

**B8 · Failure policy is per callback, and the timeout bounds the wait, not the work.** Each registration declares whether its own failure is fatal to the triggering operation, defaulting to the correctness-safe side. Paired with a versioned rejection envelope with a bounded reason string, so "threw" and "deliberately refused this save" are different signals. `hooks.mdx:56-65,139-167,338-397` [V]; `hooks.ts:374-386` [V]. `NONE`

### System C — decentralized distribution and trust (handed to a scoped forge)

**C1 · Publisher identity is a portable key; the index is a verifying cache, never the authority.** The listing *is* a signed record in the publisher's own store; the index re-fetches it and runs an inclusion proof plus signature check before indexing, so a compromised index can withhold but cannot forge. `pds-verify.ts:1-18,90-110` [V]; `authoritative-records.ts:68-117` [V]. `NONE`

**C2 · A trust signal names the exact revision it judged.** Approval is non-transferable across edits — the publisher editing the record produces a new hash and drops out of the approved projection with no moderator action. The consumer side mirrors it: install consent is pinned to the revision displayed and re-checked at commit, turning a time-of-check/time-of-use window into an explicit drift error. `evaluate.ts:89-91` [V]; `registry.ts:217-240` [V]. `NONE`

**C3 · Admit, set-state and redact are three authorities, separately configurable.** An operator can accept one party's takedowns without accepting its approvals; two simultaneously-active terminal states fail closed rather than picking one. `policy.ts:5-14,60-62` [V]; `evaluate.ts:174-195` [V]. `NONE`

**C4 · An unhealthy required trust source is demoted, not tolerated.** Failing open would hand an attacker a takedown-evasion primitive: knock the signal source over, ship the bad revision. The health timeout is derived from the source's own reconnect budget rather than picked round, and a config-parse failure in the trust policy degrades to deny-all rather than to the previous value. `label-source-health.ts:1-4,101-147` [V]; `listing-policy.ts:113-132` [V]. `PARTIAL` — `optional-dependency-degradation/refusal-is-not-failure`.

**C5 · The display-safety claim and the artifact-integrity claim get different instruments, and the softer one can only subtract.** The content assessor is structurally forbidden from fetching the package, its bill of materials, its provenance or its source — a machine-checked fixture, not a paragraph in a prompt — so a forged approval still cannot admit a byte past the checksum and manifest gates. `inputs.test.ts:119-135` [V]; `registry.ts:840-897` [V]. `NONE`

**C6 · The automated assessor has no reachable positive verdict.** Coverage gaps and stage failures resolve to error, findings to review, and the clean assisted case *also* to review; the only path to a positive outcome is a human decision naming the exact revision. Enforced at the policy layer rather than by prompt discipline. `policy.ts:34,99-141` [V]. `NONE` → landed separately as a technique in `hitl-approval`, whose golden path enumerates only review and consent.

**C7 · Provenance is required by the publisher's own signed metadata, not by the distributor.** That makes a downgrade attack detectable — stripping provenance still leaves the signed policy saying it was required. Publishing uses an ephemeral attested workload identity with a delegation scoped to one collection and one action, so a compromised repository yields at most releases matching an already-approved tuple. `records.ts:113-117,247-268` [V]; `registry-lexicons/src/index.ts:75-78` [V]. `NONE`

**C8 · Paid distribution is reserved-but-empty, and fails closed.** The authentication field on a release is a closed union with no defined variants, and the verifier rejects any gated artifact outright rather than half-building entitlements. This corrects the run's own premise: there is no paid-plugin story in this tree; the payment package is agent-metering for published pages. `release.json:43-48` [V]; `records.ts:426-441` [V]. `PARTIAL`

### Systems D and E — the agent contract and the quality apparatus

**D1 · One instruction file, three names, joined by filesystem links — and copies at the distribution edge.** Inside the checkout drift is not representable, so no checker is needed. The moment the same content ships into a scaffolded template a link has no target and the bridge becomes an assembled copy. `AGENTS.md:5` [V]; `sync-template-skills.sh:32-49,68-78` [V]. → amendment to `single-source-topology`.

**D2 · Rules a linter cannot express are enforced by a reviewer that has been given the rulebook.** The comment doctrine and the four named kinds of invalid test are not syntactic properties; no lint rule implements either, and the enforcement point is a model told that rulebook violations are first-class findings. `.oxlintrc.json` carries no such rule [V]; `.opencode/agents/auto-reviewer.md:20,37-38` [V]. → amendment to `prose-rule-drift`, which models only *mechanised* and *unbacked*.

**D3 · A policy exemption is computed from the authored artifact's author, never the triggering actor** — because the actor becomes privileged on later events on the same change, which would let bot changes through. `pr-compliance.yml:15-22,72-85` [V].

**E1 · Untrusted measurement and trusted application are different jobs joined by an artifact.** A read-only job runs contributor code and emits; a second job with write scope applies. `auto-format.yml:3-7` [V]; `visual.yml:3-14` [V]. → technique in `ci-execution-trust`.

**E2 · A generated catalog with many writers is regenerated once, after merge, and banned from the change.** Positional references shift on every edit, so per-change regeneration guarantees conflicts between authors who wrote none of the conflicting lines. The bot commit is gated by an allowlist on its own staged diff, so a buggy regenerator cannot commit a source file. `CONTRIBUTING.md:216` [V]; `auto-extract.yml:10-12,52-57` [V].

**E3 · A second suite of prose journeys, run by an executor denied the repository, the API and the route names.** A deterministic test encodes the intended path and so cannot fail because the path became undiscoverable. The oracle stays with the coordinator and is evaluated independently, because a judgment-exercising executor will otherwise talk itself into a pass. `acceptance/tester/SKILL.md:12-16` [V]; `ux-acceptance-coordinator/SKILL.md:33,41,43-49` [V]. `NONE` → technique in `test-harness`.

**E4 · A case whose preconditions cannot be met declares that and refuses to run.** The failure mode of a prose journey is a green run against the wrong world, because the executor improvises rather than erroring. `_template.md:1-7,13` [V].

**E5 · Every destructive step in the agent-run harness re-derives its target's identity before acting** — refusing to stop a process whose command line does not match, or to delete a path outside the expected prefix. `ux-acceptance-site.mjs:125-132,168-170,196-199` [V].

## What the tree proves without being built to

The negatives, which are the half worth keeping.

- **Restartability is a property of migrations 033-and-later, not of the chain.** The rule that every step must restart after any completed statement is honoured consistently from ~033 forward; eleven earlier migrations add columns with no existence guard and seventeen create tables without a not-exists clause — all but one numbered ≤ 032. Immutability forbids repairing them, and a fresh install still runs all of them, on exactly the engine whose lost responses motivated the rule. Nobody designed this; it is what immutability plus incremental learning produces, and nothing in CI checks it.
- **Migration 010 does not exist and never can.** The frozen map skips from 009 to 011. A gap in a sequence is normally a smell; here it is accidental proof that the immutability rule is obeyed rather than merely documented.
- **The cold-start tax is ~11 round trips and is very nearly route-independent** (10 to 12 across all ten measured routes). No column in the snapshots reports this — it falls out of differencing two independently recorded phases. The instrument was built to catch per-route regressions and happens to prove that the largest single item on the read budget is not any route at all.
- **A primary-routed write sits in the cold path of an anonymous GET** — a stale-lock recovery update — which the "anonymous visitors read from the nearest replica" model does not describe, and which the tree's own guidance says to defer off the request path. A rule and a live violation of it, recorded by the harness and rejected by no gate.
- **The finest-grained privilege-escalation instrument in the tree is never called on the operator's path.** It has one production caller, on the *publisher's* side. The site's update gate uses a flat set difference that cannot see host-scope changes at all — and the code's own comment admits an update swapping one host for another "sails through the escalation diff below."
- **One third of what the manifest documentation calls the trust contract is outside every consent and escalation path.** Storage appears in no privilege category, no consent dialog and no update diff.
- **The same declared privilege is enforced more weakly in the *less* isolated mode.** The in-process host-restricted path performs an allowlist check only, while the isolate's broker runs the full server-side-request-forgery check on both restricted and unrestricted paths — with an explicit comment that the allowlist must not become an opt-out. A wildcard entry is meanwhile a valid non-empty allowlist that satisfies the "must declare hosts" refinement while granting everything, and never triggers the loud consent language reserved for the capability that means the same thing.
- **A published trust signal with a complete write path and no read path.** A publisher-verification record type is specified with careful anti-drift semantics, ingested, validated, stored, tombstoned and re-served — and is consumed by nothing that changes a decision. The public view carries no verification field at all, while the documentation promises the browse surface shows an approved author name.
- **The acceptance apparatus is entirely off-pipeline, and five of its six journeys cannot run** — their site profiles do not exist. But the hole is *declared* in machine-readable frontmatter and the coordinator is told to stop rather than substitute a simpler fixture, which is the honest version of this failure and the reason it is visible.
- **Three template-sync scripts, no drift check on any of them**, in a repository that runs exactly that check (`diff --exit-code`) on another generated artifact. The discipline exists in the tree and stops at the distribution boundary.
- **The end-to-end sandbox fixture is a no-op runner** whose own comment says it exists to satisfy config validation. The build-time rule that a marketplace requires a sandbox runner is therefore a *presence* check satisfiable by a runner that isolates nothing; real enforcement is proved only in unit tests, and no test installs a hostile bundle through the real path.

And the positive one, which no one set out to prove: **the cost of removing the central
registry is not discovery, it is agreement.** The moderation package is roughly ten
modules of reduction, collision, negation, expiry and authority-separation logic that
exists solely because no single party can say "this listing is fine" and be believed. A
central registry pays for that with a database row. The distributed design pays for it
with a label algebra, a health-demotion protocol, a replay-generation counter and a
fail-closed rule at every join. That is the real price list, itemized in running code.

## Reusable engineering

Ranked by what another codebase should actually steal.

1. **The control route.** A deliberately naive implementation is checked into the
   performance fixture and permanently snapshotted beside its optimized twin; the gap
   between them is a live, measured calibration of what the optimization is worth. If
   the gap ever closes, either the optimization broke or the naive path got fixed, and
   both are worth hearing about. Inverts the usual regression test.
   `query-counts.mjs:83-87`.
2. **Simulate the constrained platform rather than requiring it.** In-memory SQLite is
   patched to throw the production engine's *exact* error text past a measured
   compound-select ceiling, with the measurement recorded in a comment ("five branches
   compile, six are rejected"). Without it every production-illegal query shape passes
   locally, because the local engine's own limit is two orders of magnitude higher.
   `tests/utils/test-db.ts:134-198`.
3. **Build error-matching patterns from the identifier constant, not the vendor's prose.**
   One logical condition, three driver phrasings, and a regex assembled from the table
   name so a rename cannot drift and an unexpected error naming a *different* table is
   not silently swallowed. `runner.ts:287-307`.
4. **A machine-checked negative-space list for a model's inputs.** A fixture asserting
   what the assessor may never fetch and never model — diffable and reviewable, rather
   than a paragraph in a prompt. Its own limit is honest: it asserts the list, not that
   the runtime honours it. `registry-moderation/tests/inputs.test.ts:119-135`.
5. **A brand that makes "unverified" unrepresentable.** Verified-label objects carry a
   private-set membership plus a non-enumerable descriptor, and the authoritative path
   throws on anything lacking it — so a type assertion does not get you past it, and the
   test says so by name. Pair a signature check and its consumer this way whenever they
   live in different modules. `label-crypto.ts:275-282`; `evaluate.ts:223-234`.
6. **A static export-shape check that replaced a whole harness.** Failing CI if any
   package export resolves to raw source, with a four-entry annotated allowlist, because
   once raw source is not shipped there is no raw-source graph to type-check. Traded a
   slow fixture-based consumer typecheck for a sixty-line invariant.
   `scripts/typecheck-public-source.mjs`.
7. **A bot commit gated by an allowlist on its own staged diff.** Stage everything, then
   fail the job if any staged path or status falls outside a narrow allowlist, so a
   compromised or buggy regenerator cannot commit a source file.
   `auto-extract.yml:52-57`.
8. **Index-plan assertions.** Seed a *skewed* distribution — the shape that makes a
   planner choose wrong — then assert on the query plan, positively and negatively.
   Most suites test that a query returns the right rows; this tests that it returns them
   the right way. `tests/integration/database/migrations.test.ts:515-556`.
9. **A snapshot harness that defends against its own formatter**, writing with the
   indentation the repository's formatter would otherwise rewrite, because the rewrite
   would present as drift. The class of detail that decides whether a snapshot harness
   survives its first year. `query-counts.mjs:585-590`.
10. **A three-valued adoption ladder with the sequence prescribed** — migrate on
    startup, then check-and-refuse, then never-check — plus the documented path between
    the values, rather than a boolean and a breaking change.
    `core-migrations.mdx:167-187`.

**Not reusable, despite appearances**: the adversarial-review skill is a checklist
prompt with no tooling, no invocation and no output validation; a team gets the same
value by pasting the list.

## Unresolved

One contradiction the sweep could not settle and did not pretend to: the request-context
module's header says middleware *always* wraps a request in a context, while the
accessor's own doc comment says it returns nothing on the logged-out fast path. Both
cannot be true, and which holds decides whether within-render query deduplication is
active on exactly the route class the whole performance regime is built around. The
worker did not open the middleware and marked it unresolved rather than deciding.
