## The finding that organised the run

Read in order, the four release notes are **the same defect found four times**: content
vanishing from a lossy conversion without the output saying so. Equations vanished
(v0.2.1); a fix for that escaped every `$` and broke prices (v0.2.2); spreadsheet
checkboxes were dropped, so "a sheet of tick boxes lost its answers" (v0.2.3); scanned
pages were "silently missing" (v0.2.4). Four versions, one root.

The rule the source states in `src/formats/pdf.rs` is the spine of the new subject:

> a document with scanned or image-only pages errors naming them, **whether that is every
> page or one of a hundred, because output missing those pages would read as complete.**

The threshold is not a fraction. It is whether the consumer can tell.

limit, and the derivation-recorded-beside-the-number rule. Verified by opening that file.

the amplification factor** - a byte cap says nothing about a four-attribute grid
materializing four million positions. The boundary is now stated in prose on this side.
Two of the spec's three proposed rules for that technique were already covered, and the
triage table overstated the gap. Recorded so a later run does not repeat the claim.

Worker overrides accepted: two slug renames (`extraction-confidence-bands` ->
`extraction-yield-bands`, because the technique's rule is to *reject* the confidence
score and the slug should not advertise the answer being refused); keeping five
techniques instead of folding the thinnest one in, on the strength of a fourth outcome
class the reconciliation found (the source logs a font-encoding warning and returns the
garbled text as success - present, plentiful and wrong, which neither refusal nor the
cascade can express).

### 2. Two amendments in `backend-platform/resilience/error-handling`

The source's `ConvertError::is_fatal()` exempts resource-limit crossings from a lenient
parser's recovery. `taxonomy-design` states **three** axes every consumer asks about, and
says so as an enumeration - the Phase 6 step-3 hunt. The fourth axis is *recoverability in
place*, and it only appears where absorption is the default.

- `taxonomy-design.md` - new section "The fourth axis, where leniency is the design".
  The membership inverts: name the categories that may **never** be absorbed, because a
  limit that can be swallowed is not a limit - an adversary relocates the payload into
  whatever part the reader treats as optional.
- `swallowed-error-prevention.md` - new section "When leniency is the architecture,
  invert the marker". That technique already covers *per-site* declared drops; what it did
  not cover is a component where every parse step is one, where the per-site marker does
  not scale and the census denominator moves from sites to categories.

No golden-path edit was needed, so no `content` lock was taken - useful in a
six-sibling checkout.

## Identified in the applied project, not fixed this run

Triage row 11, which the operator's pick covered and this run did not execute. Recorded
here at the precision needed to act on it without re-deriving it.

The vision-OCR command parses its provider's response with
`candidates.first() -> content -> parts.first() -> text` and ends in
`.unwrap_or_default()`. A response whose shape does not match - a safety block, a refusal,
a split across multiple parts - therefore yields an **empty string**, which is persisted as
a document row and returned as `Ok`. The user is shown a successful OCR containing no
text. Taking only `parts.first()` also silently truncates any response the provider splits.

This is `failure-not-empty-success` in the same tree the run just applied
`unreadable-region-refusal` to, and it is the *same finding at a different layer*: the
extraction half was fixed, the recognition half has the identical defect. It was left
alone because it is a behaviour change in a different module that deserves its own
verification, and the run had already committed a compile-verified change beside it -
adding an unverified second one to the same commit is the trade this method exists to
refuse.

**Return condition: immediately, as its own change** - it is a bug rather than a lead, and
the technique that governs it is already landed and cited.
