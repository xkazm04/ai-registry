## Row 7 - the boundary, stated so a render can falsify it

`visual-style-locking` is written for a renderer with no memory between
calls: consistency "cannot be remembered by the system", so the style block
is restated in every call. **A deterministic renderer inverts the premise.**
When the frame is computed by a program, the style can be an importable
artifact (tokens, primitives, a motion grammar) that every strip calls, and
restating it as prose is what *introduces* drift: an author re-reading a
description re-derives the look. The source shows the shape without naming
it - seven preset styles shipped as part of the skill, and custom styles
built "from a reference image or video".

- **Discriminator:** is the frame produced by a generative model (restate
  the block) or by code the pipeline owns (import the module)?
- **Return condition:** gravitone's strip triage
  (`docs/code-rendered-strips-plan.md`) keeps a code style on two different
  briefs **by import with no restated prose**, and the replica arm shows
  approach-to-approach distance at least 1.5x author-to-author noise on the
  same approach. Then land it as a boundary section in
  `style-block-restated-every-call`, with gravitone as the application.
- **Falsifier:** kept styles drift between briefs when only the module is
  passed, or need a prose restatement to hold.
