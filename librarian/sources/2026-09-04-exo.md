# exo — an agent harness that edits itself

**Class:** vendor repository, design-deep. Read as a system (Phase 2d), not as a
set of claims. The landing page is 2,003 words against 62,842 of in-tree
markdown and ~94k lines of source — a ~31:1 ratio, the same shape as the emdash
and opik rounds, and the README is again the least reliable surface in the tree.

**Expected yield, stated before extraction** (round-14 focus item): a
self-modifying agent harness's yield would sit in whatever *enforces* "safely
edit all aspects of itself", and in the recursion control — what stops an agent
that rewrote its own harness from bricking itself — not in the architecture
prose. **The prediction held**, and the strongest finding was the negative form
of exactly that: the enforcement is absent.

## Landed

- **`termination-and-reaping`** (amendment) — where a polite stop's *receipt* is
  observable, rung 2 splits into a claim deadline and a completion deadline; a
  child that misses the claim deadline escalates immediately because it has
  demonstrated it cannot participate. Make the acknowledgement the same act as
  the receipt. Record which deadline was missed — they are different defect
  reports (version skew vs workload).
- **`operator-tier-code-loading`** (amendment) — a fourth row for the tier
  table: the agent writes the configuration. Install-time consent is
  *structurally unavailable* for that writer, and because the four conditions are
  joint, the third row's inversion cannot be taken. Two honest resolutions: deny
  code entry and extend through data, or move consent to review-time and say what
  it costs. Plus the specific self-deception — the isolation that counts wraps the
  *contributed code*, not the agent.
- **`declared-verdict-over-inferred-wreckage`** (amendment) — inferring from an
  *absence* is the same defect with the polarity flipped, and worse in one way: a
  declared marker has one author, an absence has none. The tell is a disjunction
  in the system's own description of the verdict. Instrument the start, not the
  shutdown.
- **`durable-store-failure-posture`** (new technique, `agent-memory`) — the read
  path degrades and says so; the write path refuses. The degraded read says
  "unavailable", never "empty", because the consumer is an actor that responds by
  writing. Assert the asymmetry in one paired test. Boundary: this does not cover
  concurrent loss, which the source discloses in its own tree and does not fix.
- **`execution-state-checkpointing`** (new subject, forged in-session) —
  `backend-platform/work-execution`, 4 techniques + 2 source-tree applications.
  The worker rejected two proposed techniques with arguments, folded a third into
  one, and added `resume-mints-a-duplicate` which was not in the spec: a document
  restored twice is two documents, a machine resumed twice is two machines that
  both believe they are the original. It also recommends `cost-invariant-refusal`
  be dispatched separately against `resilience/optional-dependency-degradation`,
  which it inverts.
- **Four applications** — `rust--operator-tier-code-loading` (the trust root),
  `node--indeterminate-closure-on-interruption`, `rust--dead-letter-design`,
  `node--token-usage-quadruple`. Three of the four are **negative**: a serious
  system walking into exactly what a technique predicted.

## The three findings worth re-reading

**The trust root is stated three ways and enforced by none.** `README.md:31` says
the only unmodifiable thing is the event log; `docs/RSI.md:46` says it is the
harness; `RSI.md:62` concedes it is a config default. The mount API supports
read-only (`crates/cli/src/main.rs:1700,1724`) and the canonical start mounts the
whole tree — harness crate included — read-write (`exo.sh:647`). The mechanism
existed and the default path did not use it. Found independently by the director
and by the self-control worker.

**Both halves of `indeterminate-closure-on-interruption` inverted, by a careful
team.** The synthetic result for a dangling tool call is
`ok: false, error: "tool execution did not complete before the previous turn
ended"` — a distinguishing string inside a failure, which the technique names as
"what teams actually build" — and it is written lazily at read time, which its
second half explicitly forbids. The tree reasoned its way there: it kept the log
append-only on purpose. Choosing between "write a lie" and "write nothing" is
what a two-value vocabulary forces, and the vocabulary is the defect.

**A dead-letter lane with one writer and no readers.** Five references in the
whole tree, all in one storage module; no tool, CLI verb or sweep reads it, and
it is deleted when the adapter is removed. The subject predicts the outcome in a
sentence. The generalisable half: everything on the *producing* side is reachable
from the code path already being written, so the consuming side is what gets
deferred, invisibly. The review question is not "is there a dead-letter lane" but
**"name the caller that reads it."**

## Leads (3, each with a return condition)

- **Agent-scoped stores are read-modify-write with no compare-and-swap**, disclosed
  in the tree's own `TODO(storage-rework)` at `exo/tools/memory-tools.ts:71-76` and
  `harness/skill-tools.ts:95-98`, in a system whose *default* topology is concurrent
  conversations. A live data-loss path, named and unfixed. **Return:** when it lands,
  or when a second source shows the same disclosure pattern — a durable store
  hardened against corruption while losing concurrent writes.
- **No canary path.** The tree names its own central weakness at
  `SELF-CONTROL.md:189`: every self-modification is validated in production on a
  singleton, because sandbox *cloning* (a second sandbox from a snapshot while the
  original runs) is denied to the turn scope. **Return:** when a self-modifying
  system ships validate-on-a-clone-before-adopt.
- **The clone/migration spec is already written and unbuilt.** `SELF-CONTROL.md:164-178`
  observes its own area-2 state inventory *is* the clone manifest; only export/import
  is missing, and secrets are the blocker because keychain material cannot be copied
  as files. **Return:** when export/import lands, or a second system hits the
  secret-portability wall.
