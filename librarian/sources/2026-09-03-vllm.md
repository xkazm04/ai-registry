# vLLM — an inference engine read as a system, not as a set of claims

The run the 2.0.0 method was written for. The ingest returns a 620-word landing page;
the source is `docs/design/` — **29 documents, 50,830 words** — plus a 9,100-word
security posture and a deprecation policy. Mining this at the README would have
produced quotes.

**Expected yield, stated before triage:** forge-shaped, not amendment-shaped. That
prediction held: 8 systems, 26 load-bearing decisions, **24 with `corpus: NONE`**, six
systems clearing the three-or-more threshold independently. The largest routing count
this skill has produced. The operator took all six.

The corpus had **three files total** mentioning this class of cache before today, all in
`prompt-assembly`, all client-side. There was no subject anywhere for inference-server
internals: no block allocator, no batch scheduler, no accelerator memory grouping, no
extension trust boundary.

Full design record: [`librarian/handoffs/2026-09-03-vllm-design-record.md`](../handoffs/2026-09-03-vllm-design-record.md).

## Already covered — the catch

Most of **H2 was already in the corpus** and better than I expected:
`structural-amplification-caps` already carries "a cap on the count of an expansion does
not bound the memory the expansion costs", the two-caps rule, and the generalization to
any product of an unbounded pair. The run's contribution is one boundary case, not a
mechanism. Recording this properly matters: I nearly filed it under `rate-limiting`, and
that subject's golden path **explicitly disclaims it** — it bounds work per unit time,
"not whether the work is valid (validation's job)". Reading the boundary statement is
what prevented the misfile.

## Three defects the source's own documents do not admit

Each verified in code by the director, not taken from a worker's report.

1. **The lease sweep is defeated by its own renewal.** The expiry loop early-exits on
   the first unexpired entry, on the strength of a comment claiming the map is ordered
   oldest-first. Renewal writes `max(old, new)` **through an existing key**, which does
   not change insertion order — so a renewed request keeps its early position with a late
   expiry and shields every expired entry behind it. Direction is over-retention, so it
   is safe; but worst-case retention stops being bounded by the sweep period, which is
   the exact property the lease design exists to provide.
   `base_worker.py:2313-2317` against `:2367`.
2. **A deprecation stage with a mechanism and no occupants.** The hidden-metrics flag has
   a complete chain — CLI arg, config field, validator, computed property, assigned onto
   the logger — and is **read nowhere**. Stage 2 of the published deprecation pipeline is
   plumbed and empty. (The escape hatch's design is good: it takes the version it escapes
   from, so it expires by construction.)
3. **A document and its implementation stating opposite attribution rules.** The design
   doc defines intervals from the *most recent* start event; the code keeps the *first*.
   Found by the worker forging the technique that warns about exactly this.

## Reconciliation actually reconciled

Three of six workers had their **expert draft corrected by the tree** rather than
confirmed — which is the two-phase order working, and worth recording because it is the
part that is easy to fake:

- E's draft argued removes-first exists so adds land on vacant seats. The tree says the
  opposite: a **replacing add is the normal refill path**. That correction produced a
  sharper rule than either source had — a batch member can leave three ways and only one
  has an operation name, which is where implementers leak state.
- D reversed its own step: prefer a **low default-on sample rate to default-off**,
  because a metric that must be switched on is absent during the incident that would
  justify it.
- A took the "runtime owns the entry point" rule its draft lacked.

And one worker **corrected the director's design record**. My B3 entry described the
eviction mechanism a level too coarsely. Allocation drains the front and release appends
the tail, so the queue is *already* coarse recency; reverse-order release is the
tie-break **within one release**, where recency cannot discriminate. Two things I had
missed: non-cacheable blocks are **prepended to the front** (the intuitive answer is
inverted — the back holds the longest remaining life), and the release entry point
*takes an ordered sequence whose order IS the eviction priority*. The policy is a
parameter of the release call, not a convention around it. Record amended in place with
the code anchors.

Two of my brief's instructions were wrong and were overridden correctly: the `_laws.md`
depth (three levels, not four), and C absorbing the H1 path-prefix material rather than
leaving it stranded.

## Applied (5 rows) — the fleet mostly already does this

The apply phase reshaped the direction pass. Three of my ranked candidates were
**refuted by reading the trees**:

- `export-terms-not-ratios` → tracklight publishes shed/timeout/admitted as counters,
  names the admitted counter "the denominator for a shed rate", and **declines a scrape
  endpoint on the record**. Two independent systems reaching counters-not-a-gauge is the
  run's cleanest convergence — and it refutes the obvious direction ("add `/metrics`"),
  which the tree has a stated reason against.
- `renewal-beats-a-tuned-timeout` → pumper implements it, and **validates the invariant**
  the source only states in prose: it refuses a config where the stale threshold does not
  exceed the heartbeat interval.
- `invert-the-default-for-exposed-surface` → pumper's network-exposed module surface
  already defaults to disabled.

The `renew-from-arrival-not-from-work` row is the valuable one, and it ran **upward**:
tracklight's fenced relay lease holds two refinements the standard lacked, both taken
into the technique.

1. **Liveness and progress are separate doors** — "a device that is alive but stuck
   computing something to say reads as a dead one." The subject was forged from the
   *arrival* argument (renew before you work); this is the *reporting* argument (renew
   without having to speak), a different failure, and it is load-correlated: it fires
   when the holder is working hardest.
2. **The renewal carries a generation token.** The source has none; the forging worker
   recorded that as a deviation and refused to lower the standard on "the transfer is
   read-only". A second independent tree implements the fence. The deviation was written
   down *before* this tree was opened, which makes this a genuine second sighting rather
   than a rationalization.

One correction against myself worth recording, because the discipline is the point: my
first pass at tracklight's auth surface used a grep that reported two `/v1/relay/*`
routes as unauthenticated. **Reading the handlers showed they call a different auth
function** (device-key, appropriate to a relay agent). No finding. The instrument was
wrong and opening the file caught it — which is exactly the rule about never
establishing an absence from a pattern match.

## Directions — one proposed, not three

The cap is three; **one** survived contact with the trees, and padding it to three would
have been the feature-request generator the method warns about.

- **tracklight** ← `metric-surface-contract`, a staged deprecation policy for its
  published surface. Forces genuinely present: self-hosted operators it cannot enumerate,
  three shipped SDKs, a contract suite, and deprecation discussed only in design docs.
  The proposal names its own likeliest refutation (that `/v1/capabilities` already covers
  it in practice, making this a docs gap). **Accepted at the gate; executed in a worktree
  on `direction/metric-surface-contract`, branch left for the operator.**

**Directions not proposed**, with reasons, so a later sweep does not re-derive them:

- **pumper** ← `salt-as-a-cache-partition`. Its cache key hashes method, URL, body, every
  request header and the proxy, so a credential is already part of the key and nothing is
  shared across a trust boundary. The decision's *forces* do not exist there. Not a
  candidate.
- **pumper** ← `extension-trust-boundary`. Refuted above; it already inverts the default
  and sandboxes besides.
- **personas** ← `serving-process-topology`. Plausible on purpose but unverified — I did
  not open the tree far enough to cite forces rather than features, and a proposal I
  cannot ground is one the owner has to investigate. Deliberately not written.

**A standing caveat for the whole pass:** no project on this machine has a `scope:` block
in its manifest, so the fleet map reports `scope=missing` everywhere and 7.6's judgment
step ("does `scope.does` admit the forces?") has no declared input. Every judgment here
was made from `repo.purpose` plus the tree, and the proposal says so in its own body.
Candidate counts of 57–154 per project are the "scope needs tightening" reading, not a
claim that the fleet is missing a hundred features each.

## Leads

- **The renewal/sweep ordering defect is upstream-reportable.** Return condition: if the
  operator wants it filed, the reproduction is a renewed head entry plus a later expired
  one; the fix is either an ordered structure that reorders on renewal, or dropping the
  early exit. Not filed from this run — reporting into another project's tracker is
  outward-facing and was not authorized.
- **System H3 — copy-all-except-denylist environment propagation**, with the tree's
  stated reasoning for why a partial isolation would be theater (cluster access already
  implies code execution, so restricting env vars alone is not a boundary). Genuinely
  good doctrine about *declining* to build a control that looks like security. No clean
  home: `per-variable-blast-radius` is the right subject matter (env vars) but the wrong
  concern (degradation, not trust), and both plausible categories sit at the cap. Return
  when a second source states the same "a control that is not a boundary should not be
  built as one" argument, or when `security/` next gains room.
- **tracklight is a peer-shaped system for system D** (it ingests what an engine like
  this emits). Under the v2.2 peer rule that warrants a **comparison study**, not three
  proposals. Not run: the operator authorized a proposal pass, and a study is a bigger
  spend than was asked for. Return condition: an operator asking for the study, which is
  now cheap because the design record and the applied rows already exist.
