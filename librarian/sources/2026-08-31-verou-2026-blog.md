# Lea Verou, four posts from 2026

Ingested as a batch of four, correctly read as a **channel corpus** at Phase 2:
one author, so within-batch convergence is void and triage had to lean on
corpus-vs-source novelty instead. The class predicted amendments and
corroborations rather than new subjects, and for the triaged rows that is exactly
what landed — two techniques into existing subjects, two golden-path sections,
one correction.

**The class prediction was then falsified by the same source, in the same
session, and the manner is worth recording.** The operator picked the banked `XL`
row, which became a new subject (`dependency-declaration`, 6 techniques). So a
channel corpus *can* yield a subject — but not through the rows that survive
triage on their own merits. It yielded one through four rows that each looked
like a minor standalone candidate and were in fact one subject that Phase 3's
splitting had shattered. The row's guidance ("amendments and corroborations,
never new subjects") predicts the triage outcome correctly and the *corpus*
outcome wrongly, and the discriminator is whether anyone looks at the untriaged
table for candidates that belong together.

The author is unusually authoritative for one narrow thing: claims about how the
web standards process behaves, which she participates in. That is the only
territory here where this source can *authorize* rather than merely originate,
and almost none of the registry's bundles are about web standards — so the
corroboration budget went unspent. **0 of 3 fetches**, the fourth consecutive
run to land everything corpus-internally.

Five siblings were live on the board at Phase 0 (`brooker-2026-08-31`,

## Accepted

### 1. `inherited-default-override` — new technique on `settings`

The source's dark-mode essay is, stripped of every proper noun, a precise state
machine for **a key whose default is a live upstream source the application does
not own**. The corpus models every default as a static constant declared in
code. That gap is real and it is on an axis the subject does not otherwise
carry: when the default is inherited, absent means *follow the source
continuously*, a write means *detach*, and a delete means *re-attach*.

Two silent-corruption failure modes came with it, and both are the good kind —
they produce no visible feedback at the moment they occur:

- **Writing unconditionally** pins a key that was merely following, the instant
  the user's target coincides with the source. The surface looks unchanged; the
  subscription is gone and there is no gesture left that restores it.
- **Clearing an override when the source moves** — which looks like hygiene —
  makes pinning *unachievable* for anyone whose environment switches on a
  schedule, because a background event they did not cause deletes the choice
  every time the source swings through it.

The near-miss that proves this was a seam and not a hole: `setting-kinds`
already refuses to store *derived* limits ("store the inputs, derive at read"),
which is the same freezing failure in a regime where the answer differs — there
you store nothing, here the user must be able to detach, so the row is
legitimate and only the *reason for writing it* is constrained.

### 2. Correction into `adaptive-fidelity-tiers/preference-short-circuits-measurement`

The strongest shape in the run: a subject that got the requirement right and the
remedy wrong. It already held that a measured tier is a default for people who
have not said what they want, that every statement retires it, and that the
control therefore must not make its first use a permanent exit — then prescribed
a visible third "automatic" option. The source supplies the mechanism that
satisfies the same requirement without spending a control state. Corrected in
place, with the boundary written from both sides, plus a caution that belongs
only there: that subject's source is a *measurement the application performs*,
which can be re-run and can change for reasons unrelated to the user, so it is
disqualified twice over as a trigger for re-evaluating a stored choice.

### 3. `fallback-retirement-condition` — new technique on `optional-dependency-degradation`

From the polyfills essay. The host subject treats absence as a **stable
per-deployment fact**; the source's whole subject is absence as a **closing
frontier**. A fallback for that kind is a bet the gap will close, and it owes a
retirement condition — which the corpus already demands of everything else, by
law: `creation-names-reaper`. Every fallback in that subject's ladder names its
*consequence*; none names its reaper.

Where the capability is testable at run time, the check **is** the reaper, and it
retires the fallback per caller with no deploy and no maintenance. The source's
sharpest contribution is the anti-pattern: deleting that check (proposed on
integrity grounds — a substitute occupying the real name becomes the de facto
contract) converts a bounded, self-clearing cost into a permanent tax that every
caller pays forever while none ever reaches the real implementation. Its second:
suppressing the fallback entirely does not remove the need, it **disperses** it
into ad-hoc conditionals at every call site that no upgrade ever retires.

## Applied (Phase 7.5) — 3 rows / 3 landings, 1 shipped

**`inherited-default-override` → an embed widget on a connected project,
`code`, `better`, shipped.** Its widget config carries a four-value appearance
setting including a distinct `auto` meaning follow-the-viewer, and resolved it
**server-side**, where the viewer's environment is invisible, to a hardcoded
constant — in two files, by two paths, one of which documented the gap in a
comment instead of closing it. n=2 viewer environments, both arms extracted from
real revisions of the source file and executed: arm A serves the right palette
to **1/2**, arm B to **2/2**. Instrument self-asserted first, and its assertions
double as regression checks — both arms byte-identical on explicit values, and
an explicit pin does not move when the viewer's preference changes.

Shipped to the project's default branch (two commits, not pushed): the palette
already travelled as custom properties, so `auto` now emits the light palette as
base plus a viewer-preference block redefining the same six. Type-check carried
the same 29 pre-existing errors before and after with none in the changed file;
linter clean on it.

**The apply step amended the technique**, which is the part worth keeping. One
of the two resolution points was deliberately left broken: the shared resolver
has the identical defect, and changing it the same way would be a *regression*,
because its consumers render one resolved palette with no viewer-preference
block. That produced a clause the desk-written technique did not have —
**deferring a resolution is only correct if the consumer can perform it**, so
where two resolution points share a downstream shape, the consumers change
first. One seam repaired on that test, one seam failing it and left alone.

*Structural fact:* the three-state **model** survived perfectly; the subscription
died at the **resolution point**. Shape and semantics were maintained by
different hands and only shape reached the renderer — which is evidence for the
technique's central claim in its strongest form, because it says preserving the
model protects nothing on its own.

**`fallback-retirement-condition` → a connected desktop application, experiment,
`better`, not shipped.** Read-only census; the repair is eight emission sites
across seven files, which is more than a reviewer reads in one diff and was not
confirmed. Census of capability-conditional fallbacks for closing gaps, with
server/browser guards deliberately excluded as a stable absence. Across 8 seams
/ 4 capabilities / 7 files: branch tests the capability rather than a proxy
**8/8**; check present **8/8**; branch emitted **0/8**.

*Structural fact, and the best thing in the run:* **the check is load-bearing and
the emission is not.** Omitting the check crashes on the runtime that lacks the
capability, so every author writes it and writes it correctly. Omitting the
signal behaves identically everywhere and fails no test, so no author writes it.
Conformance tracks consequence, not diligence — 100% on the half that breaks, 0%
on the half that only makes a future decision possible. The tree holds eight
correct automatic reapers whose firing nobody can observe, so none of the eight
paths can be deleted on evidence.

**The `preference-short-circuits-measurement` correction → simulation,
`better`**, over three real cases. The embed config above (a configuration
surface set once via parameters) — the correction's carve-out fires and three
states are **correct** there. A read-only motion preference on the desktop
project, honored across 24 components with no override control at all — the rule
predicts two states plus the divergence rule if one is ever added. That project's
theme system, which is fully app-owned with no upstream source — the rule
correctly does **not** apply. In two of three real cases the rule declines to
fire, which is what was being tested; its mechanism is exercised by the first row
rather than this one.

## Untriaged — and then rows 8–11 were built

Recorded with anchors so a later run does not re-derive them. **These are not
declines**; no one looked hard enough to say no.

**Update, same session.** The operator picked the banked `XL` row rather than
leaving it, and rows **8, 9, 10 and 11 became four of the six techniques of a new
subject**, `dependency-declaration`, in `engineering-process/codebase-stewardship`.
They are struck through below and kept for the record rather than deleted, because
the interesting fact is that they arrived as four separate candidates.

That is worth stating plainly, because it corrects the framing this note filed
them under. They were never four leads. They were one subject that **extraction
had shattered** — Phase 3 splits a source into candidates, and a subject-sized
finding necessarily arrives as several of them. The cost of building it was far
below what pricing it against the four small rows would have suggested, because
the four small rows *were* the subject; folding them in was most of the work
already done. A triage table that prices an `XL` row as additive with the cheap
rows beside it is still pricing it wrong, just more precisely — the relationship
is substitutive.

The remaining four (5, 6, 7, 12) stay genuinely untriaged.

## Leads

- **The whole ecosystem's stated blocker was already unblocked.** The January
  post named external import maps as the core limitation; the March post found
  the limitation liftable by a technique that had worked in every implementation
  for years — "it is unclear why it took all of us so long to discover it."
  Return condition: when a second independent source shows a field designing
  around a constraint nobody re-tested, this becomes a technique about verifying
  a constraint before building on it. Two sightings and it is real.
- **Part 2 of the polyfills post** is announced but unpublished: what platform
  gaps make workarounds hard to write, and how that varies by layer. Return
  condition: when it publishes — it is the half that would carry the
  layer-specific mechanics this run could not land.

## Method notes

- The `--min-words` floor did its one job again and nothing more: the thinnest
  article (1289 words) carried untriaged rows 9 and the strongest lead, while
  the longest (4349) produced no accepted landing at all. Both accepted
  techniques came from the middle two.
- **Row 3 is the run's best argument for opening files rather than trusting
  slugs.** `preference-short-circuits-measurement` would never surface on any
  concept query built from this source's vocabulary, and it is the one file in
  the corpus that already held the requirement. A summary would have shown it as
  covered; the full text showed it prescribing the opposite remedy.
- The purity grep was worth running on a source this dense with proper nouns —
  12,768 words of product, browser and specification names produced zero leaks
  into the upper layers, and the two `browser` hits the grep returned were
  pre-existing lines in a golden path this run did not write.
