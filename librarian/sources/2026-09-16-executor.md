A public integration-layer monorepo for agent tooling — a tool catalog with auth,
scoping, policy and a run record over it, shipping as an in-process SDK and a hosted
service from one codebase. Mined from a clone at `9c424444`, never from the landing
page.

## Design record

### System A — the agent-configuration surface

**A1 — the policy file names three write-back sinks, and all three are ignored.**
- *forces*: the repository is public and its own policy file bars private names,
  internal context, customer-derived data and model attribution from anything
  committed. A shared learnings log is exactly that content.
- *buys*: the agent gets a sanctioned destination for a discovery instead of dropping
  it or editing the shared policy file mid-run.
- *rejects*: appending to the policy file itself; a committed learnings log.
- *where*: `AGENTS.md:57` "Record mistakes in `MISTAKES.md`, missing capabilities in
  `DESIRES.md`, and environment discoveries in `LEARNINGS.md`."; `.gitignore:104-106`.
  None of the three exists.
- *stage*: post-run, write side.
- *corpus*: **NONE**. `agent-instruction-files` models the file entirely as an inbound
  brief across fifteen techniques. Nearest neighbour `instruction-freshness` owns the
  phantom gate ("enforced by X" where X never fired) — the same failure on the read
  side. **HOME IF NEW: agent-instruction-files.**

**A2 — review checklists are selected by the path globs a diff touches.**
- *forces*: a whole-repo model-graded security pass is too expensive and too noisy;
  the risk class (authorization, code execution, data exfiltration, PII, CI workflow
  injection) is a property of *where* the code lives, not of the change.
- *buys*: a judgment prompt scoped to the risk the changed path actually carries.
- *rejects*: one review prompt for everything; a human convention about who reviews what.
- *where*: `warden.toml:16-73` — six `[[skills]]` blocks, each `name` + `paths` globs;
  five resolve `remote = "getsentry/warden-skills"`, one is local under `.agents/skills/`.
- *stage*: pre-merge review.
- *corpus*: **NONE**. `quality-gates` owns gate scoping and `enforcement-demotion` owns
  prose-versus-gate; nothing owns routing a *model-graded* checklist by path, or
  sourcing that checklist from another organisation's repository.
  **HOME IF NEW: quality-gates.**

**A3 — a vendored skill is pinned by content hash.**
- *forces*: a skill body is a prompt; an upstream edit changes behaviour with no
  version to notice it by.
- *where*: `skills-lock.json` — `{source, sourceType, skillPath, computedHash}`.
- *corpus*: **NONE**, but boundary-shaped. `sibling-floor-ownership` splits installing
  from retaining as two decisions; this is the third — *what the retained body now
  says*. **HOME IF NEW: agent-instruction-files (as an amendment).**

**A4 — 34 custom lint rules carry the house idiom.**
- *where*: the repo's own lint plugin (`no-try-catch-or-throw`, `no-raw-fetch`,
  `no-switch-statement`, `no-json-parse`, `no-promise-catch`, `no-raw-error-throw`, …),
  with escapes required to name a boundary inline:
  `e2e/src/scenario.ts:203` `// oxlint-disable-next-line executor/no-try-catch-or-throw
  -- boundary: optional post-processing over external tooling (agg, ffmpeg)`.
- *corpus*: **CATCH.** `enforcement-demotion` owns it and says it better, including the
  claim-verification half this tree does not state.

**A5 — dependency source repos cloned into an ignored `.reference/`.**
- *where*: `scripts/pull-references.ts:8` (`const repos = [`) clones four upstreams (including the
  repository's own abandoned rework fork) shallow, pulls `--ff-only` thereafter.
- *corpus*: **partial** — `context-reachability` in `prompt-assembly` covers what the
  agent can reach; nothing covers deliberately *enlarging* the reachable set with
  dependency sources.

### System B — the end-to-end matrix

**B1 — a scenario's service requirements ARE its capability declaration.**
- *forces*: the same scenario runs across seven heterogeneous targets (CLI, local,
  cloud, self-host, Cloudflare, desktop, packaged desktop); a hand-maintained
  per-target support matrix rots on the first new target.
- *buys*: the declaration cannot drift from the use, because they are one expression.
- *rejects*: a `needs: [...]` list beside the body. The file header says so outright:
  `e2e/src/scenario.ts:2` "its requirements ARE its capability declaration: it yields
  services … and nothing else — no needs list."
- *where*: `e2e/src/scenario.ts:88-115` (`contextFor` adds a service only when the
  target has the capability); `:155-167` (a missing service becomes a recorded skip
  with the service named, written to `skipped.json` and folded into the matrix).
- *corpus*: **partial**. `suite-partitioning` already rules membership by location
  rather than annotation, and `derived-selection-must-be-measured` owns the
  zero-selected-reads-green failure from the *detective* side. This is the
  constructive side of the same concern. Promoting question executed (read
  `derived-selection-must-be-measured` in full): it stayed partial — that technique's
  rule is "a clause is not the cause until removing it moves the count", which is about
  diagnosing a filter, not about eliminating the second list.

**B2 — the skip signal is recovered by a regex over a rendered error string.**
- *where*: `e2e/src/scenario.ts:225-231` — `missingServices` runs
  `String(Cause.squash(cause))` and matches `/Service not found: e2e\/([^\s(]+)/g`.
- *buys*: nothing extra; the structured cause was available and was rendered first.
- *the cost*: a skip reads green, so any failure whose rendered cause contains that
  substring is laundered from a defect into a pass. Two always-provided services
  (`e2e/target`, `e2e/run-dir`) are in the same namespace, so a context lost inside a
  forked or separately-run effect classifies as "this target lacks the target".
- *corpus*: **NONE**, boundary-shaped against `test-harness`.
  **HOME IF NEW: test-harness (as an amendment).**

**B3 — `expectedFailure` runs the body and keeps the artifacts.**
- *where*: `e2e/src/scenario.ts:60-64`, `:136` (`it.live.fails`). Distinct from `skip`,
  which is reserved for a tracked out-of-scope blocker and never runs the body.
- *buys*: the suite goes red when the bug is *fixed*, so the marker cannot outlive its
  reason; and the failing run still produces the artifacts that would diagnose it.
- *corpus*: **partial** — `flake-lifecycle` owns the muted-versus-skipped choice and
  quarantine with an expiry; this is a third state neither covers, self-expiring by
  construction rather than by an owner and a date.

### System C — the integration and authority model (from `vision.md`)

**C1 — imported-spec refresh must never auto-expand authority**: new operations appear
*ungranted until reviewed*. *corpus*: **NONE**; home is `mcp-tools`, **held by a live
sibling** for the whole run, so banked rather than mapped.

**C2 — visibility is not permission**: toolkits are pure curation and carry no policy;
policy attaches to the integration and connection records, connection overriding
integration, with outer-scope authority layered on top and unweakenable inward.
*corpus*: **partial** — `deny-absorbs-and-lowest-limit-wins` owns the merge arithmetic;
the curation/governance split is stated but not owned. Same sibling-held home.

**C3 — a secret reference never appears in a tool's I/O schema or any host response**,
with no escape hatch. *corpus*: **CATCH** —
`secret-surfaces-never-exposed-to-agents` and `mcp-tools/authentication-and-scoping`.

**C4 — scope merge has three fixed rules**: visibility = union, guardrails =
deny-union outer-wins, scalars = innermost-wins. *corpus*: **CATCH** —
`deny-absorbs-and-lowest-limit-wins`.

**C5 — one Run record collapses four features into views over it**: audit log,
approvals, workflow runs, resumability. *corpus*: **NONE**, but one paragraph of
vision-tense prose with no implementation behind it; banked.

**C6 — meta-tools (`search`/`describe`/`execute`/`run_code`) are the default catalog
projection, with direct tools as the opt-out.** *corpus*: **CATCH** —
`catalog-projection-modes`.

### System D — the in-place migration plan

**D1 — hard delete makes a question structurally unanswerable.** Disconnect deletes the
connection row, so "a signed-out user is bit-identical to one who never connected" and
*which users are signed out* cannot be asked. The force that finally moved it is named
and dated: a customer's block-startup-until-reconnect flow needs
connected-then-disconnected distinguishable from never-connected. Fix is a nullable
status column plus `status_changed_at`, with the blast radius enumerated.
*corpus*: **NONE**; `creation-names-reaper` is the nearest law. Banked.

**D2 — a read-widening mode that structurally cannot write.** `reach: "bound" |
"tenant"` widens the owner-visibility condition for *reads only*; the write assertions
are untouched, and there are exactly two construction sites. Authority is bounded by
which function the mode is allowed to reach, not by a check.
*corpus*: **NONE**. Banked — this is the strongest unlanded row in the run.

**D3 — land the additive greenfield model BEFORE the removal.** Resequenced so the
legacy tables never need an in-place migration: the new model ships as the old
plugin's new internals "wearing the same costume", at the accepted cost of temporary
route ceremony a later phase deletes. *corpus*: **NONE**. Banked.

**D4 — "Constraints discovered (do not relearn these)"**: eight numbered constraints,
each naming the file that proves it. **D5 — the abandoned rework failed at ~10 of 131
legacy e2e scenarios ported**; its model docs are salvaged, its implementation
discarded. **D6 — "fuse indirection; keep dimensions"**, derived from one past mistake
and its overcorrection. **D7 — "vision mode vs build mode"**: the document declares its
own read mode and names the tell for slipping ("the next step needs two other things
built first"). All four are leads — doctrine shapes that need convergence across runs,
not a single author's account.

**Routing count: 3 / 2 / 2 / 3 NONE across four systems.** No system's NONE entries
share one home-if-new (System A splits across two subjects, System D across three), so
neither v2.2 clause fires. **No handoff; no XL spec.**

## What landed

`agent-instruction-files/techniques/write-back-sink-class.md`, plus a new golden-path
section and one failure mode. The subject had fifteen techniques and every one of them
reads the file **inbound**; the outbound half — the destinations the file tells the
agent to append to — had no instrument at all.

The rule is arithmetic rather than taste, and that is what made it landable from one
source: **a sink's sharing class is set by how its collector aggregates it.** Summed
into counts with no key on a row → must stay local, because a row surviving into a
second checkout is a second observation of one event. Deduped on a minted key → may
travel, and an undrained row on one machine is work nothing else can see.

**Within-source convergence carried the corroboration.** The tree holds the same shape
twice, independently: the policy file's three ignored sinks, and a security-review
runbook directing five scans' machine-readable findings to an ignored directory while
carrying a hand-maintained prose summary dated months earlier. Neither of the two is
evidence for a rule on its own; the pair is, because the prose half survived *for the
reason the technique gives* — something read it.

## The seam hunt was the second source, and it refuted me once

Two corrections worth recording, both caught by reading rows rather than counts.

**The first fleet seam was my own truncated read.** I concluded a project's lead log had
never been written from `ls -la .ai/ | head` — the listing was cut and the file was
there with 22 rows. That is the method's own "never establish an absence from a piped
or capped result", committed by the run that carries the rule. The lane was alive in 8
of 13 projects and has a collector; the seam was not where I said it was.

**What survived is better than what I was hunting.** Across the nine projects carrying
both logs, the count-aggregated one is shared in 2 and local in 7; the
identity-aggregated one is shared in 6 and local in 1. Three are on the wrong side —
and *both projects that share the count-aggregated log had written down a reason, and
the two reasons contradict each other*. One argues the lane must travel because the
registry is read from more than one machine; the other argues counts reach the
aggregate and the log stays local. Neither is drift: **each reason is correct about one
of the two logs and false about the other**, and each project applied its reason to
both. The contract line names them together and assigns no class, so each generalised
from whichever half it thought of first. That is the one-clause trap, found in the
fleet rather than in the source.

The scripted enumeration also over-reported by an order of magnitude on one project
whose agent configuration includes a long historical run journal — prose *about* past
writes is line-for-line indistinguishable from an instruction *to* write. The fleet
split above was confirmed by hand, per repository; the script is not reportable as a
measurement and its count is not in this note.
