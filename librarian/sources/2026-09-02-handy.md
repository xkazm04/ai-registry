## Landed

**#1 - amendment, `atomic-downloads` § "The resume contract, check by check".**
The technique said "the partial content must be validated as belonging to the
same remote artifact" and left the how to the reader. The source's downloader
enumerates it as five checks, each with a test against a local socket server
that replays that check's failure, and the module doc lists them in the order
the failures appear. Corroborated against the HTTP semantics specification (1
fetch: RFC 9110 §14.2 a server MAY ignore Range; §15.3.7 a 206 MUST carry
Content-Range; §14.4 416 semantics and "a client cannot determine the effective
length ... from Content-Length"). Also carried: the connect-vs-stall timeout
split, stall keeps the partial. **Applied** (experiment, `ab-paired`): the
politicas contract-dump harvester holds the registry index's per-month byte
size and compares it to nothing. Six replayed cases, predicate "month marked
done over a non-artifact": A 1/6, B 0/6. Two structural facts: the runtime's
HTTP client already fails a short body and stops at the advertised length, so
two of the five checks are made by the transport there - written into the
amendment as a caution - and the hole it cannot close is a server that
advertises *and* delivers a smaller total, which the catalog comparison alone
catches. **Shipped** as `73a9443` (politicas, master, pathspec, not pushed):
partial name, size pinned, compared, rename last; the project's doc-sync hook
demanded the coupled doc be updated in the same change, and it was.

**#2 - technique `voice-io/transcript-handoff-receipts`.** The stt-pipeline
stage table ends at "awaiting disposition"; in a dictation product the
disposition is "put it where the cursor is", which is a foreign application
reached through the system clipboard, and nothing owned that step. The
source's module doc for its receipt-sequenced paste (#502) is a complete
technique: a timed restore races the target's event loop and pastes the old
clipboard on a loss; publish lazily and restore on the OS read receipt; count
only receipts after the chord; restore only while ownership is unchanged;
quiet period after the last receipt; bounded wait whose failure mode is
"lingers" never "stale content lands"; short grace when injection failed; a
pure decision function over the transaction record. Plus what the restore must
preserve (an image when no text; clear when empty) from the legacy path's
comments, and the one-variable rule for the chord hold from the constant's doc.
Corroboration: training-data convergence on delayed-rendering / owner-callback
clipboard APIs (both major desktop platforms expose one), 0 fetches.
**Unapplied**: no fleet project injects text into a foreign application; the
desktop shell in the fleet owns no paste path. Return: when one grows the seam.

## Lead

**#4 - activation edges.** The source's coordinator (`transcription_coordinator.rs`)
carries three rules the endpointing section of stt-pipeline does not: (a)
physical key edges are debounced and a key-up is deferred by a short grace so a
synthesized auto-repeat can cancel it, but **external triggers - signals, CLI
flags, pedals - are never debounced**, because each is a deliberate edge and
dropping one desyncs toggle parity and wedges recording on; (b) a press that
arrives while the pipeline is still processing is *remembered* and starts the
next recording when it drains, and a second press during the same busy window
cancels the first - parity preserved, never a silent drop; (c) one machine
runs push-to-talk, toggle and hold-or-toggle, differing only in how a session
ends, with a hold threshold separating tap from hold. Real gap; no fleet
project has a push-to-talk or toggle-triggered capture, so an amendment would
be unapplied by construction. Return: a fleet project grows a keyed or
signal-triggered capture, or a second source states the external-trigger rule.
