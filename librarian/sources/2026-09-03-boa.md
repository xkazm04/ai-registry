## Design record

Grouped by the system each decision belongs to. `corpus:` names the subject whose
golden path models the forces, or NONE with the nearest neighbour and why it does not.

### System A - the object model

**A1.**
- decision: Objects carry a *shape* (hidden class) from a transition tree rooted at a
  prototype-less root shape; adding a property is a transition, shapes share a
  `PropertyTable` until a divergent insertion forks it, forward transitions are weak
  pointers so unused shapes die, and a shape that reaches 1,024 transitions from the root
  is converted to a *unique* (dictionary-mode) shape.
- forces: property lookup on a dynamic language must be O(1) in the common case without
  a static type; objects built the same way must share layout so a cache can key on it;
  objects mutated endlessly must not grow an unbounded transition chain.
- buys: a monomorphic site sees one shape and one slot index; memory for the chain is
  bounded by liveness (weak forwards) and by the 1,024 cap (unique fallback).
- rejects: per-object hash maps for every object (the naive reading); a fixed
  transition chain with no dictionary fallback (`shape/mod.rs:81-83` states the cap).
- where: `docs/shapes.md:14-16,148-150,187,217-220`;
  `core/engine/src/object/shape/mod.rs:80-83,113,134,155,169`.
- stage: object creation and every property definition.
- corpus: NONE. Nearest `client-architecture/client-fetch-cache` (slug overlap on
  "cache"); it models fetch admission, not layout sharing. HOME IF NEW:
  `backend-platform/language-runtime`.

**A2.**
- decision: Indexed (array) storage is a five-state enum that widens monotonically -
  dense `i32`, dense `f64`, dense boxed value, sparse value map, sparse full-descriptor
  map - and the default for a new object is the narrowest.
- forces: arrays of small integers dominate real programs and must not pay a boxed value
  per element; a single hole or a non-simple descriptor must still be representable.
- buys: element access on the common array is a typed vector index; the representation
  is observable and testable (`$boa.object.indexedStorageType`).
- rejects: one representation for all arrays; narrowing back after widening (never
  done, by design - the transitions are one-way).
- where: `core/engine/src/object/property_map.rs:37-58`; `docs/boa_object.md:166-192`.
- stage: element definition.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

**A3.**
- decision: Named property access instructions carry an inline-cache index; the cache
  stores the last-seen shape and slot, and a shape match skips the lookup entirely
  (polymorphic since v0.22).
- forces: the shape tree only pays off if the *site* can remember what it saw.
- buys: monomorphic sites are a pointer compare and an index.
- rejects: a global property cache keyed on name alone.
- where: `docs/vm.md:308-314`; `CHANGELOG.md` (v0.22, "polymorphic inline cache").
- stage: bytecode emission (the ic index) and execution.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

### System B - the virtual machine

**B1.** *(corrected by the VM scout against the tree: operands are fixed-width `u32` -
the varying-width encoding in `docs/vm.md:68-69` was removed, `core/engine/src/vm/opcode/args.rs:149-181`;
the frame pointer is stored explicitly at push rather than re-derived,
`core/engine/src/vm/call_frame/mod.rs:55-62`; and the stack default is 10,240 slots,
`runtime_limits.rs:24`, not the 1,024 the doc says. The docs are the naive reading; the
tree is the design.)*
- decision: A register-based bytecode executed over a *single* shared value stack; a
  call frame owns no storage of its own - `this`, the callee and the argument range are
  located from the frame pointer, register pointer and argument count; generators resume
  by re-pushing the saved frame with a "registers already pushed" flag.
- forces: a stack per frame costs an allocation per call; a suspended generator must
  keep its registers without copying them back; bytecode size matters for a cache.
- buys: call and return are pointer arithmetic; resume is a frame push with the
  allocation step skipped.
- rejects: per-frame register vectors; lowering async/generators to state machines in
  the compiler (`docs/bytecompiler.md:121`).
- where: `docs/vm.md:99-155,179-184,191-192,296-300`; `docs/vm.md:68-69`
  (`VaryingOperand`); `docs/bytecompiler.md:107-117` (jump patching).
- stage: compilation and every call.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

**B2.**
- decision: Every opcode declares a `COST`; the async run loop decrements a budget per
  instruction and yields to the host executor when it hits zero, using a *second*
  dispatch table so the synchronous loop pays nothing.
- forces: module evaluation and promise jobs run inside a host's async executor, and a
  long script must not starve the host's other tasks; the sync path must stay fast.
- buys: cooperative fairness without threads; a per-instruction cost model the embedder
  can reason about.
- rejects: a wall-clock check per instruction; a single dispatch table with a branch.
- where: `core/engine/src/vm/mod.rs:953-986`; `docs/vm.md:77-83,227-230`.
- stage: the execution loop.
- corpus: NONE. Nearest `backend-platform/work-execution` (home-if-new hit on "execution
  budget"), which models job admission, not instruction budgets. HOME IF NEW:
  `backend-platform/language-runtime`.

**B3.**
- decision: The embedder sets `RuntimeLimits` - recursion depth (default 512), value-stack
  size (10,240), loop iterations (unlimited by default), backtrace depth (50) - checked at
  call boundaries and loop back-edges; exceeding one throws a *non-catchable* error that
  bypasses every guest exception handler and unwinds to the host.
- forces: guest code is untrusted and may recurse or loop forever; a guest `catch` must
  not be able to swallow the host's decision to stop it.
- buys: ceilings the runtime can *count* are enforceable without a process boundary;
  the fuzzer relies on the instruction budget to make infinite loops terminate.
- rejects: a catchable error (the guest could retry forever inside a handler); a thread
  with a watchdog.
- where: `core/engine/src/vm/runtime_limits.rs:3-26`; `docs/vm.md:270-274,318-321`;
  `tests/fuzz/README.md:52-56`; `docs/boa_object.md:278-345` (`$boa.limits`).
- stage: context construction (the embedder) and every call and loop (the VM).
- corpus: PARTIAL - `security/untrusted-extension-host`. Its golden path says an
  embedded in-process scripting runtime has "one honest containment, reach without
  ceilings", and `capability-subtraction-sandbox` owns that. This tree is a
  counter-example to the denial: an interpreter that counts its own frames, stack slots
  and loop iterations can enforce ceilings on exactly those. Boundary case of a
  mechanism the corpus owns -> amendment (Phase 7).

### System C - the embedding boundary

**C1.**
- decision: The host customises the engine through a `HostHooks` trait whose methods
  mirror the specification's host-hook summary one to one; every method's doc carries a
  "Requirements" section restating what the spec obliges that hook to do, and every
  default is the spec's default.
- forces: an embedder overriding a hook must know which invariants the engine's
  correctness depends on (determinism of "source text available", normal completion of
  the rejection tracker); the engine cannot check them.
- buys: the contract travels with the override point; conformance is preserved by
  reading, not by testing.
- rejects: a flat callback struct with no stated obligations.
- where: `core/engine/src/context/hooks.rs:11-60,66-140`.
- stage: context construction.
- corpus: NONE. Nearest `llm-agent/runtime-and-io/agent-runtime-assembly`
  (`honest-hook-registry`): an event registry for contributed callbacks with timeouts;
  not a spec-mirrored override surface. HOME IF NEW: `backend-platform/language-runtime`.

**C2.**
- decision: Promise, timer, interval, native and native-async jobs go through a
  pluggable `JobExecutor`; the engine ships an executor that does nothing (which
  *disables promises*) and a FIFO one that blocks on async jobs; jobs deliberately do not
  implement the collector's `Trace`, so anything a job captures is a GC root for the
  job's life and a job can never be stored inside the heap.
- forces: hosts have their own event loops; a job that could be reached from the heap
  could be collected mid-flight or run twice.
- buys: bring-your-own event loop; captured values cannot be freed under a pending job.
- rejects: an engine-owned event loop; traceable jobs.
- where: `core/engine/src/job.rs:1-31,795-845`; `CHANGELOG.md` (v0.22 "Redesign CLI
  executor to avoid spin looping when idle").
- stage: job enqueue and the host's run loop.
- corpus: NONE. Nearest `backend-platform/work-execution/job-coordination` (leases and
  state machines for durable jobs; not an in-process microtask contract). HOME IF NEW:
  `backend-platform/language-runtime`.

**C3.**
- decision: Module loading is an async host hook (`load_imported_module`) with the
  spec's idempotency requirement stated in its doc; the shipped path resolver normalises
  `.`/`..` and refuses any resolved path outside a declared base.
- forces: the spec says a (referrer, specifier) pair must resolve the same way every
  time; a file-system loader is the one hook that can reach outside the sandbox.
- buys: hosts get a single async seam; the default loader is containment-safe.
- rejects: a synchronous loader; a resolver that trusts the specifier.
- where: `core/engine/src/module/loader/mod.rs:23-33,143-180`.
- stage: import resolution.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

**C4.**
- decision: The crates are layered by *standards body*: `boa_engine` implements
  ECMA-262 only; `boa_wintertc` implements the TC55 Minimum Common Web API and depends
  only on the engine; `boa_runtime` depends on `boa_wintertc`, re-exports it and adds
  non-standard extras (console logger, fetch backends); the CLI sits on top.
- forces: an embedder wanting "portable server-side JavaScript" wants exactly the
  cross-runtime baseline and nothing vendor-specific; the engine must stay pure spec.
- buys: a dependency choice *is* a conformance claim; TC55 compliance is a crate, not a
  feature flag.
- rejects: one runtime crate with feature flags per API.
- where: `core/wintertc/src/lib.rs:1-25`; `core/runtime/src/lib.rs:1-3`; `CHANGELOG.md`
  (v0.22 "add boa_wintertc crate skeleton for WinterTC compliance").
- stage: crate dependency selection by the embedder.
- corpus: NONE. Nearest `engineering-process/codebase-stewardship/module-design`
  (module depth and seams; not layering by external standard). HOME IF NEW:
  `backend-platform/language-runtime`.

**C5.**
- decision: Host data lives inside a guest object through a `NativeObject` wrapper that
  forces 8-byte alignment with a compile-time assertion, and is reached only by typed
  downcast.
- forces: the collector casts erased pointers; misaligned host data would break the GC
  metadata invariant on some architectures.
- buys: any host type with alignment <= 8 is embeddable; larger ones are boxed by rule.
- rejects: trait-object storage with a fat pointer.
- where: `docs/native_object.md:17-32,47-54`.
- stage: host-object creation.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

### System F - strings

**F1.**
- decision: The engine string is a thin pointer to an allocation whose first field is an
  inline vtable (clone, drop, slice, code points, refcount, length, kind); the kind is
  Latin-1 sequence, UTF-16 sequence, slice-of-another-string, or static; a table of
  common names is compiled in and returned without allocation; the interner in the
  compiler maps identifiers to symbols so comparison is integer equality.
- forces: strings dominate engine memory; most are ASCII; substring must not copy;
  property names repeat endlessly.
- buys: 8-byte string handles; half the memory for Latin-1 text; zero-copy slices;
  zero-allocation well-known names.
- rejects: a fat `Rc<str>` (length duplicated); UTF-16 everywhere.
- where: `docs/string.md:5-55`; `core/interner/src/lib.rs:1-11`;
  `docs/boa_object.md:347-377` (`$boa.string`).
- stage: string creation and identifier interning.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

### System H - the collector

**H1.**
- decision: A thread-local mark-sweep collector with derived `Trace`/`Finalize`,
  ephemerons and weak maps as first-class roots, a collection threshold of 1 MiB grown
  at 70% used space, and an explicit rule that jobs are *not* traceable (C2).
- forces: a single-threaded engine embedded in a host that owns the threads; weak
  references are needed by the object model (A1 weak forward transitions) and the
  language (`WeakRef`, `FinalizationRegistry`, added in v0.22).
- buys: no atomic refcounts; cycles collected; weak semantics for shapes and the language.
- rejects: reference counting for the heap; a stop-the-world barrier the host must
  cooperate with.
- where: `core/gc/src/lib.rs:1-5,44-75`; `core/engine/src/job.rs:22-28`.
- stage: allocation and collection.
- corpus: NONE. HOME IF NEW: `backend-platform/language-runtime`.

### System I - the introspection surface

**I1.**
- decision: A `$boa` global, injected only under a CLI flag, exposes engine internals *to
  the guest language*: force a collection, print a function's bytecode, trace one
  function (including across suspensions), flowgraph it, read an object's shape identity
  and type, an array's storage kind, a string's encoding and storage, and set the runtime
  limits.
- forces: engine behaviour that is invisible from JavaScript (did two objects share a
  shape? did a string allocate?) is exactly what an engine developer needs to assert
  from JavaScript.
- buys: engine tests written in the guest language; the docs' examples are executable.
- rejects: a host-side debugger API only; always-on introspection.
- where: `docs/boa_object.md:1-6,148-192,239-276`; `docs/debugging.md:84-97`.
- stage: context construction (the flag) and any guest evaluation.
- corpus: NONE. Nearest `game-production/engine-integration/runtime-observation-evidence`
  (cross-bundle; cannot link). HOME IF NEW: `backend-platform/language-runtime`.

### System D - conformance measurement

**D1.**
- decision: The external conformance suite is pinned to a commit in a config file that
  also lists ignored features with a reason class ("unimplemented", "pending proposal");
  every test is classified by the *minimum specification edition* that requires it via a
  feature-to-edition map, and the run can report per edition; a pull request's run is
  compared against a baseline stored in a separate data repository (refreshed on every
  push to main) and the delta - fixed tests, broken tests, new panics, fixed panics, and
  the counts - is posted as a comment, not enforced as a gate; benchmarks run only when a
  label asks for them.
- forces: the suite moves (new tests every month) so a bare percentage is not a trend;
  the specification has editions, so an "ES5 conformance" and an "ESNext conformance"
  are different claims; a crash is a different class of failure from a wrong answer;
  the run takes long enough that gating it would slow every PR.
- buys: a stable number per edition; a diff a reviewer reads in the PR; crash regressions
  named separately from behaviour regressions.
- rejects: gating merges on the percentage; a single undifferentiated pass rate.
- where: `test262_config.toml:1-12`; `tests/tester/src/edition.rs:1-14`;
  `tests/tester/src/main.rs:153-159,396-463`; `tests/tester/src/results.rs:172-260,
  303-360`; `.github/workflows/test262.yml:43-76`; `.github/workflows/test262_release.yml`;
  `.github/workflows/pull_request.yml:16-40`.
- stage: CI, per pull request.
- corpus: `engineering-assessment/maturity-and-conformance/conformance-checking`.
  `pass-ratio-comparability` *names* the force ("a new standard version moves every
  score... two different measurements sharing an axis") and offers no mechanism;
  `declared-deviation-register` covers the ignored list as profile scope (it says so:
  declining an optional feature is scope, not deviation); `finding-severity-ladder` has
  no crash rung. REAL GAP -> technique `edition-stratified-conformance` (Phase 7).

### System E - the testing strategy

**E1.**
- decision: The parser fuzzer generates an arbitrary AST, prints it, parses it
  (discarding errors, because generated trees need not be parseable), prints again,
  parses again, and asserts the second parse succeeds and equals the first - a two-hop
  round trip whose first hop *normalises* and whose second hop is the oracle.
- forces: the generator's output is not guaranteed valid; a one-hop round trip would
  either reject most inputs or assert against garbage.
- buys: an idempotency oracle that tolerates an over-approximating generator.
- rejects: a one-hop round trip; filtering the generator to valid trees only.
- where: `tests/fuzz/README.md:20-36`.
- stage: fuzz oracle design.
- corpus: PARTIAL - `test-input-generation/model-based-oracle` lists "a round trip that
  must return the original" as an invariant rung and does not state what to do when the
  generator emits inputs the system may legitimately reject. Boundary case ->
  amendment (Phase 7).

**E2.**
- decision: Three fuzz targets, one per pipeline stage (parser, bytecompiler, VM), with
  the middle one justified explicitly as draining assertion failures that "may block the
  discovery of crash cases in the VM fuzzer"; the VM target runs under an instruction
  budget and treats "took more than a second" as a secondary signal of a VM defect.
- forces: a crash in an upstream stage masks every deeper defect on that input; an
  infinite loop is indistinguishable from a slow input without a budget.
- buys: each stage's crash set is findable on its own; a time signal that is a
  diagnostic, not a flake.
- rejects: one end-to-end fuzzer.
- where: `tests/fuzz/README.md:38-56`; `tests/fuzz/fuzz_targets/`.
- stage: fuzz target design.
- corpus: PARTIAL - `test-input-generation` (`swarm-feature-sampling` owns masking by
  feature interaction; nothing owns masking by pipeline stage). Promoting question
  answered in Phase 5. -> technique `stage-ordered-fuzz-targets` (Phase 7).

**E3.**
- decision: Bytecode output is snapshot-tested with an explicit review step.
- corpus: CATCH - `test-harness/approval-snapshots-with-guarded-update` says exactly this.

**E4.**
- decision: Contributors map implementation lines to specification steps in comments and
  note every place a step is not implemented as written, with the reason.
- corpus: LEAD - nearest `conformance-checking/declared-then-proven` and
  `declared-deviation-register` (the "note the difference" half). Return condition:
  a second engine or protocol implementation that carries step-level comments as a
  reviewed convention.
