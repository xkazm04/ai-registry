## Catches — the corpus says it, and says it better

- **Progressive discovery inside one tool.** `catalog-projection-modes` already holds
  the "compressed catalog must stay self-teaching" rule: an unnamed operation returns
  the sub-catalog rather than erroring. The source's first rung is exactly this. Only
  the second rung was new.
- **The pinned reference bank.** `generated-shot-sourcing` already answers
  sequence-scale drift with "pin the origin, roll the recent", bounds included. The
  source's contribution was the *anchor-minting* topology, one layer up.
- **Pause as a suspendable request class.** `suspendable-request-classes` splits
  invocation from metadata verbs for protocol-level suspension. The source's pause is
  a different force — an agent co-resident with the GPU workload it drives yields its
  own residency at a tool boundary — but it is not a boundary case of the existing
  rule, and one sighting is not enough. Filed as untriaged, not as an amendment.

## Untriaged, with anchors (nobody verified these)

Recorded so a later run does not re-derive them. None carries any judgment.

1. **Capability descriptor probed from the initialized handler** — `docs/SETTINGS.md:340-355`.
   `frames_maximum` is obtained by calling the handler's `update_default_settings({})`
   and reading its `sliding_window_size`, falling back to `sliding_window_defaults`,
   then to the model-legal frame count nearest 97 computed from `frames_minimum`,
   `frames_steps`, `frames_offset`. Near-neighbour `measured-not-declared-capability`.
2. **Capability-filtered settings migration** — `docs/SETTINGS.md:196`, "Only flags
   listed in `model_def["image_prompt_types_allowed"]` survive settings migration";
   unsupported sliding-window modes migrate to queue-task modes.
3. **Two adapter classes, one field, a sentinel between them** — `docs/LORAS.md`,
   the `|` terminator separating accelerator multipliers from content multipliers so
   an accelerator profile can be swapped without disturbing style adapters.
4. **An accelerator carries a sampler contract** — guidance must drop to 1 or output
   is both worse *and* twice as slow; multiplier must be re-tuned with step count
   (12 steps → 0.3, 8 steps → 0.5-0.7).
5. **Two orthogonal axes in one multiplier string** — comma across steps, semicolon
   across guidance/model phases; a time-only multiplier ignores phases entirely.
6. **Adapter provenance embedded in the output artifact** — the download URL of every
   adapter is written into the generation settings stored in the video, so an output
   carries what is needed to *reconstruct* it, not merely to identify it. Boundary on
   `generated-shot-sourcing`'s "provenance travels with the clip".
7. **Overlap frames are conditioning, not committed output** — a window's stated
   duration is its contribution; overlap is generated *in addition* and never counted.
8. **Asymmetric window validation** — overrun is reported with a predicted total;
   only *starvation* (a later window receiving 0 frames) is rejected.
9. **Enhancement never compounds on itself** — the on-demand enhancer comments the
   original prompt into the same buffer (`#!PROMPT!:`) and re-enhances from the
   comment, so re-running never enhances an enhancement. Also `@` appends to enhancer
   instructions where `@@` replaces them — a two-tier override distinguished by
   doubling the sigil.

## Leads

- **The local/open-weights generation lane is absent from `media-generation`.**
  Searched untruncated: nine files in the whole bundle mention an adapter, fine-tune
  or low-rank anything, and every one means a *provider* adapter — software that
  compiles a prompt for a vendor. The bundle's boundary was drawn at hosted
  generation through APIs, and everything on the other side of it — weights,
  adapters, samplers, quantization, memory placement — has no home. This is the
  curator-boundary finding a source of this class carries exactly once, and it
  explains why nine of this run's design entries mapped to `NONE`.
  **Return condition:** when a second independent local-generation source arrives, or
  when a fleet project runs a model locally rather than calling one. `visual-generation`
  has 2 of 10 child slots free, so the placement exists today.
- **An inline window-command language that travels in the prompt.**
  `[/duration=5s,/new_shot,/loras_mult=1;3]` written beside the beat it governs and
  stripped before the model call, with `[/...]` reserved for the harness and `[...]`
  left to the model's own syntax. Per-shot parameters live with the shot's text
  because that is what the author is editing. **Return condition:** a second system
  that puts per-segment parameters in the content rather than in the settings.

## Applied

Three landings, three rows. Full detail in `librarian/applied.md`.

The **`code` row shipped into gravity** and is the run's centre of gravity, which is
worth stating plainly because it did not come from extraction: the amendment was
written at Phase 7, and the *defect* was found at Phase 7.5 while looking for its
seam. gravity was already a pure star everywhere it mints images — references are
memoized per **theme**, not per frame, so no path exists along which one frame's
error reaches another, and nobody designed that against this technique. What the
comparison exposed is the property the star silently depends on: `styleRefs` took the
**newest** four approved proofs from a pool of up to fourteen, so the founding proof
left the reference set at approval 5 and never returned, and the last frames of a
sheet were judged against four references sharing nothing with the four the theme was
founded on.

**The apply step corrected its own landing.** The amendment as first written implied
the pinned-bank rule delivers master *stability*; the measurement says it delivers
origin *retention* only — both arms still see 14 distinct masters over 14 approvals.
The corpus text now separates the two properties and names freezing-per-series as what
would actually deliver stability. That correction exists because the number was taken.
