# llmfit — a hardware-fit advisor over six local inference runtimes

Operator's expected dimensions: **(1) architecture for composing LLM
gateways/wrappers, (2) Rust design practices in mature codebases.** Both were
present; the first was the run's strongest cluster and the second turned out to
be thinner than expected as *general* practice and sharper than expected as one
specific structural finding.

Source class: **first-party practitioner codebase in repository form** (single
maintainer plus community contributions). Expected yield for the class is high
and the class rule held exactly — the landing page is 1,612 words and the in-tree
operating documents are 28,584, a ratio of ~18:1. Everything below came from the
clone; nothing came from the README, which was read last.

The tree's distinguishing property, and the reason it produced four systems'
worth of design rather than a list of claims: **its code comments carry issue
numbers, measurement dates, and the refuted alternative.** `providers.rs:476-486`
records which live servers were probed on which date to establish each identity
discriminator. `how-it-works.md §6` records a removed heuristic and both
directions in which it was wrong. That is a first-party practitioner account
distributed through a codebase, and it is worth more than the same author's prose
would have been.

Thirteen load-bearing decisions with no corpus home, in four systems. Counted per

| **A** — discovering and identifying local runtimes | 3 | `multi-provider-gateway-plane` exists but starts *after* candidates are known | technique triple + a stage-zero section in that subject |

| **D/E** — Rust posture | 2 | none | folded into A's techniques and one amendment |

The A count is the one worth explaining, because it is the case the v2.2 rule
was written for. `multi-provider-gateway-plane` was forged the day before this
run and is thorough: policy trees, failure attribution, translation strictness,
stream framing. Every one of those begins from *a configured tree of candidates*.
Nothing in it asks how the plane learns which upstreams exist or which
implementation is behind each address — a **missing stage**, not a missing
opinion, and exactly the Phase 6 hunt shape. So A landed as that subject's stage
zero rather than as a competing sibling subject.

### The design record

**A1 — identify by a route only that implementation serves.**
*forces:* six runtimes, one wire protocol that deliberately does not identify its
implementation; model ids must not be imported before the endpoint is recognized
(#791, #790); a framework header identifies the framework, not the product.
*buys:* correct attribution before any data crosses the boundary.
*rejects:* header sniffing; trusting the per-record ownership field alone — an
empty inventory carries no marker, so identity falls back to a root banner.
*where:* `providers.rs:476-664`. *corpus:* NONE.

**A2 — the aggregate of a plugin set is named fields, not a collection behind the
trait.** *forces:* one runtime's ids are matched by substring and its disk-derived
names by equality; one member is enrichment whose failure must not take the
analysis down; one slow backend must not serialize ~9s of timeouts.
*buys:* per-member match semantics and per-member failure policy, both writable at
the join site. *rejects:* `Vec<Box<dyn ModelProvider>>` — **the trait is
implemented eight times and dispatched through zero times anywhere in 54k lines.**
*where:* `analysis.rs:16-101`, `providers.rs:15-29`. *corpus:* NONE.

**A3 — a fallback belongs to a guessed value, never a configured one.**
*forces:* a loopback hostname may resolve to IPv6 while the server listens on
IPv4; but an explicit host that fails must fail loudly, and a wildcard bind
address leaks from the server's environment into the client's.
*buys:* operator misconfiguration surfaces instead of being masked.
*where:* `providers.rs:83-137`. *corpus:* **partial** — a boundary case of
`absent-degrades-malformed-fails-fast`, which has absent and malformed and not
*well-formed-but-wrong-for-this-role*.

**A4 — join breadth follows the cost of a wrong match.**
*forces:* catalog names vs runtime tags; a sized tag already names the artifact,
and contributing the family stem as well marked **238 of 9,250 models installed
from one install** (#861); a non-local entry's stem would mark unrelated locals
(#619). *buys:* an inventory that does not over-claim.
*where:* `providers.rs:295-369`. *corpus:* NONE — **and it inverts a rule this
corpus already publishes.** See below; this is the run's strongest finding.

**B1** — the confidence class travels with the value when measured and modelled
share a unit (`fit.rs` `EstimateConfidence`, five rungs, first match wins).
**B2** — "not estimated" is encoded outside the measured domain (`null`, not
`0.0`, *"which would read as 'immeasurably slow' rather than 'not estimated'"*).
**B3** — the resolved basis is reported beside the output so any estimate can be
re-derived (`estimate_basis.gpu_bandwidth_gbps`).
**B4** — a calibration fallback is scoped so a new entry only moves what it names.
**B5** — a verdict is a pure function of one ratio, then capped by capability;
the two-input version was removed with **both** directions of its error recorded.
*corpus:* B2 is a catch (the law `unknown-is-not-a-value`); B3 partial
(`derivation-names-recomputation`); B1, B4, B5 NONE.

**C1** — content-hash naming makes the publish idempotent. **C2** — capture
locally, publish separately; declining never discards. **C3** — strict at
ingestion, lenient at consumption (`build.rs:50-58`: *"a warning beats breaking
every build"*). **C4** — plausibility bounds "generous on purpose", plus a
timestamp floor derived from the share feature's own ship date. **C5** — validate
the whole directory with the return condition stated. **C6** — the validator is
the contract; the generated naming convention is a triage signal.
*corpus:* C4's "reject the impossible, not the atypical" half is a **catch** —
`hub-ingest-plausibility-gates` already argues it better (*"Plausibility means
'arithmetically possible for a benchmark to produce', not 'close to the
consensus'"*). The rest NONE.

**D1** — a platform probe takes its root and its resolver as parameters so it is
testable off-platform. *where:* `hardware.rs:848` — **and not** at `hardware.rs:505`.
**E1** — the concurrency substrate is chosen by the most constrained consumer of
the interface (`std::thread::scope`, no async runtime, one blocking client by
written policy).

## The strongest finding: a rule that inverts across two bundles

`llm-observability`'s `provider-family-matching` says resolve provider identity by
**family membership, not exact equality** — because a miss makes spend
unpriceable, and *"each miss silently removes real spend from cost accounting."*

llmfit's `#861` records the inverse, measured: broadening by family stem marked
238 of 9,250 catalog rows installed from a single install, including an entry
roughly thirty times the size of the artifact actually present.

Both are correct. The discriminator neither bundle stated:

> **Does a miss delete something real, or does a false positive assert something
> false?** A priced total lives in the first world — a miss is invisible, so
> breadth is right. A presence claim lives in the second — a false positive is
> specific, user-visible and checkable, so the specific key must win, and a broad
> key is reserved for entries whose exact identity is genuinely unavailable.

Landed on both sides, in prose, with no cross-bundle link: as a technique in
`software-engineering` and as a new section plus a decision rule in the
`llm-observability` technique. This is the shape the method prizes — a source
that implements a good idea *differently* is worth more than one that implements
it identically.

## The structural fact (Phase 8 step 6)

Nobody designed this and the tree proves it anyway. The AMD device-tree probe was
extracted as `detect_amd_gpu_sysfs_info_from_root(root, resolve_name)`
(`hardware.rs:848`) explicitly *"so tests can supply a fixture directory"*, and it
has three fixture tests. Its NVIDIA sibling (`hardware.rs:505`) hardcodes
`/sys/class/drm`, takes no root, and has **zero** tests — its name appears exactly
twice in the file, at its definition and its single call site.

And the untested one is the **fallback**: it runs only when `nvidia-smi` is
absent. So the least-tested probe is the one that executes only on machines where
things are already unusual. The general mechanism — testability seams get built
where somebody had a reproducible failure, and a fallback has no reproducible
failures because nobody's machine is in that state — landed as an amendment to
`fallback-retirement-condition`, whose existing rule measures the fallback's
*traffic* and had no build-time sibling.

## Leads

1. **The identity rules are dated observations and the tree knows it.** Each
   discriminator carries the date and version it was measured against. Whether a
   corpus technique should require a *decay policy* on such tables — not just a
   date — is unresolved. **Return condition:** when a second source is found whose
   identity/capability table has gone stale in production and the failure is
   recorded.
2. **The peer-comparison lane was not run.** `tracklight` is a genuine peer for
   System C (it operates a federated benchmark network) and the front-half check
   found real convergence — its `aliases.rs` reaches the same conservative
   conclusion by a different argument. A full comparison study was not dispatched
   because the run already carried two dispatches. **Return condition:** the next
   run that touches `federated-benchmark-sharing` with fewer than two dispatches
   in flight.
