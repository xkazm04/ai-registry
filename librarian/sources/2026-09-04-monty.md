# Monty (pydantic/monty)

An 18-crate Rust workspace implementing a sandboxed Python interpreter for
model-written code. Mined as a repository from a clone at `fdd2628`, never from
the ingest.

**The ratio that names the anti-pattern.** The README is **392 words**. The
in-tree operating documents are **~63,000** — a 64 KB `CLAUDE.md`, 34 files under
`docs/limitations/`, a `docs/` tree with a security model, a pool-architecture
document and an alternatives comparison, five `.macroscope/` review-instruction
files, and nine skills plus one subagent under `.agents/`. That is a **160x**
ratio, the widest this ledger records. A run that had extracted from the landing
page would have produced 392 words of pitch.

**Swept**, in the method's order: `.macroscope/` (5 files) → `docs/limitations/`
(AGENTS.md, index.md, pool-architecture.md) → `.agents/skills/` and
`.agents/agents/` → `CLAUDE.md` §§ VM architecture, docs-sync, limitations →
`crates/monty/src/bytecode/op.rs` + `builder.rs` → `docs/security.md` →
`scripts/startup_latency_chart.py` → **README last**.

**Board.** Claimed `monty-0904` before reading anything. Two siblings live at
claim; `arxiv-27454` held `agent-instruction-files`, which is the subject this
run's largest catch sits in — checked at Phase 7 and not written to, so no
collision. 0 of 3 fetches spent: the tree carried every primary it needed.

*suppresses* a forge (the material has somewhere to go) and *raises* the value of
the landing (a second independent system is corroboration available no other

Also checked at Phase 1, per the same round's other focus paragraph: no fleet

## Design record

Grouped by system, because this tree holds two and the routing count is per
system.

### System A — the agent-governed review process

**A1. Every harness-expected path is a symlink into one authored tree.**
- *forces*: four readers demand four paths — one agent standard reads `AGENTS.md`
  and this repo authors `CLAUDE.md`; one harness reads `.claude/skills` and the
  files live in `.agents/skills`; the docs build needs the limitations directory
  under `docs/` for its `nav:`, while every instruction file, skill and review
  brief references `limitations/<x>.md` from the repo root.
- *buys*: drift is unrepresentable — one inode, no second copy.
- *rejects*: copies plus a drift check; a generator.
- *where*: `git ls-files -s` returns mode `120000` for `AGENTS.md`→`CLAUDE.md`,
  `limitations`→`docs/limitations`, `.claude/skills`→`../.agents/skills`,
  `.claude/agents`→`../.agents/agents`. `CLAUDE.md:1040-1046` states the reason.
- *corpus*: **MODELED, and better than the source states it.**
  `agent-instruction-files/single-source-topology` owns the link regime, the
  distribution edge, the format edge, *and* the failure this tree is one platform
  away from — a symlink materialised as "a regular file containing the target's
  path", which is exactly what this Windows checkout produced (9-byte `AGENTS.md`
  reading `CLAUDE.md`). **Catch.**

**A2. One review concern per instruction file, scoped by path glob, each with a
model, a flag list, a do-not-flag list, and its own severity.**
- *forces*: a single pass over a large diff is not exhaustive (the repo says so
  outright in `review-verbosity`); and an LLM detector has no threshold knob, so
  precision is controllable only through prose.
- *where*: `.macroscope/correctness/{cpython-parity,drop-discipline,resource-limits,sandbox-and-panics}.md`,
  each with `include:`/`exclude:` frontmatter.
- *corpus*: nearest `quality-gates/false-positive-economics` — which models the
  spiral and the measurement, all of it numeric. HOME: quality-gates (existing).

**A3. Approvability is a separate check from correctness: default approve,
enumerated withhold categories, enumerated not-reasons, correctness inherited as
a premise.**
- *forces*: both questions run on **one substrate** — the same model reading the
  same diff — so no configuration can partition them; and the open form of the
  question ("could a human add value?") is trivially yes, so an unbounded gate
  withholds on everything.
- *buys*: a nonzero auto-approval rate without lowering the correctness bar.
- *where*: `.macroscope/approvability.md`, whole file.
- *corpus*: nearest `quality-gates/instrument-answers-only-its-own-question`,
  which covers partition **by configuration, discovered by a reader**. This is
  the author's chair with no configuration to write in. HOME: quality-gates.
  **→ landed.**

**A4. A mandatory divergence register recording only negative space.** Every PR
changing user-visible behaviour must add a `limitations/` page; only divergences
belong, never matching behaviour; completeness is what makes silence meaningful
("a behaviour missing from them can be assumed to match CPython 3.14").
- *forces*: the software's consumer is a language model, which has no signal to
  write something else when behaviour diverges silently; docstrings do not
  aggregate into anything queryable.
- *where*: `docs/limitations/AGENTS.md`, `docs/limitations/index.md:5-11`,
  `CLAUDE.md:1040-1078`, enforced by `.macroscope/correctness/cpython-parity.md`
  and `review-general`.
- *corpus*: contested — `game-production/reference-parity-gating` (other bundle),
  `quality-gates`, `agent-instruction-files`. **Untriaged.**

**A5. Divergence found by running both implementations on the idioms a model
reaches for first, ranking silent divergence above a clean error.**
- *where*: `.agents/skills/review-usability/SKILL.md`, `playground/`.
- *corpus*: with A4. **Untriaged.**

**A6. Facts stated in N places on purpose, N enumerated, one named
authoritative — and the drift check is a reviewer, not a generator.**
- *forces*: a reader needs the fact where they are; the copies are prose in
  different registers for different readers, so they are **not mechanically
  derivable from one another** and regenerate-and-compare has no defined answer.
- *where*: `CLAUDE.md` § "Named duplication points" (4 registers: the module
  list, the latency numbers across 4 files, the default limits, the mount modes);
  `docs-parity-reviewer` check 4.
- *corpus*: `single-source-topology`'s copy regime says the check is a CI
  generator with a non-zero exit on difference. This is the lane where that is
  impossible. **Untriaged — the strongest of the tail.**

**A7. Two reviewers of one concern, separated by obtainable evidence, boundary
stated in both briefs.** `cpython-parity.md`: *"This is diff-level review only —
the executable run-both-and-diff check is the `review-usability` skill and is out
of scope here; do not claim a divergence you cannot see in the change."*
- *corpus*: folded into A3's landing as its last section.

**A8. The ignore config replaces rather than merges, so ~150 vendor defaults are
copied verbatim — and the test-file defaults are deliberately dropped so test
code stays reviewed.**
- *where*: `.macroscope/ignore.md:1-12`.
- *corpus*: a config-semantics gotcha. **Lead.**

### System B — the sandboxed interpreter

**B1. A stack bytecode VM, not a register VM, for a workload whose headline
metric is time-to-first-execution.**
- *forces*: single-execution programs — a snippet composed per request, run once,
  discarded. The dispatch saving is paid per executed instruction; the register
  allocator and the wider stream are paid per compiled program.
- *where*: `op.rs:70-80` (`Pop = 0`, `Dup = 1`, `Rot2 = 2`, `Rot3 = 3`),
  `CLAUDE.md:168` ("same as CPython"), `vm/mod.rs:355` (`CallFrame`),
  `scripts/startup_latency_chart.py` `ROWS` = 4.9 ms combined.
- *corpus*: **REFUTES** `register-bytecode-execution`'s *"the measured trade is
  not close … fewer instructions is the win that matters."* **→ landed.**

**B2. Operand width is a fixed property of each opcode (0/1/2 bytes), with a wide
sibling as the overflow escape; the scarce resource becomes opcode slots,
rationed by a hotness rule.**
- *where*: `op.rs:6-11`, `builder.rs:329` ("Slots 256+ use `LoadLocalW`"),
  `CLAUDE.md:170-176`. **Exactly two** wide variants exist.
- *corpus*: **REFUTES** the same golden path's *"Operands are fixed-width, one
  word each"* — the dichotomy omits a third option. **→ landed, folded into B1.**

**B3. Opcode discriminants are explicit and part of a persisted format;
renumbering costs a dump-format version bump, not a reserved band.**
- *where*: `op.rs:64-66`. Verified: **122 variants, discriminants 0–121
  contiguous, all explicit — no reserved band at all.**
- *corpus*: refines the golden path's reserved-band claim. **→ landed, folded.**

**B4. One API surface across transports whose security guarantees differ, with
the loss enumerated per property.** *"A WebSocket remote honours the protocol
shape but **none** of the sandbox guarantees … treat the remote as a
trusted-deployment execution surface, not a sandbox."*
- *where*: `docs/limitations/pool-architecture.md:1-35`.
- *corpus*: contested (untrusted-extension-host / a transport subject).
  **Untriaged.**

**B5. Capability absence rather than denial** — *"Not 'it is blocked' — the
capability does not exist in the bytecode VM"* — plus removing the dangerous
names from the bundled typeshed so type checking rejects before runtime.
- *where*: `docs/security.md:22-33`.
- *corpus*: nearest `untrusted-extension-host/capability-subtraction-sandbox`
  (1 day old). **Untriaged.**

(new technique) + a scoping correction to the golden path's "Registers, not a
stack" section and its operand/reserved-band paragraph. Three unqualified
sentences in a one-day-old, single-sourced subject were scoped by a second
independent system, not deleted:

1. *"fewer instructions is the win that matters"* → now carries "wherever a
   program is executed far more often than it is compiled", with the ratio named.
2. *"Operands are fixed-width, one word each"* → now says the pair omits the
   opcode-encoded option, priced in slots rather than branches.
3. *"a healthy instruction set leaves a reserved band"* → now says the band is
   the protection while the numbering is private to one build, and that a
   serializing interpreter needs an explicit discriminant plus a version bump.

**`quality-gates/shared-substrate-check-partition`** (new technique). The
partition seen from the author's chair, where both checks are one judgment engine
and no configuration can express the split: the inverted bounded question, the
negative scope naming its owner, the sibling verdict inherited as a premise, the
not-reasons list as the tuning surface, and the evidence boundary between a check
that reads and one that runs.

**Two source-tree applications**, both `verified_against` a witness the tree
carries (`Cargo.toml:28` → `rust@1.95`; the review process has no version, so its
witness is the pinned commit).

### A number I had to correct mid-run

My first count of the `Opcode` enum returned **144** variants from a grep that
matched a second `#[repr(u8)]` enum in the same file. Written into the
application before it was checked. Re-derived by parsing the enum body
(`op.rs:69-558`): **122 variants, discriminants 0–121, contiguous, all
explicit.** The corrected number strengthened the finding — contiguous 0–121 is
positive evidence that there is **no reserved band**, which the 144 figure could
not have shown. Corrected in place before commit.

## Applied (Phase 7.5)

**`shared-substrate-check-partition` → politicas, `experiment`, `better`,
shipped.** The seam is a design-review agent brief that excludes the mechanical
detector's whole domain in one sentence — *"Do not run a second detector pass;
mechanical findings belong to the parent's hooks"* — naming no rule from it and
inheriting no verdict, while capping its own output at 8 ordered fixes.

Measured over the real population with a stated predicate: the detector defines
**66 distinct rule ids**, and **39 of them** name a condition the reviewer's own
TYPE/MATERIAL/density row also classifies. Arm A: 39 of 66 ambiguous. Arm B
(patched): the detector's verdict inherited as a premise, the shared surface
named, the split stated as comp-character vs value-in-band, plus a five-entry
not-reasons list → ambiguous set 0 by construction.

**Gate reached:** the project's blocking `commit-msg` doc-sync gate, 0 drifted of
83 checked. No gate failed. **What was not measured:** the behavioural rate — the
tree holds no recorded reviewer returns, and running the agent needs screenshots,
an approved comp and a quality card this run did not have.

A side check worth recording: the brief has a **generated** twin under
`reference/degraded/`. All four agent/degraded pairs were diffed (CRLF
normalised, frontmatter and banner stripped) and found **identical** — a clean
negative for the copy regime, at this moment. No generator ships in the repo, so
the patch was applied to both and the pair re-verified identical.

**`instruction-format-follows-program-lifetime` → unapplied.** All twelve fleet
trees searched per-project with `git grep` for opcode/bytecode/interpreter; every
hit is lockfile or prose noise. No managed project embeds a language runtime,
which independently confirms the statement this subject's note made on
2026-09-03. Return condition in `librarian/applied.md`.

**On the focus's third item — is `ship` fleet-bound?** This run is a data point
for "no": the landing that shipped went to a mid-maturity project, and the one
that did not ship failed on a genuine absence of the seam in *every* tree, mature
or not. A technique about language runtimes has nowhere to go in a fleet of web
applications, and that is a property of the fleet, not of the funnel.
