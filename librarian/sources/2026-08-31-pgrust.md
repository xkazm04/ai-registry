# pgrust — the class was right about the README and wrong about the ratio

## Class reading, stated before triage

**Vendor repository.** The class entry predicts three parts of wildly differing
reliability: a marketing surface written to be quoted, a "things we learned
running this" page that is the densest thing present, and the types of whatever
open client renders the closed engine. Two of the three held. The third did not
apply, because nothing here is hosted — the engine is the repository.

What the class did not predict is the **ratio**. The usual vendor repository is
mostly advertisement with one honest page; this one is 2,480 rendered words of
benchmark claims against roughly 7,500 words of operating documents that read as
paid-for failure modes, plus a 1,241-row per-unit catalog whose `notes` column
carries assembly-level attribution, watch items and contract statements. It
behaves like a *first-party practitioner account* that happens to arrive as a
repository. Expected yield was called **above the class norm, 3-4 findings,
mostly amendments rather than new subjects**, on the ground that this corpus is
already deep in testing and measurement discipline. That is what happened: one
technique, two amendments, two catches.

Swept in the Phase 2b order — operating documents, instrument, measurement,
types, tests, README last. The README was read as an index and as the proper-noun
list to strip. A run that had mined the ingest alone would have extracted
benchmark percentages and a feature bullet list, and every one of them would have
failed the strip test.

## Board

Two live siblings at claim time, one of them mining a mailing list in the same

## Accepted

### 1. `tuning-corpus-disjointness` — new technique, measurement-honesty

**Anchor:** "the ordinary train-on-test failure, and it is invisible from the
outside unless the training corpus is published alongside the binary."

The source ships a profile-guided-optimisation training corpus in version
control, a denied set holding the published benchmark's own statements, and a
dependency-free linter proving the two disjoint — comparing *canonical forms*
(literals, numbers and placeholders collapsed, scaffolding stripped, case folded)
so "a denied statement cannot be smuggled in by changing a search term, a bound,
or a binding."

**The prior art denied too much.** `instrument-exposure-control`, landed in the
same subject six days earlier, closes with "it cannot certify an instrument as
uncompromised… there is no self-check." That is exactly true for exposure you
*suffer* — a measure published into the world its future subjects learn from —
and exactly false for exposure you *cause at build time*, where both sets are
files you hold. Every probe in the neighbour is detective and one-way; this case
admits a proof, in advance, and the number is not publishable without it.

The half that makes it worth a document rather than a paragraph is the source's
own honesty clause: **the split between enforced and disclosed.** Literal overlap
is enforceable. Shape-class overlap is not, and should not be avoided — "choosing
a training workload *is* choosing which code paths get optimized, and a corpus
that exercised nothing the product is used for would produce a worse binary and a
less honest number." So the residual travels with the number as a sentence. No
document in the corpus made that split; `packaged-surface-evaluation` (landed by
a sibling the same day, from the other side) treats contamination as fully
eliminable by separating the surface, which is right for a package and impossible
for a binary.

### 2. `model-based-oracle` — amendment, test-input-generation

**Anchor:** "equivalence proofs find *porting* errors, never *inherited* ones —
where pgrust faithfully ports a C bug, the proof is green."

The technique's disqualifier list says: "When the behaviour is the reference. For
a system whose whole job is a well-defined transformation with an existing
trusted implementation, compare against that one rather than writing a third." It
recommends the reference oracle and never says what that oracle is structurally
blind to. **This is a denial that denied too much** — the enumeration is right
about cost and silent about reach.

A written model can be wrong *visibly*; the disagreement fires and you learn
which side erred. A reference cannot play that role, because your artifact was
derived from it: every faithfully reproduced defect produces agreement, and
agreement is what correctness produces too. `one-authority-per-vocabulary` at its
degenerate case — the reference became the sole authority, so nothing left in the
system can contradict it. The scope claim has to read *no divergence from the
reference*, never *correct*.

The remedy is the source's, and it is cheap: **make the reference disagree with
itself.** Two of the four upstream defects the campaign isolated "surfaced as
cross-platform splits when the proof suite was replicated on Linux-aarch64" — a
signedness the platform chooses, a library routine whose acceptance differs, an
overflow that traps on one architecture and wraps on another. The amendment is
written against the mechanism, not against any specific vendor defect, so it does
not depend on the source's bug reports being real.

### 3. `suppression-hygiene` — amendment, dead-code

**Anchor:** three independent instruments in one tree saying one thing —
`crash-simulator/warts.toml` ("a wart hit is counted — suppressed, never
invisible"), the lint's exemptions file ("the lint prints each exemption it
applies… it never skips one silently"), and the corpus quarantine ("prints a loud
line for every exclusion, so it appears in the build log and cannot rot into
silence").

The technique names **two** rot axes and says so explicitly: "Stale-match failure
reaps entries whose *target* died; the reaper clause covers the other rot axis —
entries whose target survives but whose *justification* died." Both are properties
of the entry as written. Neither can see the third: an entry whose target is alive
and whose reason still holds, but whose **reach** grew. The file names that hazard
in its own stale-match prose ("will eventually re-match something new, silently
exempting code its author never saw") and has no instrument for it, because the
only check aimed at it fires on entries that match *nothing*.

Corroboration is within-source convergence across three subsystems by different
workstreams, plus the law the corpus already holds: an entry doing its job and an
entry eating a hundred unread findings produce the same silence, and only a count
separates them.

## Applied — three rows, three `better`, three `ship 0`

Every landing carries a row. Two arms were run today, one was reconstructed from
a real tree's history. **No project tree was modified**: the triage answer named
no project, and Phase 8 requires that confirmation before an edit.

- **`tuning-corpus-disjointness` / personas / experiment / better.** A prompt
  sanitiser of 13 pattern families, graded by a 9-payload fixture corpus in which
  **every label is the name of a pattern family**, with assertions written from
  the same list. Arm A 9/9. Arm B — same shape classes, phrasings the module's
  own header names as defeating a phrase blocklist — also scored **11/11**, while
  **9 of those 11 passed through the sanitiser completely unmodified**. The
  predicate is fitted too, and a predicate built from the pattern list cannot fail
  on an input the list ignores. **The apply refuted the completeness of the
  document it was testing**: the draft covered the corpus and not the grader, and
  a section was added before commit. The tree already carries the *artifact*
  vacuity guard (`INJECTION_PATTERNS.length >= 10`, commented "a truncated
  blocklist is a silent regression") — somebody held the instrument-assertion
  discipline exactly and still shipped a self-graded eval, which is the finding.
- **`suppression-hygiene` / gravity / experiment / better.** A lint debt ratchet
  whose committed baseline states its own predicate, including that the population
  is "the whole repository minus that config's `ignores` block". One entry —
  correct, well-reasoned, its comment recording why — removes **305 of the 677
  files the two arms cover between them (45%) and 19 live warnings**, and no
  output names either number. The entry passes stale-match (it matches), passes
  the reaper (its reason holds) and passes the delegation audit. The tree already
  paid for this once: the config records the day a worktree doubled every bucket
  and "the gate read as 'you added fourteen hook violations' and pointed at a
  refactor nobody needed to do" — the ratchet could not say *reach changed* rather
  than *debt grew*, because reach was never a number. **Structural fact nobody
  designed**: this entry's reach is a function of how many agent worktrees exist
  that day, so it moves without any commit touching config, baseline or source.
- **`model-based-oracle` / tracklight / simulation / better.** Three real cases
  from the tree's history under policy A (single-arm, the embedded-store
  conformance check) and policy B (as shipped, three backends against one suite).
  Case 1 is the discriminator and its commit message states the mechanism: usage
  caps rode the trait's default check-then-insert, **the embedded store overrode
  that default** and was green, the hosted backend admitted 8/8 against a cap of 4
  under a live burst. A single arm is not merely silent there, it is actively
  reassuring, because the implementation it runs has already solved the problem
  privately. Cases 2 and 3 are a surface that answered 501 only on the production
  backend, and capability gaps "masquerading as data" until two implementations
  were asked the same question. **My first hypothesis was wrong and checking cost
  one command**: I expected the non-embedded arms to be env-gated out of CI; the
  workflow runs all three and marks two as required. **Negative structural fact**:
  this tree has no designated reference at all, so the amendment's ledger clause
  has nothing to attach to — the mechanism transferred, the vocabulary did not.

## Leads (with return conditions)

- **Rename doctrine: enumerate the frozen surface before a mechanical rename.**
  `RENAME-MAP.md` separates code identity from observable surface and freezes the
  second by asking *what else matches on this string*: object names in the query
  language, 22 environment variables, storage/bank keys and format lineage, every
  runtime error and marker literal that regression output and in-repo scripts grep
  for, setting descriptions, and script basenames that are gate identity. It also
  splits **living documents (renamed) from historical records (untouched)** —
  notes, postmortems, ledgers. Real, and it has no clean home: `docs-sync`'s
  `coupled-surface-inventory` is adjacent and is about documents, not identifiers.
  **Return when** a second independent source states the frozen-surface rule, or
  when a managed project performs a rename large enough to have the problem.
- **Gate a performance claim on two metrics whose failure modes are opposite.**
  "Both, not either: wall-time wins that ride on instruction bloat are fragile
  across microarchitectures, and instruction wins that lose wall time are not
  wins." `quality-gates` carries 18 techniques and none is about dual-metric
  construction; `microbenchmark` returns **zero prior art** across the whole
  corpus, which is a real hole rather than a slug artefact. Left as a lead because
  one project's threshold is thin evidence for a rule about measurement pairs, and
  because the honest home may be a subject that does not exist.
  **Return when** a second source pairs metrics this way, or when a managed
  project acquires a performance gate.
- **Pin the comparison baseline as a vendored snapshot; score against the field.**
  "A leaderboard that moves under you makes two runs incomparable for reasons that
  have nothing to do with the engine," and the competitors' rows are vendored with
  publication dates so scoring is reproducible offline; five other systems are
  carried beside the primary "so the result can be placed in the field rather than
  against a single chosen opponent." Adjacent to
  `peer-benchmarking/comparability-filters`. **Return when** a managed project
  compares itself to an external published number.

## Untriaged — extracted, reached the table, nobody verified

Recorded with anchors so a later run does not re-derive them. **Nobody looked at
these; they are not declines.**

1. **Triage verification targets by circuit structure, not input-space size.**
   "SAT cost tracks the arithmetic circuit structure, not input-space size (all
   proofs quantify over full 2^32-2^96 spaces; that part is free)." A 2,547-word
   measured cost model with a named wall taxonomy and a remedy per class. Probably
   XL — a subject on machine-checked equivalence-proof engineering — and adjacent
   to `test-input-generation/exhaustive-when-bounded`.
2. **Two environments disagree with the cause unisolated; publish the conservative
   observation and name the split.** "We had previously reported… over 50% faster.
   On Kubernetes we measure a larger OLTP gap, 50-60% rather than 30%, and we have
   not isolated why the same binaries behave differently there than on bare EC2,
   so we quote the lower number." `lower-bound-disclosure` case 3 explicitly
   *denies* bound framing to an estimate of unknown sign; this is a third shape it
   does not carry — two observations, both real, no mechanism.
3. **Disclose that the published artifact is not the measured artifact.** "The
   binaries we publish are generic for their architecture. The benchmark numbers
   come from builds tuned for [one microarchitecture], so you will not reproduce
   them exactly from a download."
4. **Reconstruct and pin a competitor's methodology before comparing to its
   numbers, and state where the reconstruction is incomplete.** A 1,116-word
   pinned methodology with fetch dates, verbatim commands, and the explicit note
   that the competitor's own harness "is not public… there is no public repo with
   full automation or raw results."
5. **A status vocabulary whose parenthetical is load-bearing** — `proved(<bounds>)`
   / `wall(<mechanism>)` / `excluded(<reason>)` / `blocked(<refactor needed>)`, with
   "the parenthetical is load-bearing: a `proved` row states exactly what domain and
   modulo which documented seams the theorem holds." Direct independent
   corroboration of `count-carries-predicate` and probably belongs in the law's
   evidence rather than as a technique.

## Method notes

- **0 of 3 fetches spent.** The class predicted it: a first-party account in
  repository form corroborates corpus-internally, and the two amendments were
  corroborated by opening the neighbour files, not by the web. Both landings were
  written against the *mechanism* rather than against the source's vendor-specific
  claims, which is what made the fetch unnecessary.
- **All three landings came from the same Phase 6 hunt** — an enumeration that
  claims completeness and misses a case the same file describes. Two rot axes
  named; a third in the prose. "No self-check exists"; true for one direction of a
  distinction the file does not draw. "Compare against that one rather than writing
  a third"; silent on what that oracle cannot see. This is the third consecutive
  run in the ledger where the denial hunt carried the whole yield.
- **The declared focus could not fire.** The scorecard asked for the mechanical
  half of Phase 6 to be parallelised when a wave returns more candidates than the
  director can verify. One repository is one document, not a wave, and agent
  dispatch is disabled in this session by a standing operator instruction. Six
  picks were verified serially. The focus is not refuted; it was not exercisable.
