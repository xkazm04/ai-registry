## Accepted

### 1. `baseline-species-degradation` — se/ui-surfaces/data-display/diff-comparison

The subject enumerates five baseline species and states that a baseline is
chosen by the question. It does not say what happens when the species the
question demands **does not exist for a whole class of objects** — which is
this tree's situation, and is not an edge case there: `last-applied-configuration`
is written by client-side apply, so it is absent for every GitOps-reconciled
object, i.e. exactly the clusters where "what changed under me?" is asked in
anger. Found by interrogating the enumeration, per Phase 6 step 3.

The mechanism the corpus lacked: a declared fallback ladder; a label carried
**in the same value as the baseline content** so no path can render one
without the other; the label naming species *and* scope (`session: previous`,
not `previous`); the empty result carrying the label too; and refusal as the
last rung, naming every failed precondition rather than the first checked.

Corroboration: the tree's own selection code (`src/app/details.rs:223-252`, a
two-element tuple returned from a single `match`), plus training-data
convergence — the declared baseline's dependence on a client-side workflow is
reachable without this source — plus the corpus's own
`absent-degrades-malformed-fails-fast`.

### 2. `control-failure-is-not-a-datum-state` — se/…/measurement-honesty

The golden path asserts "a datum has seven states, not two" and enumerates
them; a later technique adds an eighth mechanism that "sits outside the seven
states entirely". Walking this source's **withheld CPU measurement** against
all seven plus the eighth, it fits **none**: measured, well-formed, unrefuted,
uncontaminated, nothing errored — and the *contrast* is invalid because a
condition that had to hold across the arms did not. Every one of the seven is
a property of a single value; none is a property of a pairing. This is a
confound rather than measurement error, and a model built for data has no slot
for it.

The landing appends rather than rewrites: the golden path already has a
paragraph shape for "a mechanism outside the seven states", and the sentence
"a datum has seven states" stays true, because a contrast is not a datum.

## Already covered (catches)

- **The harness floor.** The benchmark measures its own screen-capture cost
  (median 6.26 ms) and an input-to-screen floor near 12 ms, then declines its
  own win on row movement (12.42 vs 12.77 ms) as "at the harness floor".
  `measurement-honesty#noise-band-and-hysteresis` says this better and more
  generally — the band is a property of the instrument, as real as its units.
  The source is a good *instance*, and became part of application 2.
- **The redaction manifest.** `src/bundle.rs` has `redact_object` **return** the
  list of what it removed, so the disclosure is the redactor's return value
  rather than a separate audit pass over its output. `telemetry-pii-redaction`
  owns this (`redaction-invariants-as-tests`, `denylist-plus-pattern-pass`).
- **Generation-tagged watch messages.** Every `Msg` variant in `src/store.rs`
  carries `generation: u64` so a context switch invalidates in-flight streams.
  `streaming-output#emit-behind-the-revision-window` covers it.

## Untriaged — nobody judged these; anchors kept so a later run need not re-derive

- **Strictest-of policy composition.** `src/app/guardrails.rs:39-88` iterates
  **every** matching rule and takes `level.max()`, `cap.min()`, and any `deny`
  — there is no early break. `ConfirmLevel` is an ordered enum *specifically*
  so `.max()` is meaningful ("ordered weakest → strongest"), with a test
  asserting the ordering. `src/config.rs:1003-1022` carries `deny: bool` and no
  `allow`/`except` field, so an exception is **unrepresentable**: rule order
  cannot create a hole, and any rule can only tighten. A real mechanism with
  real forces — a mis-ordered exception in a destructive-action policy is a
  silent hole — and the opposite of the first-match semantics firewalls and
  RBAC use. Untriaged because the home is genuinely contested: the map put it
  between a gateway subject, a UI modal subject and `data-retention`, and none
  of the three has composition of multiple matching rules as its job. It
  deserves its own run, not a wedge.
- **Read-only is two axes, not one.** `docs/plugin-authoring.md` requires
  `network_load = true` "for load-test tools, even if their HTTP requests use
  `GET`" — an action that mutates nothing and still must not run in prod.
  Mutation-of-state and generated-load are separate hazards, and the usual
  read-only predicate conflates them.
- **Partial serialization inside a parallel hook runner.** `.lefthook.toml`
  runs every hook in parallel *except* the three sharing cargo's build lock,
  which are ordered by `priority` with the race named in a comment. Nearest
  prior art is `runner-fleet#shared-resource-serialization`; whether this is a
  boundary case or a distinct mechanism was not judged.
- **Source-side correction.** `docs/safety.md:29` says "The first matching rule
  wins." The instrument does not: it evaluates all matches and composes the
  strictest. The doc's *next* sentence ("applies the strictest of…") is right,
  so the two contradict each other. The divergence is in the safe direction,
  but the doc teaches an authoring model under which an author would expect a
  narrow earlier rule to shadow a broad later one — and no such shadowing
  exists.

## Leads

- **Delegated authorizers return incomplete rule reviews.** `docs/safety.md`:
  the empty browse list hides kinds the user cannot `list`, but an explicit
  search includes every discovered kind, "because delegated authorizers can
  return incomplete rule reviews" — so a self-capability review is a hint for
  narrowing a default view and never a gate. *Return condition:* a second
  independent source stating that a self-capability review is non-authoritative
  under delegated authorization, or a connected project that filters a UI by
  one.
- **Whole-argument substitution as a standing boundary.** Plugin arg
  placeholders and `$MESSAGE` in the notify command are both "substituted as a
  whole argument, never through a shell" — the same rule in two subsystems,
  internal convergence within one tree. *Return condition:* a second source
  outside this tree drawing the same boundary, which would promote it from
  house style to technique.
