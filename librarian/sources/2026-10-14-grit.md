# grit (rtk-ai): claims below the file, a merge door, a lock store for agents

Class: practitioner tool repository from the same owner as `rtk-ai/rtk`, in
repository form; mined from a clone pinned at `0f3c9d04` (crate 0.4.0,
2026-06-14) and unshallowed to read the history. Expected yield, said before the
table: one to three techniques in the existing coordination subjects plus source
applications, and catches for the lock mechanics the corpus already owns; the
paid-for failure modes sit in the 0.4.0 fix commits, not in the README.

What grit is, read from the tree rather than the README: a command-line
coordination layer. Agents `claim` syntax-tree symbols (functions, classes) as
read or write locks with a time to live, work in a per-agent linked worktree,
and `done` commits, rebases inside the worktree, merges under a file lock and
releases. Locks live in an embedded database for one machine or in an object
store with conditional writes for many machines.

Swept in order: `CHANGELOG.md` and the full commit history (the 0.4.0 fix
commits `65f0ebb`, `8ad1fa5`, `db8b068`, `ae8bded`, `59f349b`, `c75aea9` carry

## Design record (two systems: the claim-and-integration protocol, the lock store)

### Protocol

- **D1 claim unit is a syntax-tree symbol.**
  decision: a claim names `file::symbol`, not a path.
  forces: many agents on one module serialize under path claims while the line merge would combine them.
  buys: parallelism inside a file. rejects: path claims.
  where: `src/parser/mod.rs:357 "id: format!("` ; `src/db/mod.rs:92 "CREATE TABLE IF NOT EXISTS locks ("`
  stage: claim. corpus: NONE (nearest `concurrent-vcs/intent-ledgers`, path scope declared as coarsely as honest; it does not model sub-file forces). HOME IF NEW: concurrent-vcs.
- **D2 claims block and lease.**
  decision: a claim is a lock with a time to live and a heartbeat; a refusal lists free symbols and may queue or wait; all-or-nothing only inside the timed wait.
  forces: an autonomous agent has nobody to surface a conflict to.
  where: `src/cli/mod.rs:603 "let available = db.available_symbols_in_files(&files)?;"` ; `src/cli/mod.rs:625 "all-or-nothing"` ; `src/cli/mod.rs:612 "return if blocked.is_empty() || queue {"`
  stage: claim. corpus: partial (`intent-ledgers` argues against hardening a ledger into a lock; `concurrency-guards` names refuse/join/queue/coalesce; multi-unit hold-and-wait not modelled).
- **D3 one merge door.**
  decision: `done` commits in the worktree, takes a file lock, refuses a dirty main checkout, rebases inside the worktree, merges with a merge commit, and tears down only after a confirmed merge.
  forces: the version-control tool cannot merge twice in one checkout; a rebase from the main checkout fails on a branch checked out elsewhere; teardown before confirmation loses the commit.
  where: `src/git/mod.rs:184 "let _lock = self.acquire_file_lock(&lock_path)?;"` ; `src/git/mod.rs:198 "--untracked-files=no"` ; `src/git/mod.rs:222 "rebase"` ; `src/cli/mod.rs:931 "if merged {"`
  stage: integration. corpus: NONE (nearest `physical-isolation`, which owns create and remove; merge-back is one clause). HOME IF NEW: concurrent-vcs.
- **D4 claims released whatever the merge did.**
  decision: locks are released at the end of `done`, merged or not, and queued agents are promoted.
  forces: a crashed or failed `done` must not orphan locks.
  rejects: holding the claim until the work is integrated.
  where: `src/cli/mod.rs:951 "Release locks regardless of merge outcome"`
  stage: integration. corpus: NONE (`intent-ledgers` deregisters at session end with outcome and does not address a failed integration). HOME IF NEW: concurrent-vcs.
- **D7 dependency read-claims.**
  decision: `--with-deps` takes read locks on every transitive callee from a call graph resolved by bare name.
  forces: a callee's contract change breaks callers no claim covers.
  where: `src/parser/mod.rs:104 "function_name -> [symbol_ids]"`
  stage: claim. corpus: NONE. HOME IF NEW: concurrent-vcs.

### Lock store

- **D5 one lock interface over three substrates.**
  decision: an embedded database inside an immediate transaction; two object stores with create-if-absent writes; TTL leases; queue, index and availability always in the local database.
  where: `src/db/sqlite_store.rs:68 "TransactionBehavior::Immediate"` ; `src/db/s3_store.rs:389 "refusing to fall back to non-atomic locking"` ; `src/cli/mod.rs:581 "db.enqueue(s, agent, intent, mode)?;"`
  corpus: `concurrency-guards/cross-process-exclusion` and `data-access/cross-driver-invariant-parity` model the forces. Catch, with live violations recorded in the source application.
- **D6 shared and exclusive modes by announce and verify.**
  decision: write locks take the canonical object; each reader writes its own object; each side announces then checks the other class and backs off.
  forces: several readers cannot live in one object; the store has no multi-object transactions.
  where: `src/db/s3_store.rs:214 "The reserve-then-verify ordering guarantees"` ; `src/db/s3_store.rs:90 "fn reader_key"`
  stage: claim, cross-machine. corpus: NONE (nearest `cross-process-exclusion`, single holder only). HOME IF NEW: concurrency-guards.

## Corrected premise, recorded for the source class

The README's benchmark ("git throws away 70-90% of work, grit 0%") is not a
measurement for the tool arm: the chart draws the tool's failures from a literal,
the tool arm's counter reads conflict markers after the tool aborted the merge,
agents beyond the symbol count idle silently in the tool arm, and only the tool
arm rebases. The rows it would have authored are catches; the boundary it
pointed at without seeing it (the import block no symbol owns) is the strongest
section of row 1. A wrong benchmark handed over the remainder hole.
