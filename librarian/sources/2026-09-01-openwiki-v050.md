# OpenWiki v0.5.0, 2026-09-01 - the run where the source moved to our position

A delta re-scan, at the operator's request, of a repository this registry
already mined on 2026-08-27. The prior note is the most important input to this
one, and reading it first changed the whole shape of the run.

## Class: vendor repository, re-scanned as a version delta

The sub-class is worth naming because its yield profile is unlike a first scan
of the same repository. **A delta's unique product is not new features - it is
reversals**, because a reversal is a design decision that production tested and
found wrong. Everything else in a seven-day window is already-covered or thin.

Expected yield, said out loud before the triage table: a high catch rate, 2-4
landings, and at least one of them an *amendment corroborated by the vendor
moving to our position* rather than a new technique. That held exactly.

Mined from a clone, never from the ingest, per the repository rule. Swept in
yield order: the 23 changed documents under `openwiki/` (this tool documents
itself with itself, so its workflow pages are first-party practitioner
documents whose revisions are paid-for failure modes), then the new instrument
(`src/generation/page-manifest.ts`, 416 new lines), then the model-facing
standard (`src/claims/guidance.ts`), then the testing doctrine
(`openwiki/testing/overview.md`, +359), then the changelog. The README was read
last and mined for nothing.

0 of 3 fetches - the class predicted this, and the prediction is now sixteen
runs old for sources carrying their own primary material.

## The run: our correction, shipped by the source, one release later

On 2026-08-27 this corpus read v0.4.0's claim-reconciliation contract, agreed
with its set-level shape, and rejected one detail: **omission as the retraction
signal**, on the grounds that it makes forgetting and deciding produce
byte-identical results. `dated-corrections` was amended to say so.

v0.5.0 reverses it. `reconcilePageClaims` (`src/generation/page-jobs.ts:402`)
now takes a sparse payload with an explicit `retractedClaimIds` field, retains
an omitted healthy claim, and **throws `invalid_input` on an omitted flagged
claim** - "a validation error the runtime refuses", which is the phrase the
technique already used. Verified against the implementation, not the prose, per
the standing rule from the last run on this same repository.

**The reversal is not the finding; the way it is cheaper than ours is.** Our
rule refused *every* omission, which forces the worker to re-declare the
complete set on every pass - exactly the round-trip cost that makes claim-level
freshness unaffordable, and which our own `repair-rides-the-open-page` exists to
avoid. v0.5.0 binds omission to the **non-destructive** reading and reserves the
refusal for the subset where retaining is *also* unsafe: a claim already flagged
stale, where the retain path re-resolves evidence and would launder a
known-broken claim into a fresh confirmation. Three-way, not two-way.

The load-bearing half, which is what makes a sparse protocol safe at all: **the
obligation set is enumerated by the system, not by the worker.** The assignment
states the page's claim count and lists only the flagged ones; a worker needing
the full set asks on demand, scoped to the unit it owns.

Two more details from the implementation that no design document states:
**withdrawal is idempotent while confirmation stays strict** (a retry after a
durable write but a failed checkpoint must not fail forever - the code comment
says exactly this), and a **result floor** - a pass that withdraws everything
and adds nothing is refused, checked on the result rather than the payload.

## What landed

**One amendment, one technique, one golden-path amendment, two applications.**

- **Amendment, `docs-sync/dated-corrections`** - three new sections under
  "Retraction is a verb, never an absence": the three-way omission rule, the
  idempotent/strict asymmetry, and the result floor. The prior run's finding is
  not retracted; it is sharpened, and the technique now carries the cheaper
  resolution.
- **New technique, `test-harness/gate-scope-is-not-report-scope`** - from the
  same source's testing doctrine, which sets coverage `all: true` with an
  explicit whole-tree include so a file no test imports reads as 0% rather than
  vanishing from the denominator, and which pairs every coverage exclusion with
  the tested module its extractable logic must live in. The technique's own
  contribution is the **duality**: the gate needs a scoped population or it is
  unpassable and gets deleted; the report needs the total one or it redefines
  the codebase as the part already tested. One include list cannot be both.
- **Golden-path amendment, `test-harness`** - its lane-health section opened
  "Two failure modes destroy a harness's authority, and both are silent." Both
  named are failures of the *tests*. The third is a failure of the
  *denominator*, and it hides better than either because nothing is red,
  nothing is flaky, and the arithmetic is correct. Now three.

Boundary recorded rather than linked: `docs-sync/checked-vs-skipped-denominators`
is the nearest prior art and is a **different** failure. It fixes arithmetic over
a work set the report set out to evaluate - checked, failed, skipped. The
coverage case is upstream of that: the file was never in the set at all, so it is
not skipped, and no third state recovers it. The enumeration is the defect, not
the summing.

## Applied - 2 rows, both `better`

**`gate-scope-is-not-report-scope` -> two Node codebases, mode `code`.** Same
suite, same inputs, both arms, one variable (the include set).

| | arm A (shipped) | arm B (whole tree) | `src/` files |
| --- | --- | --- | --- |
| codebase 1 | 5 files, 95.74% lines | 1,171 files, 4.32% | 1,156 |
| codebase 2 | 175 files, 58.54% | 1,529 files, 68.98% | 1,529 |

The second codebase is the instructive one and cuts against the obvious reading:
its whole-tree number is **68.98%**, so the suite is genuinely broad and the
scoped report was *understating* it. What the scope hid is a population - **490
files at 0%, none previously visible** - and no floor in the three gated
directories can ever be lowered by a four-hundred-and-ninety-first. Both shipped
(pathspec, not pushed); every existing threshold still passes, because neither
gate's population changed.

**`dated-corrections` -> this registry's signals lane, mode `experiment`.** The
seam is `scripts/signals-collect.mjs`: a rolling 30-day window (`:32,46`) folded
into a whole-file replace (`:109`). A subject witnessed 31 days ago is not
marked expired - it is simply not written, and the replacement artifact carries
no evidence it was there. Omission is the retraction signal, in our own tree.

Same recorded inputs (104 consult lines, six projects), same fold logic, one
variable - the window:

| window | pairs witnessed | dropped with no record |
| --- | --- | --- |
| 30d (shipped) | 87 | **0** |
| 8d | 71 | **16** |
| 4d | 51 | 36 |

At the shipped window the defect is real in code and **not yet observable**: the
oldest consult is 2026-08-23. Moving the boundary into the data measures the
arrival - 18% of pairs lost, every one a real subject a real consult logged.
**The first genuine silent drop lands 2026-09-22.** Nothing committed to the
collector; the schema decision belongs to a lane that already owes an unemitted
key from the last run on this source, and adding a second before the first is
emitted would widen the gap rather than close it.

The **asymmetry** is the part worth keeping: `librarian-scan.mjs` models
unknown-versus-zero at *bundle* granularity with visible care, documenting that
"nobody consults this" and "nobody has told us" are opposite. At *subject*
granularity the same distinction is destroyed - not by a decision, but by the
write path. One lane, one author, modelled where it was thought about and lost
where it was not.

## Leads (banked, return conditions attached)

- **A no-op path that proves its own stability.** v0.5.0's skip path snapshots
  the source, finalizes, snapshots again, publishes, snapshots a third time, and
  falls out to the full path on any drift - the *cheapest* branch carrying the
  most proof, which inverts the usual instinct. Real, and it did not survive
  triage into a landing. **Return when a second independent system does this**,
  or when a fleet project grows a skip path whose correctness matters.
- **Fail closed on the adversarial race, absorb the platform's benign drift.**
  The same fingerprinter rejects a TOCTOU symlink swap and tolerates Windows
  `dev`/`ino` inconsistency, and the discriminator between the two decisions is
  not written down anywhere in this corpus. Home is contested between
  `readiness-passports/fingerprint-provenance` and
  `test-harness/platform-quirk-absorption`, which is itself the reason it is
  banked rather than landed. **Return on a second sighting in a different
  bundle.**

## The untriaged table paid, for the first time measurably

Two of the prior run's untriaged rows are **confirmed real by this delta**:
row 12 (a streaming-only gateway answering 200 with empty content) is fixed by
#744, and row 14 (a framework's model metadata capping tokens) by #743. Both
were recorded on 2026-08-27 as unverified, nobody looked at them, and the vendor
has now shipped fixes for both.

This is the first return this registry has measured on recording untriaged
candidates, and it is an argument for the practice that no amount of reasoning
about it could produce: the value is not only that a later run re-picks them, it
is that a later scan of the same source can *confirm* them for free.

## Method notes

- **The prior source note was the highest-value input to this run**, and the
  method already requires reading it. Worth stating more strongly: for a delta
  re-scan the prior note is not context, it is the *instrument* - it is what
  turns a changelog line into "the source reversed our disputed claim."
- **Verifying against the implementation caught nothing this time, and that is
  the point.** The prose in `claims-reconciliation.md` and the code in
  `page-jobs.ts` agreed completely. The rule is cheap enough to run when it
  returns nothing.
- **Two things the gate caught that review would not have**: a `verified_against`
  free-text string where the schema wants `<stack>@<version>`, and the word
  "JavaScript" in an upper-layer body. Both were mine, both in the first draft.
- **A sibling's file was red in the gate throughout this run**
  (`quality-gates/techniques/instrument-answers-only-its-own-question.md` exists
  and its golden path does not declare it). Not touched, not fixed - reported
