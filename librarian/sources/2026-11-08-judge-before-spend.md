## The decision: pass marks, label source and grader order for a pre-render gate

For gravitone's `/trailer-clip`, before GPU time is spent on a shot:

- **Grader order.** At run time: code checks first, as a hard block; then a local judge of another
  family than the writer, advisory only; then the operator at the STOP the skill already has. At
  build time the order is the other way round: a person reads real shots, names a fault class, and
  only then writes the code check or the rubric for it. The voices chose opposite orders because each
  states one axis: M the run order, P the build order. **Discriminator: are you deciding which grader
  runs first on each item, or which grader you write first?** The corpus owns both
  (`error-analysis-first-taxonomy` for build, `assertion-vs-judgment` and `deterministic-dimension-kinds`
  for run), so this is a catch, with two voices.
- **Pass marks.** For an ordinal clarity question, pass on the probability of reaching the bar's
  level, not on the mean. For the binary rule question, pass below a probability fitted on planted
  traps and clean controls. Report recall on traps, never a raw agreement rate. Row M3 carries the
  pass-mark rule and stays banked (below).
- **Labels.** No operator per-shot verdicts exist on disk (both miners, and the lander's read of the
  operator folder). Calibration stays a lead (M18, refined by P11). Until labels exist, planted traps
  stand in, and the judge cannot be more than advisory: an uncalibrated judge's scores are leads
  (`judge-calibration-and-drift`, "Trust is a verdict").
