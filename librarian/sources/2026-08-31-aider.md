## Accepted

### 1. Structural centrality as a retrieval lane — `new-technique`

`retrieval` golden path enumerates its lanes and then denies a symmetry:
*"Every other lane is a function of the query"*, with the proximity lane
called out as *"a function of results rather than of the query."* An
enumeration plus a denial is the highest-yield shape this method hunts, and
the missing kind was a lane that is a function of **neither** — a stationary
property of the corpus, computed before any query exists, then *steered* by
the query as a personalization vector rather than *scored* by it.

`repomap.py` is that lane in production: a def/ref graph over the whole repo,
personalized PageRank, edge weights by discrimination (identifiers defined in
more than five files ×0.1, long multi-word identifiers ×10, `_`-prefixed ×0.1,
`sqrt(num_refs)`), and — the move that is easy to miss — **rank redistributed
across out-edges** so the emitted unit (a definition) is ranked rather than
the graph's node (a file).

`"pagerank centrality"` returned zero hits corpus-wide. Landed as
`structural-centrality-lane`, absorbing the salience-weighting candidate as a
section. Roster bullet added to `hybrid-lane-fusion`; the lane names the
failure it covers and the lane it is not independent of, which is the roster's
stated admission price.

### 2. Non-additive admission cost — `corrects-claim`, amendment

`ranking-budgets` argues at length that admission *value* is set-conditional
("the tenth near-duplicate is worth nothing") and then models admission
**cost** as per-item and additive: *"walk the fused order, admit each item
whose cost fits the remaining budget."* That is an asymmetry inside a mature
technique — the file noticed one half of the conditionality and not the other
— and it is the kind neither a slug map nor a summary can see, because both
files "cover" budgeting.

aider cannot use the greedy pack: its artifact is a rendered tree where one
more tag costs zero (same file, adjacent line, shared header) or a lot (new
file, new header). So `get_ranked_tags_map_uncached` bisects over prefix
length, re-rendering and re-measuring the whole artifact per probe, with a 15%
tolerance band (`ok_err = 0.15`), a best-under-budget ratchet, and a first
probe seeded at `max_map_tokens // 25`. `RepoMap.token_count` makes the probes
affordable: exact under 200 chars, sampled every Nth line and extrapolated by
character ratio above it.

Landed as an amendment section on `ranking-budgets`, absorbing the sampled
token-counting candidate as its closing paragraph.

## Applied — both `experiment`, both `better`

Both findings were A/B tested against `personas` in one read-only script over
the live 1,630-node corpus. No product code changed, which is why the mode is
`experiment` and `ship` is 0.

- **`structural-centrality-lane`** — `companion_edge` holds **0 rows** against
  1,630 nodes, and the tier it should inform ranks on `companion_node.importance`,
  which is `DEFAULT 3` and holds that default for **478 of 510 (93.7%)** of the
  tier. Deriving the graph from content instead yielded **3,523 edges** and 44
  distinct rank levels, with **0/10 top-10 overlap** against the importance
  order; the importance-order winner sits at centrality rank 470 of 510.
  Verdict `better`.
- **`ranking-budgets`** — `RECALL_EPISODE_TARGET = 20` is a count over episodes
  spanning 2 to 4,918 chars, so a fixed 20-episode window renders between
  1,560 and 39,212 chars: **25.1x** at a constant budget. Tier framing costs
  83 chars paid once per non-empty tier — **17.9%** of the block at the small
  end and **0.14%** at the large end, a 128x swing per-item accounting cannot
  see. Verdict `better`.

The centrality result extends the 2026-08-27 application on this same tree,
which found the relation stores had no request-path reader. The store is not
merely unread — it is empty, and the signal it was meant to carry was
derivable from content the tree had already stored. **The curated path did not
decay; it never started**, and `importance` at 93.7% default shows why: nobody
was going to hand-author relations for 1,630 nodes.

## Untriaged — extracted, never picked, nobody verified

Recorded with anchors so a later run need not re-derive them. No judgment is
implied by their presence here.

1. **Locator leniency follows the anchor kind.** `editblock_coder.py:184` has
   a bare `return` immediately above a fully implemented
   `replace_closest_edit_distance` (0.8 similarity threshold), making it
   unreachable; `udiff_coder.py:206` keeps a full ladder of 3 strategies × 4
   preprocessings. The rule that would explain the asymmetry: leniency is
   admissible where a format identifies its target by **position/context** and
   must fail closed where it identifies by **content**, because a near-miss
   there applies an edit to code the model never looked at. My read was `real
   gap`; not picked. Home is contested between `structured-output` (whose
   `schema-validation-and-repair` carries a sibling asymmetry — "repair what
   was never claimed, reject what was claimed wrongly") and a new subject.
2. **Parse-tree ERROR nodes as a language-agnostic syntax gate.**
   `linter.py:201 basic_lint` reuses the tree-sitter parser the repo map
   already loads, walks for `ERROR`/`is_missing` nodes, and returns *context
   around the error line* rather than a message. Ships a per-language opt-out
   (typescript, issue #1132). Would amend `quality-gates`, held by two live
   siblings at triage time.
3. **Failure-taxonomy counters beside the pass rate.** `benchmark.py` scores
   pass/fail and separately counts `syntax_errors`, `indentation_errors`,
   `lazy_comments` (regex for elision comments), `exhausted_context_windows`,
   `test_timeouts`, `num_error_outputs`, `num_user_asks` — so two runs with an
   identical pass rate are still diagnosable into prompt, format or model.
   Would land on `eval-harness`, held by two live siblings.
4. **Bounded reflection with a stated cap.** `base_coder.py:100-101`
   `max_reflections = 3`; lint and test failures re-enter as
   `reflected_message`, and exhausting the cap emits a warning rather than
   failing silently. Adjacent to `retry-backoff`, held by a live sibling.

## Leads

- **The disabled tier is the finding.** Across this tree, three separate
  leniency mechanisms are implemented and switched off in place rather than
  deleted: the fuzzy replace above, the reverse-lines preprocessings in
  `search_replace.py:533-536`, and `git_cherry_pick_sr_onto_so` in the
  commented strategy list at `search_replace.py:636-641`. A codebase that
  keeps its rejected fallbacks compiled and unreachable is recording a
  negative result in the only place it cannot be lost. Possible technique on
  `dead-code`, whose `quarantine-vs-delete` may already own the shape from the
  opposite side. **Return when** a second independent source treats disabled
  code as a deliberate record rather than as rot.
- **Two-role split: architect proposes in prose, editor renders the diff.**
  `architect_coder.py` + the `editor-diff`/`editor-whole` formats, whose
  documented rationale is that a model solving the task and a model conforming
  to a format are different jobs with different prompts. Adjacent to
  `agent-chaining` (held by a live sibling this run). **Return when** the
  sibling's landings are committed and the boundary can be read against them.
