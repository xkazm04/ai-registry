# Opik (comet-ml) — a mature system whose whole design surface lands as four techniques

Two live siblings when this run started: `fluxer` (14 subjects, none shared)
and `everywhere` (3 subjects, none shared). No contention on any of this run's
four homes at Phase 5 or at the write.

## Class and expected yield, stated before the triage

**Vendor repository.** The class's reliable surfaces are its operating docs and
its client's types; its README is its advertisement. The ingest returned 2,799
words of rendered landing page and was used only as the trigger. The tree was

A vendor repository this mature meeting a corpus this mature should yield a
small number of mechanisms and a lot of confirmation. It did.

## The design record

**D1 — vendor-neutral source directory, per-host targets derived.** `.agents/`
is the single source; one host gets a symlink, another gets a generated tree via
a make target that converts frontmatter and file extensions.
`corpus:` **`single-source-topology` + `host-contract-compilation` — models it.**
Catch. The differences here live in a make target rather than in a per-host
declarative contract, which is the shape `host-contract-compilation` argues
against; that is a confirming negative example, not new material.

**D2 — the copy regime begins at a format edge, inside one checkout.** The
symlinked host accepts the canonical bytes; the generated host does not (a
different rule-file extension and a renamed frontmatter key), so no single inode
can serve both. `corpus:` **NONE.** `single-source-topology` states the
link/copy boundary as the *distribution* edge and calls a copy inside one
checkout "a consistency problem it did not have". Landed as an amendment.

**D3 — the generated directory preserves unmarked local files.** The sync step
deliberately keeps destination files with no counterpart in the source, and the
cleanup step will not delete them; nothing marks which half is which, so
"regenerate and compare" has no defined answer. `corpus:` NONE at directory
granularity — `machine-owned-regions` fences within a file. Folded into the same
amendment.

**D4 — the instruction system has its own admission gate**, a subagent that runs
before a rule/skill/agent/tool-server is added, routing by artifact kind and
estimating context impact. `corpus:` `line-earning` + `sibling-floor-ownership`
cover per-line admission and the installed floor; the four-kind placement
routing is not modeled. **Untriaged** — the operator picked four rows and this
was not one of them. Anchors below.

**D5 — the CI matrix is derived by replaying the hook runner's own path
matcher**, one job per hook with work, with the modeled subset declared in the
source and a hard failure on configuration outside it. `corpus:` partially —
`change-scoped-work-selection` and `runtime-pipeline-generation` model the
selection, the scope reporting and the generator's failure contract. What is
NOT modeled: that the generator's input is *another tool's decision function*,
and what follows from that. Landed as a technique.

**D6 — the sandbox pre-registers stdlib-only stubs of the host SDK** under the
real import path, with a lazy fallback to the full package, because importing
the real client costs ~2.5s of a 9s execution timeout under pool contention.
`corpus:` NONE — `untrusted-extension-host` models the timeout as bounding the
host's *wait*, and nothing models the host's own API consuming the extension's
budget. Landed as a technique.

**D7 — the backend metric spec is designed for a reading order.** Producer
counters at every stage that emits work "so a producer that emits nothing makes
downstream starvation explainable rather than mysterious"; queue delay kept
separate from processing time so a backlog is distinguishable from a slow
worker. `corpus:` NONE — `metric-surface-contract`'s admission bar is per-metric
and cannot see a quantity whose value is that it disambiguates a neighbour.
Landed as a technique.

## Catches — already covered, and better

- The per-host compilation of a neutral instruction source: `host-contract-compilation`
  states the declarative-contract rule this tree does not follow.
- The derived CI matrix and its rendered skipped-check list: `change-scoped-work-selection`
  already owns both, including the three-outcome reporting rule.
- The generator's own failure contract (refuse an unjustified empty plan, strict
  failure propagation): `runtime-pipeline-generation`, in more detail than the
  source carries.
- "Success is derived, never double-counted — throughput minus errors":
  `export-terms-not-ratios`.
- Marker-fenced generated regions inside a hand-written instruction file:
  `machine-owned-regions`, applied correctly by the tree.

## The structural fact

The repository derives its **entire lint matrix** from one configuration file so
that local and remote gates cannot disagree — and applies **no drift check at
all** to the instruction tree it generates from `.agents/`. Verified against all
82 workflow files and the hook configuration, with the instrument asserted
against a known positive first: zero references to the source directory, the
generated directory, or the sync target. The drift rule exists only as an
anti-pattern bullet inside a subagent's prompt — a checkable condition delivered
as advice, in a repository that demonstrably knows how to build the gate. That
is the amendment's evidence and it is better evidence than a conforming tree
would have been.

## Lead

**The `.agents/` convergence as a boundary statement.** This tree declares one
directory canonical and explicitly names a foreign vendor's instruction
directory as an *ignored surface* other agents must not read — a negative
pointer, which is not the same as a bridge and is not modeled by
`single-source-topology`'s import-or-pointer rule. One tree is not enough to say
whether the negative pointer is a pattern or a local workaround.
**Return condition:** when a second independent repository declares an
instruction directory out of scope for agents other than its owner.
