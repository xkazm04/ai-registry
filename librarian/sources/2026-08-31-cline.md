# Cline

## Class and the sweep

Vendor repository, **open-tree variant** — the class entry sends you hunting
for the product's data model in a client's types because the archetype's
engine is hosted. This one has no hosted engine to hide: the agent loop, the
provider layer, the hub daemon and the eval harness are all in the tree, and
the only closed part is a billing endpoint. So the "stated production rules"
third of the class is not a docs page, it is a 6,243-word `sdk/ARCHITECTURE.md`
written as design rules with their paid-for corrections recorded inline.

Read fraction: **1,178 words of landing page against 124,315 in-tree**
(~105x). Every accepted candidate came from the architecture doc or the eval
instrument; **zero came from the README**, which is the class prediction
holding for the ninth consecutive repository run.

Swept in Phase 2b order: `sdk/ARCHITECTURE.md` and `AGENTS.md` (operating
documents); `evals/analysis/src/classifier.ts` + `patterns/cline-failures.yaml`
(the instrument and its rules); `evals/analysis/src/metrics.ts` and
`evals/ARCHITECTURE.md` (the measurement); `docs/` operating pages; README
last. **Fetch budget: 0 of 3** — tenth consecutive zero-fetch run for a source
carrying its own primary material.

**Board: 8 live siblings at claim time**, holding `eval-harness`,
`measurement-honesty`, `health-checks`, `model-routing`, `admission-queue`,

## Accepted

**1. `absent-status-passthrough` → fleet-orchestration** (new technique).

The finding is a **missing producer**, and it arrived as two candidates that
turned out to share one root — which is the landing that matters more than
either half. `lifecycle-signals` models exactly two sources of session state:
the session reporting itself, and the sweeper inferring from silence. Both
*observed* something. The source's architecture doc states two rules that are
neither:

> "Session status is reported, never fabricated… a defaulted `running` with
> no owning turn leaves such gates blocked with nothing to clear them."

> "Process probes distinguish an absent process from an unavailable identity
> provider. Transient probe failures… are never treated as evidence of
> command completion."

Same shape twice: a layer that observed nothing supplies a definite value
anyway. The first is a transport projector rendering a snapshot that carried
no status; the second is the sweeper's own probe collapsing *could not ask*
into *not there*. Landed as one technique with three laundering points
(projector, probe, creation-time seed) rather than two techniques, per the
operator's standing critique that the synthesis step must come from the skill.

**The sweeper is structurally blind to this**, which is what makes it a
technique rather than an amendment: the mislabelled session is alive and
recently heard from, so every staleness budget and every process check
passes. A fleet with both tiers working correctly still deadlocks. The
technique's own test is stated as *would the sweeper's evidence look healthy
while the state is wrong?*

`lifecycle-signals` cites `failure-not-empty-success`,
`one-authority-per-vocabulary` and `gate-sees-target` — and **not**
`unknown-is-not-a-value`, which is the law that governs this exactly. The
subject's state-truth technique had never reached for the corpus's own law
about rendering unknown as definite.

**2. `reliability-aggregation` → eval-harness** (new technique).

Found by the **enumeration hunt, paying an eleventh consecutive run** — and
this time the enumeration is a list of aggregation rules. The golden path
says a non-deterministic result is a distribution, that N is declared, and
that the aggregation travels with the number, then names the rules available:
*mean, median, worst-of-N, pass-rate against a threshold.* That list does not
contain **all-of-N**, which is the one a shipping decision actually rests on.

`metrics.ts` supplies both estimators over one trial set and states their
questions in its own comments — `passAtK` is *"Can this model solve the
problem?"*, `passCaretK` is *"Can I rely on this model?"* — with the source's
own worked example: 2 of 3 trials gives any-of-3 ≈ 96% and all-of-3 ≈ 30%.
Same trials, 3x apart.

The corpus already had both halves and had never joined them: `count-carries-
predicate` requires the rule to travel with the number (a *labelling*
obligation), and `metric-role-contract` requires the harness to state what
decision the numbers are for (a *selection* obligation). Reliability
aggregation is the second one's answer for repeated trials — declaring the
rule is not enough when the reader is comparing the number against a decision
rather than another number. The asymmetry is folded in as the point rather
than a caveat: any-of-N rises with more trials and all-of-N can only fall,
and confidence that something works every time *should* be harder to earn
from more evidence.

## Applied — both same-run, 2 rows owed and 2 written

**`reliability-aggregation` → personas, `experiment`, `better`.** The seam is
`buildEvalGridData`, the prompt lab's entire aggregation layer: every number
it emits is a mean, the leaderboard sorts on a composite of means, and
`winnerId` is the top row. Trial-level distribution is discarded at the
accumulate step, though `scenarioName` is on every row — the data for an
all-of-N figure is present and unused. A/B in the project's own vitest, two
prompt versions over 3 scenarios × 3 trials, identical input both arms:
**arm A ranks the spiky version first (composite 73 vs 70); arm B ranks the
steady one. The winner flips.** The spiky version is exactly the technique's
third reading — any-of-N 0.67, all-of-N 0.33 — and averaging renders an
unusable third of its runs as a three-point advantage. Probe deleted after
reading; no product code changed.

Second finding the A/B was not looking for: the finalize step reads
`count > 0 ? sum / count : 0`, so **a metric with no scored samples averages
to zero** and sorts as though it performed badly. The module excludes null
scores from averages deliberately and its `…Count` fields exist to do that
correctly — the care is real and stops at the empty case.

**`absent-status-passthrough` → personas, `simulation`, `better`.** Three
cases from the tree, and case 1 is the one worth having: the auto-kill gate
takes `Option<FleetSessionState>` and its doc comment ends *"`None` (unknown
id) fails closed"* — the passthrough, correct, at the gate where being wrong
destroys a working session. **But the `Option` is the return type of a map
lookup, not a modelled unknown.** `FleetSessionState`'s eight members are all
definite claims; there is no "not stated". So the discipline holds exactly
where Rust's type system imposed it and nowhere it would have had to be
chosen — and `doze()`, which frees a live process, guards on a *non-optional*
`session.state` and gets no such protection. Nobody designed that boundary,
which is what makes it evidence.

Bounded honestly in the application: the process scan feeds an
operator-facing orphan list, not an automatic reaper, and the ticker that
does reap works from `last_activity_ms` and never probes — so case 3 is a
latent hazard rather than a live one. Mode is simulation because **the
missing vocabulary member is simultaneously the defect and the reason the
defect is invisible**: a fabricated `Stale` and a reported `Stale` are the
same byte, so nothing in the tree can measure it. Instrument named: adding
`Unknown` makes transitions *out of* it countable before any gate changes —
the fix and the meter are one change.

## Already covered — 3 catches

- **PID + process-generation start token against identifier reuse.** The law
  `identity-survives-reuse` owns it, and `lifecycle-signals`'s sweeper
  already says to corroborate a PID match with start time and command
  identity before trusting it. Corpus is ahead.
- **Classify the failure before counting it** (`cline-failures.yaml`'s
  provider_bug / transient / harness / environment / policy / auth). Covered
  twice and better: `error-classification-for-retry` classifies at the
  boundary against structure and quarantines message-matching, and
  `failure-attribution` carries **eight** owners with a stated general form —
  *"the funnel's tells are written from inside a completed run, so any owner
  that can end a run early is invisible to all of them."* The source's own
  classifier is the anti-pattern that technique warns about: regex over a
  whole log, three layers from the boundary.
- **Anchor completion telemetry to the declaration with a teardown
  fallback.** `lifecycle-signals` already draws the distinction at higher
  altitude — what the sweeper declares is *lost*, never *exited*, because
  "we stopped hearing from it" and "it told us it finished" are different
  facts — and the source's `source` field is that same split under another
  name.

## Leads — 6, each with a return condition

- **Order builds in time, or two installs replace each other forever.** The
  source embeds a *build epoch* alongside a source fingerprint so a mismatch
  resolves by age rather than by inequality; without the ordering, two
  concurrent installations each retire the other's daemon indefinitely. Maps
  near-empty (`p2p-networking/peer-state-honesty` is about *displaying* peer
  state, not arbitrating replacement). This is a builder-position systems
  concept and lands on the **construction frontier** the tigerbeetle run
  named — third sighting. *Return when a second source states the ordering
  rule, or when a managed project grows a self-replacing daemon.*
- **An explicit endpoint is a sticky exact target.** Recovery paths may retry
  the same socket but must never substitute a discovered endpoint for a
  configured one, or custom and remote hubs silently drift to a different
  process. *Return on a second independent sighting.*
- **Client surface and initiation mode are two orthogonal facts.** The source
  keeps `source` (which client) and `mode` (user / automation / subagent /
  team) separate on the session envelope, with a stated default and an
  explicit requirement that automation adapters pass their mode. *Return when
  a managed project conflates them.*
- **Lazy identity: allocate in memory, persist on first accepted turn.**
  Closing before a user turn leaves no empty history row, and persistence
  never allocates a replacement id for an unknown session. Sits beside
  `session-registry`. *Return when a project grows an empty-session problem.*
- **Two independently restorable timelines.** Code and conversation advance
  together and fail apart; the useful restores are the off-diagonal ones
  ("your reasoning was good, the code was wrong"). `undo-history/checkpoint-
  restore` owns capture boundaries and `undo-scope` owns which fields join
  the slice; neither models a second timeline. *Return when a second agent
  harness ships the same split.*
- **A conversation backup is a code exfiltration channel by construction.**
  The source's own warning: the uploaded history includes *all tool inputs
  and outputs*, so every file read and every command output leaves with it.
  *Return when a managed project enables conversation upload.*

## Untriaged — 3, unverified, nobody looked

- Specialized provider operations fail closed unless the manifest *and* the

  implies an image, audio, transcription, or video endpoint." Near
  `adaptive-fidelity-tiers/measured-not-declared-capability`, graded *likely
  catch* at triage and never verified.

  *immediately preceding* assistant message is reused, never one from across
  intervening turns.
