## Class and expected yield

Vendor repository, and the ingest was the trigger only: the landing page is 730
words of product copy. The tree is a system — an embedded appliance firmware in
Go with a React UI — so the design read (Phase 2d) was the run, and the expected
yield was stated before the triage table as *design decisions, not claims*.

Docs are unusually thin for a tree this size (5.6k words of markdown against

## The two maps disagreed, and the disagreement was the signal

Round 7's standing check, answered directly. The concern-phrased query
("failsafe", "degraded mode", "crash classification") returned **`PRIOR ART:
none`** for the central term and weak noise for the rest. The forces-phrased
query ("restart storm", "recovery exhaustion") landed on
`process-graph-runtime/fault-signal-propagation` and
`backend-platform/resilience/retry-backoff` at the top of its ranking.

Neither found `self-healing`, which is where the work went. So the honest reading
is stronger than "prefer the forces phrasing": **a total empty from the
concern-phrased query over a mature bundle is evidence the concept lives under a
different name, and the instrument cannot find a different name at all.** What
found it was reading the category listing in `taxonomy.json` — nine subjects
under `resilience`, two of which (`self-healing`, `optional-dependency-degradation`)
never surfaced in twenty mapped terms.

## Landed

1. **`self-healing/healer-death-as-promotion`** — the healer's own terminal
   exhaustion is a promotion trigger, written before the exit and addressed to
   the successor. All five existing triggers are evaluated by a healer that is
   still running; that assumption breaks exactly when the healed component is
   mandatory, and `retry-backoff`'s stated destination for an exhausted ladder (a
   dead-letter lane, an operator queue) has nothing to route into.
2. **`self-healing/declared-verdict-over-inferred-wreckage`** — the successor
   matches a declared marker and never reconstructs the verdict from the corpse.
   `fault-signal-propagation/no-synthetic-terminal` forbids the same fabrication
   on the live side; this is that law with the boundary being a process death.
3. **`self-healing/consume-once-mode-handoff`** — a file is not a message:
   consumed once by unlinking, authenticated by shape, read under a derived
   bound, with an out-of-band door spelled differently in the record.
4. **`test-harness/far-side-oracle`** — when the product's claim is an effect on
   a system it does not own, the oracle is deployed onto the far side.
   `live-app-harness` models readback *inside* the product, which for this class
   of product is a tautology.
5. **`signed-artifacts/bypass-is-a-versioned-policy`** — the signature exemption
   as one pure predicate over declared inputs, deny by default, with its refusal
   table. Nothing in the subject covered a deliberate exemption.
6. **Amendment to `release-pipeline/updater-chain`** — "Two baselines, and they
   answer different questions." The technique names the *previous shipped
   release* as the rehearsal's starting point; the boundary case is a **synthetic
   baseline** built from the candidate's own tree, which localises a failure to
   one program but structurally cannot catch a break in the old reader. Both
   lanes belong in the pipeline, and the source runs both.

Four applications: two against the source tree (Phase 7 v2) and two against
projects that were opened.

## Applied (Phase 7.5)

| Finding | Project | Mode | Verdict |
|---|---|---|---|
| healer-death-as-promotion + declared-verdict | a fleet speech service | `code` | **better**, shipped |
| far-side-oracle | — | — | unapplied, no seam |
| bypass-is-a-versioned-policy | — | — | unapplied, no seam |
| updater-chain amendment | — | — | unapplied, no seam |

**The shipped row is the run's result and it inverted mid-test.** The service
already computed a terminal give-up verdict correctly and spelled it distinctly
in its health body, and two of its own docstrings promised the verdict "lets the
process supervisor replace the replica". The deployment could not read it: the
readiness probe branches on a status code that three different not-ready states
share, and the liveness probe — the only one that can replace a pod — was a TCP
connect that a worker-less process with a bound port passes forever. A replica
that spent its restart budget left the load balancer's rotation and was never
replaced.

Sharper still: the chart's own policy gate had a `probes-distinct` rule whose
**remediation text prescribed the defect** ("point liveness at tcpSocket 8080").
The guard existed, engaged, passed, and recommended the broken configuration.

Fixed with a liveness path that fails only on the terminal state, a chart policy
asserting it with a must-fail fixture, and the remediation strings corrected.
Paired over five engine states on three arms: correct replacements 0/1 → 1/1,
false replacements 0 → 0 (the naive fix — pointing liveness at the readiness
path — would have been 3, two of them wrong). Gate green: 43 service tests, 14
chart policies. Committed on the project's active branch with a pathspec, not
pushed.

**Fleet reach (round 9, focus 3).** Three of four findings are unapplied for want
of a seam *anywhere* in the twelve authorized trees, and that is a state rather
than a miss: no fleet project verifies signatures on artifacts it installs, none
ships a self-updating client, and the one project that drives a system it does
not own already implements two of `far-side-oracle`'s three properties (it reads
the far-side filesystem for its growth measurement, and it skips-not-fails when
the far host is absent) while having no deployed agent for runtime facts. The
corpus is landing techniques whose preconditions this fleet does not meet.

## Untriaged — real, extracted, nobody verified them

Recorded with anchors so a later run does not re-derive them. No judgment
attached to any of these; they reached the table and were not picked.

- **Sender-side authoritative override when the receiver's adaptation is a
  one-way ratchet** (`internal/playoutdelay/interceptor.go:1-22`). The package
  doc is a complete design record: the receiver's adaptive buffer grows on jitter
  and never shrinks, three named receiver-side knobs cap the floor but cannot
  pull a ratcheted buffer down, so the sender stamps an authoritative override on
  every packet. Mapped near-empty; no home found in one pass.
- **Certificate issuance gated on clock trust** (`web_tls.go:57`). A device with
  no RTC refuses to mint a self-signed certificate until time has synced, because
  the notBefore would be a lie. Nearest: `secret-custody-and-issuance/issuance-policy-ladder`.
- **A declarative changeset over a hostile config surface**
  (`internal/usbgadget/changeset.go:38`, `config_tx.go`). Ansible's file module
  rebuilt as a library, with a DAG for ordering, because **symlink order is part
  of the desired state** on the kernel interface it drives — the enum carries
  `SYMLINK_IN_ORDER_CONFIGFS` and `SYMLINK_NOT_IN_ORDER_CONFIGFS` as distinct
  states, and the whole thing commits as a transaction.
- **Preflight the external preconditions before the build**
  (`Makefile:66-78`). Bucket reachability, signing key present in the keyring by
  fingerprint, branch, clean tree, upstream sync, CLI authenticated — all before
  a cross-compile and a hardware sweep. Nearest: `quality-gates`.
- **A leak test asserts a derived budget, not zero growth**
  (`ui/e2e/remote-agent/ra-usb-idle-no-leak.spec.ts:20-24`). Per-rebind cost,
  permitted rebinds per window, steady-state allowance — three named constants
  rather than one threshold. Partly absorbed into `far-side-oracle`; the general
  form was not landed.
- **Test file ordering encodes irreversible state cost**
  (`ui/e2e/zz-login-rate-limit.spec.ts:7`). The `zz-` prefix is load-bearing and
  says so: running last avoids a device reboot to clear in-memory rate-limit
  state. Nearest: `test-harness/isolation-lanes`.
- **Instrumented synchronisation primitives behind a build tag**
  (`internal/sync/`). Drop-in `Mutex`/`Once`/`WaitGroup` that log lock/unlock
  counts with caller file, line and function under a `synctrace` build tag, zero
  cost otherwise.
- **A linter that forbids the standard library's print functions by pattern**
  (`.golangci.yml:8-14`), with per-file exemptions for the two places a logger
  cannot exist yet. The rule the README would merely name, in the form that
  cannot hedge.

## Leads

- **The four translation-hygiene instruments** (`ui/tools/*.py`): find duplicate
  targets across keys, find keys present in other locales but absent from the
  base, find keys no source file references, re-sort. Dependency-free Python,
  JSON reports. `localization/craft/translation-pipeline-topology` is the home
  and has no technique on the hygiene sweep itself.
  **Return when** a fleet project's locale files drift, or when the localization
  bundle is next deepened.
- **Per-language localization doctrine for a technical appliance UI**
  (`I18N_BEST_PRACTICES.md`, 1,226 words, 14 locales). Names the exact terms that
  must stay English per language, and the specific wrong translations to avoid
  ("chiffré" not "crypté", per the French standards body; Taiwan's 韌體 not the
  mainland 固件). A stated boundary between the translatable and the not.
  **Return when** a second such document appears from an unrelated product — a
  single vendor's style guide is one opinion, and convergence across two is what
  would authorize a technique.
- **`nmlite`: a network manager written rather than adopted** (`pkg/nmlite/`,
  ~2,500 lines: link management over netlink, its own DHCPv4/v6 client with a
  vendor identifier, resolv.conf and hostname management). The decision to reject
  the platform's network stack on an appliance is load-bearing and the tree does
  not say why anywhere — the forces have to be inferred, which by this method's
  own rule makes it a feature description rather than a design record.
  **Return when** a second appliance tree makes the same rejection, or when the
  project documents it.
