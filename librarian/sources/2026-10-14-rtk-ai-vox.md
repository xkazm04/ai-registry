# vox: one binary that speaks and listens for coding agents

**Class:** vendor repository for a local product (no hosted engine): the company that
makes rtk ships this as a single Rust binary with five speech engines, a speech-to-text
recognizer, a resident daemon, a tool server for agents and an editor plugin. Its
operating documents are in French (`docs/ARCHITECTURE.md`, `docs/BENCHMARKS.md`,
`docs/FEATURES.md`, `docs/GUIDE.md`, about 17,500 words), and the code carries about
12,300 words of why-comments, which is where most of the design lives. Landing page
4,780 words (the ingest), README 4,842. Commit `96fe9dbc` (0.17.1, 2026-10-06), clone
deepened to sixty commits to date one decision.

Swept in order: the four docs and `CHANGELOG.md`; the instruments (`src/audio.rs` stall
tests, `tests/mcp_test.rs`, `tests/security_test.rs`, `.github/workflows/ci.yml`,
`install.sh` by its doc); the measurement (`docs/BENCHMARKS.md`, `tests/perf_test.rs`
headers); the types and config (`SpeakOptions`, the tool schema, `models.toml`); the
source modules for audio, levels, mic, daemon, mcp, clone, piper; README last. Not
swept: the TUI, the sound packs, the chat streaming module beyond its doc, the plugin's
drawing code, the five non-English READMEs.

**Expected yield said before the table:** a medium tree in a subject the corpus already
models in depth (voice I/O has nineteen techniques), so most decisions should read as
catches; one or two mechanisms where the tree met a failure the subject has no stage

## Design record (one system: the speech tool and its agent doors)

```
E1 decision: a playback wait is bounded twice: the device open by a fixed limit, the
     drain by a deadline derived from the queued audio's length plus a grace
   forces:   the tool is run from an agent's stop hook and tool calls; a sound server
             reachable but connected to nothing accepts audio and never drains it
   buys:     every speak returns within audio length + grace + open limit, with an
             error that names the file route
   rejects:  waiting on the sink until empty (the default it used before 0.17.1)
   where:    src/audio.rs:246 "never hands control back to the agent that ran it"
             src/audio.rs:371 "expected_end = expected_end.max(Instant::now())"
             CHANGELOG.md:8 "never block on a dead audio device"
   stage:    playing -> completed|failed, the transition a waiting caller blocks on
   corpus:   NONE. Nearest voice-io/tts-pipeline: its lifecycle has terminal states and
             no deadline; voice-ux-integration says nothing waits, which is false for
             these callers. HOME IF NEW: voice-io
E2 decision: playback state for an out-of-process visualizer is a file written beside and
     renamed, removed only by the playback that wrote it, synchronized by its start time
   forces:   the observer is an editor plugin in another process with no socket API;
             vox processes are short and several may play
   buys:     no half-read file, no deletion of another process's announcement, a dead
             writer's leftover never replays because its start time is past
   rejects:  a stream or socket, src/levels.rs:6 "no stream, no socket, nothing to keep open"
   where:    src/levels.rs:263 "A reader must never see half a file, so write beside it and rename."
             src/levels.rs:276 "another vox process started in the meantime"
   stage:    playing, as published to an observer
   corpus:   concurrency-guards/atomic-file-publish (writer) + release-guarantees
             (owner-checked release); the reader's sync-by-start-time rule is not modelled
E3 decision: the agent door is a strict subset of the command line (no output path), and
     both doors resolve a request through one function
   forces:   an agent-supplied path is an arbitrary file write; a stored preference once
             reached only one door
   where:    src/mcp.rs:547 "Deliberately not exposed over MCP: an agent-supplied path would be"
   stage:    request resolution at the tool boundary
   corpus:   mcp-tools/caller-differentiated-capability (catch)
E4 decision: models stay resident in an opt-in daemon (and in the tool server), routed to by
     a health probe, bypassed for requests whose meaning depends on the caller's directory
   where:    docs/ARCHITECTURE.md:274 "Il n'est jamais demarre automatiquement."
             src/main.rs:383 "if is_heavy && opts.output.is_none() && daemon::is_running() {"
   stage:    the process boundary between request and engine
   corpus:   voice-io/real-time-synthesis-budget, "the process boundary is part of the rate" (catch)
E5 decision: the daemon start marks its own standard handles non-inheritable before
     spawning the detached daemon
   forces:   on Windows a child inherits every inheritable handle; an agent reading the
             start command's output waited until the daemon exited
   where:    src/daemon.rs:499 "On Windows a child inherits every inheritable handle of its parent, not"
             src/daemon.rs:532 "SetHandleInformation(handle, HANDLE_FLAG_INHERIT, 0);"
   stage:    spawn of a long-lived child
   corpus:   NONE for this force. Nearest subprocess-lifecycle/spawn-contract, which says
             all five spawn inputs are explicit and wires the three streams; the
             inheritable handle table is a sixth. HOME IF NEW: subprocess-lifecycle
E6 decision: every engine runs in the one binary; the two that needed a manual Python setup
     were removed in 0.17.0
   where:    CHANGELOG.md:15 "Both required a manual Python setup"
   corpus:   voice-io/real-time-synthesis-budget, "keep one tier that needs nothing" (catch)
E7 decision: the release profile aborts on panic, so every agent-reachable panic site is a
     server kill, and each one found got a guard and a test named after it
   where:    Cargo.toml:85 "panic = "
             src/mcp.rs:609 "Truncating by byte index aborts the whole"
   corpus:   error-handling/containment-boundary-restores-state, "check that the platform
             can unwind at all" (catch)
```

## Phase 6, what verification changed

- Row 1 was written from a tool with no pause. The falsifying seam (below) measured that a
  browser engine ends a clip on time with no audio output and that a pause stretches the
  end arbitrarily, so the technique landed with an audio-clock rule for pausable channels
  and a "measure the engine first" rule. Without the seam it would have shipped a
  wall-clock deadline that breaks pause.
- Row 2 started as a one-line note about the tree's environment write. Reading
  trust-base first (operator instruction) showed the subject's census counts spellings,
  and the fleet census turned it into a technique: 38 marker sites against 103 unmarked
  members in one tree, 0 against 49 in another.
- The tree's note on the environment write was dated: written 2026-05-14 (`b251c3c`),
  invalidated by the latency change of 2026-10-05 (`33398d4`) that opened the output
  device on a new thread one line before the call path that reaches the write.
- Primary fetched (1 of 3): the standard library's page for the environment write, read
  verbatim: sound in a single-threaded program, always sound on Windows, otherwise no
  other thread may write or read the environment by any route.

## Leads

- **Clone reference length dominates synthesis time:** a 6 s reference at 24 kHz took 21 s,
  a 14 s reference at 48 kHz took 11 minutes, same sentence, one machine
  (`docs/FEATURES.md:143 "reference de 6 s a 24 kHz, 21 s"`). Return when a second engine or
  machine measures reference length against synthesis time; then it is a rule for
  authored-voice-identity's enrolment cost.
- **An agent cannot discover a plugin that is not installed, so the tool server's own
  instructions carry the install commands** (`docs/ARCHITECTURE.md:270 "Un agent ne peut pas decouvrir un plugin"`).
  Return when a second tool does the same or a fleet project ships an agent-facing plugin.

## Rust practice worth learning from (operator focus)

- Tests named after the failure they pin, with the bound asserted: `a_device_that_never_plays_is_an_error_not_a_hang`, and a device fake whose release blocks thirty seconds.
- Each guard against a hostile input carries its arithmetic reason at the site (a zero sample rate saturating to an aborting allocation; a clamp whose bounds cross).
- Where it falls short: the environment write's safety note argued a narrower precondition than the function's and decayed (row 2, row 3); no junk-argument sweep over the tool server under abort-on-panic (containment application).
- CI comments carry their measured reasons (why compute capability 8.0, why the cache key holds it, why the accelerator job is blocking again).
