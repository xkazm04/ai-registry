# Sozu - a system whose every mechanism the corpus already owned

**Class read at Phase 2, before extraction:** first-party practitioner account in
repository form. The landing page is 1,465 words; `doc/` is 61,681 across 27 files,
a 1:42 ratio, and the densest documents are exactly the ones the class predicts -
`doc/testing.md` (4,392 words of testing doctrine with three cited public sources)
and the 2,399-word agent instruction file. **Priced before mining** (round 23 focus
item 1): forecast 4-7 landings with a real chance of an XL, on the reasoning that
the corpus has no Rust-slug subject while carrying `rust` as a stack on many
subjects - the seam shape round 23's refinement names. **Actual: 5 amendments, 0
subjects, 0 techniques.** Inside the band on count, and outside it on shape, for a
reason worth more than the count.

## The routing count, and why nothing was handed off

Phase 2d asks how many load-bearing design decisions this tree carries that no
subject models. Computed per system, before deciding:

| System | Decisions read | `corpus: NONE` |
|---|---|---|
| A - the proxy runtime (`lib/`, single-threaded mio loop, sans-io cores) | 4 | 1 |
| B - the testing doctrine (assertion-first + deterministic simulation + swarm + fuzz) | 5 | 1 |
| C - the control plane (protobuf IPC, hot reconfig, fd handoff) | not swept | n/a |
| D - the agent instruction surface | 3 | 0 |

No system reached three, and no three entries shared a `HOME IF NEW`. **Neither
clause fired, so there is no forge handoff** - and that is a finding rather than a
shortfall. A 175,000-line production system with 27 design documents produced zero
new subjects because the corpus already models its ground, and it models it well
enough that every one of this run's five landings is a *boundary* on an existing
mechanism rather than a mechanism the corpus lacked. Each was checked against the
v2 rule before being written as an amendment: in every case the host file's own
rule survives the finding and gains a condition, which is the amendment's
definition and not the excuse version of it.

The one place that judgement was close is the swarm classification (row 3), which
adds a three-way sort the host technique did not have. It landed as an amendment
because the host already owns a "choosing the feature set" section that the sort
refines, not because a paragraph was cheaper than a technique.

## What was verified, and how

Three verification workers ran against the corpus, each asked to be adversarial
toward its own conclusion and to say what it searched that would have refuted it.
The director re-read every host file before writing.

**Row 1 was verified against the tree twice, in opposite directions.** Arm A: the
source's own checkout - `git ls-files -s` reports mode `120000`, `ls -la` reports a
regular file, `od -c` reports nine bytes reading `CLAUDE.md`, and `git config
core.symlinks` reports `false`. Arm B: six repositories in this fleet that ship
both filenames all use a reader-resolved import directive instead, and all seven of
their directives resolve. The corpus's claim that "drift is not representable...
nothing can differ" is false on this platform, and the fleet had already voted
against the default without a rule telling it to.

**Row 4's second half resolves a contradiction the corpus was already carrying.**
`ratchet-design.md` instructs deleting an emptied baseline; a landed application
records the opposite decision with a reason. The source is a third instance of a
deliberately-empty allowlist. The amendment names the retention case rather than
picking a side by majority.

**Row 3 landed on both sides of a boundary.** `blocking-by-input-determinism.md`
states "a gate is the all-of-N position by definition", which forbids row 3's
merged-campaign gate as written. One sentence was added there naming the
discriminator (verdict predicate vs reach predicate) rather than leaving two
subjects in contradiction.

## Untriaged (with anchors, so nobody re-derives them)

- **A streaming sans-io core is re-fed the whole window, not a delta.** The
  accumulation buffer belongs to the shell; every `Input::Bytes` carries the full
  window from wire offset 0 (`lib/src/protocol/tcp_preread/mod.rs:14-21`). This is
  what makes byte-for-byte replay possible and keeps the core near-stateless, at
  the cost of re-parsing. `io-free-core` says inputs are values but never says who
  owns the accumulator for an incremental protocol. Scored 1/0/1.
- **Guards are selected by syntactic locality, not by the cost of drift.**
  `prose-rule-drift` explains that *action*-shaped rules go unmechanised. Both of
  this source's conventions are artifact-shaped, and only the syntactically local
  one got a guard: "a log macro within 24 lines" is a window scan; "this unwrap is
  unreachable from network input" is a call-graph reachability property. The region
  is narrower than the host technique says. Scored 1/0/1.
- **Cite the commits that exist only because a rule was skipped.** The source does
  this literally - "Commits `7a7e87d9`, `6bd85a3f`, `73341f4f` exist only to paper
  over this being skipped - do not add to them." Proposed host
  `substrate-coupled-expiry.md:130-135`, which already says to stamp a rule with
  its origin but treats the origin as prose recollection; a commit list is
  retrievable, survives a bulk rewrite, and is a *re-measurable* predicate whose
  growth refutes the rule. Scored 1/0/1.

## Lead

- **The link regime's platform precondition is now stated, but nothing in the
  corpus tells a repo how to detect that its own checkout broke.** The assertion
  named in row 1's amendment ("the bridge resolves to the canonical document") has
  exactly one implementation in the fleet, in one project, and it is 539 lines
  solving a larger problem. Return condition: a second fleet project grows a
  guidance checker, or a portable ten-line form of the check is written - at which
  point it is a `scripts/` landing rather than a lead.

## Directions not proposed

None. The direction pass requires a design-record entry whose `corpus:` names a
subject *and* a fleet project whose `scope.does` admits the decision's forces. Both
Rust projects in the fleet were checked and neither is a peer of a network proxy:
one is an observability service, one is a data-pipeline workspace. The two
instruction-file decisions (rows 1 and 5) are fleet-wide and were discharged as
coverage measurements in Phase 7.5 rather than as directions, because every project
already has the context. **The owed peer study is retired explicitly for this round**
(round 23 focus item 3): no fleet project is a peer of a reverse proxy, and the
nearest candidate by domain - the observability service - shares no forces with it.
