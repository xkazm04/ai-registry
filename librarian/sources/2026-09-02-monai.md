## Landed

### 1 -> amendment, `test-harness/platform-quirk-absorption` ("The quirk that survives main")

The source's test helper computes a 1024-square matrix product in double and in single
on the accelerator, compares against a 0.001 threshold, and relaxes every numeric
tolerance in the suite when the reduced mode is detected - with a comment that the mode
is ~8x faster and ~2 digits less precise. Beside it, a doc page lists three layers that
override one precision flag (the library default, an environment variable, and a
container image's environment layer that sets it on every boot). Strip test: the flag is
not the mode; probe by computing. The corpus already held the doctrine
(`gate-sees-target`; `probe-the-grant-not-the-config` in the permission domain) and had
no numerics instance, and the boundary test in the technique ("would it bite an empty
suite?") excluded this class by construction - the amendment refines the boundary for
post-main quirks. Applied at `simulation` over three real Rust tolerance sites:
**not-better**, the substrate has no mode; condition written into the amendment.

### 7 -> technique, `release-pipeline/deprecation-by-version-arithmetic`

The source's decorator takes `since`, `removed`, an injectable version, and a message
suffix; warns from `since` naming `removed`, raises from `removed`, and raises
immediately when neither is given. Its contributing guide states the forecast rule
(next major for significant, `Y+2` minors for minor), requires tests for both APIs,
and requires the recommended replacement to be behaviour-exact. Applied on a
single-owner web app at `experiment`, **better**: 24 live tags, a version unchanged
for fifteen months, two zero-importer modules five and seven months old that no clock
would fire. Carried back into the technique: the operand is whatever the project
actually advances. Note: that project declares no registry domains in the fleet file
and has no `.ai` directory, so the experiment is recorded registry-side only.

### 9 -> technique, `supply-chain/unsafe-deserialization-off-by-default`

Four advisories across two releases, each a load path: checkpoint loading moved to
weights-only, an array loader gained a default-off pickle flag, algorithm serialization
moved from pickling to structured text with an environment escape hatch, and shell
variable expansion was hardened. Strip test: the restricted loader is the default, the
permissive one is a per-call opt-in named for the hazard, the format migrates. Applied
on a game project's motion scripts at `code`, **better**, `ab-paired` over the
producer's own key set; three readers flipped and committed on the project's active
branch, not pushed.

## Leads (banked, return conditions attached)

2. **Deferred composition of geometric transforms.** A chain of spatial operations
   (resample, reorient, crop, rotate, zoom) is recorded as pending homogeneous
   matrices and applied in one resample when a data-reading stage forces it, with three
   controls: a pipeline-level lazy flag (true / false / honour-per-stage), a
   per-stage `requires_current_data` declaration that forces materialization, and an
   explicit apply-pending barrier. The source claims fewer resampling artifacts and
   that a crop deferred past the spatial ops keeps data an eager crop would have thrown
   away. No subject owns transform-chain execution; pipeline-dag owns user-authored
   graphs with human gates. *Return when a managed project grows an image or geometry
   transform chain* - then leads 2 and 4 are one spec, and candidate 3 is its test
   strategy.
4. **Applied-operation tracing for invertible pipelines.** Every transform pushes a
   record (class, id, whether it fired, parameters) onto a stack carried with the
   tensor, so a prediction can be mapped back through the inverse of each into the
   input frame; the trace is thread-local and stripped on pickling. *Return with lead 2.*
5. **Object-graph configuration with explicit merge semantics.** A `_target_` key
   instantiates, `@` references, `$` evaluates, `%` textually substitutes, `+key` on a
   later file merges (dict update / list extend) where an unprefixed key overrides, and
   `_requires_` declares an ordering dependency that no argument carries. The `+` marker
   is the reusable half: layered config files need a per-key merge-vs-override marker or
   they silently override. *Return when a second independent system carries a per-key
   merge marker, or when a managed project layers more than two config files* - and
   note candidate 14 then: `$` makes the config a code-execution surface.
