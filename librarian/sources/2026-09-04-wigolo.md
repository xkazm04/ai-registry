## The design record

Seven entries. The `corpus:` line is the routing count.

**D1 — Pre-route named addresses past the signal-driven escalation.**
*Forces:* signal-driven escalation is reactive and needs a response to classify;
two failure modes deliver none — a connection that dies before any status, and a
response that carries enough chrome to clear an emptiness threshold while the
substance mounts later. *Buys:* the refusal-routing rule keeps its cost
discipline where it can observe a refusal and stops silently failing where it
cannot. *Where:* `src/fetch/router.ts:76-90` (the load-bearing half),
`:401-423` (the routing predicate), runtime-extensible via an operator
environment variable. *Corpus:* `document-text-extraction/recognition-boundary-and-escalation`
— **AMENDMENT** (boundary case; the technique's own rule survives intact).

**D2 — Classify the refusal before choosing a response; let the class refuse to
act.** *Forces:* the responses cost wildly different amounts and each is
meaningful against one shape only; running them speculatively spends money
against an impossible outcome and manufactures a "we tried" the caller cannot
distinguish from a real attempt. *Where:* `challenge-classify.ts:1-40`,
`solve-ladder.ts:8,94`. *Corpus:* **NONE** — `scrape-scheduling` models the
refused state as a single terminal *run outcome* and does not model it as a
classified space at all.

**D3 — Under-claim capability when ambiguity and confidence run opposite.**
*Forces:* the evidence for the tractable classes is exactly the evidence an
adversary can fabricate. *Where:* `challenge-classify.ts:22-33`.
*Corpus:* **NONE**.

**D4 — A delegated step's product is not promoted to an in-house step's trust
level.** *Forces:* a uniform interface across steps of unequal trust makes the
tiers invisible at the point of reuse. *Where:* `escape-hatch.ts:9-18`.
*Corpus:* **NONE**.

**D5 — A credential is bound to the egress that minted it, and hard-refused
elsewhere.** *Forces:* the credential is bound to a fingerprint the issuer never
disclosed; two different normalizations across write and read kill reuse
silently for exactly the population that needed it. *Where:*
`clearance-reuse.ts:26-38,40,52,64,73-90,132-147`. *Corpus:* PARTIAL —
`device-pairing/token-binding-and-transport` owns this entirely from the
**granting** side. The holder's half is a mechanism it never had → folded into
the new subject, with a reciprocal paragraph landed in the neighbour.

**D6 — The human step hard-no-ops unless consent AND a surface both exist.**
*Forces:* on a headless host nobody is watching, and a step that merely times out
there burns every refused request's full budget. *Where:* `human-solve.ts:8-20,84,108`.
*Corpus:* **NONE**.

**D7 — The sequencer imports no engines, and a wrapping escalation is not a rung.**
*Where:* `solve-ladder.ts:1-26,117-121`. *Corpus:* partly generic. The worker
declined it as a technique and folded it into the golden path — recorded as its
decision, with the argument, not as a deviation.

### Untriaged — extracted, reached the table, never picked

Recorded with anchors so a later run does not re-derive them. **Nobody verified
these; they are not declines.**

- **A status transition is a change at equal body hash.** A 200 that becomes a
  404 with an identical-looking body IS a change; pretending otherwise is a
  silent-failure mode. `src/cache/change-detector.ts:26`. Nearest:
  `web-scraping/shape-change-detection`, `cicd-monitoring/transition-detection-and-notify`.
- **Null the LLM-sourced field that is not literally in the source.** Per-field
  provenance; verify literal presence for `llm`-provenance fields only, null on
  failure with a warning; heuristic and structured-data values are exempt because
  they are already trusted. `src/extraction/schema-truth.ts:1-20`. My read was
  `likely catch` — the law `grant-funding#provenance-per-field` plus
  `recruiting/candidate-evidence/*` look like they own it — but nobody opened
  those files this run, so this is untriaged and not a catch.
- **Two gates with deliberately disjoint jobs.** A URL-shape gate and a content
  gate that is explicitly NOT a relevance filter *because the reranker already
  owns relevance*, plus a never-empty floor that keeps the single best candidate.
  `src/research/source-validation.ts:1-6,40`.
- **A baseline you could not capture is a dated document.** `_skip-reasons.md`
  names the syscall that blocked it, both workarounds tried and why each failed,
  the exact corpus/metric/output-path recipe for the host that can, and a status
  of PARTIAL with the reason "environmental constraint, not a code issue".
  Nearest: `quality-regression-gating/baseline-carries-its-conditions`.
- **SSRF guarded at the persist door, on both the watched URL and the webhook
  URL, with stable machine-readable reason codes the HTTP adapter keys on —
  never the prose, which embeds host values and can be reworded.** A test pins
  the adapter's key set against the code object so wording drift cannot silently
  break status mapping. `src/watch/ssrf.ts:1-19,33-42`.

## Leads

- **An in-process plugin host that validates shape and isolates nothing.**
  `src/plugins/validate.ts` checks that an export has a name and two functions;
  `loader.ts` then `import()`s it into the server process. The corpus has
  `security/extension-trust/untrusted-extension-host` with
  `capability-subtraction-sandbox` and `pluggable-isolation-runner`, which is the
  opposite posture. This is a real gap in the tree rather than a finding for us —
  worth returning to only as a *negative* application. **Return when** a fleet
  project grows an operator-supplied-code surface, or a second independent source
  shows this shape being closed.
- **The declared refusal names the class but not the election.** A caller cannot
  distinguish "the vision step ran and failed" from "no provider was configured,
  so it was skipped cleanly" (`solve-ladder.ts:109`). The new subject's standard
  asks for the elected set on the value; the tree falls short of its own idea.
  **Return when** a second source carries an election-bearing outcome value, at
  which point this becomes a technique amendment rather than a shortfall note.

## Contradiction worth keeping

The corpus said the acquire stage's failures are *loud* and that a refused state
is terminal. The tree says both are wrong for one half of a boundary the corpus
had not drawn. Neither party is mistaken — `web-scraping` is right about the
scheduled harvest, and the source is right about the single-shot retrieval — so
the landing was the **discriminator**, stated in both subjects, rather than a
correction on either side. A run that had "resolved" this by preferring one
would have damaged a well-forged subject to make room for a new one.
