## Catches

Four picks resolved to already-covered, recorded so nobody re-proposes them:

1. **Statement-level restartability under a lost response.** `idempotent-steps` already
   owns the ambiguous *probe* and resolves it toward running the step. The source's
   case is finer-grained (the ambiguous *statement*), but the technique's rule covers
   the decision; only the granularity differs, and it did not earn a section.
2. **The admin extension surface as a block protocol.** `schema-driven-ui` owns the
   machinery entirely. The forge worker was asked whether it earned a technique and
   correctly answered no — the addition is the *force* (a trust boundary rather than
   flexibility) and it is one paragraph in the new subject's golden path.
3. **Install-time consent as a gate.** `hitl-approval/consent-gates` owns it; what was
   new was the truncation, which landed as row 8.
4. **Immutable published migrations.** `migrations` opens with "migrations are one-way
   doors" and says it better than the source does.

## Leads

- **A content-binding law is missing from this bundle.** `recruiting` carries
  `a-verdict-is-bound-to-what-it-judged` and `game-production` carries
  `a-verdict-is-bound-to-its-content`; `software-engineering` has
  `verdict-survives-boundary`, which is a different claim. This source is a third,
  independent instance from a fourth domain (a moderation label bound to an exact
  content hash; install consent pinned to the displayed revision). **Return condition:**
  a fourth sighting in this bundle, or a run that finds a `software-engineering`
  technique already assuming it — then propose the law rather than the technique.
- **The tree's own instruction file cites the worst example of a rule it states.** Its
  canonical pointer for looping migrations is a migration that does not do the thing,
  while two better in-tree examples go uncited — one with an explicit lost-response
  comment. **Return condition:** a second source where the instruction file's cited
  example contradicts the rule; two sightings makes it a technique in
  `agent-instruction-files` about citing examples that a checker could verify.
- **A trust signal with a complete write path and no read path.** A publisher
  verification record type, fully specified, ingested, indexed and re-served, consumed
  by nothing that changes a decision — while the docs promise the browse surface shows
  it. **Return condition:** the aggregator's view gains a verification field, or a
  second source ships the same shape; the general form is "a delegated trust root is
  not delegated until a consumer branches on it."

## Applied (Phase 7.5)

Three rows. Ship scope authorized by the operator: `ai-registry` and `kp`.

| technique | project | mode | verdict |
| --- | --- | --- | --- |
| `cache-value-not-handle` | ai-registry | code | **better** |
| `post-merge-regeneration` | ai-registry | simulation | **better** |
| `truncated-verdict-space` | kp | simulation | **not-better** |

**The code row found a real defect.** The run board's lock reclaim decided breakability
from the lock's own age alone, never consulting the holder's run record — which the same
board maintains, with a heartbeat. It was wrong in both directions: a live, heartbeating
session holding the index lock through a long regeneration had its lock broken by a
sibling (both then regenerate over each other's half-written files), and a session that
died one second after acquiring held the lock for the remaining 899. Reclaim now reads
the owner, with the wedged-owner backstop preserved. Five fixtures, both arms, one
predicate: **arm A 3/5, arm B 5/5, three controls identical.**

**The `not-better` row is the most valuable one.** kp truncates its automated verdict
space on the *adverse* side — a fairness-cleared rejection is downgraded to a hold and
routed to a human, and the admitting verdict is auto-applied. The technique as landed
described the mirror image. Applying it as written to kp would move the human gate onto
the reversible direction and leave the irreversible one automated — the exact inversion
the technique exists to prevent. The condition landed as an amendment: **polarity is not
part of the mechanism; truncate the verdict the system cannot take back**, which is
admission where a durable position is created by letting something in, and refusal where
it is created by shutting something out. kp also contributed a second mechanism the
technique lacked: re-derive the truncation at the *apply* boundary, independently of the
decider, and count the downgrades.

**Unapplied, with return conditions.** The two forged subjects' 13 techniques have no
fleet seam: no managed project hosts third-party code or distributes artifacts to
strangers. Return condition: when a fleet project grows an extension surface or ships to
an audience it does not control. `expand-deploy-contract`, `dynamic-table-set-migrations`
and `operator-defined-tables` are unapplied — no fleet project runs a rolling deploy over
an operator-defined schema. `measure-apply-split` and `counted-set-snapshot` are
unapplied: the fleet is single-owner with no external contributors, so the force is
absent. `localized-record-identity` is **unapplied against kp** with a real return
condition — kp is multi-locale but its *content* is single-language; it stores a
recipient's locale on their record. Its `comms-translator` independently draws the same
boundary the technique's decision rule names ("the request's locale is right for UI,
wrong for a letter"), which is convergence rather than adoption, and is cited into the
technique.

## Directions (Phase 7.6) — 0 proposed, and why

`build-fleet-map.mjs` was stale and was rebuilt (11 projects, 369 subjects). The
judgment the pass demands is whether a project's `scope.does` admits the decision's
**forces**, not its feature — and for the two forged subjects the forces are absent
fleet-wide: every managed project is single-owner and single-tenant, none hosts
third-party code, none distributes to strangers.

**One real candidate was found and deliberately not written**: `politicas` is a
`candidate` absence for `concurrency-guards` and carries the exact construction
`cache-value-not-handle` names as unsafe — `lib/db/store.ts:265` memoises a
`Promise<Store|null>` at module scope, and `lib/db/pglite/internals.ts:31` memoises a
`Promise<Pglite>` on `globalThis` — on a platform that tears down request contexts. That
is a latent wedge, not a knowledge gap. It was not written because the operator
authorized `ai-registry` and `kp` only, and a direction proposal is a write into a
project tree. **Return condition:** the next run with `politicas` in scope should open
with it.

Technique-grain directions blocked by grain: 3 (`counted-set-snapshot`,
`context-starved-executor`, `measure-apply-split` all land in subjects every project is
*present* for, so the subject-grain fleet map cannot express them). That is the third
consecutive round to hit this, per round 1's note.

No peer study: no fleet project is the same class of system as a CMS or an artifact
registry. Closest adjacencies (`kp` self-hostable multi-locale, `gravity`/`politicas`
content modelling) are adjacencies, not peers, and a study written over one would have
been a feature list.
