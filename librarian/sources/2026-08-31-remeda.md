# Remeda — the library was not the source

## Class reading, and how it was wrong in a useful direction

Routed at Phase 2 as **vendor repository**, whose row predicts yield in "its docs' rules page and
its client's types." Phase 2b's clone said something else. The README is **240 words**; the tree
carries **47,025 words of markdown**, and the densest part is not documentation of the library at
all — it is `AGENTS.md`, an `.agents/skills/` tree with five reference documents, three
path-scoped rule files, and a `.claude/hooks/` directory containing a working turn-end gate whose

So the operative class for the run was **first-party practitioner account**, and the subject it
gives an account of is not utility-library design. It is *what happens when a single-maintainer
project instruments itself for agent contributors.* That reading is worth recording for the
class: a repository's declared purpose does not decide which of its surfaces is first-party
evidence, and the `.agents/`-shaped tree is now a surface worth checking for on every repository
source, because it is where a project writes down what its agents got wrong.

Expected yield was stated before the triage table as "the rules page and the types." Actual yield
was four landings, none of which touches the library.

## Accepted (4)

### 1. `mutating-local-gates` — new technique, machine-paced-delivery

**Anchor:** `.claude/hooks/lib/stop-handlers.ts`, `mutatingCommandStopHandler`.

The corpus holds a flat prohibition — `hook-hygiene`: "Hooks observe; they never mutate" — with
exactly one carve-out, the editor-on-save loop "where the author watches it happen." This source
runs a **mutating gate at the agent's turn boundary**, a third position the rule was never
written against: no commit exists, so there is no staging split to corrupt, and no human is
watching either.

Checking the prohibition's three contracts one at a time rather than inheriting the verdict:
the review contract survives and is binding, the staging contract does not apply, the shared-tree
contract survives and is satisfied by scope rather than prohibition. **Two of three transfer**,
which is what makes this a technique rather than an exception.

The finding the enumeration could not contain: permitting mutation creates a contract that
verdict-only gates never had — **termination**. The source's own comment names the mechanism
("this can happen, for example, when lint has two contradicting rules") and its remedy: block on
the first firing, degrade to advisory on re-entry. Also landed: the snapshot-before-fixing rule
(a mutating check is the one instrument that destroys its own input, so the diff is captured, not
reconstructed) and the requirement that the block reason carry the **patch** rather than a count
of changed files.

**Corrected during Phase 7.5, by the seam — twice.** Draft 1 said "only mutation creates" the
termination contract. The apply step found a managed project's turn-end gate that honors
`stop_hook_active`, so draft 2 said *blocking* creates it. The same file refuted that in its own
header — *"Nothing here ever blocks"* — and the gate still guards re-entry, because its advisory
exit feeds the model, the model acts, and acting ends another turn. **The contract is created by
the gate's output re-entering the agent's loop**, and the landed technique carries a three-tier
ladder (advisory / blocking / mutating) naming the advisory tier as the one most likely to ship
unguarded, because it looks harmless. Both rewrites happened before the commit. Worth noting as a
method observation: the apply step refuted the technique it was testing, twice, which is the first
time in this ledger it has run in that direction.

### 2. `stake-before-merit` — new technique, machine-paced-delivery

**Anchor:** `AGENTS.md` — "Adding PR load to a single-maintainer project without a real stake is
the highest-cost form of unhelpful help"; `CONTRIBUTING.md` — "Please no auto-piloted PRs!"

`human-gate-capacity` already models the merge gate as a fixed-rate server and names demand
reduction as the only lever. Its four levers — send fewer changes, cheaper verdicts, narrower
classes, stated service level — **all assume the party feeling the overload generates the
arrival**, stated outright as "a decision the team is already making and usually not looking at."
Every one is unavailable at an outward-facing gate. That is a missing stage, not a missing
opinion.

Two things landed that the source located and did not itself articulate:

- **The filter that disappeared without being removed.** Contribution surfaces were rationed by
  an accident: producing a plausible change was expensive, so submission carried evidence of
  investment. Nobody wrote that rule down, so nothing announced its removal when machine
  authorship decoupled production cost from evaluation cost. Exactly the shape
  `absent-guard-is-loud` forbids.
- **Triage is the resource being rationed.** A merit filter cannot work here for a structural
  reason rather than a matter of degree: deciding whether a change is worth reviewing means
  reviewing it. Any predicate over the diff has already spent the budget — and spends it on the
  population it wanted to reject, because the cheap tells that once separated serious submissions
  from casual ones are precisely the tells machine assistance now supplies for free.

The admission predicate must therefore be readable **before** the diff. Also landed: the policy
restricts *unattended* submission and not tool assistance, and saying so explicitly is
load-bearing, because a policy read as anti-tooling is routed around by the contributors worth
keeping.

### 3. Reaper forms ranked — amendment, `suppression-hygiene` (dead-code)

**Anchor:** `AGENTS.md` — "**Never use date-based expiration** (those explode unexpectedly for
whoever runs lint that day)."

`suppression-hygiene` offers three reaper forms as interchangeable: "an expiry date, a re-review
cadence, or the checkable condition under which it lapses." **This is one of our own
enumerations presented as flat when it is ranked**, and the source ranks it from operational
experience with the opposite of our implied default.

A date fires on a schedule nobody chose, at whoever runs the instrument that day — no context,
mid-task on something unrelated, holding a red build they did not cause. It works exactly as
designed and still arrives at the wrong person, so the repair it forces is the cheapest one:
push the date out. **A reaper whose most probable outcome is its own postponement has bought a
recurring interruption and no reaping.** The amendment ranks the forms, names the version
threshold as the practical realization of the checkable condition (it fires when someone takes
the action that makes the work relevant, so the person present has the context and the work is
already open), and confines dates to the case where an external deadline genuinely *is* the
condition.

Second half, and the sharper one: **the suppression's form can carry its own reaper.** A
directive that asserts a finding is expected stops being satisfied when the finding stops
occurring; an override that forces the value through succeeds identically forever. Where both
exist the first is mandatory — the one case where `creation-names-reaper` is satisfied with no
reaper clause at all, and strictly better than any clause because it fires on the real condition
rather than a proxy. With the corollary for suspected tool defects: suppress and flag, never
reshape the code, because a reshaped workaround is indistinguishable from intended design and
outlives the defect silently.

### 4. The vantage axis — amendment, `build-measurement` (build-economics)

**Anchor:** `.agents/skills/remeda-utility/reference/implementation.md` § Type-level performance —
"import from the *built* `dist/index.d.ts` (not source — source-mode compiles all of remeda and
drowns the signal in ~115K symbols of baseline overhead)."

`build-measurement` is thorough on scenario labelling — which build, which variant, which
machine, when — and every axis describes a build happening *in this repository*. It has no axis
for **whose**. Some costs a repository creates are paid entirely elsewhere: a published
artifact imposes compile cost on everyone consuming it, that cost accretes for the same reasons
local build cost does, and no instrument in the subject is standing where it is paid. It also
passes every other check — a change that doubles a consumer's compile time is correct, tested and
green.

The amendment adds the vantage axis and the harness that follows from it (a minimal project
consuming the published entry point and its generated type surface, never the source tree), with
the measured reason the intuitive approach fails: **~115,000 symbols of baseline before the
measured change is even reached**, against an effect worth low single-digit percent. Folded in
from a separate candidate: the artifact-freshness precondition, scoped to inputs that actually
reach the artifact (the source excludes test files from its staleness computation for exactly
this reason — a freshness check that cries wolf gets disabled). Plus the warm-up-and-discard
protocol, and a `## Gate on the number that moves first` section: the count of intermediate
compiler work items moves before wall time or memory, and a metric that only shifts once the cost
is perceptible is a detector, not a gate.

## Already covered (2)

- **A local gate running the same checks CI runs, before the commit** — `pre-authorship-verification`
  owns this completely, including the never-invent-a-command rule the source's hook obeys by
  construction (it shells out to the repository's own declared scripts). The source's variant
  applies CI-grade coverage thresholds locally *for agents specifically*; that is an instance of
  the technique, not an addition to it.
- **The silent skip** — `gate-liveness` ("A gate that skips silently when its scanner is not
  installed is reporting its own absence in the voice of success") plus
  `pre-authorship-verification`'s "*not configured* rendered distinctly from *passed*". The
  source's refinement is a fourth state — *ran, correctly had nothing to do, and the consumer's
  instructions promised it would run* — which is a real edge but sits inside `gate-liveness`, a
  file tigerbeetle-2026 held. Recorded as one paragraph inside `mutating-local-gates` attributing
  the general rule to `gate-liveness` rather than re-deriving it.

## Leads (1)

- **Canary cadence sets the bisection window.** `canaries.yml` runs a daily scheduled matrix
  against four release channels of the type-checker, with the comment "Run daily to make it the
  easiest to track down what changed." The generalizable claim — a canary against an upstream you
  do not control is scheduled by cadence rather than by your own commits, and the cadence *is* the
  size of the change window you will have to search when it goes red — is real and has no home:
  it is neither `release-pipeline` (this is not our release) nor `versioning-snapshots`.
  **Return condition:** when a second independent source states the cadence/bisection tradeoff,
  or when a managed project acquires an upstream canary.

## Applied

Four findings, four rows in `librarian/applied.md`. See that ledger; summary here:

- `mutating-local-gates` → **pumper**, `experiment`, **better**. The project's `Stop` hook is
  read-only and blocking, already honors `stop_hook_active`, and its own header records the
  measurement that makes the technique's liveness paragraph concrete: the hook **detected nothing
  for its entire life** — replayed over all 31 recorded transcripts, 1,136 Edit/Write calls, zero
  detections — because its turn-boundary predicate broke on line one. A blocking gate that finds
  nothing is indistinguishable from a working one. This is also the seam that corrected the
  technique.
- `suppression-hygiene` (reaper forms) → **personas**, `code`, **better, and SHIPPED as a slice
  (`ba7f613e`, master, not pushed)** after the operator confirmed the lane and set the size
  constraint. The self-retiring form is used 6 times against 829 permanent-form suppressions;
  a paired check on one crate went **0 warnings → 63**, so 63 of 71 suppress nothing. Slice: one
  file, 7 sites, +2/-7, verified by removal (0 warnings with the attributes gone, across lib and
  all test targets). **The slice corrected the finding**: the crate is a *library*, so the lint
  cannot fire on a reachable `pub` item, and 42 of the 71 sites are on `pub` items — inert from
  the moment they were typed rather than stale-since-written. Two causes, one repair, different
  preventability.
- `stake-before-merit` → **unapplied**. Single-owner fleet, no outward-facing contribution
  surface in any managed project. Return condition: when a managed project accepts external
  contributions.
- `build-measurement` (vantage axis) → **simulation**. No managed project publishes a
  library-shaped artifact whose consumer compile cost is measurable from a separate harness.
