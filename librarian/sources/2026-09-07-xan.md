# xan — the CSV magician

A record-oriented data CLI from a social-science research lab: 56,751 lines of
Rust, 67 commands, an embedded expression language, and roughly 85,000 words of
in-tree design documents sitting behind a 4,320-word landing page. Mined from a
clone at `0149e93c`, never from the ingest.

**Class and expected yield, stated before the table.** A repository, so the
landing page is the advertisement and the tree is the source. The expected yield
for a repository this size was stated at Phase 2 as *design decisions, not
claims* — and that is what it produced: the Phase 2d routing count came out at
six load-bearing decisions with no home in the corpus, which is a forge job by
the method's mechanical trigger rather than by anyone's judgment.

**Board.** 0 live siblings at claim time. Claimed
`software-engineering/backend-platform/data-pipeline-semantics` at Phase 5.

**A run-blocking condition that was not this run's.** At Phase 4 the checkout was
mid-merge (`origin/main` → local `main`, 724 staged files, 14 unmerged paths,
conflict markers inside four bundle indexes and the catalog), which made
`research-map` fail its own assertion and made a pathspec commit mechanically
impossible (`fatal: cannot do a partial commit during a merge`). The run routed
around it read-only with a detached worktree at `HEAD` rather than resolving
another session's merge. The merge was resolved and committed externally
(`2b10d868`, `9f3c335f`, `93b9df33` — "Fox 60 + Wolf 64") while the design read
was in progress; **every absence claim below was then re-verified against the
merged corpus**, which had grown from 220 to 228 subjects and 1,644 to 1,692
techniques in `software-engineering`. None of the incoming work touched this
ground.

## Design record

Seven entries across three systems, with forces, buys, rejects and anchors. The
full record is reproduced in the XL spec's evidence and is summarised here.

**System A — the parallel read plane over an ambiguously framed file.** Six
decisions, all `corpus: NONE`, all sharing one `HOME IF NEW`:

| | Decision | Corpus |
|---|---|---|
| A1 | Resync into a self-ambiguous stream by parsing both live hypotheses and rejecting the structurally inconsistent one; tie-break on a field-size profile from a head sample | NONE |
| A2 | Bound the speculative read in bytes derived from the sample, because the wrong hypothesis reads to EOF | NONE |
| A3 | Refuse when the evidence does not separate the hypotheses | **OWNED** — `refuse-rather-than-emit-a-sentinel` |
| A4 | Segment first, then parallelize — row work is IO-bound, so a broadcast topology pays coordination for nothing | NONE |
| A5 | A sorted artifact plus approximate random access is already a read-only index | NONE |
| A6 | Verify a partitioner with no oracle by conservation across a swept parameter | NONE |
| A7 | Symmetric (doubled) escaping makes the stream reversible, which buys constant-time tail reads and resume-from-your-own-output | NONE |

**System C — the command-composition plane.** C1 self-invocation of the tool's
own binary as its composition primitive (`current_exe`, four call sites);
C2 a generator that can be told to stop owning a file; C3 the `-S/--sorted`
precondition flag as the streaming opt-in, spelled the same way across the
surface. One amendment, two partial.

**System D — the expression language.** D1 a temporal type lattice with implicit
construction but explicit refusal on mixing; D2 lint as design enforcement
(`clippy.toml` disallows the standard hash containers tree-wide). Not swept in
depth.

**Routing count, both clauses (v2.2).** Per system: A = 6 NONE, C = 1 NONE,
D = 0. Across systems: the same six share one `HOME IF NEW`. **Both clauses fire
on System A alone**; C and D stay in intake. Handoff taken — the operator chose
the forge dispatch at the Phase 5 gate.

## Untriaged, with anchors so nobody re-derives them

- **Self-invocation as the composition primitive.** `src/cmd/parallel.rs:974,980,996`,
  `src/cmd/run.rs:109`, `src/processing.rs:33`. 67 commands each written as a
  streaming main; composing them in-process would need a second execution model,
  so the tool spawns itself and inherits the shell's semantics exactly. Home
  contested.
- **The precondition flag as the streaming opt-in.** `CHANGELOG.md` 0.58.0 on
  `window -g`, plus `sample -g -S` and `top -g -S` in 0.60.0. Default buffers and
  is always correct; the flag is the caller asserting an ordering the tool cannot
  verify without doing the work it is avoiding; the same spelling everywhere.
- **Temporal type lattice with implicit construction and explicit refusal.**
  `docs/design/dates_overhaul.md` § "Design decisions" — one parse function
  returns a zoned or a civil value depending on the input, and expressions error
  when the two are mixed, "so people don't footgun themselves". An ADR with its
  open questions still open, which is the rarer and more useful shape.

## Caught

- **D2, lint as design enforcement.** `quality-gates/enforcement-binding` owns

## Lead

**Ordering restored by bounded buffering when per-segment output cardinality is
known.** Segmenting a file for parallel readers costs output order; the source
buys it back with `--buffer-size -1`, holding a whole segment's output before
flushing, and it is only affordable because the pipeline guarantees one row per
group per segment. Return condition: **when a second independent source states
the rule**, or when a fleet project ships a parallel reader whose output order
matters — the general form (order costs memory proportional to per-segment
cardinality, so bound the cardinality first) needs corroboration this run could
not spend.

## Apply

One row, `simulation`, **`not-better`** — and it is the most useful thing the run
produced after the subject. The seam search ran the applications directory first
(round-29 focus 2) and then across the fleet; the strongest seam for the
amendment was the project carrying 68 generated-marker files and two committed
exception lists. All three cases from that tree favoured the existing design:
the excepted artifacts are contract artifacts the amendment itself forbids
adopting; four of the exceptions are *absences*, and an ownership bit cannot live
in a file that does not exist; and the lists are **two-sided** — they fail when a
listed name stops being an exception — so the drift the amendment predicted
cannot accumulate.

Both constraints went back into the technique: the absent-artifact case, which it
did not have, and the correction that drift is a property of one-sided lists
rather than of lists. The amendment is narrower and true, which is the shape a
`not-better` row is supposed to produce.

## Self-contradiction, and which reader it was resolved for

Round-29 focus 3. The source contradicts itself on whether the seeker is
trustworthy: the blog post's body presents the technique as "reasonably robust"
and "already in production", while its own § Caveat emptor enumerates three file
shapes that defeat it outright. Resolved **for the reader deciding whether to
adopt the mechanism**, not for the reader implementing it: the defeaters are
folded into the technique's own body rather than left as a caveat, because a
reader who learns the mechanism and meets the caveat later has already built it.
The trade recorded for the other reader: an implementer wants the optimistic
framing first, and the source's ordering is right for them.
