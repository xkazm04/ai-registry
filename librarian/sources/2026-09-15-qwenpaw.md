reasoning loop with composable stop gates, a context manager with a durable log,
a governance layer, and adapters that wrap other coding agents. It is not a

### System A - loop control plane (src/qwenpaw/loop, modes, runtime)

A1. Only a positive CONTINUE keeps the loop going; no gates, all-BYPASS, or a raising gate all mean stop; a TERMINATE anywhere beats an earlier CONTINUE.
- forces: every mode, plugin and custom loop contributes gates to one stop hook; if silence or a crash held a session open, any buggy plugin could run it forever.
- where: loop/gates/handler.py:102-131 [director]; runner.py:106-128; base.py:15-26. Stage: end of each iteration (agents/react_agent.py:1038).
- corpus: session-continuation (ordered-yield-composition; advisory-guard-fail-mode). CATCH.

A2. One mode scope decides at a time: the first active non-default scope replaces the default scope; a second explicit mode is refused.
- where: runner.py:47-80; modes/base.py:97-109; tests/unit/loop/test_mode_lifecycle.py:40-67.
- corpus: session-continuation/single-loop-authority. CATCH, with a boundary: unscoped handlers still run beside the active mode (runner.py:67), and the plugin API cannot set scope (plugins/api.py:1096-1122).

A3. A stop decided on a tool-call iteration is deferred until tool results are in, then applied before the next reasoning call; ordinary continue prompts are dropped; only inject_on_tool_call warnings are delivered; time limits checked at boundaries only.
- forces: gates run every iteration; stopping mid-batch cuts running tools and orphans calls.
- where: loop/gates/runner.py:156-226 [director]; react_agent.py:1040-1048; doom_loop.py:163-167; tests/unit/loop/test_custom_loop_modes.py:551-568.
- corpus: NONE. Nearest session-continuation enforces only at the yield moment. HOME: session-continuation (technique boundary-applied-stop).

A4. Gate objects are shared; state is per session (`_sessions` keyed by session contextvar) with three lifetimes: per turn, per session, and a sub-turn reset of peers on a rubric continuation - except token usage, which never resets.
- forces: one handler serves every concurrent session; verification must not inherit exhausted limits; budgets must stay honest.
- where: loop/gates/loop_gate.py:49-80 [director]; handler.py:160-183 [director]; base.py:121-130; limits.py:65-66.
- corpus: NONE. Nearest stuck-loop-detection "two counters, asymmetric resets" (progress counters, not ownership/lifetime). HOME: session-continuation (technique gate-state-lifetimes).

A5. User-composed loops compile only from a closed catalog of seven built-in gates, strict params, exclusive groups, order -> priority index*10.
- where: loop/catalog.py:19-22,154-196,246-270; loop/compiler.py:11-41.
- corpus: NONE; home contested (quality-gates vs session-continuation). UNTRIAGED.

A6. Request handling in eight fixed runtime phases with before/after-ordered hooks, cycle -> HookCycleError; runtime hooks fail closed while stop gates fail open.
- where: runtime/hooks.py:46-51,168-253; runtime/runtime.py:66-221.
- corpus: agent-runtime-assembly/semantic-hook-placement. CATCH.

### System B - context economy and memory (agents/context, tool_calls, memory)

B1. The durable log is the source of truth; every live turn written through before compaction may evict it; eviction leaves an index and a continuation summary; recall by seq address.
- where: config/config.py:1240-1247; agents/context/scroll/manager.py:478; scroll/eviction_index.py:1-31.
- corpus: prompt-assembly/tiered-history-projection. CATCH.

B2. Graduated pressure pipeline; the two active-turn folds touch only blocks acknowledged by a completed model call (snapshot and acknowledge are separate calls); unread/pending/newest-5 never shortened; still unfit -> typed ContextWindowUnfitError.
- forces: shortening unread evidence destroys what the current step consumes; a failed/interrupted request consumed nothing.
- where: scroll/manager.py:265-315, 399-429, 622-705 [director]; react_agent.py:933-953 [director].
- corpus: NONE (grep of the corpus for acknowledged/unread folding returned no llm-agent row). HOME: prompt-assembly (technique fold-only-acknowledged-evidence).

B3. The continuation summary is a checked state cache: Markdown in a fixed schema, parsed locally, deterministic gate (source pointers exist, no identifier absent from evidence, no secrets, no duplicates), one repair, provider failure keeps the previous valid summary.
- where: scroll/continuation_summary.py:1-22, 690-735 [director]; manager.py:1304-1447.
- corpus: partial - history-compaction names the risk (two disciplines), tiered-history-projection requires identifiers survive; no mechanical admission gate. HOME: prompt-assembly (technique summary-evidence-gate).

B4. Two deadlines per tool call: offload (leave the foreground) strictly before kill (stop running); offload refused without >=30s seedable kill budget; keep-foreground may clear offload only if kill exists (#6245 hang).
- where: tool_calls/_coordinator.py:135-175, 972-1024 [director].
- corpus: NONE; home contested (agent-runtime-assembly vs subprocess-lifecycle termination-and-reaping's own "two deadlines"). UNTRIAGED.

B5. Compression rewrites a copy of the outgoing request, never stored history; any failure falls back to the plain path (visual compression, thinking hide, scroll wiring).
- corpus: elision-to-a-refetch-pointer partial. CATCH-adjacent; untriaged.

B6. Auto-recall is live-only, stripped before write-through.

**Drafter overrides, all kept:**
- **The stop boundary is a question, not a timing split.** "Decided while tools run" versus "known before dispatch" does not separate cases, because gates are evaluated before dispatch on every tool-call iteration. The rule became one question: will any reasoning call read this batch?
- **What counts as a meter.** "Tokens and cost" became the un-spend test, which puts elapsed time among the meters.
- **The approval round-trip has two answer channels:** a server mode, or a delegation hook. The session binding must be enforced.
- **The preset line anchors were corrected** (`registry.py:65-110`, `:142-181`).

## The source contradicts itself, and those are the boundaries

- **Stop rule.** The loop docs say the first definitive gate wins. The handler lets a later TERMINATE beat an earlier CONTINUE (`handler.py:121-126`), while plugin registrations really are first-wins (`runner.py:119-135`).
- **Sandbox fallback.** The sandbox blog and in-code comments say an unusable sandbox escalates to ASK. The code returns ALLOW unsandboxed (`governance/resource_governor.py:253-265`), a test locks it in (`test_policy.py:921`), and `sandbox_enabled` defaults False.
- **ACP approvals.** The ACP docs say the runtime "does not decide on the user's behalf". Every built-in runner ships `trusted=True`, and a trusted client auto-approves everything that is not destructive or out-of-directory, with no approval record (`agents/acp/client.py:166-184`, `config.py:164-195`, `test_acp_client_trusted.py:32-56`).
- **Unfinished work.** The source's own last-round tools also run unread: `IterationGate` returns TERMINATE at the cap (`iteration.py:73-80`), and the stop is deferred (`runner.py:168-174`). Its channel layer commits turn usage only on success and discards it on error or cancellation (`app/channels/base.py:1003-1020`). Both are the boundary cases the landed techniques state; the source implements the good idea and misses its own edge.
