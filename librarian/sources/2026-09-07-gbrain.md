# gbrain — a memory system that measures itself well and cannot run its own supersedence

## Class and expected yield, said before the table

A repository-form first-party practitioner account, in the one domain where this
registry holds a **measured baseline** rather than only a corpus. Per the memory
lane, every memory claim was priced against the seven-arm ladder in
`personas/evals/memory-year/` before it was mapped against bundles. Expected yield
for the class: high on mechanism, low on currency — and that is what it produced.

Swept in the order the method prescribes, changelog first as the index: `CHANGELOG.md`
(337k words), `docs/` (394k, led by `architecture/KEY_FILES.md` at 114k), the two
incident write-ups, `docs/protocol/MEMORY_VERBS_v1.md`, the eval layer
(`evals/`, `docs/eval/`, `.gbrain-evals/`), the search and doctor sources, then the
README last. Four parallel sweep workers; the director held every write.

## What landed

**1. `second-pass-rescoring` — new technique in `retrieval`.** The subject's golden
path states its own query-time pipeline as *decomposition → per-lane execution →
per-lane floors → fusion → budget cut → the slice*. There is no stage between fusion
and the budget cut, and `rerank` appears nowhere in the subject's ten techniques or
its golden path — only in two applications. (Absence established uncapped and against
a known-positive control: `fusion` returns 117 files corpus-wide, `rerank` returns 10,
none of them a technique.) The whole of this source's v0.48.4.0 wave lives in that
gap. The technique's core rule, taken from the tree: a scorer structurally blind to a
class of evidence is admitted by `min(fused_rank, rescored_rank)` — **it may promote a
blind-class row and may never bury one**. Plus: the rescoring window is a shortlist,
not a truncation; the no-op is detected by reference identity rather than a flag; and
a trimmer placed after it must be exempted from the pinned rows *and* those rows
excluded from its own cliff computation.

**2. `coverage-instrumentation` — a fourth honest zero.** The technique enumerated
"three cases where the instrument must resist the flattering reading", all about the
denominator. This source supplies the fourth, about the numerator: a counter
incremented only by a status its call site cannot produce, and a health line whose
severity is a tautology over a count. Both verified by the director:
`src/core/facts/backstop.ts:637-646` discards the incoming fact on a dedup match, the
three `superseded += 1` sites follow inserts passing no supersede reference, and
`src/core/postgres-engine/facts.ts:65-69,115-117` returns that status only when one is
present; `src/commands/doctor.ts:3791` grades the hot tier with
`health.total_active >= 0 ? 'ok' : 'warn'` over a `COUNT`. The amendment also carries
the *detection* rule this source taught: trace the exported symbol, not the module —
`classifyAgainstCandidates` (`src/core/facts/classify.ts:69`) has five test callers and
zero production callers, while the one production import from that file takes
`cosineSimilarity`, the arithmetic helper beside it. Every "is it wired in" check
answers yes.

**3. `baseline-ladder` — the boundary where under-spend is not the signature.** The
file states under-spend as *the* cheapest check for a cap inside an arm. It detects a
cap that admits fewer things and is blind to one that admits the right things and
shortens them: the budget reads fully spent, the provenance names the right item, and
the consumer gets a full-looking context without the answer. Two independent trees
carry the shape — a per-item character ceiling inherited from an unrelated consumer,
five times smaller than the items it now cut, whose first judged run abstained on 11
of 25 questions whose source was retrieved at rank one; and this fleet's own
`compiled_truth` arm, which slices its top item to the remaining budget unlogged. The
signature there is abstention or a confident wrong answer, and the counter-instrument
is a per-item truncation count.

**4. `recall-injection` — where a scoped call still ships an unscoped tier.** The
technique's three tiers assume each tier's selection logic was *chosen*. The cheap arm
often inherits it: a bundle scoped to named subjects returns tightly-scoped cards
beside items selected by nothing but recency, because reusing an existing helper that
already had visibility and caching right was free where threading the scope through
was not (`src/core/context/turn-context.ts:413-435` forwards no entity filter). Two
consequences: the least-filtered content arrives in the most-trusted envelope, and the
recency window that makes it survivable is not governance — re-keying that arm from
"the last day" to "this session" silently removes the only bound it had.

## What the memory lane's ladder said first

The lane's four unchallengeable claims held, and two were sharpened.

- **"Published memory numbers are leads, not evidence"** — confirmed by the source
  about itself. The documented benchmark invocation was rejected by the project's own
  generated flag validator for roughly a month spanning two published releases
  (`CHANGELOG.md:258-260`, validator introduced at `:5687`), so the strict figures came
  from a shell script in a sibling repository, and the shipped CLI's own summary
  reported the *looser* metric. The parity row reproducing the two harnesses against
  each other — 439 vs 438 of 470, 469 of 470 rows agreeing per question — is the
  honest measure of harness identity, and publishing it is the right move.
- **Restraint is two numbers** — confirmed verbatim, including the anti-gaming
  argument ("'always inject' cannot win both"), in one eval lane; and *absent* one lane
  over, where only the correctly-abstained side is published.
- **The format assumption** — confirmed: the reader is told to answer concisely, the
  judge grades a subset as wrong, and the worst-scoring question type by 14 points is
  the one whose retrieval was perfect.
- **Scope-crossing supersedence** — the lane's first open question gets its sharpest
  answer yet, and it is not "nobody handles it". This system's supersedence is
  same-entity + same-kind by rule, frozen into a v1 wire contract whose versioning
  policy says a v2 is "expected never", with a stated engineering reason: the
  entity-scoped candidate query is the only one that indexes, and a cross-entity search
  would be a full-source vector scan on the per-turn hot path. **The moves it cannot
  see are exactly the moves that change the partition.** Recorded as a lead, not
  landed — see below.

## Applied (Phase 7.5)

One row, mode `code`, verdict `better`, shipped.

The seam was chosen to falsify, per the standing focus: the `baseline-ladder`
amendment claims under-spend is *not* the signature, so the seam picked was the one
that would expose a truncation the under-spend check misses. **It refuted the
hypothesis and produced a better finding.** The truncation branch exists but cannot
fire at this scenario's scale (six pages, mean 988 characters, against a 6,000-token
budget). What the same seam showed instead was the plain form of the corpus rule,
unnoticed across four published arms: realized context spend of **15%, 27%, 32% and
54%** of one shared budget — a 3.5x spread — with both numbers already printed in
every report and never subtracted. The three arms below half are exactly the three
lowest-accuracy arms; the one above is the highest. The ladder comparison the
findings table publishes is confounded to a degree nothing in the run output stated.

Shipped: the report now prints utilisation and calls out an arm leaving most of its
budget on the table. Paired proof over the four completed runs, re-rendered from their
own headers and answers with no model calls: **0 of 4 flagged before, 3 of 4 after.**

## Untriaged — reached the table, nobody verified them

Recorded with anchors so a later run does not re-derive them. **None of these is a
decline**; each lost on score or on run budget, not on judgment.

1. **A gate reading "no evidence" must first confirm the evidence channel was open.**
   `metadata-boost-gate.ts:31-38`: the lexical-vote gate exempts image queries because
   the lexical arms never run for them, so a structural zero would read as a
   measurement. *Promoting question:* does `relevance-floors` or `hybrid-lane-fusion`
   already distinguish "the lane returned nothing" from "the lane did not run"?
2. **A corroborating suite whose corpus cannot express the signal returns blindness,
   not confirmation.** `docs/eval-bench.md:436-441`. Nearest prior art is
   `eval-harness/discriminating-task-selection`, whose rule is about a suite ceasing to
   separate *candidates*. *Promoting question:* does that technique cover a null read as
   safety for one particular change?
3. **A fallback correct for a runtime failure is wrong for a configuration failure.**
   `src/core/verbs.ts:299-305` refuses when no model is configured, *before* the
   extractive-fallback branch at `:329-341`, even though a non-empty gather would have
   produced a good degraded answer — because that answer would mask the misconfiguration
   forever. This **inverts** the absent branch of
   `optional-dependency-degradation/absent-degrades-malformed-fails-fast` ("absent →
   the declared fallback, and the process continues"). Director-verified; scored
   accept; **cut for run budget, not for score** — the strongest untriaged row here and
   the first one a follow-up should take. Note a live sibling (`unstorage`) held that
   subject during this run.
4. **A blind scorer's config parser answers "unset" on an out-of-range value** rather
   than clamping, so a typo falls through the resolution chain instead of taking
   effect (`relational-rerank-pin.ts:73-99`).
5. **A knob whose default folds into a cache key has two defaults on purpose** — the
   module keeps the pre-wave value so a legacy config literal preserves its hash
   identity, while every shipped bundle sets the new one (`metadata-boost-gate.ts:66-67`).
6. **Weight penalty attached to the act of correcting.** `src/core/takes-write.ts:666`
   applies `target.weight - 0.1` to the **new** row, so ten unattended corrections drive
   a claim to zero and a well-maintained record becomes indistinguishable from an
   untrusted one.
7. **A change feed's cursor needs a tiebreaker in the key.** `MEMORY_VERBS_v1.md`:
   a keyset cursor of `(updated_at, slug)`, because bulk writes stamp identical
   timestamps and a cluster larger than the fetch limit livelocks on timestamp alone.
8. **Observe-only enforced by the return type, with fail-closed loading and fail-open
   classification.** `docs/guardrails.md:15-21, 95-98` — `runGuardrails()` returns
   `void` so no caller can branch on a verdict; a configured-but-broken module exits 1
   while a registered provider that throws never breaks an ingest.

## Leads

- **Scope-crossing supersedence, now with a cost model.** Two independently built
  systems key supersedence on the partition the classifier assigns — this source at
  same-entity + same-kind (`MEMORY_VERBS_v1.md:169-173`, enforced independently at
  `write-single.ts:136`, `backstop.ts:624-629`, `consolidate.ts:69`), and this fleet's
  own harness at `write_verdict.py:232-244`, whose neighbour pool is hard-filtered to
  one scope with an argued reason. Neither can see a move that changes the partition.
  The lane's rule says a mechanism becomes an **arm** before it becomes a technique.
  *Return condition:* when a cross-scope candidate pass — same key, different scope,
  which is the signature of a move — is built as an arm on the memory-year harness and
  scored against the changed-value and adaptation probe classes. Landing it as a
  technique before that would be exactly the "published number as evidence" error this
  lane forbids.
- **Per-arm binding-constraint reporting.** The apply row shipped a utilisation
  callout that still asks a human to name what bound the pack. Each backend knows
  whether it stopped on budget, on item count, or on store exhaustion, and does not
  report it. *Return condition:* when a ladder run compares arms whose binding
  constraints differ, which is every run to date.
