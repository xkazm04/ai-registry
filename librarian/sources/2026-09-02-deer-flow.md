README is its advertisement. Expected yield stated before triage: 2-4

## Accepted (4)

1. **completion-claim-verification** - NEW technique, fleet-orchestration.
   Anchor: subagents module guide, "Acceptance checklist" and "Report
   contract"; CHANGELOG #4659, #5076/#5090/#5109. Strip test: survives
   entirely. Prior art: result-harvest ("report only what was declared") and
   worker-trajectory-anatomy ("verify against the artifact") name the target
   and leave the mechanism open; quality-gates/self-reported-gate-inputs is
   the general form. `research-map` returned "none" for *subagent
   delegation* - a total empty on a concept term that was still wrong,
   because the corpus's house vocabulary is session/member/worker. Landed
   with the three layers (runtime receipts the report must cite; decidable
   leaves checked parent-side with UNVERIFIED never spelled as pass;
   evidence provenance - a test run in the worker's persistent shell proves
   nothing, unknown session semantics fails closed) and the boundaries the
   source states for itself. Applied: personas, simulation, **better**.
2. **write-freshness-gate** - NEW technique, mcp-tools. Anchor: the
   read-before-write design spec and CHANGELOG #3912. Prior art: the concept
   grep found nothing (no subject owns an agent's edit tools); the general
   optimistic-concurrency form lives in concurrency-guards/attempt-attribution
   and client-state/optimistic-write-path; the agent-specific half - the proof
   bound to context survival, writes never refreshing it, check-and-write as
   one critical section - had no home. Placed beside egress-argument-gating as
   the second host-side gate over tool calls; the subject note records that
   concurrency-guards holds the general form. **Unapplied**: no managed
   project exposes its own write tool to a model (pof's tool server has
   feature-matrix and harness tools only; the fleet's edits go through the
   coding agent's own tools). Return: when a managed project grows a write
   tool over shared artifacts.
3. **lease-renewal amendment: "Absent is not lost, and a teardown is a held
   state"** - job-coordination. Anchor: sandbox module guide, the ownership
   store section (`take` vs `claim`, `own:` vs `del:`, `LAPSED` vs `LOST`,
   the held teardown marker, adoption grace after a store flush). Prior art:
   lease-renewal's two-way channel says zero rows means lost; the source paid
   twice for that sentence being one fact short. Applied: pumper, simulation,
   **not-better** - the tree's lease is a column on the job row with
   attempt-fenced writes, so absent and lost are one fact; the condition is
   the amendment's closing paragraph. Separate structural fact against the
   base technique recorded in the project's own ledger (the worker discards
   its heartbeat's result).
4. **decay-and-forgetting amendment: "A review window is not an expiry"** -
   agent-memory. Anchor: memory module guide, staleness and consolidation
   passes; CHANGELOG #3996, #4143, #4225. **A contradicted pick, and the
   right one to keep**: the technique says a claim that states no boundary
   gets none invented; the source assigns every fact an expected-valid
   window. Both are right about different fields - an expiry is a property of
   the claim, a review deadline is a property of the store's confidence, and
   its consequence is a question rather than a removal. The consolidation
   inheritance rule (earliest source deadline, newest source clock) is the
   half the corpus's consolidation technique lacked. Applied: personas
   (persona memory store, the tree's second belief store), simulation,
   **better** - the reflection pass's `synthesize` restarts the clock at merge
   and preserves no source clock, which is the structural argument.

## Leads (3, with return conditions)

- **Additive stop-reason over a status enum.** A cap that ends a run early is
  surfaced as `completed` plus an optional `stop_reason`, because a new
  status value breaks every v1 consumer and an optional field is ignored by
  old ones. This sits against fleet-orchestration's closed status
  vocabulary and result-harvest's "timed out / cut off" account, and the
  reconciliation is unwritten: terminal state and stop cause may be two
  axes. Return: a second source that splits them, or a fleet project whose
  status enum grows a cause.
- **A directory containing the skill manifest is the package boundary;
  nested manifests are data, not skills** (#4098). Relevant to the registry's
  own skill layout and the harness-resolution memory rather than to a bundle.
  Return: the first nested manifest in a managed project's skills tree.
- **The blocking-IO guard as an instrument pattern**: a static scan routes
  candidates (guard / fix-and-anchor / no-action), a runtime anchor proves the
  offload with teeth, and "a real block that stays green" is the route to a
  new detector rule. Practices-lane candidate. Return: a fleet project with
  an async event loop and sync IO on it (none today; the Rust trees offload
  by construction).

## What the tree does that we do worse (the excellence sweep)

Two things worth naming beyond the landings. The per-package module guides are
maintained as **the source of truth for agent guidance** (`AGENTS.md` imported
by the assistant's instruction file, #3770), and they are dense in exactly the
way this method wants: paid-for failure modes, deliberate boundaries pinned by
named tests, and the reason a placement is what it is. The registry's own
skill files are comparable; the fleet projects' overlays mostly are not. And
the tree ships a **blocking-IO guard** whose skill routes every candidate
through a deterministic scan and refuses to accept an anchor that has not
been seen red - the negative-control discipline as a mandatory step with a
"rule" exit, which is one step further than the corpus's technique takes it.
