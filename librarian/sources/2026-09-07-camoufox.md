# camoufox - what a patched-upstream fork taught, and what it did not

**Class read before content: vendor repository.** Expected yield stated before the
triage table - its operating documents and its enforcing instrument, not its claims.
The prediction held: the landing page carried 4,227 words, the in-tree markdown carried
20,012, and every accepted or caught row came from `docs/` or from a checker. None came
from the README, which was read last.

Swept in yield-density order: five operating documents (9,073 words), the lint that
enforces the tree's sharpest invariant, the config-schema DSL, the client library's
source-precedence table, the tests. Board: 1 live sibling at claim, holding a
data-pipeline category this run never touched.

## The run's shape

**One landing, and it is the one the source did not state.** The strongest material in
this tree - a first-party post-mortem of four deadlocks, and the chokepoint plus lint
that ended them - is *already covered*, twice, and better. What landed instead came out
of the Phase 6 enumeration hunt against our own corpus, with this source as the occasion
rather than the authority.

## Accepted (1)

**`invariant-placement/repairing-check-erases-its-evidence`** - new technique.

The subject's golden path enumerates four altitudes at which a rule can be enforced, and
its table says a call-site violation "looks like a failure at run time". All four
altitudes *refuse*. A check that **repairs** - clamps, saturates, coerces - has no
violation signature at all, because it turns the invalid state into a valid one before
anything downstream can see it. An enumeration is a claim, and this is the member it did
not contain.

The landing's shape was decided by the score. Written as a **fifth altitude** it makes
the golden path's "four addresses" sentence false - a shared-spine rewrite, RISK +2,
total 1, below the +2 threshold. Written as a **posture of the fourth altitude**, every
standing sentence stays true and it scores 4/1/2. The arithmetic caught a restructuring
that nothing about the finding required.

Cross-bundle sighting recorded rather than linked: another bundle's cap technique carries
a law requiring every cap to publish the population that hit it. Same mechanism, opposite
reading of a non-zero count - where the cap is the designed rule, firing is correct
behaviour; where the clamp is defensive, firing is a defect count. The discriminator is
stated in prose on this side, per the no-cross-bundle-links rule.

## Applied (1 of 1 owed) - `experiment`, verdict `better`

Seam chosen to falsify, and **the first seam refuted the finding**. A declared
cohort-size threshold in the consumer tree was the obvious instance; its fixtures
deliberately straddle it, with in-source comments saying so and three different values
across the suite. A *declared* threshold advertises both of its sides, so fixture authors
cover both. That refutation narrowed the claim from "a fixture pins a deciding variable"
to "a repair placed against a **derived** quantity is invisible to an assertion over the
repaired range" - a better technique than the one the seam was picked to confirm, and the
fifth consecutive round in which a falsifying seam returned something the run was not
hunting.

The surviving instance: a deterministic jitter helper whose doc promises a half-open
fraction, whose test asserts the **closed** range, and whose defensive clamp is currently
dead code. Arm B applied the one-bit maintenance error the clamp exists to survive and
ran the same unmodified test - **50.0% of seeds collapsed onto the excluded bound**
(n=1,000,000), the lower half of the distribution lost a quarter of its mass, and the
test passed.

Mutation reverted. `ship 0 (unspent)` rather than `(unrunnable)`: an arm existed and the
run chose not to ship a product change out of an experiment, because the one-character
fix belongs to the tree's owner and the tree carried another session's uncommitted work.

## Dispatched (1) - XL, forged in session

Phase 2d routing count: **4 `corpus: NONE` entries in one system** - the fork/patch-stack
maintenance system - which fires the mechanical XL trigger. Spec at
`librarian/handoffs/2026-09-07-vendored-patch-stack.md`; forge worker dispatched in
session per the do-not-bank rule, after the operator answered the E4 escalation.

The count survived a real challenge. `supply-chain/vendored-fork-ledger` is the nearest
neighbour and models the fork's **provenance** - which upstream commit, what changed on
top, who reaps it, and the fact that forking converts a governed dependency into an
ungoverned subdirectory. It models none of the **mechanics of keeping the stack alive**,
and the subject begins exactly where the ledger stops.

The four decisions: the vendored tree is a build output that is also a VCS workspace and
the two disagree about what a reset means; patches are derived artifacts authored by
round-tripping a workspace, never hand-edited; regeneration must concatenate the staged
and unstaged diffs or new files are dropped from a patch that still applies cleanly; and
two patch axes that edit the same hunks were collapsed into one, because independence of
the hunk sets is the precondition for keeping a second axis at all.

## Already covered (4) - catches

- **Chokepoint plus a mechanical ban on the raw primitive.** The tree's headline
  engineering - one module owns the conversion and the ack wait, and a static check fails
  the build if anything else does either - is `ipc-contract/call-wrapping`, which already
  says: ban the raw primitive mechanically, because convention plus review catches most
  uses and the mechanical ban catches the rest, which is the part that matters.
- **A deadline sized above the slowest legitimate responder, not near the typical one.**
  The source measured p99 1ms acks and set a 5s deadline because the responder inherits
  blocking from a thread it shares; it recorded one ack delayed 2,849ms by a synchronous
  script. `guest-execution-bounding/terminate-from-outside-when-you-cannot-count` already
  carries this as a decision rule.
- **Per-item budgets that do not bound the aggregate.** Roughly 110 bounded waits summing
  into an unbounded slot is exactly the accumulation escape `nested-liveness-ceilings`
  models, ladder and all.
- **Declaring the layer beneath which the abstraction cannot reach.** The source's
  limitations table - the operating system renders text and the layer above cannot lie
  about it - is the same honesty `guest-execution-bounding` states as: what it does not
  count it cannot cap, and the honest design says so beside the ceilings it does publish.

## Untriaged (2) - nobody verified these

- **Abandon-the-remainder as an alternative to another rung.** Where sub-units are
  causally chained - later items are meaningless if an earlier one did not land - the
  first breach can abandon the rest, and the accumulation escape closes with no outer
  ceiling at all. `nested-liveness-ceilings` enumerates three cases in its "when not to
  use it" and this is a fourth of a different kind: not one granularity, but many with a
  dependency between them. Scored 1/0/2, below the +2 threshold, banked with its anchor
  rather than filed as a decline. **One more sighting and it is an amendment.**
- **A three-tier read fallback** - in-process cache, then a shared store the platform
  syncs across processes, then a synchronous call to the owner - with a main-thread guard
  on the third tier only. Adjacent to `settings/cross-source-precedence-chain`; nobody
  opened that file this run, so this is untriaged and not a catch.

## Leads (2)

- **A privileged setup capability that deletes itself after first use**, so later
  inspection cannot see it existed. A real mechanism whose only stated purpose in this
  tree is evading detection, which is not a use this corpus serves. Return condition: a
  second, non-adversarial source showing the same shape - an initialization-only
  capability withdrawn once used, so it cannot be re-invoked or discovered - at which
  point it is a capability-lifecycle question. Not landed from this source alone.
- **A maintenance runbook written explicitly for an LLM audience.** The tree's upgrade
  guide names its reader in its own title, and its instructions are shaped for an agent:
  search for moved code rather than trusting line numbers, do not leave TODO comments, do
  one patch per session. Return condition: a second tree carrying an agent-addressed
  runbook kept distinct from its human documentation, at which point
  `machine-authored-documentation` has a question about who a document's reader is.

## The source class, for the next run

A patched-upstream fork is a **vendor repository whose operating documents are a
post-mortem lane**. They record failures the maintainers paid for in production, dated
and with commit anchors - this tree's deadlock table carries four dates, four commits and
four triggers, and the accompanying lint explains in its own header why review could not
have caught any of them. That is first-party practitioner material of the highest tier
the class offers, and it sits three directories below a README that describes none of it.

The ratio worth computing on the next one of these is operating-document words over
landing-page words. At 4.7:1 here, everything that mattered was in the numerator.
