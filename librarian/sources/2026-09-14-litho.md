## Design record

Grouped by system. The tree is one system, so the per-system and home-if-new counts are
taken over the same entries.

**D1 - layout is a pure function of immutable inputs, so it may run on any thread.**
- forces: host views are mutable and owned by the frame thread; laying them out elsewhere races every setter.
- buys: layout off the frame thread; sync and async entry points both thread-safe, last root set wins.
- rejects: laying out the host tree itself (`docs/asynchronous-layout.md:30-33`).
- where: `docs/asynchronous-layout.md:63-77`, `docs/architecture-overview.md:29-33`.
- stage: resolve and layout.
- corpus: partial - `chat-transcript/immutable-model-cached-layout` freezes a model for layout caching; `diff-comparison/computation-offload` moves compute off the interactive thread. Neither states that purity is the precondition for leaving the frame thread. HOME IF NEW: render-mount-pipeline.

**D2 - one shared computation per equivalent request; a deadline-bound waiter preempts and continues it.**
- forces: the frame thread may need a layout a background thread is already computing; waiting drops frames, recomputing wastes the work.
- buys: the frame thread never blocks behind background work; a background sync waiter pins the future so it never waits on an interrupted result; the running thread's priority is raised while the frame thread waits.
- rejects: plain join (block) and plain recompute; the opt-out was deleted (`CHANGELOG.md:74`).
- where: `litho-core/.../TreeFuture.kt:140-166, 268-437, 532-594`.
- stage: layout scheduling.
- corpus: NONE for the preemption - `concurrency-guards/single-flight-primitives` enumerates five second-caller policies (refuse, join, queue, coalesce, merge) and none is "a waiter that cannot afford to wait takes the work over". `client-fetch-cache/in-flight-dedup` owns the dedupe half. HOME IF NEW: render-mount-pipeline.

**D3 - layout emits a blueprint; containers vanish at mount unless they need a host capability.**
- forces: every host object costs memory and draw time; but touch, accessibility and invalidation confinement only exist on host objects.
- buys: a flat mounted hierarchy by default, with automatic promotion for nodes that declare a host-only capability.
- rejects: one host object per layout node.
- where: `docs/view-flattening.md:10-21`, `litho-core/.../CommonProps.kt:156-161`.
- stage: collect results, then mount.
- corpus: NONE - no subject models a layout output decoupled from host objects or a promotion rule. HOME IF NEW: render-mount-pipeline.

**D4 - incremental mount at leaf granularity, over edge-sorted indices.**
- forces: a partially visible item can hold hundreds of off-screen primitives; item-level windowing keeps all of them.
- buys: per-scroll work proportional to what crossed an edge; a leaf leaves even when its container is still visible.
- rejects: item-level recycling only (`docs/deep-dive/incremental-mount.md:9-12`).
- where: `IncrementalMountExtension.java:268-283, 494-608, 630-691`.
- stage: mount on visible-bounds change.
- corpus: partial - `table/techniques/performance` rung 4 windows rows; `canvas-graph/techniques/render-budget` culls elements. Neither carries sub-item granularity or the edge-cursor walk. HOME IF NEW: render-mount-pipeline.

**D5 - mountedness is a reference count that independent features acquire and release.**
- forces: features disagree about whether an off-screen element must exist (a transition needs it, the window wants it gone); a boolean owned by one breaks the others.
- buys: features compose without knowing each other; mounted iff at least one holds a reference.
- rejects: the monolithic mount state (`docs/mountextensions.md:6-11`).
- where: `docs/mountextensions.md:19-28, 79-80`, `MountDelegate.kt:39, 66-69`, `IncrementalMountExtension.java:398-413, 442-464`.
- stage: mount.
- corpus: NONE - `accessibility/hidden-but-mounted-inertness` owns how a mounted-but-hidden subtree is made inert, not who decides mountedness. HOME IF NEW: render-mount-pipeline.

**D6 - premount into frame gaps before the next deadline.**
- forces: mounting on arrival costs the frame the element enters.
- buys: off-screen neighbours mounted in idle time up to deadline minus a buffer.
- rejects: mount-on-intersection only.
- where: `IncrementalMountGapWorker.kt:46-109`; when on, the window stops releasing (`IncrementalMountExtension.java:461, 514, 582`).
- stage: mount scheduling.
- corpus: partial - `canvas-graph/render-budget` mounts first-frame waves under a frame budget. Folded into D4's technique as a section.

**D7 - pool host objects by leaf content type, scoped to the owning context's lifetime.**
- forces: pooling by item type allocates on the first appearance of every item type, inside the frame that shows it.
- buys: any text recycles into any text; preallocation off the critical path; bounded pools with a discard hook.
- rejects: item-type pools (`docs/recycling.mdx:17-27`).
- where: `docs/recycling.mdx:29-42`, `MountItemsPool.kt:86-206`.
- stage: mount content acquisition.
- corpus: NONE in this bundle (game-production holds an object-pool doctrine; cross-bundle, not linked). HOME IF NEW: render-mount-pipeline.

**D8 - mount binders and attach binders, each with its own should-update.**
- forces: content binding is expensive and listener binding is cheap; one update path re-runs both.
- buys: an update re-runs only the binders whose inputs moved (mount diffing).
- where: `RenderUnit.kt:31-44, 58-62, 77-79`, `docs/architecture-overview.md:47-48`.
- stage: mount update.
- corpus: partial - memoization on identity and version (`table/performance` rung 3). HOME IF NEW: render-mount-pipeline.

**D9 - working ranges: enter and exit events at a position distance from the viewport.**
- where: `docs/sections/working-ranges.md:10-106`.
- corpus: likely catch - `client-fetch-cache/techniques/prefetch-and-defer`.

**D10 - reconciliation keeps the previous tree to clone unchanged subtrees, and trades memory for it.**
- where: `docs/deep-dive/reconciliation.mdx:8-28`, `CHANGELOG.md:309`.
- corpus: partial - no subject states the memory price. Not scored (a boundary for the forged subject at most).

## Apply (Phase 7.5)

**Seam hunt before drafting (the declared focus).** A per-project grep over the thirteen
fleet trees (asserted against a per-project positive first) found userland mount layers
in three: personas (four virtualizers), goat (two), pof (one). No fleet project owns a
renderer, a blueprint pass or a content pool, so the seam for this subject is the one
place web code decides which elements exist: a virtualizer's range.

**Two seams, and the one that could falsify was chosen.** The personas deck rail keeps a
keyboard cursor in view by index, but its keyboard handling is a single global listener
(`useDeckControls.tsx:16`), so DOM focus loss there costs nothing: an arm there could only
have confirmed. The trace waterfall is different - its rows carry expand toggles, focus
IS the reader's position, and a trace runs to 10,000 spans. A CAUGHT outcome there would
have taught that a web virtualizer's own overscan already covers focus, which would have
demoted `mount-references-across-features` for this stack.

**mount-references-across-features x personas - code, `better`, `ab-paired`.**
Measurable: where focus is after a focused row scrolls out of the window and overscan,
with the created-row bound held. One fixture (5,000 spans, row 0's toggle focused,
scrolled 2,000 rows), three observation points each arm:
- A (tree as it was): window moved (row 2000 mounted), fewer than 200 rows created, focus on `body`.
- B (focus holds its own claim, keyed by span id, window UNION focused row): same window, fewer than 200 rows, focus still on row 0's toggle. A second test proves the claim is released when focus leaves the list.
- Suite 88/88, eslint clean, `tsc --noEmit` exit 0.
Shipped: personas `d0709a8f2` (fix + test + changelog), ledger row committed after it.
Not pushed.

**Structural fact the tree carries.** The same file had already resolved one mount
conflict by deleting a feature: its per-row entrance animation is switched off on the
virtualized path because recycled rows replay it. A feature with no claim on
mountedness loses to the window, and the only lever the code had was to remove it.

**What the realization cannot do.** A row kept for focus sits at its true offset outside
the viewport; a screen reader in browse mode still loses the rows around it, and the list
declares no row count or row index.

Techniques landed by the forge with no fleet row this run: `blueprint-then-mount`,
`edge-sorted-incremental-mount`, `recycle-by-content-type`,
`preempt-and-continue-shared-computation`, and `mount-binders-versus-attach-binders` if it
survives. Return condition for each: when a fleet project grows a renderer of its own
(canvas, terminal or native display list). The grep found none on 2026-09-14.
