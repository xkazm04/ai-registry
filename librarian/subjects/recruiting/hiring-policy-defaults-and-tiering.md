## 2026-09-26 - widened to react, the version rule flipped, four absolutes conditioned

**Depth rung:** L2 primary for the corrections (statute and regulation text, a
meta-analysis, vendor documentation, schema-evolution rules). L3 empirical for the
applications: read against the tree, with two simulations run on the tree's own SQL and
version builder.

**Lanes:** counter-evidence (web, unconstrained), training-data-only (blind),
consumer-tree re-verification, and a react read of the settings screen.

**Landed** in two commits, 96043f39 and 9aea4066:
- NEW `react--organisation-baseline-with-a-team-override` (react@19). It clears the
  single-stack finding; scan points went from 5 to 3, and the remaining reason is "never
  swept by the librarian".
- NEW `node--per-role-family-threshold-overrides`, from the calibration apply path.
- **Flipped (three-way convergence: tree, web lane, blind lane):**
  `policy-version-sealed-into-every-decision` and the golden path. "Omit absent values"
  becomes "digest resolved values; omit a dimension only at its inert value". A default
  resolved at the point of use is absent from storage and present in behaviour, so the
  old rule let a changed default move every rulebook without moving any version. New
  decision rule: one approval means one version string on every record, and per-subject
  values go in inputs.
- **Conditioned (two lanes each):**
  - Default effect: "brutally low everywhere" becomes "large and uneven"; the
    implementation project is the buyer's real default.
  - Auto-reject: a knockout on a declared, objective answer is a separate capability. It
    ships unwritten and owes job-relatedness, a notice and a route to a person. A
    statutory question is a constraint.
  - Role-family bars: anchor to proficiency, not to the family's own distribution. Write
    the grouping as a job analysis. Name the review direction by its effect, because
    "stricter" is not safer for a reject-below threshold. Never tune a family bar to a
    demographic outcome.
  - Baseline and override: pin is a third key state; show the per-team diff before a
    baseline change lands; an editor writes the tier it shows; an automated apply writes
    a delta.
- Re-verified: all three existing node applications moved to 2026-09-26. Two claims had
  gone stale. The per-candidate record version was reversed in the tree, so the
  application's praise for it is withdrawn. The best-effort seal is gone: a rejection's
  seal is now its precondition.

**Consumer defects found.** They are recorded as deviations and not fixed, because a live
sibling run (dp-cvas-0926) holds kp on the board:
- **The auto-reject switch can fail to turn off.** The rules screen posts with no scope,
  so it writes the org tier. The calibration apply writes a full team row, which shadows
  the org row. After one apply, unticking auto-reject leaves the workspace running with
  it on, and the screen says "Saved". This was reproduced in simulation.
- The rules screen does not echo the concurrency token the GET serves, so the switch's
  editor is last-write-wins.
- The apply route applies "raise" and "lower" under the same one-click review.
- The knockout decline names no gate and offers no person.
- The language knockout states no job-relatedness.
