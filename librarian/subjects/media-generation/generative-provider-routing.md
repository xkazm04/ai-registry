## The adjudication, and why it did not become a technique

The banked proposal was the omit-when-undefined wire idiom - a request body
assembled by dropping whatever the caller left unset, so a caller who sets
nothing hands the dial to the vendor's default, defeating a doctrine the
module's own docstring states.

- **One voice, not two sightings.** The idiom appears in two modules, but it is
  one author's idiom copied across them: same header style, same error-class
  shape, same commit history. Two modules reached by copying one idiom is one
  observation. For a *new technique* that fails the convergence bar outright.
- **The inversion framing was rejected on mechanism.** `non-silent-elimination`'s
  unit is a vendor *candidate*; an omitted request field eliminates no
  candidate, because the intended vendor still serves. Widening the trail to
  carry it would break that technique's own closed-vocabulary rule.
- **But it is the same failure mode the golden path already names** - the silent
  near-miss. So it landed as an **enumeration repair**: the elimination has an
  *outbound* door, a field the router itself never sends. The reasoning worth
  keeping: *an enumeration gap is repairable on a single sighting, because the
  sighting's job is to prove the door exists, not to establish a rate.*

Golden path extended in the same change so layers 2 and 3 do not disagree.
Still 7 techniques.

A **counter-example** was found while looking for a third sighting: the same
tree does this correctly elsewhere, materialising a named default and coercing
at the boundary rather than letting the field go absent. The tree contains both
the failure and the correct handling, which sharpens the doctrine without
adding a failure sighting.
