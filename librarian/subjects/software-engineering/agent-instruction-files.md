## 2026-08-28 — /intake, [[../../sources/2026-08-28-autosaddler-harness-optimization]]

Two new techniques (6 → 8) from a research-code release about optimizing agent
harnesses from failed traces. Both were found in the subject's **structure**
rather than in its prose, and both are cases where a correctly written file is
still the wrong instrument.

**`workspace-ancestry-isolation` — the subject had no reader's chair.** Every
existing technique is written from the author's position: what a line earns, where
the canonical file lives, which regions the machine owns, when to prune. The
question none of them can answer by editing the file is *which directories does
this file govern* — and the answer is not "the repository". Discovery is an
ancestry walk with no boundary at the repo root, concatenating rather than
overriding, plus lazy loading of per-directory files beneath the launch point. So
the governed region is a cone, and a directory a program creates inside it is
briefed by a file written about something else.

The confirming read was the golden path's **seven-item failure-mode enumeration**:
every entry is the file's *content* being wrong, and none is a correct file
applying where it was never meant to. `single-source-topology`'s loading sort
(always-loaded / loaded-on-touch / per-user) has the same blind spot — all three
categories describe files an author placed deliberately.

**`capability-before-steering` — the demotion sort has an unstated precondition.**
`enforcement-demotion` asks whether a program could decide compliance and routes to
a gate or to prose. Both branches presuppose an agent that *can* perform the
behavior. `line-earning`'s two halves (unreachable, behavior-changing) are both
questions about the line, not about the agent's means. A capability gap passes the
admission test on its face and still cannot be fixed by text.

The cost argument came from this subject's own foundation and is what promoted it
from a nicety: compliance falls with instruction count roughly uniformly, so a line
that cannot work still taxes every line that could. **That makes it the only
strictly negative instruction-file edit**, and it gives the subject a name for a
pattern it could previously only describe — a rule restated with escalating force
across revisions is nearly always a capability gap being sharpened as a wording
problem.

**For a later run:** the two techniques form a pair with the rest of the subject
that is worth watching. The subject now has an admission test, a capability gate,
an enforcement sort, a topology, a machine-region rule, a freshness practice, a
composition balance, and a span rule — eight techniques, and the newest two are the
only ones that are not about the file's text. If a ninth candidate arrives that is
also not about the text, the subject may be carrying two concerns and the boundary
should be stated before it is grown further.
