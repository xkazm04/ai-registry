## 2026-08-31 — `/intake`, `2026-08-31-verou-2026-blog`

A **correction**, not an addition: no technique count change.

`preference-short-circuits-measurement` already held the requirement — a
measured tier is a default for people who have not said what they want, every
statement retires it, and the control must therefore not make its first use a
permanent exit from the adaptive system. It then prescribed a visible third
"automatic" option as the remedy. A source arguing the opposite case supplied a
mechanism that satisfies the same requirement without spending a control state:
store the user's target only when it **differs** from what the source currently
resolves to, and **delete** the stored value when they coincide — so the way back
is a property of the write, and the absence of a row is what "automatic" means.

Corrected in place, keeping the file's voice, with the boundary written from
both sides. The full rule (including the two silent-corruption failure modes)
belongs to `operations/governance-and-records/settings` as
`inherited-default-override`; this subject keeps the pointer and one caution
that is true only here.

**The caution is the part worth remembering.** That technique's source is a
*setting the application reads*. This subject's source is a **measurement the
application performs**, which can be re-run and can return a different answer
for reasons having nothing to do with the user's environment. A measurement is
therefore disqualified twice over as a trigger for re-evaluating a stored
choice: the comparison must happen at user interaction only, *and* a fresh probe
result must never be read as evidence that a stored preference became redundant.

## 2026-10-22 - measurement-settle-budget applied outside React (intake-apply-msb-1022)

The first application in a stack other than React, and the first seam with a
whole-session per-frame sampler and no tier at all: a Kotlin game's frame-time ring,
written every frame and pulled by a stats endpoint. The seam was chosen to falsify,
because the technique's use_when matches it word for word. Experiment: the write cost
5.6-5.7 ns per call on a desktop JIT, and it rides a callback the game runs anyway. A
60 s deadline replayed over the project's five recorded 360 s runs would have hidden
5 of the 6 race-start hitch bursts in every run, and those bursts are the evidence the
project's own optimize card used to find and fix them. Verdict not-better. The
technique gained a boundary section: settle a sampler that a decision reads, keep one
that a pulled diagnostic reads, and split a sampler that feeds both. Return condition:
a second tree with a decision-read sampler outside React tests the settle rule itself
rather than its boundary.
