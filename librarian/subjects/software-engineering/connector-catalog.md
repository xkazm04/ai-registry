## Touch log

### 2026-09-23 - `/deepen` batch ([[2026-09-23-2]])

First sweep. Chosen on 4 deviations across two projects. Of those, one was fixed in the
second project on 2026-09-05, one was superseded by a deliberate project decision the
subject now matches, and two stand.

**No new technique; corrections.** The door serves **two reads** - offer (every predicate
applies) and resolve (any identity, whatever its gates) - and applying predicates to the
only list turns every predicate into a way to lose rows. Deprecation hides from offers,
never from lookups. The lifecycle has a **front end** (announced, preview) on the same
axis as deprecation, kept separate from the support tier. A row with fields and **no
probe is a third outcome** - neither a green nor a locked save - declared explicitly at
authoring time. Deriving a key from a label is fine when the **mint is checked**. The
union of old and new category axes needs both inputs to reach consumers. The offer/resolve
split converged across five lanes but had homes in two existing techniques.

**Apply (four rows, [[applied]]):** 3 `better`, 1 `not-better`. The not-better refuted the
research pass's own prediction: the project's store door already checks the key inside a
write transaction, so a schema constraint would change nothing; the exposure is a seeder
inserting by id. Condition written. The two-reads row corrected the application - in this
tree the only gated row is credential-less, so the loss runs through declared references,
not credentials; the technique now says which resolve readers are at risk. The no-probe
row found 7 of 10 consumers drawing an unverifiable credential as passed through a
compatibility boolean - the same shape credential-vault's fourth narrowing names,
sighted independently the same day. The ascent row is a confirmation, not evidence.
