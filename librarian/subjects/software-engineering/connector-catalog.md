## Touch log

### 2026-09-23 - `/deepen` batch ([[2026-09-23-2]])

First sweep. Chosen on 4 deviations across two projects. Of those, one was fixed in the
second project on 2026-09-05, one was superseded by a deliberate project decision the
subject now matches, and two stand.

**No new technique; corrections.** The door serves **two reads** - offer (every predicate
applies) and resolve (any identity, whatever its gates) - and applying predicates to the
only list turns every predicate into a way to lose rows. Deprecation hides from offers,
never from lookups. The lifecycle has a **front end** (announced, preview) on the same
axis as deprecation, kept separate from the support tier. A row with fields and **no
probe is a third outcome** - neither a green nor a locked save - declared explicitly at
authoring time. Deriving a key from a label is fine when the **mint is checked**. The
union of old and new category axes needs both inputs to reach consumers. The offer/resolve
split converged across five lanes but had homes in two existing techniques.

**Apply (four rows, [[applied]]):** 3 `better`, 1 `not-better`. The not-better refuted the
research pass's own prediction: the project's store door already checks the key inside a
write transaction, so a schema constraint would change nothing; the exposure is a seeder
inserting by id. Condition written. The two-reads row corrected the application - in this
tree the only gated row is credential-less, so the loss runs through declared references,
not credentials; the technique now says which resolve readers are at risk. The no-probe
row found 7 of 10 consumers drawing an unverifiable credential as passed through a
compatibility boolean - the same shape credential-vault's fourth narrowing names,
sighted independently the same day. The ascent row is a confirmation, not evidence.

### 2026-09-26 - `/deepen` dispatched (dp-cc-0926)

Curator dispatch on "single stack (react)". The `next` application is the react family, so
the finding stood. **The event:** the 2026-09-23 pass never measured stack diversity. The
local scan scored the subject 0 points before this pass and 0 after. It does not count
`next` as react, so the dispatcher's lens and the scan's lens disagree on this subject.

**A rust second stack** from the tree's boot seeder, on the one technique that had no
application: shipped-vs-operator-ownership. The golden path's canonical instance (nine
columns rewritten, one surviving by accident) was re-verified unchanged at the tree's HEAD.

Enumerating the writers found five. A replay of their SQL showed four things:

- the import writer's appends are erased at the next launch;
- a label edit reverts while the color edit survives;
- a rename silently forks the row out of refresh, because the insert keys on id and the
  update on name: no duplicate, and no fixes ever again;
- a deleted row is resurrected.

The live store (read-only) has 135 rows with 34 distinct creation instants and one
`updated_at`.

**Lanes.** A counter-evidence lane read primary sources:

- package-manager conffile handling;
- declarative field managers;
- dashboard provisioning;
- copy-to-customize platforms.

A blind training-data lane ran beside it. Claim 4 (structural split) was confirmed with a
refinement (the type must tell unset from empty). The other five of the six claims were
conditioned, and none was refuted.

**No new technique.** Every convergence lands as a condition on shipped-vs-operator-ownership:

- a list column is owned per element;
- one vendor-minted key serves every statement of the refresh;
- a deleter is a writer (tombstone);
- read-only vendor rows are a complete contract, enforced at the door;
- the clobber is a defect only for other writers' columns;
- a boot resolves conflicts by a declared default plus a record;
- hash a canonical form;
- the timestamp confession holds only when creation times are spread.

The blind lane predicted a duplicate row on rename. The replay refuted that for split keys.

**Apply (four rows, [[applied]]):**

- 1 `better` at `code`: the seeder carries import-tagged services entries. The boot-path
  test fails on the old seeder and passes on the new one. Pushed to the project's default
  branch.
- 3 `unapplied`: deletion, split key, and read-only-at-door. Each seam exists at a
  privileged door with no UI caller.
