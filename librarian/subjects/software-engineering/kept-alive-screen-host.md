# kept-alive-screen-host

Forged from the afterlife console's screen host: a golden path, five techniques
and two applications. Both applications cite the public tree `xkazm04/afterlife`
and were verified on 2026-10-27. The librarian had not swept this subject before
this run.

## 2026-11-16 - first /deepen (loop 3, run filler-deepen-20261116g, /shift filler)

**Round 1 (web survey): not dry. One golden-path hedge, two technique amendments, no new technique.**

- **Golden path and host-click-delegation: the host inherits the router's
  accessibility duties.** Three lanes converge.
  - The blind lane predicted it.
  - The framework's route-announcer source shows the announcement is keyed to
    the router's own tree.
  - A published client-routing user test found the same failure shape: a
    catch-all that kept route changes from the router lost its focus
    management. Focus on the main heading was the best-received approach.

  The host now announces the screen once, places focus by the kind of arrival
  (heading on a first showing, the left element on a return), and keeps hidden
  screens out of reach. The text is labelled craft, not conformance.
- **Golden path boundaries: the framework may keep pages alive.** Sources: the
  framework's preserving-UI-state guide (16.4.3 docs: route pages hidden under
  the boundary primitive, at most 3 kept) and the tree, which runs both kept
  sets. Use the framework's kept routes when returning warm is the whole need.
  Build the host when the click must paint before the server answers. Where
  both run, there is one kept set of real screens.
- **hidden-but-alive-screens: "stopped" has a moment.** The boundary primitive's
  reference docs say a passive cleanup can be delayed by a re-suspending
  boundary or an animated transition. So cleanups that must coincide with the
  hide go in the layout phase. A test-query caveat was also added.
- **host-click-delegation: the platform's single door.** The navigation
  interception event has been in the baseline since 2026-01-13 (web-features
  explorer, read 2026-11-16). It is the stronger door where no router patches
  history. Capture-phase delegation remains the door beside a history-owning
  router.
- **Read lane:** both applications were re-read at `009c7893`, which is still
  `main` per `ls-remote` on 2026-11-16. Every anchor resolved, both moved to
  `verified_on: 2026-11-16`, and no correction was needed.
- **Volatile facts:** 5 documents, all tree durations or sizes. There is no
  vendor quantity. Untouched.

**Round 2 (training-data first): not dry. Two amendments.**

- **sliced-screen-stream:** per-slice arrival is a property of the whole path.
  A buffering proxy (the common reverse proxy's buffering defaults to on, read
  on its own docs) or a compressing layer that does not flush collapses the
  stream into one reveal. Measure through the deployed path. This converges
  with the blind lane and with the application's unmeasured production build.
- **frame-first-no-skeleton:** a dash is not a progress cue. Response-time
  guidance (a cue past about 1 s, an expectation and an exit past about 10 s,
  read 2026-11-16) asks for one quiet in-flight cue that is not a shape.

**Round 3: not dry.** It corrected an overclaim in round 2's own landing ("the

it"). Everything else held:
