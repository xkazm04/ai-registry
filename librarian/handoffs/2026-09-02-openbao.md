### 1. `seal-and-key-hierarchy` (entries D, E)

A layered key hierarchy over untrusted storage where each layer rotates by
a different mechanism, N independent custodies of one root key coexist, a
break-glass custody is not a recovery path, and the seal is a boundary
that must exist before storage is readable.

- `any-one-seal-unseals` - one encryption of the root per seal, unsealed
  in priority order; security is the weakest seal's.
- `recovery-key-is-not-unseal-key` - recovery shares authorize privileged
  operations and are verified against a stored copy; they never decrypt.
- `append-only-keyring-rotation` - rotate the data key by appending a
  term; term-prefixed ciphertext lets old terms decrypt; never re-encrypt.
- `rewrap-root-not-data` - the root rotates by re-wrapping the keyring
  blob; needs the quorum because the operator never holds the barrier key.
- `transient-upgrade-entry` - publish N+1 under N for a grace window so a
  replica unsealed with N can lead without a fresh unseal.
- `usage-triggered-rotation` - count AEAD operations cluster-wide, rotate
  on max-ops (NIST minus a margin), interval, or age; count the write that
  persists the count.
- `seal-before-storage-plugins` - anything needed before storage is
  readable is declared in config and stored in plaintext, never in a
  storage-backed catalog.
- `per-tenant-seal-chain` - a sealed tenant has its own KEK -> root ->
  keyring; the global root cannot decrypt it; sealing cascades down; a
  sealed child stops tree loading.

### 2. `read-serving-replicas` (entry C)

Every replica runs the full post-unseal and serves reads; writes are
refused by the storage layer and forwarded on the error, not classified
by verb; caches are invalidated from the committed-write stream, never by
TTL; consistency is carried by the client.

- `forward-on-storage-error` - a read-only shim returns a sentinel; the
  middleware forwards on that error, not on the HTTP verb.
- `preemptive-forward-for-known-writes` - the few write-shaped reads
  (response wrapping, use-count tokens) forward before dispatch.
- `committed-write-invalidation-hook` - fire with the batch's put/delete
  keys only after the store's update commits; a non-replicated layer's hook
  is a deliberate no-op.
- `evict-not-update-on-commit` - under no global lock, removing the cache
  entry is the only correct move; report the applied index, not the
  accepted one.
- `fairshare-invalidation-queues` - core path on its own queue, per
  tenant otherwise, per peer so a slow standby starves nobody; a queue
  that grows too old steps the replica down from read-enabled.
- `client-carried-index` - an opaque monotone index the client echoes;
  fail / forward / await per listener (accepted RFC, not landed).
- `shared-then-active-unseal-strategy` - one post-unseal every node runs,
  one wrapper only the leader runs.

### 3. `transactions-over-a-replicated-log` (entry A)

Interactive transactions built on a single-writer embedded store beneath
a consensus log by shipping read and list hashes for re-verification at
apply time, with a conflict taxonomy proven by a differential conformance
suite across every backend and wrapper.

- `snapshot-read-plus-verify-log` - never hold the writer across the
  round trip; open a read snapshot, ship verifications, settle at apply.
- `capture-index-before-snapshot` - take the log index before opening the
  snapshot, never after.
- `skip-verify-for-in-tx-writes` - a key already written in this
  transaction needs no verification entry.
- `list-verification-by-present-keys` - hash what storage returned, not
  what the caller saw after reconciliation.
- `no-writes-no-log` - a read-only or unwritten transaction never enters
  the log even when it would have conflicted.
- `same-value-still-conflicts` - first committer wins on the key; a
  "possibly modified" signal narrows, only the hash decides.
- `three-sentinel-errors` - read-only, commit-failure, already-finished;
  commit-failure is the one client-retryable class.
- `compose-then-conform` - every wrapper (cache, encoding, view, fault
  injector) re-enters the conformance matrix in and out of a transaction;
  random-op replay diffs at first divergence; the one tolerated
  divergence (nil vs empty) is declared.
- `leak-detector-on-finalizer` - a transaction neither committed nor
  rolled back logs its birth stack.

### 4. `bounded-enumeration` (entry B)

Enumeration as a policy-governed, bounded operation: a seek-by-key page
primitive from the store to the CLI, page sizes derived from a memory
budget, limits and result filtering as ACL properties, and data structures
reshaped when a single entry's size limit binds.

- `after-plus-limit-not-cursor` - seek by key, no opaque cursor, so a
  filtered page cannot leak inaccessible keys.
- `page-size-from-memory-budget` - derive the default from worst-case
  path length times a memory target.
- `declare-the-inconsistency` - pages may miss or duplicate entries
  created mid-iteration; say so in the contract, not the bug tracker.
- `required-limit-breaks-unaware-clients` - only when `limit` is required
  do limit-less requests fail; otherwise clamp; the `max` literal lets a
  client that does not know its limit iterate until empty.
- `deny-absorbs-and-lowest-limit-wins` - across merged policies, explicit
  deny wipes the set and the smallest limit applies.
- `filter-after-return-under-limit` - per-key accessibility filtering is
  admissible only because a limit bounds its cost; an empty filtered page
  is not the end.
- `split-table-one-way-migration` - one entry per row under a
  transaction, migrated on first start, no downgrade.

### 5. `priced-authority` (entry F)

Every unit of authority is a persisted artifact whose cost is a storage
write; exactly one class never persists; a single-use cubbyhole token is
the primitive for secure introduction and second-party approval.

- `never-persisted-token-class` - encrypt the entry into the token, store
  nothing, lose renewal, children and accessor.
- `inline-auth-cannot-lease` - authority carried on the request itself
  is never returned or stored; anything creating a lease takes the
  persisted path or is revoked and errored.
- `secondary-index-before-primary` - write the parent index first; a
  dangling pointer beats an escaped revocation chain.
- `write-ahead-revocation-marker` - set a sentinel before deferred
  revocation so lookups fail immediately.
- `single-use-cubbyhole-wrap` - an unsigned single-use token whose
  cubbyhole holds the response; creation path recorded; unauthenticated
  lookup lets the client verify origin before unwrap.
- `approver-not-requester` - second-party approval parks the request in
  wrap metadata; the requester may not approve; one approval per entity.

### 6. `dynamic-secret-lifecycle` (entry F, issuer side; engines scout)

The issuer's side of a leased credential: create in the remote only after
the lease can persist, expire the remote after the lease, revoke
idempotently, prefer native tracking when the artifact self-revokes, and
maintain revocation artifacts.

- `persist-before-provision` - refuse the remote create when the lease
  cannot be stored.
- `expiry-buffer-beyond-lease` - remote expiry = lease TTL + buffer so
  the lease is always the earlier death.
- `idempotent-revoke-and-give-up` - revoke succeeds when the target is
  already gone; local revocation lands first, publication is best effort.
- `ttl-ladder-derivation` - period > increment > backend default > system
  default, capped by the minimum of mount, role and explicit.
- `wal-per-external-side-effect` - write a WAL before each remote
  mutation; roll back after a minimum age longer than a successful create.
- `lease-vs-native-tracking` - a self-revoking artifact (a certificate)
  is tracked natively, not leased, unless the operator opts in.
- `tidy-after-not-after-only` - remove revocation and cert records only
  past expiry plus a safety buffer; keep an expired issuer's key.

### 7. `issuance-policy-ladder` (entry G, engines scout)

A role that shapes an issued artifact: constraint ladders, reference
floating, bound modes, a separate door for unconstrained signing, and a
user-authored program that must return the finished artifact or a refusal.

- `require-one-constraint` - a role that binds nothing is refused.
- `explicit-forbid-beats-allow-any` - a wildcard forbid overrides an
  allow-any flag.
- `float-references-resolve-at-use` - issuer references are warned at
  definition and resolved at issue time so `default` floats.
- `bounds-as-modes` - a validity bound is permit | limited | forbid |
  timestamp, and the ladder from request to CA limit is stated once.
- `verbatim-is-a-separate-privilege` - unconstrained signing is its own
  endpoint, never a role flag.
- `program-role-returns-the-artifact` - the program returns the final
  template or auth object, or a refusal string, or false; protocol checks
  still run outside it.

### 8. `node-boot-and-declarative-bootstrap` (entry G; core + periphery)

The startup dependency graph of a stateful node, the reload/restart
partition of its config, and privileged bootstrap as a once-only config
request chain bracketed by a failure marker.

- `ordered-boot-dag` - storage -> seal -> core -> listeners -> unseal ->
  bootstrap -> serve; a component starts after what it reads.
- `reload-partition` - reload only what swaps without invalidating
  in-flight state; a bad reload still runs the safe reload functions.
- `once-only-bootstrap-with-marker` - write a failed marker before,
  remove after; refuse to unseal while present; revoke the bootstrap
  credential on every exit path.
- `config-objects-are-api-immutable` - config-created devices and plugins
  live under a distinct type; a mismatch fails startup, the API cannot
  alter them.
- `request-chain-not-dsl` - bootstrap is ordered ordinary API requests
  with history-keyed references, not a new language.
- `unauthed-workflow-never-recurses` - synthetic chains: unauthenticated
  may not call any chain; authenticated depth is capped by counting.
- `diagnose-as-dry-boot` - the health checker replays the boot order as
  non-fatal spans; the check list is the graph.

### 9. `quorum-and-recovery-procedures` (periphery scout; not in the record)

Multi-holder operations and offline repair as resumable state machines
run by humans - the half of availability the record's seal entries
assume.

  cancel discards all progress; new shares are invalid until verified.
- `cancel-leaves-prior-state-valid` - every quorum ritual can be
  abandoned with nothing lost.
- `migration-lock-in-source` - the lock lives in the source backend;
  file-locked engines are exempt; reserved keys are never copied.
- `single-node-recovery-resize` - recovery shrinks the cluster to one
  because no quorum can form; reforming is part of the exit.
- `non-persisted-recovery-token` - issued like root, never stored;
  restart means regenerate.
- `pick-highest-applied-index` - repair from the node with the largest
  applied index, read while all are sealed.
- `snapshot-restore-force-guard` - refuse a snapshot from a different seal
  without an explicit override.

## Proposed laws (director mints; ≥2 scouts or ≥3 sites each)

1. **The record precedes the effect.** Write the marker, the index, the
   WAL, the audit line before the action, and refuse the action if the
   record cannot be written. Sites: `token_store.go:1561-1565`,
   `namespace_store.go:468-481`, `self_init.go:27-29`, `audit_broker.go:145-168`,
   `database/path_creds_create.go:115-120`, `operator_migrate.go:220`.
   Nearest existing anchor: `creation-names-reaper` (different claim).
2. **Taint before you remove; only rollback and revoke may cross a taint.**
   `routing/router.go:301-302`, `mount.go:433-440`, `token_store.go:1649-1656`.
3. **Forward on what the handler will do, not on the verb.**
   `barrier/aes_gcm.go:808-811`, `request_handling.go:1239`,
   `sdk/framework/backend.go:245-256`, `pki/path_revoke.go:208-210`.
4. **Cancel discards partial progress and leaves the prior state valid;
   restore on failure; a transaction that touched nothing leaves no
   trace.** `operator_rekey.go:727`, `keysutil/policy.go:1884-1912`,
   `raft/transaction.go:586-593`, `cache.go:394-395`.
5. **Most-specific rule wins, and the ladder is stated once.**
   `quotas.go:475-479`, `user-lockout.mdx:38-48`, `api/env.go:27-33`.
6. **Limits are derived, not chosen.** `raft.go:85-86, 168-176`,
   `cache.go:22-24`, `logical/storage.go:30-33`, `keyring.go:17-22`.
7. **What must be readable before unseal lives in plaintext and config,
   never behind the barrier or in a storage-backed catalog.** `seal.go:26-40`,
   `plugin_catalog.go:359`, `audit.go:45-50`.
8. **Same error, same time, for every credential failure.**
   `approle/path_login.go:109-237`, `userpass/path_login.go:90-101`,
   `cert/path_login.go:320`.
9. **A user-authored program returns the finished object or a refusal.**
   `pki/path_issue_sign.go:845-878`, `jwt/path_cel_login.go:203-224`.
