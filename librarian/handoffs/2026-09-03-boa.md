## Subjects (nine), with technique lists and anchors

### 1. `object-shape-representation`

Objects carry a shared layout descriptor from a transition tree so property access is a
pointer compare plus an index; every structure in the model is bounded by a stated constant
and every weak edge is pruned on a counter.

Techniques (5):
- `transition-tree-with-shared-table` - reuse the transition and share the property
  table when two objects add the same key with the same attributes from the same shape;
  fork the table only on divergent insertion; bound lookup by the shape's own property
  count; delete by rollback-and-replay. `docs/shapes.md:14-15,130-138,187,218-220`;
  `core/engine/src/object/shape/property_table.rs:95-118`;
  `shape/shared_shape/mod.rs:214-245,335-413,435-450`.
- `weak-forward-transitions-with-counted-prune` - forward transitions are weak; prune on
  a wrapping 8-bit counter (every 256 insertions) and on any upgrade miss, never per
  insertion. `docs/shapes.md:148-150`; `shape/shared_shape/forward_transition.rs:10-17,29-37,57-66`;
  `shape/shared_shape/tests.rs:5-58`.
- `dictionary-mode-fallback` - at 1,024 transitions from the root convert to a unique
  shape; in unique mode insert mutates in place but delete, width change and prototype
  change mint a new identity because caches key on identity. `shape/mod.rs:79-83,109-120`;
  `shape/unique_shape.rs:84-90,219-229`; `object/jsobject.rs:211-227,236-256`.
- `polymorphic-inline-cache-with-weak-shapes` - one cache per access site minted by the
  compiler; weak shape references compared by address; capacity 4 then a megamorphic
  latch; cacheability decided during the prototype walk (first prototype yes, deeper no,
  foreign receiver no, proxy never). `core/engine/src/bytecompiler/mod.rs:1010-1016`;
  `vm/inline_cache/mod.rs:16,65-84,86-113`; `vm/opcode/get/property.rs:40-60`;
  `object/shape/slot.rs:108-119`; `object/internal_methods/mod.rs:686-690,869-875`;
  `builtins/proxy/mod.rs:472`.
- `monotonic-typed-element-storage` - start at dense 32-bit ints; widen to floats, to
  boxed values, to a sparse map, to a sparse descriptor map on the first value that does
  not fit; never narrow; a float that round-trips through int stays int; the state is
  observable from the guest. `object/property_map.rs:36-59,172-178,280-298,374-408,743-745`;
  `vm/opcode/push/array.rs:53-63,96-100`; `docs/boa_object.md:166-192`.

Neighbours to bound against: `client-architecture/client-fetch-cache` (admission and
keys for fetched data - not layout sharing); the sibling `guest-execution-bounding` (owns
limits, not layout). Web hardening: 2 searches (hidden-class and inline-cache literature).
Constants for the golden path: 1,024; 256; 4 entries; slot widths 2/1; initial table
capacity 4 (`shared_shape/mod.rs:180-181`).

### 2. `engine-string-representation`

An immutable string is a thin pointer whose target begins with an inline vtable;
encoding, length and kind are fixed at construction; well-known names never allocate;
substrings never copy; the compiler compares identifiers as integers.

Techniques (5):
- `inline-vtable-thin-handle` - the vtable is the allocation's first field so the handle
  is one pointer; length is a field, not a call, because the string is immutable;
  equality and hash by content. `docs/string.md:11-29`; `core/string/src/vtable/mod.rs:15-39`;
  `core/string/src/lib.rs:144-145,758-777,885-910`; `vtable/sequence.rs:13-27`.
- `narrowest-encoding-at-construction` - one-byte encoding if every unit fits, else
  two-byte; decided once, never re-encoded; the interner records the same flag at intern
  time. `lib.rs:819-836`; `core/string/src/type.rs:35-39`; `core/interner/src/lib.rs:418`;
  `CHANGELOG.md:311`.
- `compile-time-static-string-table` - a const table of common names with const search
  for constants and a lazily built hash cache gated by the longest static length; every
  construction path checks it before allocating. `core/string/src/common.rs:30-73,217-235`;
  `lib.rs:742-748,839-844`.
- `zero-copy-slice-string` - a slice holds its owner strongly plus bounds and its own
  count; degenerate ranges return the static empty string. `vtable/slice.rs:8-20,30-47`;
  `lib.rs:586-596`.
- `dual-encoding-symbol-interner` - two index-aligned interners, a sentinel for text only
  the wide encoding can hold, symbols offset past a perfect-hash common set so reserved
  words are contiguous ranges, a niche-optimised symbol. `core/interner/src/lib.rs:1-11,252-258,387-425,453-456`;
  `core/interner/src/sym.rs:5-8,48-66`; `core/macros/src/lib.rs:209-222`.

Neighbours: `integration/import-normalization` (durable intermediate representation of
foreign formats - not engine-internal text). Web hardening: 1 search (small-string and
rope literature, to say when a rope beats a slice).

### 3. `embedded-tracing-collector`

A single-threaded mark-sweep collector for an engine embedded in a host that owns the
threads: roots are discovered by counting rather than registered, tracing is derived,
weak semantics are ephemerons, and collection triggers on an allocation threshold that
grows.

Techniques (5):
- `derived-trace-with-escape-hatches` - derive tracing for every heap type; explicit
  escape hatches for untraced fields, plain data, and layout-cast types; the derive
  replaces destructor with a finalizer that runs only when the collector says it is safe.
  `core/macros/src/lib.rs:302-365,409-427`; `core/gc/src/lib.rs:95-121`; `core/gc/src/trace.rs:63-113`.
- `root-discovery-by-counting` - count heap-internal references in a pre-pass; a node is
  a root iff internal count < total; saturate the internal count and panic on total
  overflow so a live object can never read as unrooted. `core/gc/src/internals/gc_header.rs:40-63,76-96,102-110`;
  `lib.rs:280-298`; `CHANGELOG.md:196,1104`.
- `mark-finalize-remark-sweep` - mark, finalize the unreachable, mark again because
  finalizers resurrect, sweep under a guard that forbids dereferencing; tracing is a
  queue, not recursion. `lib.rs:209-278,446-496`; `trace.rs:20-56`; `internals/vtable.rs:5-59`.
- `ephemeron-fixpoint-marking` - trace a value only if the box and its key are marked;
  iterate the pending list to a fixpoint; weak references are ephemerons with unit
  value; weak maps cleared after sweep. `internals/ephemeron_box.rs:139-164`; `lib.rs:341-417,256-273`;
  `pointers/weak.rs:4-12`; `internals/weak_map_box.rs:8-39`; `test/weak.rs:144-231`.
- `allocation-threshold-growth-policy` - collect above a byte threshold (1 MiB); if still
  above 70% afterwards, raise the threshold to bytes/70*100; shrink bookkeeping vectors
  after collection. `lib.rs:61-72,188-201,275-277`; `CHANGELOG.md:948`.

Neighbours: none in the corpus; bound against the sibling `engine-host-contract` (which
owns the untraceable-jobs rule - cite it as a consequence, do not restate it). Web
hardening: 2 searches (ephemeron semantics; generational vs non-moving trade-off, to say
what this design refuses).

### 4. `register-bytecode-execution`

A register bytecode whose call frames own no storage: one value stack carries prologue,
arguments and register file for every frame, frames are pointers into it, suspension is a
stack split rather than a copy, and the compiler that produces it is single-pass with
patched jumps and a leak-checked register allocator.

Techniques (8):
- `frame-as-two-pointers-into-one-stack` - set the register pointer to the current top
  and resize by the register count instead of allocating per frame; return is one
  truncate; store the frame pointer once at push. `core/engine/src/vm/mod.rs:105-120,588-619`;
  `vm/call_frame/mod.rs:20-41,55-62`.
- `resume-by-frame-repush` - on yield, split the stack at the frame pointer, rebase, and
  flag "registers already pushed" so the next push skips the resize; rejects lowering to
  state machines. `builtins/generator/mod.rs:66-95`; `vm/mod.rs:592-605`; `docs/bytecompiler.md:121`.
- `placeholder-patch-jumps` - emit a sentinel address and patch by label; assert a
  handler's end is set once and never before its start. `bytecompiler/mod.rs:589-592,1125-1129,1421-1428`;
  `bytecompiler/jump_control.rs:416-431`.
- `finally-jump-table-with-reserved-fallthrough` - route break/continue/return through
  a protected region to one continuation table whose entry 0 is the fallthrough because
  the index register starts at 0; replay pending actions per record. `jump_control.rs:21-68,597-642`;
  `CHANGELOG.md:370`.
- `handler-ranges-with-environment-depth` - handlers are half-open ranges with an
  environment count; find the innermost by reverse scan; truncate environments on
  unwind. `vm/code_block.rs:75-97,305-311`; `vm/mod.rs:646-663`; `jump_control.rs:402-414`.
- `leak-checked-register-allocation` - a register handle that panics on drop unless
  deallocated or persistent; low registers reserved for the undefined value and the
  promise capability. `bytecompiler/register.rs:62-77,141-150`; `vm/call_frame/mod.rs:114-119`.
- `fixpoint-pass-with-iteration-cap` - iterate an optimisation pass until unchanged,
  cap at 10, and report mutating and checking passes separately. `core/engine/src/optimizer/mod.rs:17-34,62-87,105-128`.
- `dce-refuses-hoisted-declarations` - never eliminate a branch containing hoisted
  declarations, because hoisting makes the dead branch observable. `optimizer/pass/dead_code_elimination.rs:10-76`.

Neighbours: sibling `guest-execution-bounding` (owns every limit and the budget loop;
this subject owns the frame and the compiler); `engineering-process/build-and-release/test-harness`
(`approval-snapshots-with-guarded-update` already covers bytecode snapshot tests - cite,
do not restate; `tests/insta-bytecode/README.md`). Web hardening: 2 searches (register vs
stack bytecode; exception-table designs). Constants: two dispatch tables of 256 with 61
reserved (`vm/opcode/mod.rs:410-457,2147-2267`); prologue 2; persistent registers 0-4.

### 5. `guest-execution-bounding`

How an interpreter enforces the ceilings it can count - frames, stack slots, loop
back-edges, instructions, backtrace depth - as failures the guest cannot catch, and how
it yields cooperatively to a host executor without taxing the synchronous path.

**Boundary sentence you must carry, from this side:** the security subject
`untrusted-extension-host` says what an in-process sandbox cannot contain and, in its
`capability-subtraction-sandbox` technique (amended this run), that where the runtime
counts, the ceiling set is not empty and is published as counted versus uncounted; this
subject owns the *mechanism* of counting and stopping, and nothing about reach or grants.
Link that technique from the golden path (`../../../security/untrusted-extension-host/techniques/capability-subtraction-sandbox.md`).

Techniques (6):
- `cost-budget-cooperative-yield` - every opcode declares a static cost; the async loop
  decrements a budget through a *second* dispatch table and yields at zero; the sync
  loop pays nothing; default budget 256 with a stated "clock cycle" caveat.
  `vm/opcode/mod.rs:127-132,420-457`; `vm/mod.rs:953-986,1037-1055`; `core/engine/src/script.rs:185-215`.
- `uncatchable-limit-errors` - a limit error is an engine-class error that catchability
  rejects; skip every handler, pop to the first early-exit frame, return to the host.
  `core/engine/src/error/mod.rs:304-317,818-822,850-854`; `vm/mod.rs:803-837`; `vm/tests.rs:556-595`.
- `count-host-reentry-in-recursion-depth` - native code that re-enters the run loop
  (accessors, promise callbacks) adds to the depth, because guest frames alone
  undercount and the process stack overflows first. `vm/mod.rs:90-95,1017-1033`;
  `object/operations.rs:451-461`; `CHANGELOG.md:88`.
- `back-edge-iteration-counter` - count per frame with an explicit opcode placed after
  the condition and before the body so every loop kind counts identically; extend into
  builtins that loop natively. `bytecompiler/statement/loop.rs:135-138`;
  `vm/opcode/iteration/loop_ops.rs:13-30`; `vm/tests.rs:313-436`; `CHANGELOG.md:199`.
- `instruction-budget-for-fuzzing` - terminate by instruction count behind a feature
  gate and treat time-over-budget as a defect signal, not a timeout. `vm/mod.rs:777-801`;
  `tests/fuzz/fuzz_targets/vm-implied.rs:12-18`; `tests/fuzz/README.md:52-56`. State the
  boundary with `test-input-generation/stage-ordered-fuzz-targets` (landed this run):
  that technique owns *where* the budget sits in a fuzz portfolio; this one owns how the
  interpreter implements it.
- `bounded-shadow-backtrace` - a parallel stack of (pc, source position) capped by a
  backtrace limit, captured before handler search so internally caught errors keep
  positions. `vm/shadow_stack.rs:10-58`; `vm/mod.rs:615-616,804-813`.

Defaults for the golden path: recursion 512, stack 10,240, backtrace 50, loop unlimited
(`vm/runtime_limits.rs:17-27`); guest-settable via the debug object
(`docs/boa_object.md:278-345`). Web hardening: 1 search (cooperative scheduling in
embedded interpreters).

### 6. `engine-host-contract`

An embedded language engine exposes every host-varying behaviour as a named seam whose
obligations are stated by the specification, defaults to the specification's default,
and is filled by exactly one host; the engine owns no event loop, no filesystem and no
clock of its own.

Techniques (6):
- `spec-mirrored-hook-surface` - one method per specification host hook; the spec's
  requirements in the override's own doc; the spec default as the body. `core/engine/src/context/hooks.rs:11-14,60-226`;
  `module/loader/mod.rs:155-168`; `job.rs:579-589`.
- `null-and-blocking-executors` - ship a no-op executor (disables promises) and a
  blocking FIFO that bails on first error; the host brings the real loop. `job.rs:13-19,795-846,863-868`;
  `context/mod.rs:1225-1227`. Record the deviation: `job.rs:16-17` says the null executor
  is the default; the builder defaults to the FIFO.
- `untraceable-jobs-as-roots` - jobs do not implement tracing, so captures are roots for
  the job's life and a job can never live in the heap. `job.rs:21-27`; `module/synthetic.rs:45-53`.
- `idle-aware-job-loop` - one task per job kind with a wake event; exit when all
  foreground tasks are idle; cleanup jobs only in idle gaps; stop outranks everything;
  1 ms minimum timer; one macrotask per microtask drain. `cli/src/executor.rs:19-30,55-67,206-211,258-310`;
  `examples/src/bin/smol_event_loop.rs:127-135,243-245`; `CHANGELOG.md:116`.
- `contained-async-module-loader` - one async hook with the (referrer, specifier)
  idempotency stated; normalise without canonicalising (the file need not exist);
  refuse any result outside a root canonicalised once; an idle loader for hosts with no
  filesystem; an embedded loader with a byte budget. `module/loader/mod.rs:23-33,87-108,143-198,322-338`;
  `module/loader/embedded.rs:12-19,40-58`.
- `monotonic-and-wall-clock-split` - a monotonic clock the engine assumes for timers and
  a wall clock only for dates, a fixed clock for tests; a build-time check that a
  blocking agent is alone on its thread. `context/time.rs:146-159,207-212`;
  `context/mod.rs:1165-1208`.

Neighbours (read all three, one boundary sentence each): `llm-agent/runtime-and-io/agent-runtime-assembly`
(`honest-hook-registry`: many contributed callbacks with timeouts; here one implementor
per hook, obligations authored by a standards body); `security/untrusted-extension-host`
(whether an in-process runtime is an isolation tier; here a trusted host filling seams -
the loader's containment is the one touch point); `backend-platform/work-execution/job-coordination`
(durable jobs that outlive their executor; here in-memory, run-once, untraceable).
Web hardening: 1 search (host-hook designs across engines).

### 7. `native-guest-interop`

Host data and host functions cross into guest objects only through typed,
alignment-checked cells and conversion traits whose safe surface is restricted by a type
bound, with the unsafe surface spelled as such.

Techniques (6):
- `aligned-native-data-cell` - a C-layout cell forced to 8-byte alignment with a
  compile-time assertion; larger alignments boxed by rule. `docs/native_object.md:17-32`;
  `core/engine/src/object/datatypes.rs:214-256`; `object/mod.rs:168-184`.
- `typed-downcast-access` - reach host data only by typed downcast; per-context host
  state in a type-id-keyed map with a stated invariant. `docs/native_object.md:47-54`;
  `core/engine/src/host_defined.rs:8-17`; `context/mod.rs:575-582,612-640`.
- `copy-closure-safe-api` - the safe constructor accepts only copyable closures or
  explicitly traced captures; anything else is spelled unsafe, because the collector
  cannot see captures. `native_function/mod.rs:118-130,229-276`; `interop/mod.rs:11-13,55-66`.
- `explicit-lossy-conversion` - implement fallible conversion only where exact; refuse
  the lossy width and make the caller cast. `value/conversions/try_from_js.rs:11-34`;
  `try_into_js.rs:4-17`.
- `async-native-as-promise` - a host future becomes a guest promise by enqueueing a
  native async job that settles the resolvers. `native_function/mod.rs:167-215`.
- `class-from-impl-with-borrow-warning` - derive a guest class from an impl block and
  state in its doc that self-borrowing methods hold a runtime borrow, so re-entering
  guest code from them is a hazard; typed wrappers over builtins. `core/macros/src/lib.rs:52-93`;
  `object/builtins/mod.rs:1-3`.

Neighbours: sibling `engine-host-contract` (what the seams are; this subject is how a
value crosses one); `security/untrusted-extension-host` (what an extension may reach;
this is how any host value is represented once reached). Web hardening: none.

### 8. `standards-layered-runtime`

Runtime crates are layered by standards body: the engine is the language specification
only; one crate per external standard, depending only on the engine; a non-standard
extras layer above; the executable as a thin assembler - so a dependency choice is a
conformance claim.

Techniques (6):
- `crate-per-standards-body` - each standard's API set in its own package depending only
  on the engine, because a feature flag cannot be depended upon as a claim. `core/wintertc/src/lib.rs:1-14,53-82`;
  `CHANGELOG.md:58,376-384`.
- `status-header-per-api` - every API module states which standard requires it and a
  marker while it still lives in the extras layer; the package is a claim in progress
  and says so. `core/wintertc/src/timers/mod.rs:1-7`; `abort/mod.rs:9-11`; `events/mod.rs:10-16`;
  `fetch/mod.rs:9-11`; `core/runtime/src/console/mod.rs:14-16`. Record the deviation:
  `core/wintertc/src/lib.rs:68-70` admits one registrar takes no realm while every
  sibling does.
- `baseline-plus-extension-tuple` - registration is a fixed baseline plus caller
  extensions composed as a tuple trait up to 12, with a late-registration door.
  `core/runtime/src/lib.rs:167-200`; `core/runtime/src/extensions.rs:8-18,149-173`.
- `backend-parameterised-web-api` - the API is the standard's; the I/O backend is a host
  trait (logger, fetcher, message sender, process provider); a backend error becomes a
  guest exception. `extensions.rs:86-122,136-147`; `core/runtime/src/fetch/mod.rs:38-58`;
  `message/mod.rs:29-44`; `process/mod.rs:28-37`; `console/mod.rs:56-63`.
- `re-export-preserves-import-path` - migrate an API down a layer by re-exporting it
  under its historical name. `core/runtime/src/lib.rs:94-108,143`.
- `cli-as-thin-assembler` - the executable only picks executor, loader root, blocking
  flag and runtime. `cli/src/main.rs:570-590,830-843`.

Neighbours: `engineering-process/codebase-stewardship/module-design` (depth and seams

### 9. `guest-language-introspection`
