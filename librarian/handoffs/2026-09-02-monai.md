## Scout report C - inference, metrics, library infrastructure (`monai/inferers`, `monai/metrics`, `monai/losses`, `monai/networks` blocks/layers/utils, `monai/utils`, `monai/apps`, tests)

### D8 - Windowed inference over inputs larger than memory: CONFIRMED, with four corrections

Confirmed as reconstructed: roi windows, overlap, constant vs gaussian blending, padding when roi exceeds input, `sw_device` vs `device`, `cpu_thresh`, `buffer_steps`/`buffer_dim`, PatchInferer/SliceInferer as modular generalization, optional `condition` conditioning.

1. **The blending rule is a two-tensor accumulate-then-divide.** Every window's prediction is multiplied by the importance map `w_t` and added into `output_image_list`, while the same `w_t` is added into a separate `count_map_list` at every slice position. The final step is `output /= count_map` (`monai/inferers/utils.py:325-326`). A normalized weighted average, exact regardless of overlap geometry; `constant` mode is the special case `w == 1`. The count map is built once, on first window.
2. **The gaussian map is floor-clamped.** `min_non_zero = max(min(map), 1e-3); clamp_(map, min=min_non_zero)` (`monai/data/utils.py:1108-1110`). Zero weight anywhere would make the count map zero and produce NaN on divide. Rule: importance weights must be strictly positive everywhere the window covers.
3. **The window/network shape constraint is an arithmetic contract, not enforced.** The predictor may emit a different spatial size than it consumed; the code derives `z_scale = seg_shape / roi_size` and rescales both the weight map (`F.interpolate(..., "nearest-exact")`) and every output slice coordinate. Documented caller obligation: `overlap*roi_size*output_size/input_size` must be an integer per dimension (`monai/inferers/utils.py:69-71`). Multi-output (tuple/dict) supported with per-output resolutions, flattened and repacked with sorted dict keys.
4. **`SlidingWindowInfererAdapt` is a self-tuning OOM ladder.** On out-of-memory it degrades: GPU stitching -> buffered stitching (writing back `self.cpu_thresh = numel-1` so the next similar image skips the failed rung) -> halve `buffer_steps` repeatedly -> CPU stitching, at most 10 trials; auto-picks `buffer_dim` as the longest spatial axis when >= 2x the last (`monai/inferers/inferer.py:641-694`). A memory policy that learns from failure at runtime.

Also: buffered mode enables non-blocking copies only after proving the buffers do not overlap (`utils.py:210-215`); with non-blocking on, the output is allocated with `torch.empty` because every voxel is written exactly once (`utils.py:302`); padding removal re-derives the crop in output coordinates via `zoom_scale` (`utils.py:333-344`).

Forces: volumes exceed accelerator memory by 1-2 orders of magnitude; the network is fixed-input-size; seams are visible; the same code must run on a laptop and a large server. Buys: arbitrary-size input with a fixed-size network; seam-free output; graceful degradation; identical results across stitching devices. Rejects: adaptive network input shapes; validating the roi/output arithmetic (documented as the caller's obligation); streaming out-of-core output in this lane (the disk-backed merger exists only in `PatchInferer`).

Anchors: `monai/inferers/utils.py:243-256` (window slicing, batching, condition co-slicing); `:295-311` (count map with `z_scale`); `:325-326` (the blend); `monai/data/utils.py:1094-1110` (gaussian map and clamp); `monai/inferers/inferer.py:641-694` (OOM ladder); `monai/inferers/utils.py:410-421` (`_get_scan_interval`: `int((1-overlap)*roi)`, floored to >= 1).

### D9 - Optional dependencies invoked lazily: CONFIRMED; the 1.6.0 leak fix located

`optional_import(module, version, name, ...) -> (module_or_lazy_proxy, bool)`. On failure a `_LazyRaise` proxy's `__getattr__`/`__call__` raise `OptionalImportError` carrying the reconstructed command, the original exception text, an install-docs link, and the original traceback (`monai/utils/module.py:402-427`).

Deepening: `as_type` selects when the proxy detonates - `"default"` (first call), `"decorator"` (constructor succeeds, second call raises), anything else returns a lazy class usable as a base class (`module.py:340-343`). A deferred failure has to be shaped like the syntactic role the missing symbol plays, or the module fails at import anyway.

The 1.6.0 memory-leak fix (`monai/utils/module.py:390-393`): the traceback is formatted to a string and then `import_exception.__traceback__ = None`. Because `_LazyRaise` closes over the string and lives for the process lifetime, retaining the live traceback would pin every frame of the failed import forever. `CHANGELOG.md:46`, #8782.

Proof of the minimal install: `tests/min_tests.py:31-224` - a 190-entry `exclude_cases` list followed by two self-validating assertions: no duplicates (`:225`), and every excluded name must have matched a real test file or the run fails listing the stale entries (`:239-240`). The exclusion list cannot rot.

Forces: the install must be small enough for a container and complete enough for a workstation; a missing package must not break the top-level import; the error must be actionable at the point of use. Buys: one import graph, N install profiles; a testable minimal install; errors naming the exact package and its install page. Rejects: `try/except ImportError: pass`; import-time hard failure; a drifting exclusion list.

Anchors: `monai/utils/module.py:389-395`, `:409-427`, `:454-490` (`require_pkg` with `raise_error=False` warn-only); `tests/min_tests.py:225,239-240`; `tests/test_utils.py:231-253` (`SkipIfNoModule`/`SkipIfModule` on `optional_import(...)[1]`); `runtests.sh:690-694` (the `--min` lane).

### Candidate subjects and techniques (scout C)

**`windowed-inference-over-oversized-inputs`** - running a fixed-input-size model across an input far larger than accelerator memory and reassembling one seam-free result.
- `overlap-weighted-stitching` - accumulate `pred*w` and `w` in parallel tensors; divide at the end; never average incrementally.
- `strictly-positive-blend-weights` - floor any tapered weight above zero so the normalizer is never zero at a covered voxel.
- `resolution-decoupled-window-mapping` - when output size differs from input size, carry a per-axis scale and rescale weights and slice coordinates rather than resizing predictions.
- `split-device-inference-and-stitching` - windows on the fast device, the canvas on the large device, two independent parameters.
- `failure-driven-memory-degradation` - on OOM step down a fixed ladder and persist the observed threshold so the next similar input skips the failed rung.
- `axis-buffered-writeback` - batch windows along one axis into a device-local buffer; non-blocking transfer only after proving no overlap.

**`deferred-optional-dependency-binding`** - importing what may not be installed without failing at import and without failing silently.
- `lazy-raising-import-proxy`; `role-shaped-failure-timing`; `detached-traceback-capture`; `minimal-install-test-lane` (assert no duplicates and no stale entries); `capability-gated-test-skips` (execute a probe, not a version string); `warn-or-raise-requirement-decorator`.
- **Phase 1 note:** overlaps `optional-dependency-degradation` (its golden path states the forces). Probably two or three techniques into that subject rather than a subject - the source-tree application already written there is the reconciliation target.

**`accumulate-then-aggregate-metrics`** - per-batch computation reduced once, correctly, across ranks and missing labels.
- `per-iteration-buffering`; `nan-as-undefined-not-zero` (return the not-nan count alongside); `lazy-rank-synchronization` (pad to evenly divisible, cache); `reduction-axis-vocabulary` (`mean_batch`, `sum_channel`); `detached-buffer-reads`.
- **Phase 1 note:** `nan-as-undefined-not-zero` converges with the bundle's law `unknown-is-not-a-value`; cite, do not re-mint.

**`declarative-tensor-op-conventions`** - a family of losses/layers configurable by flags whose interactions are validated up front.
- `mutually-exclusive-activation-flags`; `separately-smoothed-ratio-terms`; `degenerate-flag-warning-not-error`; `dimension-keyed-component-factory`; `constructor-introspecting-adapters`; `state-restoring-context-manager`.

### Five densest blocks (scout C, verbatim, with anchors)

A. The blending rule - `monai/inferers/utils.py:295-311` and `:325-326`: allocate output (`torch.empty` if non-blocking, else zeros) and a count map; for every slice add `w_t` into the count map (rescaled by `z_scale` when set); finally `output_image_list[ss] /= count_map_list.pop(0)`.

B. Positive-weight clamp - `monai/data/utils.py:1094-1110`: separable 1-D gaussians with `sigma = patch_size * sigma_scale`, outer-multiplied per axis, then `min_non_zero = max(min(map), 1e-3); clamp_(map, min=min_non_zero)`.

C. The OOM ladder - `monai/inferers/inferer.py:667-690`: on a runtime error whose type name contains `OutOfMemoryError`: if GPU stitching, disable it and set `self.cpu_thresh = numel - 1`, then buffered stitching unless skipped; else if `buffer_steps > 1`, halve; else fall to CPU stitching.

D. The leak fix and lazy failure - `monai/utils/module.py:389-395, 409-419`: format the traceback to `tb_str`, set `import_exception.__traceback__ = None`; `_LazyRaise.__init__` composes the message from the reconstructed command, the install-docs link and `tb_str`, and stores an `OptionalImportError` raised on any attribute access or call.

E. Archive extraction guard - `monai/apps/utils.py:137-166`: reject symlink and hardlink members; normalize; reject absolute paths and `..` segments; then `commonpath([realpath(extract_to), realpath(full_path)]) == realpath(extract_to)` or refuse.

### What this territory does better, and what it refuses (scout C)

A generic deep-learning utility library assumes the input fits in memory, the labels are complete, and the install is whatever the requirements file says. This territory assumes none of those and pays for each with explicit machinery: inference is a memory policy (window/stitch/buffer/degrade) that under the adaptive inferer learns its own failure threshold at runtime; metrics treat "undefined for this sample" as NaN carried through NaN-weighted reductions with a returned not-nan count, so an absent organ does not become a zero that drags a mean down; and the dependency graph is a lattice of import proxies whose failure is deferred to the exact call site, shaped to the symbol's syntactic role, and proved minimal by a self-validating 190-entry exclusion list. It refuses to be clever where cleverness is unfalsifiable: no dynamic network input shapes, no validation of the roi/output arithmetic it documents as the caller's obligation, no streamed output in the sliding-window lane, no silent degradation on a missing package, and `set_determinism` states outright that it does not cover `Randomizable` objects' independent random states.

### D2 - Traceable and invertible: CONFIRMED; the rules are written down

Developer contract at `monai/transforms/inverse.py:404-416`: inherit `InvertibleTransform`; call `push_transform` in `__call__`; `extra_info` must have the same keys whether or not `do_transform` fired and may only contain collate-compatible values (`None` forbidden); `inverse` must `pop_transform`.

Where inversion is refused or lossy: refused if pending ops leaked - `Compose.inverse` scans `applied_operations` for a `PENDING_DURING_APPLY` status written at push time and raises with the accumulated reasons (`compose.py:388-419`, `inverse.py:274-286`); refused if tracing is off (`inverse.py:341`; `set_track_meta(False)` empties the stack); identity matching degrades gracefully - `id(self)`, a `TraceKeys.NONE` skip sentinel, and under `spawn` a class-name match (`inverse.py:319-337`); `PersistentDataset` blanks ids via `reset_ops_id` (`monai/transforms/utils.py:1850`) because cached tensors outlive the instances that made them. Lossy by design: `Invertd(nearest_interp=True)` rewrites the recorded interpolation to nearest (`post/dictionary.py:902`); `OneOf`/`RandomOrder` invert only the branch or order they recorded (`compose.py:547-564, 638-661`); test-time augmentation only warns when a random transform is not invertible. Batch inversion is a full round trip through `decollate_batch`, a synthetic dataset and a second loader with no collation (`inverse_batch_transform.py:99-112`).

Forces: inference must be reported in the original frame; the trace must survive collate, multiprocessing, pickling. Buys: inversion as a data property, not a pipeline replay; `__getstate__` drops the thread-local tracing so transforms stay picklable (`inverse.py:73-89`). Rejects: closures or objects in the trace; inverting a batched tensor; inverting a lazily executed pipeline (`compose.py:396-400` warns and forces eager).

### D3 - Lazy resampling: CONFIRMED; the forcing rule is one function

`apply_pending_transforms_in_order` (`monai/transforms/lazy/functional.py:146-193`): pending ops are flushed unless the transform is a `LazyTrait`, does not declare `requires_current_data`, and is running lazily. Everything else forces evaluation - a plain `Transform`, `ApplyPending[d]` (not a `LazyTrait`, `lazy/array.py:19-26`), or a lazy transform with `lazy=False`. `requires_current_data=True` is declared by the crops that read voxels (`croppad/array.py:871,1179,1362`; `croppad/dictionary.py:536,917,1123,1282`); they still emit pending ops, they just refuse to consume stale ones. Fusion is conditional: `apply_pending` inserts an intermediate resample whenever `is_compatible_apply_kwargs` fails (mode, padding, dtype, align_corners differ; `lazy/functional.py:255-266`); `combine_transforms` supports affine-with-affine (matmul) and field-with-field (addition) and raises on a mix (`lazy/utils.py:66-79`). The `Compose(lazy=...)` tri-state: `False` default, `None` honours each transform, `True` forces (`compose.py:213-222`). `overrides` are silently ignored when lazy is false and validated against a closed keyword set otherwise (`lazy/functional.py:37, 250-252`); `execute_compose` always drains pending at the end (`compose.py:135`).

### D4 - Array/dict duality: CONFIRMED; randomness sync is a two-call idiom

A dictionary random transform calls `randomize` exactly once per sample, then passes `randomize=False` into the array transform for every key (`spatial/dictionary.py:1917-1938`: "all the keys share the same random rotate angle"). The wrapper owns the draw; the array transform is a pure function of frozen parameters. Multi-sample crops extend it: one `randomize`, then `num_samples` shallow-copied dicts with non-key entries deep-copied to preserve pass-through (`croppad/dictionary.py:1286-1299`). `key_iterator` is the sole key gate and the only place `allow_missing_keys` is honoured (`transform.py:470-491`); `allow_missing_keys_mode` is a context manager `Invertd` uses because the inverse dict has fewer keys (`transforms/utils.py:1765`); `map_items` is an integer nesting depth and `ReduceTrait` transforms opt out of mapping (`transform.py:143-153`); `Compose.flatten` refuses to inline a child with a different `map_items` (`compose.py:341-368`); `Compose.set_random_state` reseeds children from its own state (`compose.py:282-289`).

### D5 - Deterministic-prefix caching: CONFIRMED, boundary rule CORRECTED

The boundary is not "first `Randomizable`". The predicate, identical in three places (`dataset.py:337-339, 359-361, 945-947`):

```python
lambda t: isinstance(t, RandomizableTrait) or not isinstance(t, Transform)
```

It keys off the trait, so a transform can declare itself uncacheable without inheriting an RNG; and any bare callable in the chain terminates the cache, because it cannot be assumed deterministic. Invalidation: `CacheDataset.set_data` refills and mandates `persistent_workers=False` (`dataset.py:854-892`); `PersistentDataset.set_data` removes the cache directory (`:317-325`); keys are a hash of the data item plus an optional hash of the transform chain documented as best-effort ("not guaranteed", `:206-210`); entries are written to a temp path then moved for atomicity under concurrent workers (`:410-424`); corrupt files are unlinked and recomputed (`:397-400`); weights-only loading means non-serializable metadata silently forces recompute (`:213-219`); threaded prefill deep-copies every `ThreadUnsafe` transform per item (`compose.py:130-131`); `copy_cache=True` deep-copies before the random suffix runs because it may mutate in place (`:951`). SmartCache's non-working cases are enumerated verbatim at `dataset.py:999-1004`.

### What this territory does better, and what it refuses (scout A)

A generic data-pipeline library treats a sample as an opaque value and the pipeline as the only place semantics live; this territory inverts that. Because the datum carries its geometry, its applied-operation journal and its not-yet-applied queue, three things become properties of the data rather than features of the framework: a pipeline can be run backwards on a tensor produced in another process by instances that no longer exist; a chain of spatial operations can be fused into one resample decided at flush time; and the cache finds its own split point by scanning for a capability marker. The framework then spends most of its remaining complexity on the seams that choice creates: collate/decollate that must rectangularize heterogeneous metadata, thread-local tracing stripped on pickle, an identity check that degrades to class-name matching under spawn, and an equivalence oracle testing the lazy path against the eager path for every transform. It refuses to invert a batched tensor, to invert a lazily executed pipeline, to accept an unknown override keyword or an unknown callable inside a cacheable prefix, to fuse an affine with a displacement field, and to pretend its transform-hash invalidation is sound. The recurring stance: a mechanism that can be wrong records why at the moment it happens and refuses loudly later, rather than degrading quietly.

### D6 - The bundle as a self-describing model package: CONFIRMED, four corrections

Confirmed: normative layout; metadata contract verbatim (symbolic `spatial_shape`, `value_range`, `is_patch_data`, `channel_def`, `required_packages_version`, `post_processed_outputs`, self-referencing `schema`); the config sigils; `BundleWorkflow` plus property dicts.

1. **The id separator is `::`; `#` is a legacy synonym** normalized away (`reference_resolver.py:206-213`). Relative references (`@#A`, `@##A`) and `%` macros are resolved *textually into absolute ids before parsing* (`config_parser.py:537-573`), so a macro can splice a fragment of another file as text before any object exists.
2. **`check_properties` is two checks.** The base class reports missing *required* properties by attribute probe (`workflows.py:256-264`); `ConfigWorkflow` additionally validates that each *optional* property, if present, is wired at the **expected reference id** (`_check_optional_id`, `workflows.py:632-661`) - the contract constrains not only that the object exists but that it is plugged into the graph where a consumer expects. `evaluator`/`val_interval` are special-cased because the validation handler's index in the handler list is unknown.
3. **Version floors are advisory.** `_examine_monai_version` (`scripts.py:314-331`) only warns when the installed version is below the bundle's; `required_packages_version` is never checked at runtime - documentation for the consumer.
4. **`PythonicWorkflow` is a hybrid, not code-first.** It still owns a config parser for hyperparameters and metadata (`workflows.py:322-331`); property lookup has a four-tier precedence - user-set, cached, meta config, then a `get_<name>()` method (`:352-373`); a required property with no getter is a hard error. The same contract honoured by a class instead of a graph; federated and AutoML consumers cannot tell the difference.

Forces: a model must travel between an author, a zoo, a labeling app, a federated client and an AutoML ensembler, none of whom can read the author's code; checkpoints carry no semantics, plain configs carry no contract. Buys: a third party can `create_workflow` on an unknown bundle and ask for `network_def`, `preprocessing`, `max_epochs` by canonical name (`scripts.py:1940-2009`). Rejects: a plugin registry or allow-list - instantiation is unrestricted `locate()` plus `eval()`, sandboxing traded for expressiveness and paid for with trust advisories (`scripts.py:949-953`; `workflows.py:38-52`).

Export freezes via `_export` (`scripts.py:1277-1338`): instantiate from config, load the checkpoint, convert, then serialize **every config file as JSON regardless of source format** keyed by basename (collision is an error), with metadata popped out as the compiled container's meta values - the artifact contains the config that produced it. `verify_metadata` (`scripts.py:1109-1123`) downloads the schema named inside the metadata (optionally hash-pinned) and validates. `verify_net_in_out` (`scripts.py:1250-1274`) is the executable half: it solves the symbolic shape with user-supplied `p`/`n`/`any` (`_get_fake_spatial_shape`, `:142-164`, only `p` and `n` allowed), forward-passes fake data, and asserts output channels and dtype match.

Reference resolution (`reference_resolver.py:107-179`): depth-first with a waiting set - a revisit is a cycle error; all `$import` statements are hoisted and evaluated first; references inside `$` expressions are rewritten to scoped locals passed as eval globals (`:311-318`); a whole-string `@x` is substituted by object, an embedded `@` in text is left alone; `_disabled_` components resolve to `None` and are dropped from their parent container (`:365-369`); run/init/finalize results are deliberately evicted so a workflow can be re-run in-process (`workflows.py:555-571`).

Anchors: `docs/source/mb_specification.rst:71,111`; `monai/bundle/workflows.py:632-661`; `monai/bundle/properties.py:11-23`; `monai/bundle/reference_resolver.py:147-165`; `monai/bundle/scripts.py:1309-1338`.

### D7 - Workflow as an event-driven engine: CONFIRMED, sharpened

The handler-versus-iteration rule, explicit in code: `_iteration` owns everything that touches tensors and gradients and leaves its result in `engine.state.output`; everything that observes or reacts goes in a handler keyed to an event. The seam is `IterationEvents` (`engines/utils.py:47-65`): `FORWARD_COMPLETED`, `LOSS_COMPLETED`, `BACKWARD_COMPLETED`, `MODEL_COMPLETED`, `INNER_ITERATION_{STARTED,COMPLETED}` - mid-iteration hook points the engine itself does not provide. Decollation and postprocessing are themselves handlers on `MODEL_COMPLETED` (`workflow.py:196-227`), registered in that order because the transforms need per-item channel-first data. Validation is triggered by a handler, not the trainer: `ValidationHandler` attaches to `EPOCH_COMPLETED(every=interval)` and calls `validator.run(engine.state.epoch)` (`handlers/validation_handler.py:66-85`); the validator is a full second workflow; `set_validator` lets config wire it after construction, which is why the bundle property `evaluator` has a reference id that is an argument name (`properties.py:100-104`). Cost: ordering is implicit in registration order; a non-scalar key metric silently skips comparison with a warning (`workflow.py:236-242`). Rejects: a bespoke loop per task; any "callback returns a value" protocol - handlers mutate state only.

Anchors: `monai/engines/workflow.py:124, 196-227, 227-262`; `monai/engines/utils.py:47-65`; `monai/handlers/validation_handler.py:66-85`; `monai/engines/evaluator.py:131-137`.

### D10 - AutoML as bundle generation: CONFIRMED, with corrections

`AutoRunner` fronts `analyze -> algo_gen -> train -> ensemble` with stage-level caching (`auto_runner.py:66-76`).

1. **The stats schema is an enum contract**: `DataStatsKeys` (`monai/utils/enums.py:580-593`) splits `stats_summary` from `stats_by_cases`; `ImageStatsKeys:596-608`, `LabelStatsKeys:611-622`. Two analyzer kinds compose it - a **case analyzer** (a transform over one sample) and a **summary analyzer** (over the list of case outputs), `seg_summarizer.py:34-42`. That two-tier split is the reusable idea.
2. **Template filling is optional and overridable**: the base `fill_template_config` returns `{}` and pre-filled configs are legitimate (`bundle_gen.py:155-170`); `export_to_disk` copies the template and fills in place, recording `fill_records = {config: {placeholder: value}}` (`:172-195`) - a provenance log of what the statistics decided.
3. **Ranking is argsort on `AlgoKeys.SCORE`** with two policies: best-N globally (`ensemble_builder.py:251-281`) or best per cross-validation fold (`:283-315`, the default).
4. **JSON serialization re-expresses the algorithm object in the config language**: `{"_target_": fqcn, "_state_": state_dict, "template_path": ...}`, reloaded through the config parser then `load_state_dict` (`auto3dseg/utils.py:328-358, 423-468`), forcing a state-dict convention and a no-arg constructor onto `Algo`; pickle survives behind `MONAI_ALLOW_PICKLE=1` with a future warning (`utils.py:678-693`).
5. **Hyperparameter search is an `AlgoGen` subclass** (`hpo_gen.py:35-63`), implemented by re-serializing a mutated algorithm per trial; only grid search on one backend is supported.
6. **Limitations are scattered**: segmentation only, a preferred label shape (`data_analyzer.py:48-55`), a silent nearest-neighbour resize under a shape-difference tolerance, per-template opt-out (`bundle_gen.py:105-114`), templates fetched from an external pinned-hash release (`bundle_gen.py:405-407`).

Buys: the AutoML output is a directory of ordinary bundles readable and runnable without the AutoML system. Rejects: a monolithic search space; opaque model objects - every intermediate is a file on disk.

### D11 - The federated client as an abstract algorithm: CONFIRMED, deepened

`BaseClient` (initialize/finalize/abort) -> `ClientAlgoStats` (+ data stats) -> `ClientAlgo` (+ train/get_weights/evaluate), `client_algo.py:17-149`. `ExchangeObject` is a dict subclass carrying weights, optimizer state, metrics, weight type, statistics, whose `summary()` reports sizes and types, never values (`fl/utils/exchange_object.py:85-101`).

What leaves the site: summary statistics only - per-case stats are written to local YAML and explicitly not returned (`monai_algo.py:250-252, 267-269`); the server pre-declares histogram bins and range so histograms are commensurable (`:231-238`); weights leave as full weights or a tagged difference, moved to CPU, NaN-checked (`:652-666`, `:77-95`); four filter hooks (`constants.py:56-59`) are the sanctioned seam for privacy, encryption and compression, a filter being `ExchangeObject -> ExchangeObject` (`filters.py:19-36`).

How bundle properties are used - the crux: `MonaiAlgo.initialize` never reads the config by hand; it sets `workflow.bundle_root` and `workflow.max_epochs`, and reads `workflow.trainer` / `workflow.evaluator` through the property protocol (`monai_algo.py:507-539`); the stats client reads `dataset_dir`, `train_dataset_data`, `val_dataset_data` the same way (`:227-259`), which is why those exist as properties. It also rewrites the graph: `disable_ckpt_loaders` flips `_disabled_` on any checkpoint loader in the validation handlers (`:98-103`) so a local checkpoint cannot override the round's global weights. Round accounting rides on engine state (`:599-601, :659`). Accepted cost, stated in code: the federated system provisions the whole app directory including configs, so a compromised server gets code execution with no human in the loop (`monai_algo.py:38-55`).

### What this territory does better, and what it refuses (scout B)

A generic experiment-config framework binds parameters to a script that already knows what it is doing; this territory binds a contract to an artifact that a stranger must operate. Three things fall out. The configuration is a first-class object graph with a resolver - cycle detection, lazy per-id instantiation, cross-file macro splicing, disabled components that vanish from their parent - so it expresses a training program, not just settings. The metadata is machine-actionable: a symbolic shape grammar plus a solver plus a forward-pass check makes "does this bundle accept my data" a command rather than a reading exercise. And the property contract decouples consumers from config layout: the federated client and the AutoML ensembler read `workflow.trainer` and `workflow.train_dataset_data` by name, and `check_properties` tells them up front whether an unseen bundle can be driven - which is why a code-first workflow could be added in 1.5 without touching either consumer. It refuses deployment: bundles "focus on description, code definition, application, usage" while application packages "focus on deployment, containerisation, integration into existing clinical systems" (`docs/source/bundle_intro.rst:23-45`); a bundle is deliberately lighter, includes training scripts, and leaves clinical-database interfacing to the package that wraps it. It equally refuses to sandbox: `_target_` resolves any importable callable with no allow-list and `$` goes to eval, a choice now documented as a trust boundary in three separate advisories rather than papered over.
